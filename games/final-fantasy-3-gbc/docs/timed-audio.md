# VGZ 타이밍 재생 테스트

기준일: 2026-11-22. 개발용 사운드 단독 테스트이며 완성 게임의 오디오 엔진이 아니다. 이번 경로는 VGZ를 입력으로 변환·컴파일·실행하며 새 녹음을 만들지 않는다. 기존 ROM 입력 비교 실험과 WAV 파일은 보존한다.

후속 청취에서 사용자가 잡음과 음색 차이를 지적했다. 타이밍 검증 통과와 음질 미해결을 구분하며, 사용자 결정에 따라 음색 조정을 보류했다. [판단 기록](audio-backlog.md), [원작 제어부 이식](audio-control.md)을 따른다.

## 구현 범위

제공 팩의 59개 트랙을 2 MiB CGB 전용 MBC5 ROM에 넣는다. 49개는 원본 루프 포인터로 반복하고, 10개는 끝에서 정지한다. NES 레지스터 이벤트 스트림은 1,182,025바이트, 73개 데이터 은행에 걸쳐 저장된다. 원본 쓰기 382,733개의 순서·레지스터·값을 유지하고 시간만 출력 타이머 단위로 변환한다. 최대 한 시각의 소스 쓰기는 27개다.

`tools/timed-stream.mjs`는 지연 u16, 개수 u8, NES 레지스터/값 쌍을 만든다. 개수 254는 루프 시작 표식, 255는 구간 종료이며, 긴 대기는 30,000틱 이하로 나눈다. 같은 원본 시각에도 루프 앞/뒤 쓰기가 있을 수 있어 바이트 오프셋으로 경계를 구분한다. 반복 시 채널 상태를 초기화하지 않는다. 루프 길이의 소수 나머지를 누적하여 반복 횟수에 따라 시간이 계속 어긋나지 않게 한다.

CGB 배속 CPU와 TAC=5, TMA=128로 4096 Hz 타이머를 사용한다. 1틱은 약 0.244141ms다. 각 구간 내 시각 내림은 1틱 미만이고, 루프 시작 위상과 구간 내 상대 시각을 합친 원본 대비 오차는 2틱 미만이다. 인터럽트 진입·레지스터 쓰기 자체의 틱 내부 지연은 별도다. 샘플 단위/CPU 사이클 단위의 완전한 NES 파형 재현을 뜻하지 않는다.

메인 루프가 NES 상태를 GBC 레지스터 쓰기로 미리 계산하고 32×64바이트 링 버퍼에 넣는다. 타이머 인터럽트는 준비된 쓰기만 실행한다. 인터럽트에서는 ROM 은행을 바꾸지 않는다. 출력 패킷이 23개 쓰기를 넘으면 오류로 정지한다. 개발 초기의 재생 시각 직접 계산 방식은 수 ms 지연과 DAC 펄스 늘어남이 검출되어 채택하지 않았다.

소스 쓰기는 모두 순서대로 해석하지만 같은 출력 틱 안에서는 갱신된 채널 상태와 트리거를 합쳐 GBC 쓰기를 만든다. 따라서 틱 내부의 원래 NES 쓰기 간격까지 보존하지는 않는다.

펄스 음정은 팩의 NES 클록 1,789,772 Hz를 기준으로 변환한다. triangle은 CH3 파형, noise는 CH4 근사 주기를 사용한다. 소프트웨어 스윕은 약 120 Hz로 처리한다. 하드웨어 엔벌로프·길이 카운터·DPCM·다른 APU 프로필은 지원 범위를 벗어나면 빌드에서 거절한다. 같은 타이머 틱으로 양끝이 합쳐지는 DAC 펄스도 거절한다.

NES 직접 DAC 타격음은 CH4 버스트로 근사하되 원본 이벤트의 시작과 끝을 각각 예약한다. 이 길이 보존은 음색 동일성의 증명이 아니다. 볼륨 변경의 위상 재시작, duty/노이즈 특성, 스윕의 프레임 시퀀서 위상 등에도 차이가 남는다. SELECT는 정지 상태에서만 이 근사 후보를 전환한다.

## 실행 및 검증

프로젝트 폴더에서 실행한다. VGZ 폴더와 GBDK는 사용자 로컬 입력이다.

```powershell
node tools/build-timed.mjs --dir "D:/private/ff3-vgz" --gbdk "D:/tools/gbdk"
node tools/build-timed-verifier.mjs
node tools/verify-timed.mjs
```

빌드는 컴파일러 해시, 원본 이벤트의 링크 결과, MBC5/CGB 헤더, ROM 크기와 체크섬을 검사한다. `local.json`에서 MesenCore와 .NET 8 경로를 지정한다. `--track 3 --loops 2`는 특정 곡의 반복을, `--track 3 --seconds 6`은 제한 구간을 검사한다. 기본 명령은 전 트랙의 두 번째 반복 경계 또는 유한 곡 끝까지 실행한다.

기본 병렬 수는 4이며 `--jobs 1`로 순차 실행할 수 있다. 각 곡은 설정·출력·에뮬레이터 홈 폴더를 따로 사용한다. `--reuse`는 ROM·에뮬레이터 해시, 곡 번호, 반복 목표와 실행 상한이 일치하는 관측만 다시 대조한다. 일치하지 않으면 해당 곡을 새로 실행한다. 이 검사는 로컬 원시 증거를 신뢰하는 개발 도구이며 서명된 증거 검증기가 아니다.

네이티브 검증기는 녹음 API를 선언하거나 호출하지 않는다. 디버거로 재생 요청 변수를 설정하고 에뮬레이터를 실행한다. 안정된 경계에서 준비된 NES 상태와 실제 소비한 패킷의 쓰기 수·순서 해시·루프 수를 독립 JS 디코더와 대조한다. 타이머 드리프트, 지연, 버퍼 고갈, DAC 펄스 길이도 검사한다. 개입은 곡 선택/시작에 한정되며 원본 게임의 호출 경로 검증은 아니다. 실제 버튼 경로는 별도 부팅·선택·재생·정지·설정 전환·재시작으로 확인한다.

검증 ROM SHA-256: `6f4fc6a89cc7a04ec0fbd9f39e78262d98da966dd71b9dc9e7a330cb3618618e`.

검증 환경: GBDK 4.5.0, Node.js 20.11.1, .NET SDK 8.0.424, Mesen CE 커밋 `20ba206cef5ba207c21203176d02cb9f43dda9fb`, emucap patchset `2e5e6e9db63a24b3fc549f026ce7f4d69b7aa539bc859b537a002cdc116210dd`. MesenCore SHA-256는 `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.

공개 소스 allowlist만 빈 별도 폴더에 복사하고 로컬 VGZ/GBDK 경로를 지정한 재빌드에서 동일한 ROM 해시를 확인했다. 기존 7개 구간의 NES/GBC 비교 WAV 14개와 초기 사운드 ROM도 이전 기록의 해시를 유지했다.

최종 집계는 로컬 `evidence/timed/verification-all.json`에 저장했다. 위 ROM에서 전 트랙이 통과했다.

| 검사 | 결과 |
|---|---|
| 반복 곡 | 49/49, 각각 두 번째 반복 경계 도달 |
| 종료 곡 | 10/10, 끝에서 정지 |
| 준비/소비 상태 대조 | 3,594개 안정 경계 관측 일치 |
| 예약 시각 지연 / 버퍼 고갈 | 0틱 / 0건 |
| CPU 클록 대비 타이머 경과시간 차이 | 절댓값 최대 0.198365ms |
| 완료된 DAC 펄스 | 735개, 예약된 틱 길이 대비 오차 0틱 |
| 가장 짧은 출력 DAC 펄스 | 2틱, 약 0.488281ms |
| 회귀 테스트 | 13/13 통과 |
| 공개 소스 별도 재빌드 | ROM 바이트·해시 동일 |

DAC 길이 오차 0틱은 **양자화된 예약 시각 대비** 결과다. 원본 샘플 시각 대비 오차와 틱 내부 인터럽트 지연은 위에 명시한 범위로 남는다. 원시 관측은 곡별 JSON에 보존하며 소스 이벤트·메모리 내용을 포함하므로 업로드하지 않는다. 재생 검사 통과는 음질 승인, 실기 검사, 다른 에뮬레이터와의 독립 검증, 화면 처리와 함께 돌리는 CPU 예산 검사를 대신하지 않는다.

## 다음 이식 단계

VGZ는 전체 곡과 타이밍의 비교 기준으로 유지한다. 팩의 59개 파일은 원작 음악 65슬롯이나 효과음 97슬롯과 일대일 대응하지 않는다. 원본 ROM 드라이버에서 효과음 우선순위·음악 채널 점유/복원·곡 변경·페이드의 의미를 가져와 이 출력 계층에 연결해야 한다. ROM에서 동일한 타이밍 이벤트를 생성하거나 원작 음악 명령을 실행하는 경로가 최종 빌더에 필요하다. VGZ 팩을 배포 패키지 필수 자산으로 바꾸지 않는다.

형식과 타이머 근거: [VGM 명세](https://github.com/vgmrips/vgmplay-legacy/blob/master/VGMPlay/vgmspec171.txt), [Pan Docs 타이머](https://gbdev.io/pandocs/Timer_and_Divider_Registers.html), [CGB 배속](https://gbdev.io/pandocs/CGB_Registers.html), [GBDK 인터럽트 API](https://gbdk.org/docs/api/gb_8h.html). `nowait_int_handler`를 사용해 TIM 인터럽트 반환 때 LCD 안전 구간을 기다리지 않는다.
