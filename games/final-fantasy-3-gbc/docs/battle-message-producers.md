# 원작 메시지 선택·HP 숫자 생산자

PR 71의 행 렌더러는 글리프 배열을 받았다. 이번 후속은 원작 명령과
공격자/대상/메시지 번호, 16비트 HP로 그 배열을 **GBC에서** 만든다.
사용자가 승인한 V6 배치, 원작 프레임·팔레트·창 겹침, 7×7 글꼴과
HP 전용 작은 숫자, 공백 폭 3픽셀은 바꾸지 않는다.

## 원작과 유지하는 구조

`34/905B..91FB`의 공격자·우상단 메시지·대상·상태 문구 선택을 C로 옮겼다.
파티 이름은 호출자가 소유하는 4×6 글리프 레코드에서, 적 이름은
`7ECD[slot] → 7D6B[type] → 0520+monster`의 두 단계 참조에서 가져온다.
우상단은 아이템 플래그, 빗나감, 명중 횟수, 소환, 전투 문구, 상태 문구,
마법 이름의 원작 분기/8비트 덧셈을 유지한다. 전체 적 대상 `88`도 별도 처리한다.

`34/91FE`가 읽는 `34/9575`의 72바이트 표는 원본 ROM에서 추출한다.
하단 메시지 타입 0/1은 문자열 ID와 A 입력 대기 여부를 반환한다.
타입 2/3/4의 HP 조사·수치·아이템 치환은 명시적 미지원 오류다.
`34/94D6..950A`의 닫기 조건과 큐가 남은 경우 스크립트 인덱스를
4 또는 5 되돌리는 조건도 반환한다. 이 값은 호출자가 처리할 의무이며
되돌림이나 대기 자체를 완료했다고 간주하지 않는다.

`34/95E1..9647`의 십진수 변환은 앞자리 공백과 0을 보존한다.
`34/9BA2..9CE0`의 숫자 표시 모드 `7CE8=FF`에 대응해 뒤의 네 자리를
HP 창에 넣는다. 10000 이상 진단 값에서도 임의 상한을 씌우지 않는다.
명령명/상태명/마법명으로 최대 HP를 대체하는 다른 모드는 오류로 거절한다.
HP API는 한 행을 받으며, 네 행 반복과 전투 상태 확정은 호출자의 책임이다.

## GBC에서 바꾸는 부분과 수명

`battle-message.c`는 bank 44, 읽기 전용 문자열 인덱스·글리프·프레임은
bank 43에 둔다. 원작 문자열 ID를 검토된 비공개 번역 바인딩으로 조회한다.
번역 원문, 폰트, ROM, 추출 표와 완성 화면은 공개 소스에 들어가지 않는다.
표시 가능한 검토 바인딩이 없는 문자열은 오류 3으로 반환하며, 폭 초과는 오류 4다.
임의 번역·자동 축약·원작 숫자/도트 생략은 없다.

명령 입력 10바이트, 이름 24바이트, 적 참조 12바이트와 상태/임시 패킷이
정적 WRAM에 추가된다. WRAM 끝은 `$CD73`으로 70바이트 증가하고
`$D000` 전 여유는 653바이트다. 생산자 코드 1,864바이트, bank 43의
전체 UI 자산 3,380바이트다. 원작의 메모리 주소 자체는 이식하지 않지만
조회 순서와 생성 시점, 창 내용의 독립 수명은 유지한다. 결과는 기존
행별 렌더러와 VBlank 묶음 전송으로 넘긴다. 글꼴 전체를 매번 전송하거나
완성 프레임을 ROM에 저장하지 않는다. 오디오 서비스/예약량은 PR 71과 같다.

## 검증 범위

`battle-message-source.mjs`는 실제 원작 6502 핸들러를 실행한다.
화면 그리기·입력 대기 말단만 가로채고, 문자열 조회와 숫자 변환은
원작 명령을 실행한다. 이 결과가 GBC 생산자의 ID·대기·되돌림·오류·글리프
레코드 및 실제 화면의 정답이다. GBC에 검증용 완성 글리프 배열을 주입하지 않는다.
미지원 변수 메시지 5개 입력은 ROM의 타입 표를 대조해 거절하는 검사이며,
그 치환 핸들러 전체를 실행·이식했다는 주장은 아니다.

- 기존 16개 아이템/독 메시지 및 HP 호출을 원시 의미 값 입력으로 전환.
- 우상단 256개, 상태 메시지 256개, 하단 등록 범위 144개를 대조.
- 파티·적 이름, 전체 적 대상, 닫기/큐 되돌림, 0..65535 HP 경계 포함.
- 총 711개 호출 중 59개 화면 변경, 12개 생략/되돌림,
  635개 표시 바인딩 없음, 5개 미지원 변수 메시지 경로.

상태 회복 `010C..0115`와 명중 `0633` 등은 현재 검토된 번역에 없다.
따라서 **3번 창의 원작 ID 선택은 검사하지만 한글 상태 회복 문구를 실제
표시했다고 주장하지 않는다.** 미등록 ID 전체는 비공개 빌드 보고서의
`liveUi.cases`에 남는다. 바이트 입력 전체 검사는 정상 게임 도달성의 증명이 아니다.

실제 GBC 검증은 988개 등장/명령 화면과 59개 메시지/HP 화면, 총 1,047장의
픽셀·원작 상태/OAM 대조를 통과했다. 711개 생산자 호출의 문자열 ID·반환 상태·
글리프 레코드도 일치했다. 표시하지 않는 요청은 이전 표시 패킷을 변경하지 않았다.
28,800개 원작 음악·효과음·페이드 틱의 입력/변환 출력 해시가 일치하며,
오디오 부족·늦음·잘못된 DMA·활성 보스 셀 쓰기는 모두 0이다.
최대 present는 330.078ms, 메시지/HP 요청은 737.275ms다.
후자는 화면 변경 관측용 두 프레임을 포함하며 전체 원작 속도 달성을 뜻하지 않는다.
PR 71과 같은 16개 요청의 최대는 619.658→636.330ms다. 737.275ms는
추가한 창 조합에서 나왔다. 선택/포맷 및 프레임 대기가 합쳐진 비용이며
최대값 차이를 순수 CPU 비용으로 단정하거나 속도 향상으로 주장하지 않는다.
메뉴 패턴 47,360바이트·맵 2,560바이트의 소유권을 검사했다.
호스트 회귀 164개와 수정된 이름 패킷 기대값의 추가 2개 검사가 통과했다.
이름은 원작의 6자리 뒤쪽 공백을 보존한다. 처음 작성한 검증기의 가변 길이
이름 기대값을 바로잡았고, 동일 ROM·동일 원시 입력의 캡처를 다시 대조했다.
533개 허용 소스의 별도 공개 빌드와 ROM/report가 바이트 일치한다.

- ROM SHA-256: `0a021c8005d14dd4ed1d24b7444afd8c1df34ab46b401855c180b09576fcbec7`
- report SHA-256: `a74134cfad8d16b81941a1ad30e664e52e96511fa3cc54c8a92e06a49277d589`
- 검증 근거: 비공개 `evidence/battle-boss-windows/`와 `.local/message-*.log`.

초기 로드의 500ms 목표와 전체 원작 속도는 여전히 미달성이다.
이번 변경은 메시지 생산 책임을 런타임으로 옮긴 것이며, UI 속도 향상으로 세지 않는다.

## 다음 연결

원작 `8FF7` 행동 스크립트 실행기가 메시지 생산자와 실제 애니메이션·숫자·
사망/포격 소비자를 호출하고, 대기·큐 반복·완료 복귀를 소유하게 한다.
기존 `battle-action.inc`의 미리 합성된 그림 재생을 정상 실행기로 옮기지 않는다.
미등록 상태/명중 번역과 변수 메시지의 치환 위치를 따로 검토해야 한다.
보스/석화/무기·마법/숫자 공존과 정상 이벤트 전투도 미완료다.
제품 관문 0/3, R2 전체 통합 0/8은 유지한다.
