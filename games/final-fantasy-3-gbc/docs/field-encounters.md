# 일반맵 조우 판정과 전투 요청 경계

2026-11-27. 기준은 PR 107의 단일 부팅 표시 왕복이다. 이 변경은 원작 일반맵의
조우 판정·편성·배경 선택과 요청 시점을 연결한다. **실제 파티/선택된 편성의 표시와
승패 처리는 아직 연결하지 않았다.** 미지원 요청은 오류 4로 유지하며 고정 진단 전투로
대체하지 않는다. 월드맵/차량 조우는 다른 소비자이며 이번 범위가 아니다.

## 원작 소비 순서

- `3F/E37E → E396`: 앞 타일과 NPC 접촉, 타일 속성, 조우 가능 비트 `$44 & $40`,
  통행 판정을 이 순서로 처리한다. 트리거 타일 `$80`은 일반 조우보다 먼저 분기한다.
- `3D/BC5B`의 carry-set 경로 → `BDB9..BDDD`: 이벤트 `$6C`가 있으면 난수를
  소비하지 않는다. 그 외에는 `3E/C711`의 `$F5/$F6`와 `$F8` 확률로 판정한다.
  확률 0이라도 해당 호출에 도달했으면 판정용 난수는 소비한다.
- 성공 시 `2E/92F0,93F0`에서 맵별 그룹을 읽고 `3D/BD4D..BD76`으로 선택한다.
  별도 `$F7`을 먼저 증가시켜 `3F/FE00`을 읽고 하위 6비트를 `3D/BD78` 슬롯 표에
  넣는다. `2E/94F0 + 그룹×8 + 슬롯`을 `$6A`에 쓰고 `$AB=$20`을 예약한다.
  NPC 이동의 `$F4`와 두 종류의 조우 난수 상태는 독립적이다.
- 슬롯 표 실제 분포는 **12,12,12,12,6,6,3,1 / 64**다. 원본 주석의 `/256`을
  복사하지 않고 `AND #$3F`와 표 바이트를 기준으로 삼았다.
- 이후 통행이 거부되면 `3F/E3E5..E3EF`가 `$AB`를 지운다. 이미 소비한 난수나
  선택된 `$6A`까지 되돌리지는 않는다.
- `3F/E54C → E5EB` 이동 갱신 후 `E20F..E21D`는 이동 중이면 디스패치를 미룬다.
  마지막 픽셀까지 끝났을 때 다음 방향 입력보다 먼저 전투를 호출한다.
  `E26A`의 `$40` 이상 트리거는 전투가 아니므로 `$20` 비트만 검사해서는 안 된다.
- `3F/E283 → 3A/8533..854D`가 `39/BC00,BD00`의 배경/플래그 원시 바이트를 읽는다.
  이후 `3E/C049`의 가방 포장 및 전투 전달, `E7F8` 복귀는 별도 연결 과제다.

## GBC 구조와 수명

`field-encounter.c`는 뱅크 9에 원작 표 3,392바이트와 작은 선택 함수를 함께 상주시킨다.
매 이동마다 자산을 복사·해독하거나 화면 전송을 추가하지 않는다. `encounterAssets()`가
원본 ROM에서 추출하고 두 빌더가 링크된 모든 표 바이트를 출처 SHA-256과 비교한다.
표의 은행/주소/길이/소비자/해시는 로컬 빌드 보고서에 기록한다. 데이터 자체는 배포하지 않는다.

`FF3Exploration` 뒤에 `$F7/$6A/$6B` 3바이트를 추가했다. 기존 `DB70..DBBF`의
80바이트 예약 중 79바이트를 사용하며, 공통 RAM이나 장면 DATA는 늘리지 않는다.
기존 WRAM7 필드 문맥 보존 영역에 포함되므로 왕복 시 재설정하지 않는다.
완료된 마지막 이동 픽셀은 오류 경계에서도 표시를 갱신한다.

원작의 고정 표와 별도 난수 커서 구조를 유지했다. 표를 RAM에 선복사하거나 단계마다
전체 편성을 해독하는 대안은 여기서는 비용만 늘린다. GBC 렌더러의 실제 편성 공급은
이 선택기와 분리되어 있으며, 연결 전까지 진단 프로필 진입도 오류/트리거를 우회하지 못한다.

## 검증 범위

`node tools/verify-exploration.mjs --encounters --scene-layout`는 원본 6502 소비자를
실행해 만든 7,505개 사례를 실제 GBC 코드와 비교한다. 두 맵 표/배경 표 전체,
비영 월드 플래그 분기, `$F7`의 256개 커서, 이벤트 255종, 확률 경계, `$F5/$F6`
방향/랩, 네 방향의 16픽셀 이동, 통행 불가에 따른 요청 취소를 포함한다.
기대값 생성기는 ROM을 수정하거나 성공 스텁을 넣지 않는다.

같은 부팅 왕복 검증은 기존 두 번의 전투 표시/마법/이동/한글 대화 뒤에 실제 버튼으로
조우 경계를 검사한다. 검증용으로 마을의 안전한 다음 타일에 조우 비트를 부여하고
확률/커서를 지정한다. **일반 플레이에서 그 마을에 전투가 발생한다는 주장이 아니다.**
선택 결과는 원작 코드와 비교하고, 한 칸 완료 후 요청이 멈추는지, 추가 입력/진단 요청이
이를 우회하지 못하는지, 파티가 보존되고 오디오가 계속 진행하는지 검사한다.

## 완료 기록

- 원본 ROM SHA-256: `262a98737975df25fff80ad91090c3da039d2828035c6253140d2c5f3b176ea2`.
- 최종 통합 ROM SHA-256: `50eda75a269f518e556cee77b00ae2f770e1e750d07a712e3e2769a433d606e7`.
- 고정 MesenCore SHA-256: `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`.
- 원작 대조 7,505사례와 기존 단위 검사 194개 통과. 추출 표 5개의 링크 바이트도 전부 일치.
- 같은 부팅 2회 왕복, 화면 79장 픽셀 일치, 원작 마법 70표시 프레임(본체 54+점멸 16) 유지.
  오디오 7,200틱·7,105관측·실제 APU 쓰기 30,438회 일치, late/underflow 0.
  타이머/마스터 클럭 편차 범위 340.939µs로 기존 500µs 한도 이내.
- 왕복 후 통제된 조우에서 한 칸만 이동하고 요청을 유지했다. 30프레임 동안 추가 이동이나
  진단 전투 진입 없이 오디오 30틱이 진행했다. 보고서의 803.776ms는 이동과 이 의도적
  30프레임 관측을 합친 값이며 전투 로딩 시간이나 조우 처리 지연이 아니다.
- 연속 탐색 회귀: 7,193관측, 화면 12장, 원작 NPC 전이 1,024개, 오디오 7,200틱 일치.
  실제 스크롤 간격 최악 50.442ms/p95 상한 34ms, 준비→커밋 최악 30.398ms로 기존 한도 유지.
- 공통 RAM 끝 CA78, 장면 DATA CA80..CFCB(여유 53바이트), WRAM7 보존 4,050바이트,
  고정 ROM 끝 3FE2(여유 30바이트)는 유지. 뱅크 9 코드는 7,883바이트로 16KiB 이내.
  왕복 스택 워터마크 230바이트/남은 282바이트, 가드 손상 0. CPU 뱅크 복사 최악
  79.632µs와 기존 DMA 1,076클럭도 각 한도 이내.
- 진입 자원 준비는 1,057.568/1,015.812ms로 여전히 0.5초 목표 미달. 본 변경을 로딩
  성능 개선으로 세지 않는다. 원래 도트·숫자·음악·효과음 변환은 유지하며 음질 개선은 후순위다.

로컬 원시 증거는 `evidence/exploration-scene-layout/encounters*`, `play*`,
`evidence/scene-roundtrip/*`와 빌드 보고서에 보존한다. ROM/추출 표/번역/스크린샷은 Git에 넣지 않는다.
