# 전투 작업 공간의 수명과 타일 할당

2026-11-26. 기준은 PR 67 병합 `19731b7917e1940ac2b72115447bcbed3914bfda`다.

## 원작과 이식 구조

원작 `2F/B6C8..B72A`는 배우별 두 열의 석화 맵을 게시한다. 앞서 읽은
글리프 포인터를 행마다 2씩, 맵 주소를 32씩 진행하며 완성 화면을 쌓아 두지 않는다.
현재 이식도 원작 요청과 게시 순서를 유지한다. GBC의 위치·팔레트 차이에 필요한
부분 셀 합성과 보조 OBJ 마스크만 대상 플랫폼의 작업이다. 아군 무축소·적 28×28,
V6 지형, 원작 도트·피해 숫자·음악/효과음 데이터는 이번에 변경하지 않는다.

## 동시에 살아 있어야 하는 자료

`present()`는 적 BG 준비 → 지형 준비 → 상태 OBJ → 석화 준비 → 게시 순으로 실행한다.
적 BG의 704바이트 맵 임시는 동기 전송이 끝나면 필요 없다. 전송 함수는 별도의
`text_staging`에 복사하고 완료를 기다린다. 석화의 배경 셀/행 읽기는 원본 ROM과
`text_staging`을 사용하므로 그 맵 임시를 참조하지 않는다. 오디오 서비스와 IRQ도
이 공간을 읽지 않는다.

따라서 `D200..D4BF`를 `Ff3BattleWorkspace` 공용체로 선언했다. 적 맵 704바이트와
석화 임시 목록 297바이트는 순서대로 같은 영역을 쓴다. 페이지별 VRAM 태그·입력 서명,
OAM·마스크·원작 글리프 점유 비트는 다음 요청에도 필요하므로 공용체 밖에 유지한다.
배경 프로필 교체나 다음 맵 준비는 임시 공간을 덮어써도 된다. 같은 상태 페이지의
빠른 경로도 남아 있는 임시 값에 의존하지 않는다.

예약/전송 여부는 두 배열 대신 타일당 한 바이트의 세 상태(빈 슬롯, 유지, 변경)로
표현한다. 예약을 전부 끝낸 뒤에는 슬롯을 해제하지 않으므로, 빈 슬롯 검색은 마지막
검색 위치부터 진행한다. 기존과 같은 첫 빈 슬롯을 선택하면서 이미 사용한 앞부분의
반복 탐색을 없앤다. 고정 WRAM은 344바이트 줄고 끝 주소는 `CE63`, 여유는 413바이트다.
기존 패턴 버퍼·VRAM 두 페이지·큐 크기는 늘리지 않았다.

새 소비자가 이 공간을 함께 쓰려면 수명을 다시 확인해야 한다. 보스·창·숫자까지
지금의 공용체 계약이 자동으로 적용된다는 뜻은 아니다.

## 오디오 준비량 비교

채택안은 기존 오디오 준비 계약을 유지한다. 실제 소유권 변경에는 3틱, 같은 상태
페이지에는 기존 일반 작업의 2틱 목표를 쓴다. 셀이 0개인 해제 요청도 진입 시 보충을
생략하지 않는다. 큐 용량·명령 처리·소비 시각·타이머·출력 변환을 바꾸지 않는다.

별도 후보에서 합성·마스킹이 끝난 뒤 전송 구간만 2틱으로 돌려 비교했다.
664개 step의 전송 전용 경과는 4095→4011ms로 줄었지만 오디오 경과는
15657→16907ms, 전체 요청 합계는 40227→41342ms로 늘었다. 최대 전체 요청도
486.825→503.671ms로 늘어 채택하지 않았다. 두 실행의 후속 음악 위상은 다르므로
이를 틱 하나의 처리 비용 증가로 해석하지 않는다. 요청 전체에서 이득이 없다는 판단이다.
이 후보도 668/642화면과 각 10,800틱은 통과했다. 겹침 present 최대는 같았고
혼란 present 최대는 268.555→263.672ms로 소폭 줄었지만, 혼란 최대 전체 요청은
309.088→367.929ms로 늘었다. 유리한 일부 지표만으로 채택하지 않았다.
이전에 모든 구간을 2틱으로 바꾼 후보의 버퍼 부족 문제도 여전히 별도 근거로 보존한다.

## 검증 방식

공용체 크기는 컴파일 시 704바이트, 주소는 링크 후 `D200`인지 확인한다.
`--poison-workspace` 검증은 CPU가 멈추고 모든 화면 요청·게시가 끝난 경계에서만
704바이트를 요청마다 다른 값으로 덮어쓴다. 원작 입력이나 페이지 캐시, 큐, 시간을
바꾸지 않는다. 이후 실제 화면의 모든 픽셀·원작 상태·OAM·패턴·맵과 메모리 경계를
기존 독립 기준으로 검사한다. 이 조작은 검증기 전용이며 제품 ROM에는 들어가지 않는다.

## 채택안 결과

표시 ROM은 `03dc546081d088036c247830a4ff515b8e568b1e45e774892e2c94ac32636620`,
혼란 회귀 ROM은 `5f96f2755af40cc4e94cb7455061f708258713878c462e00f8dda1c3ea4e85b3`다.

| 지표 | PR 67 | 채택안 |
|---|---:|---:|
| 정적 WRAM 여유 | 69바이트 | 413바이트 |
| 석화/혼란 겹침 present 최대 | 511.963ms | 479.736ms |
| 혼란 단독 present 최대 | 280.518ms | 268.555ms |
| 겹침 664 step 경과 합계 | 41.333초 | 40.227초 |

| 겹침 석화 전용 경과 합계 | 9.189초 | 8.701초 |

present 함수와 전체 요청은 측정 범위가 다르다. 석화 전용 시간은 오디오·전송을
제외한 경과다. 전체 요청 감소는 같은 원작 작업의 결과이며 모든 프레임이 빨라졌거나
원작 속도에 도달했다는 뜻은 아니다. 특히 혼란 단독 최대는 PR 66의 239.502ms보다
여전히 길다.

- 668화면·642화면 모두 작업 공간 덮어쓰기를 요청마다 수행하고, 실제 모든 픽셀과
  원작 상태·OAM·맵·패턴 검사를 통과했다. 독립 기준 자료는 PR 67과 바이트 단위로 같다.
  실제 캡처의 OAM·맵·물리 패턴 전체도 PR 67과 동일하다.
- 각 경로의 원작 오디오 10,800틱, APU/GBC 출력 해시·음악/효과음/페이드를 대조했다.
  오디오 지연·버퍼 부족·잘못된 DMA·메모리 경계 위반은 0이다.
  최대 자동 게시 간격은 두 경로 모두 5프레임, 타이머 오차는 0.108ms 미만이다.
- 석화 겹침의 패턴/맵 전송 7712/7424바이트와 272셀 합성·388셀 재사용,
  혼란 단독의 1024/1536바이트와 64셀 합성·96셀 재사용도 유지했다.
- 호스트 155검사가 통과했다. 공개 허용 513개 소스만 별도 폴더에 복사한 빌드에서
  표시 ROM과 원작 실행기 정상/오류 주입 ROM 세 개 및 보고서가 바이트 단위로 재현됐다.
- 원작 오디오 소비 틱 96/224 × 4프로필의 새 부팅 8회는 702.518/768.180ms로
  PR 67과 같았다. 첫 화면 전체·팔레트 128바이트·VRAM 11392/11584바이트,
  후속 원작 오디오 120틱을 검증했다. 초기 ROM DMA는 최대 256바이트·25회이며
  은행 복원 25쌍, 보수적인 최장 인터럽트 차단 상한은 223.637µs다.

## 다음 범위와 재현

메모리 수명 정리를 마쳤으므로 다음은 `2F/B479..B486`의 보스 조건과
`BE97..BF92`의 4타일/64바이트 블록·7→0 시프트를 상주 화면에 연결한다.
이미 대조한 원작 실행기의 게시/대기 순서를 유지하고, 28×28 축소 경계에 걸친
BG 셀과 색 보정 OBJ의 부분 갱신·복원을 함께 검증한다. 큰 보스가 이 28×28
일반 적 규격을 그대로 쓴다는 뜻은 아니다. 보스의 실제 자원 크기와 대상 영역을 따른다.
정규 진열 전 `$98` 반전 상태, 보스와 석화 자원의 수명도 별도로 확인한다.

전체 전투/정상 게임 진행, 다른 열로 이동한 석화 이력, 창·포격·피해 숫자의 같은
화면 통합은 아직 미완료다. 초기 진입 500ms 목표와 전투 중 지연도 남아 있다.
음질·DAC 타격음/CH4 효과음 충돌·실기 검증은 별도 후속이며 이번 개선으로 해결했다고
세지 않는다. 원본 ROM·번역·추출 자산·바이너리·원시 관측은 공개하지 않는다.
