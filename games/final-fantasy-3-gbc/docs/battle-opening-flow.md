# 전투 등장·포격에서 명령 선택까지의 실행 흐름

2026-11-25. PR 46 병합 `bbe2fa756aeef98bf0da14e1ae52cd0b8669d594` 이후 작업.
`ff3_opening_start/ack`는 기존 상태 표시·명령 수집기와 포격 결과를 같은 상태로 소비한다.
원작 `34/81A0→986C→35/A50B→34/8FF7→35/A458→986C`의 흐름을 GBC C로 연결했다.
화면 작업은 완료 요청/응답으로 분리한다. 렌더러가 완료하지 않았는데 다음 상태로 진행하지 않는다.

## 입력과 완료 범위

입력은 **원작 속성 로더·진입 플래그·포격 피해 준비·첫 적 AI 처리가 끝난 경계**다.
영구 상태에서 전투 레코드를 만드는 전체 로더와 적 AI를 이 함수가 대체하지 않는다.
포격 난수는 적 AI보다 먼저 소비해야 한다는 기존 `8077..8088`의 순서를 유지해야 한다.
현재 기대값 생성기의 임의 HP/상태 변경은 경계 검사이며 정상 게임에서 도달한 세이브가 아니다.

712바이트 `Ff3Opening`은 명시적 진단/호출 계약이다. 기존 `Ff3Party` 55바이트와
`Ff3Cannon` 578바이트, 상태별 표시 요청, 적 종류/원래 종류/사망 표시/보상 집계와 진행 상태를 포함한다.
공유 게임 상태와 중복해서 상주시키라는 메모리 설계가 아니다. 은행 16 함수는 접근 가능한 WRAM에서
호출하며, IRQ 안에서는 실행하지 않는다. 크기와 주요 오프셋은 컴파일 시 검사한다.

화면·입력 요청은 `pending/value/ticket`으로 전달한다. 같은 실행에서 이전 단계의 완료 번호,
진행 중 다시 시작, 종료 상태의 추가 완료 호출은 상태를 바꾸지 않고 거부한다.
첫 입력 대기는 버튼이 없으면 그대로 유지한다. 메시지 대기는 한 번의 승인당 원작 한 프레임이며,
각 프레임에 새 완료 번호를 발급한다. 실제 타이머/VBlank와 이 요청을 연결하는 일은 렌더러의 책임이다.
이 번호는 실행 내 단계 식별자이며 별도 게임 세션 ID는 아니다.

## 원작에서 이어진 경계

| 경계 | 처리 |
|---|---|
| `81A0`, `986C..990A` | 전체 저장 방어값 복원, 상태에 맞는 명령 가능 멤버 탐색. 기존 `ff3_party_enter` 재사용 |
| `9912..993F`, `2F/AD78` | 등장 완료 뒤 첫 턴 표시 갱신. 일반 전투는 버튼 대기, 기습/포격은 원작 분기로 이동 |
| `35/A50B..A525` | 그래픽 `$0F` 완료 → 메시지 `$3D`와 포격 비트 해제 → 메뉴 영역 지우기 → 스크립트 3 |
| `34/953B` | ROM 포인터로 읽은 `09 0B 0C 0E 0A 04 FF`를 지원 범위로 검증 |
| `34/934E,9354,868A` | 포격 그래픽 `$24` → 적 숫자 `$1C` → 공격자 숫자 `$1C`. 첫 숫자 표시가 끝나야 버퍼를 덮음 |
| `34/93C4,9408,8496` | 원작 상태 확정 후 죽음/소환 표시 요청 선택. 적 8슬롯의 사망 마스크 보존 |
| `2F/BAEE,BAA2,B959,B909` | 요청 완료 뒤 적 종류 제거/복원·보상 대상 수·종류별 생존 수를 인계 |
| `34/9450` | `(8-메시지 속도)×8`프레임 대기, A로 단축 |
| `34/94D6,9056` | 아래 메시지창 닫기와 그래픽 `$25` 정리 |
| `35/A458..A53E` | 실제 파티 사망/석화와 생존 적 수로 결과 판정. 포격 승리면 명령 선택으로 돌아가지 않음 |
| `34/986C,9940` | 살아 있는 멤버로 재진입, 그래픽 `$02` 완료 뒤 같은 `Ff3Party`의 선택 상태 반환 |

화면 내부의 픽셀/타일 교체 시점까지 C에서 선행 확정하지 않는다. 그래픽 요청 전후의 상태는
원작과 대조했지만, 그래픽 함수 내부에서 변하는 메타데이터의 세부 프레임은 이후 표시 어댑터가
소비해야 한다. 특히 적 소멸을 완료하기 전에 승리나 다음 선택을 표시하면 안 된다.

전원이 조작 불가능하면 원작 `A433`이 수집기를 빠져나간다. 이때 임의로 첫 멤버를 선택하거나,
등장/포격을 강제 실행하지 않는다. 혼란/수면/마비 자동 행동과 아이템 반환은 각각 명시적인
호출자 경계로 반환하며, 아직 해당 외부 처리를 끝낸 것으로 간주하지 않는다.

시나리오마다 요청 종류/값과 공유 상태 705바이트를 원작 코드와 비교한다. 전체 4,593개 경계에서
사망·상태·HP·숫자·포격 단발 예약·집계·다음 선택 멤버를 검사한다. GBC 진단은 별도로 잘못된/이전
완료 번호와 중복 시작, 버튼 없는 대기, 종료 후 진행의 무변경 계약을 검사한다.
GBC 397시나리오/4,593경계 비교 및 완료 번호 계약 검사를 통과했다. 기대값 한 바이트를 바꾼
음성 ROM은 첫 시나리오/첫 바이트에서 실패했다. 전체 호스트 회귀는 125/125를 통과했다.
bank 16은 기존 주변 규칙을 포함해 4,727바이트, 진단의 정적 WRAM 끝은 `$C64E`다.
두 구조체로 입력/무변경 검사를 하는 진단 수치이며 화면/음악 통합 상주 예산이 아니다.

- 정상 ROM SHA256: `d0c8f69e099f68095226a8a2ea1b286a4a5160e5517b960f30065a13ac75abea`
- 음성 ROM SHA256: `8976a85f5e7c4a83defa6eb10d03207aabc895920c874a5acabaedf9d0aed2ae`
- 입력/기대값 SHA256: `8c002265b1de75ceb5de7e0e9b948e2bf5087a21384150252475a9a621728c28`

공개 허용 목록 410개 파일만 별도 디렉터리에 복사하고 비공개 입력 경로를 제공해 재빌드했다.
검증 보고서와 정상/음성 ROM 두 개의 해시가 모두 일치했고, 새 호스트 시험 6개도 통과했다.
재빌드 이후에는 검증 기록만 보완했다. ROM·입력 경로 설정은 공개 패키지에 포함하지 않는다.

원작 참조의 일반 대량 시험에서는 텍스트/PPU를 가로채고 그래픽의 상태 변경 루틴을 원작으로 실행한다.
이 어댑터가 상태를 누락하지 않았는지, 정방향/백어택 × 포격 전멸/생존 4경로는
**원작 전체 그래픽 본체**와 다시 비교했다. 초기 파티는 사망·석화·개구리·정상 혼합 상태다.
전멸 경로는 11개 요청/262개 관측 경계, 생존 경로는 12개 요청/206개 관측 경계다.
두 방향 모두 포격 효과음 요청 `$80`이 관측됐고, 전멸 때는 적 소멸 요청 `$B1`도 관측됐다.
이 수치는 가상 PPU/NMI 경계와 사운드 요청이며 실제 NES 프레임 시간이나 APU 출력 검증이 아니다.

로컬 결과: `build/battle-opening/report.json`, `evidence/battle-opening/load.json`,
`negative.json`, `original-presentation.json`. 원본/생성 ROM·기대값·분해 자료는 공개하지 않는다.

## 남은 통합과 다음 순서

이번에 연결된 것은 GBC **실행 흐름과 표시 완료 인계**다. 아직 V6 렌더러에 포격 그래픽·메시지·
효과음 요청을 붙인 실행 파일은 아니다. 실제 화면에서 음악/효과음 무중단·프레임/OAM 예산을
통과했다고 주장하지 않는다. 기존 V6 UI·아군 도트·숫자 렌더러는 변경하지 않았다.

다음은 이 요청 인터페이스를 V6 표시/오디오에 연결해 등장→포격/숫자→적 소멸→승리 또는 명령 선택을
한 실행 파일에서 검증한다. 우선 초기 혼합 상태와 적 8명 생존/전멸을 포함하고, 포격의 화면 전체
좌표 및 원작 효과음 요청 시점을 함께 매핑한다. 이후 재지정·분열과 예약 명령 실행을 연결한다.
새로운 독립 계산 함수의 수를 늘리는 것으로 이 표시 연결을 대체하지 않는다.
R2 통합 0/8과 제품 관문 0/3은 유지한다.
