# 전투 중 무기·방패 교환과 능력치 갱신

기준: PR 39 병합 `cc67af9926c45b0fec4d30a9cd4a305c68014a3f`.
아이템 목록에서 왼쪽으로 이동하면 오른손/왼손 장비 열이 나온다. 장비와 가방 항목을
A로 각각 선택해 교환한다. 어느 쪽을 먼저 선택해도 원작처럼 처리하며, 성공하면
아이템 창을 닫고 **같은 캐릭터의 명령 선택**으로 돌아간다. 행동 예약이나 턴 소비를
추가하지 않는다. 단순한 표시 변경이 아니라 정본 가방·장비와 파생 능력치를 변경한다.

## 원작에서 확인한 규칙

`35/ADDF..AE3E`는 손의 아이템/수량과 가방 사용 가능성을 준비한다.
`35/AF9C..B193`이 교환, `B242..B2A6`이 양손 조합, `B1B0..B1D5`가 창을 닫고
`34/8026 → 31/AA16..AF76` 능력치 재계산 후 명령 선택으로 돌아가는 호출자다.

- `35/B8FD`, `30/9400`과 `00/8900`의 원본 직업 마스크를 사용한다. 22직업의
  허용 무기를 따로 추측하지 않는다. 장착 불가 항목은 X로 표시하며 교환을 거절한다.
- 교환 대상은 ID `<62`인 무기/방패 또는 빈칸이다. 방어구·소모품·마법은 장착하지
  않는다. 같은 가방끼리 또는 오른손↔왼손 직접 교환도 원작 목록 규칙에서 거절한다.
- 양손 조합은 원본 ID 경계 `46/4A/4F/58/62`를 따른다. 보통 무기끼리, 무기+방패,
  방패끼리, 활+화살의 허용과 하프/활/화살의 비호환 조합을 같은 판정으로 검사한다.
  동일한 두 손 ID일 때 원작이 값 비교로 반대 손을 고르는 동작도 보존한다.
- 수량 1 또는 빈 가방 칸은 그대로 맞교환한다. 여러 개의 보통 무기는 1개를 장착하고
  기존 손의 무기를 첫 빈 가방 칸에 반환한다. 빈칸이 필요하지만 없으면 무변경 거절이다.
- 화살 `4F..56`은 20개까지 한 번에 장착한다. 21개 이상이면 20개를 떼고 나머지를
  원래 칸에 남긴다. 같은 ID를 고르면 손을 비우고 가방 수량에 합산, 원작처럼 99로
  제한한다. 바이트 덧셈/자리올림·비정상 수량의 원작 동작도 함수 검사에 포함한다.
- 실패는 두 커서/장비/가방을 유지한다. 성공 시 원작이 열만 되돌리고 정규화된 행은
  남기는 미세한 상태도 보존한다. 실제 창은 닫히므로 새 임의 커서를 만들지 않는다.

실제 NES 상태에서 가방에 단검 3개를 진단 입력한 후 왼쪽 장비 열을 열고 교환했다.
장비 `1E×1 → 1F×1`, 가방 `1F×3 → 1F×2 + 1E×1`, actor=0 유지, 창 닫힘과
다시 연 목록의 수량을 관찰했다. 직업 0에 맞지 않는 `46`도 X/거절/장비 불변을 확인했다.
이는 저장 상태와 재고 주입을 이용한 경계 관찰이며 정상 획득/전투 진입 검증은 아니다.
원본 캡처·주입과 읽기 기록은 `.local/equipment-original-*`에만 보관한다.

## 능력치와 수명

`31/AA16..AF76`을 C로 이식해 기본/장비 보너스 능력치, 양손 공격 속성·횟수·명중·공격력,
방패/방어구의 흡수 속성·회피·방어·상태 저항·마법 방어, 무기 종류와 추가 공격력을 계산한다.
몽크/공수가의 맨손, 하프, 활/화살, 방패, 한 손만 사용한 경우를 구분한다. 원작 ADC
자리올림과 8비트 래핑, AF18에서 원소 강화 비트를 지우는 원작 동작도 바꾸지 않는다.

정본 GameState의 캐릭터 `+100 + actor×64`와 장비 `+200 + actor×64`에 원작 결과를
반영한다. 전투 파생 필드의 4×64바이트는 WRAM bank 5의 `400..4FF`에 보존한다.
창 전송이 끝난 뒤 조회 버퍼를 잠시 빌려 16바이트 제한의 기존 은행 복사 함수를 사용한다.
IRQ나 다른 은행으로 옮긴 스택에서 C 코드를 실행하지 않는다. 전체 전투 레코드 초기화는
아직 연결되지 않았으며, 이 저장소의 미계산 필드 0을 정상 전투 초기화 결과로 주장하지 않는다.

원작처럼 목록 닫기/대상 취소/사용 확정에서도 재계산한다. 표시만 빠져나가 HP 대상 창으로
전환하는 시점에는 재계산하지 않는다. 검증기의 진단 재시작도 게임의 닫기 호출과 구분한다.

V6 배치, 원작 파란 창/프레임, 선택된 긴 이름만 흐르는 정책과 3px 공백은 유지한다.
입력 효과음 요청 값은 원작과 대조하며, 실제 오디오 부하는 독립된 원작 음악/효과음/페이드
계획을 병행한다. UI 요청 중재 및 전체 전투 호출자의 완성을 뜻하지 않는다.

## 손가락 기준 커서 정렬

사용자 요청으로 선택창 상단을 106→103px, 높이를 38→41px로 확장한다. 글자 행을
3px 위로 옮겨, 명령/가방/장비의 손가락 끝이 글자 중심을 가리키게 한다. 손 커서는 원래
16×16 도트 전부를 유지하고 마지막 행도 y=143 안에 들어간다. 아군/적 대상 손도 대상에
대한 상대 위치를 3px 내려 맞춘다. 가방의 두 커서와 전체 대상 커서에도 같은 좌표를 쓴다. 첫 열의 가방/장비 손은
첫 OAM 조각 대신 네 조각의 최소 X를 기준으로 정렬해 왼쪽 8px가 잘리던 부분도 복구했다.
모든 표시 손 조각의 X/Y와 8×8 범위를 실제 화면 대조 때 함께 검사한다.

창이 아군 발을 가리지 않도록 선택 화면 아군은 3px, 적은 4px 위로 이동하고 배경 띠는
11→8px로 자른다. 그림 크기/색/실루엣은 바꾸지 않는다. 경계 타일 행(화면 98..105)의
아군 발은 기존 색 그대로 OBJ에 보존한다. 임의 도트 생략 대신 OAM/줄당 한계를 검사한다.
이는 현재 선택 진단 편성의 검증이며 모든 편성/직업을 합격한 것으로 확대하지 않는다.

아이템 열은 5→6 타일 행(열당 960바이트, 3슬롯 2,880바이트), HP 접미부는 30타일로
확장한다. 파란 창 상단 위의 5px는 검은 배경과 보존한 발 도트를 표시한다. 래스터 분기는
HBlank 105→97로 이동하고 WRAM 은행 복사 차단 구간도 104..105→96..97로 옮긴다.
생성 기계어의 정확한 명령열 검사를 유지하며 두 즉시 비교값만 새 분기 위치에 맞춘다.
행동 실행 표시 진단의 기존 106px 창은 별도로 유지한다. 후속 정상 전투 연결에서는
선택→행동의 위치 전환과 마법/무기/숫자 공존을 함께 재검사한다.
