# 현재 셀 호출 비용과 필드 복귀 오디오

기준은 PR 119 병합 `3e72fd08898ea185d57e6f7a4893240dca6cf383`이다.
공통 풀을 유지하면서 같은 작업의 호출·계산 비용을 줄인다. 순수 석화 통합은 아니다.

## 원작과 보존하는 수명

원작 `2F/BAA2 → A362`, `BB13/A247`은 슬롯 생존 상태와 지도를 갱신한다.
`BC84/BC87`의 두 NMI 대기, `BC8A`의 OAM 전송, `BC92..BCAC`의 변경 지도 쓰기,
`BCB1`의 다음 소거 그림 진행, `BCCC → BB44` 복구 순서를 유지한다.
GBC의 28픽셀 배치에서 한 셀에 여러 슬롯이 들어가는 경우만 현재 도트를 합성한다.

기존 비활성 페이지의 begin → 마스크/타일 공급 → finish → 지도 전송/공개는 그대로다.
슬롯 ID와 팔레트, 두 페이지, 정확한 글리프 비교, 16타일 배출, 서비스 호출 위치,
변경 없는 그림 건너뛰기 조건과 원작 대기 횟수는 바꾸지 않는다.

## 변경

마스크와 타일 배출의 뜨거운 호출자는 모두 ROM bank 124에 있다. 기존에는 각 셀마다
`___sdcc_bcall_ehl`로 같은 뱅크를 다시 선택했다. 같은 뱅크 전용 일반 CALL 경로를
만들고, 다른 뱅크와 단위 ROM에는 기존 BANKED 진입점을 유지한다. 구현 본문은 하나다.
일반 함수를 NONBANKED로 바꿔 고정 ROM을 사용하는 방식은 아니다. 통합 빌드는 호출자와
두 커널의 링크된 뱅크를 검사하여 한쪽만 옮기는 변경을 거부한다.

마스크는 매 행의 두 비트면과 소거 바이트를 한 번씩 읽고 포인터를 전진한다.
핀 고정 SDCC의 반복적인 16비트 인덱스 계산과 스택 접근을 줄인다. 변경 없음/완전 소거/
일부 변경의 반환값과 모든 출력 비트는 같다. 8행 × 8비트 × 두 비트면/마스크 8조합을
실제 SM83에서 검사하고, 기존 부분 소거·공유·충돌·상한·원작 글리프 검사를 유지한다.

## 비용 측정

`verify-dungeon --death-auto`는 실제 linked CALL 바이트와 callee를 검사한 읽기 전용
계측을 사용한다. 호출 직전부터 반환 직후까지를 재므로 이전 뱅크 트램펄린도 포함한다.
오디오 IRQ, 생산, 전송, 화면 공개 구간은 우선 분리하고 나머지만 셀 비용에 귀속한다.
전투 전송은 대화용 `text_transfer_busy`가 아니라 실제 private pending descriptor로
판정한다. 주소는 링크된 `ff3_text_transfer_idle`의 첫 로드 명령에서 검증한다.
Mesen의 500항목 로그 제한에 앞선 결과가 사라지지 않도록 완성 요약을 최종 왕복에서
재출력한다. `cell-costs.json`은 마지막 요약만 사용하여 중복 합산하지 않는다.

강제 치명적 HP와 진단 명령 제출을 사용하며 정상 턴/보상 완료로 세지 않는다.
전환 수정으로 최종 자연 조우의 시드는 94에서 138로 바뀐다. 현재 상태에서 유도한
시드라는 승인된 규칙은 유지한다. 서로 다른 난수의 전체 시간을 그대로 최적화 효과로
계산하지 않는다. 성능 비교에서는 이전 ROM의 첫 encounter_prepare 진입점에서만
시드를 138로 맞추는 별도 로컬 진단을 사용한다. 양쪽 실제 명령·전투 계산 레코드를
대조하며, 이 강제 시드 실행은 자연 조우 검증과 구분한다. 이후 조우는 성능 합산에서
제외한다. 단순 계산 절약과 전체 행동 시간도 구별한다.

## 같은 입력을 맞춘 비교 결과

두 ROM의 첫 조우를 시드 138/profile 6으로 맞춘 별도 비교에서 두 명령의 `before`,
`call`, `fight`, `after` 전체 바이트가 각각 일치했다. 아래 이전 값은 PR 119 ROM에
첫 시드만 맞춘 진단이며, 위 최종 ROM의 자연 조우 검증을 대체하지 않는다.

| 항목 | PR 119 / 시드 138 진단 | 최종 자연 조우 / 시드 138 |
| --- | --- | --- |
| 첫 치명적 행동 전체 | 10,853.024ms | 10,669.075ms (-183.949ms) |
| 다음 생존 적 행동 전체 | 6,397.941ms | 6,381.063ms (-16.878ms) |
| 화면 준비 누적 12회 | 10,559틱 | 9,708틱 (-207.764ms) |
| 최대 화면 준비 | 1,046틱 / 255.371ms | 906틱 / 221.191ms |
| 첫 행동 마스크 137호출 | 151.199ms | 103.580ms |
| 첫 행동 타일 배출 75호출 | 15.008ms | 13.015ms |
| 첫 행동 전송 잔여/대기 109회 | 552.288ms | 498.271ms |
| 첫 행동 공개 대기 133회 | 361.204ms | 393.911ms |

마스크 CALL 구간은 약 31.5% 줄었으며, 같은 도트/타일 수다. 첫 행동의 나머지
화면 계산은 3,669.953 → 3,670.136ms로 사실상 그대로다. 오디오 생산 구간의 감소를
음원 엔진 자체의 처리율 개선으로 주장하지 않는다. 종료가 빨라지면 생산할 시간도 줄고
화면/오디오 대기 정렬이 달라진다. 다음 적 행동의 전송 대기는 오히려
210.366 → 234.048ms로 늘어 모든 구간이 단조롭게 빨라진 것은 아니다.

후속 마법의 `action_enabled` 구간 합계는 1,755.620 → 1,792.596ms로 **36.976ms 증가**했다.
이는 위 명령 전체 시간과 측정 경계가 다르며 같은 표에 합산하지 않는다. 마스크는
17.634 → 12.055ms로 줄었지만 오디오 생산 790.206 → 822.558ms, 전송 잔여/대기
114.508 → 127.370ms가 늘었다. 완성 그림은 같으며 생산/전송 대기 위상에 따른
잔여 지연이 남는다.
이를 없애기 위해 도트·숫자·이벤트를 생략하거나 오디오 선행량을 낮추지 않는다.
다음 작업은 순수 석화 공존 관문으로 돌아가고, 이 비용 분류를 공통 합성에도 적용한다.

## 필드 복귀에서 드러난 타이머 차단

첫 셀 최적화 ROM의 자동 검사는 타이머 편차 551.701µs로 기존 500µs 관문에 실패했다.
원작 이벤트/APU 해시와 underrun은 정상이었지만 이를 오디오 검증 통과로 취급하지 않았다.
읽기 전용 추적으로 필드 복귀의 타이머 호출 간격 4,100 master cycles와 화면 소유자
detach의 전체 DI 2,180 cycles를 연결했다. 다른 detach는 2,452 cycles였다.
8,388,608Hz에서 각각 259.876/292.301µs이며 타이머 한 주기 244.141µs보다 길다.

원작 `3F/FAB5..FADC`, `FADD..FAE8`은 화면 인터럽트 분기 코드를 교체하고
`FAE9`의 음악 요청과 `FAF2`의 사운드 실행을 따로 유지한다. GBC에서도 콜백 목록을
수정할 때 전체 인터럽트를 길게 막을 이유가 없다. VBlank 비트만 보관/차단한 뒤
목록과 소유자를 바꾸고, 그 비트만 복원한다. leave가 해제한 STAT를 예전 IE로
되살리지 않으며, TIM과 각 콜백의 짧은 자체 임계구역은 유지한다. 셀 계산이 빨라져
정렬이 달라지며 드러난 기존 전환 경합을 함께 수정한다.

## 검증 경계

호스트 원작/자원 계약, SM83 풀 단위 ROM과 의도적 실패 ROM, 통합 자동 행동,
모든 사망·점멸·마법 그림과 필드 왕복, 복합 상태 파티 패배를 검증한다.
도트/숫자 생략, 오디오 이벤트 생략, 허용 타이머 편차 확대는 허용하지 않는다.
ROM·원작 글리프·화면·관찰 로그는 로컬 build/evidence에만 보관한다.

최종 통합 ROM SHA-256:
`c76547e93768e9ca3ae9d8ad34528f0c6c2c27acfe53e005c254d8307491b3fb`.
호스트 전체 230건과 전환 수정 후 관련 계약 18건, SM83 풀 11개 묶음 및 의도적 실패,
소유권 교대 1,481건/원작 사운드 7,200틱을 통과했다. 풀 단위 검사는 512개의 단일 비트
조합을 추가했다. 통합 고정 DATA 1,400바이트와 남은 RAM/ROM 8/894바이트는 같다.

최종 자연 조우 자동 재생은 첫 행동 10,669.075ms, 다음 생존 적 행동 6,381.063ms,
화면 준비 누적 9,708틱/12회, 최대 906틱(221.191ms)이었다. 할당 78타일/페이지 최대
12타일/공유 재사용 0회를 유지했다. 원작 오디오 4,044틱과 실제 APU 쓰기 23,672회,
타이머 편차 353.336µs, 전송 오류/underrun 0을 통과했다. 필드 복귀 타이머 최대 간격은
3,108 master cycles(370.502µs), 전체 최대는 3,952 cycles로 두 타이머 주기 미만이다.

단계별 캡처는 사망 37그림·생존 적 점멸 8단계·마법 27그림과 정확한 복구, 같은 부팅의
필드 복귀 3회 및 복귀 후 이동을 통과했다. 오디오 4,032틱/23,909 APU 쓰기, 타이머
편차 326.157µs, 은행 전송 오류 0이었다. 복합 상태 패배도 원작 사망 자세, 20 VBlank
페이드와 재시작 메뉴까지 통과했다(2,065틱/12,024 APU 쓰기, 편차 294.685µs, 오류 0).

순수 석화의 UI 겹침·회색 팔레트·마법 동결 공존, 일반 턴 수집/보상/저장 재개는
다음 관문으로 남는다. 이번 최적화로 제품 완료 관문 수를 올리지 않는다.
