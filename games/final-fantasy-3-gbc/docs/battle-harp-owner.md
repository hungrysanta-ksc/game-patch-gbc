# 원작 하프 연출의 실제 화면 연결

기준은 PR 83 병합 `9aac6f7e31e837cdfb40f4088be3a6cdd0b94469`다.
이번 범위는 무기 종류 4인 하프 4종(원작 ID 70..73), 양손과 기존 검/봉 계열의
혼합 연출이다. 전투 선택·장비 적합성·피해 계산의 정상 게임 통합을 완료한 것은 아니다.
활/화살·투척·맨손/클로, 치명타·특수 상태·아군 피격·마법·사망은 별도다.

## 호출과 소유권

- `2F/B24F..B258`: 전진 → `A9CF` 직업 그림 → `A8EA` 양손 그림/속성 →
  `AEF0` 무기 애니메이션. 끝난 뒤 `B25B → B38B`로 돌아온다.
- `33/A0F8..A10C`: 어느 손이든 종류 4이면 `A24C`가 **오른손 명중 수를 왼손에
  복사**한다. 이후 `A094..A0BD`가 각 손의 상한을 적용한다. 원래 서로 다른
  명중 수를 그대로 쓰지 않는다. 빈손은 종류 0의 상한을 적용하고 상대 손에
  무기가 있으면 `A2F2`에서 그림 없이 돌아온다.
- `33/A1A5 → A11C`: 명중 반복 수 설정, 현재 손 팔레트 로드, 캐릭터 자세 저장.
  `A1A8/A1AA`는 해당 캐릭터의 독립 OAM 영역을 초기화한다.
- `A1AD..A1AF`: `$8B` 효과음을 손마다 한 번 요청한다. 반복마다 요청하지 않는다.
- `A1B2..A1E2`: 16프레임 루프. 앞 8프레임에는 하프/캐릭터, 뒤 8프레임에는
  명중 시 종류 1의 타격을 더한다. 0명중도 하프 동작은 한 번, 타격은 없다.
  `A1E4..A1EA`가 반복을 진행하며 하프 상한은 최대 4회다.
- `A1BE/A1C8`: 오른손은 하프 frame 14 → 캐릭터 pose 7, 왼손은 캐릭터 pose 6 →
  하프 frame 15 순서다. 검 계열과 다른 OAM 순서를 유지한다.
- `A1EC → AC3A`: 자세·객체를 복구하며 `AC35`의 `$FF` 정지 요청은 지나지 않는다.
  다른 무기와 공통이라는 이유로 하프에 정지 효과음을 추가하지 않는다.

기존 상주 직업·무기 자원, 전진/복귀, 변경 객체 생성, 동일 그림 재게시와
VBlank/OAM 한도 검사를 공유한다. 프레임별 완성 OAM/영상은 런타임 ROM에 넣지 않는다.
새 자산 복제나 별도 하프 난수 상태도 만들지 않는다.

## 타격점과 좌표

`32/97B2`는 0명중이면 타격 생성 없이 복귀한다. 명중 시 `98E0..991E`는 짝수
프레임에 공통 RNG 카운터 0에서 두 값을 소비하고 `&31` 오프셋을 대상 중심에
더한다. 홀수 프레임은 이전 점을 재사용한다. 하프는 원작 프레임 8..15를 전달한다.
16프레임 한 번당 RNG 8회, 최대 양손은 64회이며 카운터의 255→0 넘침도 유지한다.

원작 OAM 생성과 GBC 투영은 구분한다. 검증기는 원작 `B24F` 전체 호출을 실행하여
`33/A1DA`와 혼합 무기의 `A3C8` 직전 OAM·팔레트·타일·자세를 수집한다.
GBC에서는 기존 봉 계열의 적 7:8 기준점과 오프셋 투영을 공유한다.
16×16 타격 도트는 줄이거나 자르지 않으며 원본 크기 아군도 그대로다.

## 검증 구성

원작 ROM으로 초기화한 편성 3에서 무기/명중 입력을 행동 호출 경계에 주입한다.
이는 연출 소비자의 증거이며 직업별 장비 취득·선택·피해 계산 경로의 증거로 세지 않는다.
정면/백어택 각 8조건은 하프 4종, 양손, 오른손/왼손 중 한 손이 빈 조합, 검/봉 혼합, 0/1/2/3/4/99
입력 명중과 서로 다른 좌우 명중을 포함한다. 별도 16조건은 아군 4명·적 8칸과
두 난수 표/카운터 넘침을 검사한다. 하프→9999 숫자도 정면/백어택으로 연결한다.

```powershell
node tools/build-battle-party-oam.mjs --effects
node tools/verify-battle-strike.mjs --harp --skip-build
node tools/verify-battle-strike.mjs --harp --back --skip-build
node tools/verify-battle-strike.mjs --harp --positions --skip-build
node tools/verify-battle-strike.mjs --harp --numbers --skip-build
node tools/verify-battle-strike.mjs --harp --auto --skip-build
```

각 배치는 전체 7,200틱 음악/동적 효과음 소비 해시와 오류 가드를 검사한다.
기존 검/봉·숫자 경로도 같은 최종 ROM에서 회귀 검사한다. 하프는 147게시로
기존 83게시보다 길어 중복 계측 행이 에뮬레이터 로그 한도를 넘었다. 완료 시각은
이미 기록하는 `action-frame-cost`의 동일 카운터 쓰기 시각에서 읽도록 통합했다.
프레임 수·연속성·독점 비용 합·실제 DMA 시각 검사를 약화하지 않았다.

## 최종 결과

검증 ROM SHA-256은 `fc534c7bc6eb94668615944a43bf27ba48c9024ffb99230079e717b1069929cf`다.

| 검증 | 결과 |
|---|---|
| 하프 정면 / 백어택 | 각 8조건·709장 |
| 하프 대상 위치 / 숫자 연결 | 16조건·816장 / 2조건·132장 |
| 기존 검 / 봉 / 봉 위치 / 봉 숫자 / 공통 숫자 | 368 / 636 / 688 / 116 / 198장 |
| 전체 화면 대조 | 4,372장, 원작 OAM·타일·팔레트와 GBC 투영/픽셀 일치 |
| 음악·동적 효과음 | 12회 각각 7,200틱, 총 86,400틱; 원작 소비/변환 해시 일치 |
| 오류 | 오디오 부족·지연, 잘못된 VRAM/OAM 접근 0 |
| 관련 호스트 검사 | motion-sprites / preparation / animation, 11검사 통과 |
| 소스 전용 재현 | 공개 허용 593파일, 별도 빌드의 ROM/보고서 등 9산출물 일치 |

자동 재생은 화면 캡처를 위한 대기 없이 별도로 검사했다. 하프 최대 양손은 본체
128프레임과 이동/복구 19프레임, 총 147회 게시·효과음 요청 2회를 유지한다.
전체 행동 3249.265ms, 최초→최종 실제 DMA 3164.372ms, 최대 DMA 간격 83.955ms다.
하프의 원작 16프레임 반복은 검의 8프레임 반복과 다르므로 둘의 총 시간을
같은 작업의 성능 비교로 취급하지 않는다. 원작 속도 달성을 주장하지 않는다.
기존 검은 2110.175ms / 실제 DMA 2025.867ms, 봉은 2110.206ms / 2025.867ms다.
검의 PR 83 기준 시간은 유지됐고 두 계열 모두 최대 DMA 간격은 83.956ms다.
모든 자동 검사의 90ms 최대 DMA 간격 회귀 기준을 통과했다.

bank 55 코드 크기는 `0xE3F`(3,647바이트, 334바이트 증가), 고정 WRAM 끝은 `0xCEF8`이며
264바이트 여유를 유지한다. 새 자산이나 고정 RAM 버퍼를 추가하지 않았다.
R2 0/8·제품 0/3은 유지한다. 다음은 남은 활/화살·투척·맨손/클로 소비자를 같은
공통 호출과 자원 수명에 연결하고, 이후 피격·감싸기·적 점멸·마법·사망으로 이어간다.
