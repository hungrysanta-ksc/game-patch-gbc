# 7:8 적 축소를 유지한 상주 배경과 실제 스크롤

2026-11-25. 기준 PR 57 병합 `0ecf63751c65c782ce72fdeab22a0af1a1b4390a`.
사용자는 32×32 적의 28×28 표현을 유지하도록 선택했다. 다른 크기의 적도 기존
7:8 좌표/샘플링을 유지한다. 모든 적을 일괄 28×28로 바꾸지 않는다.

## 원작 구조와 GBC 대응

원작 `2F/B469..B479`, `AE5E..AEA3`의 스크롤 값 `$0F`와 적 영역 페이지 `$07`을
기존 C 상태기에서 받는다. `$06`을 적 페이지로 잘못 쓰거나, 화면 프레임 번호로
좌표를 보간하지 않는다. 일반 아군은 PR 57의 상주 OBJ 소비자를 그대로 사용한다.

원작 두 페이지 512픽셀을 7:8로 변환한 **448픽셀 공간 자료**를 한 번 만든다.
원작 16픽셀 스크롤은 14픽셀, 한 페이지 256픽셀은 224픽셀이다. 448픽셀 순환과
GBC 256픽셀 순환은 다르므로 단순히 SCX에 값만 넣으면 반대쪽에 적이 잘못 나타난다.
32열의 주변 맵을 유지하고, 보이는 최대 21열이 그 안에 있으면 SCX만 바꾼다.
밖으로 나갈 때만 비활성 맵에 새 주변 32열을 적재한 후 VBlank에서 맵/SCX/OAM을 게시한다.
맵 페이지와 OAM 이중 버퍼의 소유권은 독립이다.

이 변환은 초기화된 원작의 타일·맵·팔레트에서 만들어진다. 등장 관측 목록을 비워도
공급 자산 바이트가 동일하다는 검사를 둔다. 미래 화면·프레임 번호별 맵이나 완성
화면 그림은 runtime ROM에 넣지 않는다. 원작 실행과 관측 프레임은 개발용 비교 기준이다.

범위는 대표 편성 3의 **적 BG + 일반 아군 OBJ를 함께 표시하는 등장 전반부**다.
현재 지형 마스크, `B479` 이후 정규 진열·석화 BG·상태 아이콘, 하단 창은 연결하지 않았다.
검은 상단/하단과 혼합 상태에서 숨겨진 석화 아군은 이 경계에 따른 것이며 완성 화면이 아니다.
보스·다른 편성·모든 직업·마법의 자산 공급 완료나 정상 게임 진행 완료로 세지 않는다.

## 하드웨어 차이와 자원 수명

[Pan Docs 스크롤](https://raw.githubusercontent.com/gbdev/pandocs/master/src/Scrolling.md)은
SCX/SCY가 256×256 맵에서 픽셀 단위로 순환함을 명시한다. 14픽셀 이동은 가능하며
이동량을 8의 배수로 바꾸거나 적을 추가 축소할 필요가 없다. 정렬별 그림 네 벌을
상주시켜 타일 경계를 해결하는 후보는 이 편성에서 419패턴을 요구해 채택하지 않았다.

현재 한 방향의 자산은 130패턴(2,080바이트), 공간 맵/속성 1,232바이트,
색 보정용 객체 설명 30바이트, 원작 BG 팔레트 32바이트로 **3,374바이트**다.
BG와 색 보정 OBJ는 bank 1의 같은 패턴 저장소를 공유한다. 아군은 bank 0을 유지한다.
색 보정 객체 최대 6개는 팔레트 4..7을 사용하며 아군 뒤의 OAM 순서를 갖는다.
이 123장면의 실제 8×8 OAM은 최대 총 30개, 줄당 5개다. 투명 도트만 있는 아군
슬롯도 하드웨어 선택 수에 포함한다. 숫자·무기·마법 공존 예산을 해결했다는 뜻은 아니다.

초기 적 패턴과 맵은 원작 초기화 결과에서 공급하며, 등장 전반부에서 적 패턴
`0700..0FFF`와 원작 맵 `2000..27FF`가 불변임을 매 관측에 대조한다.
소유자가 이 영역을 변경하면 자산 검증이 실패한다. 지형 `0600..06FF`는 별도 갱신 수명이다.
원작 첫 대기에서는 물리 팔레트가 검으므로 적을 숨기며, 이후 대기부터 표시한다.

새 맵 버퍼는 WRAM `D200..D4BF` 704바이트다. 주변 맵 교체 시 패턴이 아닌
11행 × 32열의 타일 번호/속성 704바이트를 비활성 VRAM 맵에 전송한다.
현재는 변경 열만 전송하는 최종 방식이 아니며, 전체 주변 맵 복사의 비용이 남는다.
새 자산 공급을 위해 두 맵을 사용하므로 지형/UI 독립 스크롤을 연결할 때 같은 맵
소유권과 raster/IRQ 비용을 확인해야 한다. 각 기능이 맵을 따로 독점한다고 가정하지 않는다.

## 검증

원작 OAM/상태를 같은 ROM에서 대조하고 실제 GBC 캡처를 원작 NES 비트플레인으로
그린 V6 기준과 비교한다. 별도 native 디코더도 같은 픽셀과 일치해야 빌드가 진행된다.
정면/백어택 × 일반/사망·석화·개구리·미니 혼합의 123장면을 검사한다.
추가로 공간 맵의 224개 짝수 스크롤 위치, 자산 불변, 왼쪽으로 일부만 들어오는
보조 OBJ, 미지원 스크롤 단위의 거부를 확인한다.

- 실제 GBC 화면 123장, OAM/상태, bank 1 상주 패턴 및 맵 버퍼 경계 검사 통과.
  정면/혼합 백어택의 최종 캡처도 직접 확인했다.
- 같은 ROM의 원작 음악·효과음·페이드 7,200틱 소비 이벤트/출력 해시 일치.
  underrun/지각 0, 오디오 시계 누적 차이 +0.1087ms로 기존 3ms 기준 통과.
- 자동 반복 등장 구간에서 패턴 전송 0바이트, 맵 전송 305,792바이트,
  OAM DMA/SCX 게시 2,854회, 잘못된 전송 경계 0. DMA 시작 최대 LY 146.
  맵 전송량은 704바이트 교체 434회에 해당한다. 초기 자산 적재량은 이 수치에서 제외한다.
- 최대 전체 준비 147.217ms, 1프레임 초과 표시 간격 1,491회, 최대 11프레임 간격.
  맵 구성 최대 56.396ms, 전송 함수 구간 최대 95.215ms,
  직접 오디오 서비스 호출 누계 최대 53.467ms. 전송 구간은 실제 DMA만이 아니라
  VBlank 대기와 내부 오디오 서비스도 포함한다. 각 최댓값은 같은 호출의 분해값이
  아니며 직접 오디오 서비스는 구성/전송 시간에 포함되므로 서로 더하지 않는다.
- 처음의 매 스크롤 맵 교체 후보는 최대 준비 233.643ms를 기록했다. 주변 맵 재사용으로
  불필요한 교체를 줄였지만, 현재도 원작 속도 목표는 미완료다. 아군만 표시한 PR 57의
  10.254ms와 작업량이 다르므로 전체 전투가 빨라졌다는 비교 근거로 사용하지 않는다.
- 호스트 검사 140개 통과. 기존 아군 단독/양성/오차 주입 ROM 세 개의 해시는 PR 57과
  동일하다. 변경한 공용 검증기로 기존 아군 단독의 원시 실행 증거도 재검사했다.
- 공개 허용 소스 473개만 복사한 디렉터리에서 새 표시 ROM·양성·오차 주입 ROM 및
  보고서가 모두 바이트 단위로 재현됐다.
- 최종 표시 ROM SHA-256:
  `3450753bf6eba98145e4a79f9b2af93f263b4d18da11c821087ea6f5dc5f7360`.

검사 도중 왼쪽에 걸친 보조 OBJ의 448픽셀 좌표를 그대로 8비트로 줄이는 오류를
발견했다. -7..-1 위치는 native OAM의 1..7로 변환하도록 수정하고 전체 경로를 다시
검사했다. 확장 전송 감사에 기존 Lua 본문을 잘못 전달한 검증기 오류도 수정해,
GDMA 목적지/길이와 실제 SCX 쓰기를 포함한 최종 실행으로 다시 검증했다.

재현: `npm run build:battle-resident-bg`, `npm run verify:battle-resident-video`, `npm test`.
원시 ROM, 초기화된 PPU 자료, 변환 자산, 캡처와 생성 ROM은 Git 밖에 둔다.

   적 SCX와 지형 고정 영역을 구분하고, 오디오 IRQ와 raster 경계의 최악 지연을 검사한다.

   되돌아가거나 일반 아군을 항상 BG로 옮겨 한도를 맞추지 않는다.
