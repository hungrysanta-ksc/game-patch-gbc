# 필드·전투 화면 소유권 경계

2026-11-27. PR 104의 자원 등록부 다음 단계다. **실제 필드와 전투 표시기를 공통
인계 API에 연결했다. 아직 하나의 ROM에서 조우하고 복귀하는 게임은 아니다.**
독립 실행기의 성능 수치를 더 줄이는 것보다, 통합 시 충돌하는 소유권과 배치를 먼저 검증한다.

## 원작 기준과 GBC 대응

- `3E/C049`의 가방 전달, `3F/FA26..FA80`의 전투 호출/복귀가 장면 경계다.
  `FB17/F83B`는 사운드 DP `$D0..DF`를 제외한 문맥을 보존/복구한다.
  `FAB5/FADD`는 6바이트 IRQ 디스패치를 교환한다. 이전 소리 상태를 덮지 않는다.
- 일반맵 `E7EC`의 신규 적재와 `E7F8`의 복귀는 다르다. 복귀는 `E811` NPC 초기화를
  건너뛴다. 따라서 화면 재부착에서 GameState나 NPC를 새로 초기화하면 안 된다.
- GBC에서는 실행 코드를 덮는 대신 GBDK VBlank 콜백을 교체한다. 공통 텍스트 전송과
  오디오 타이머는 상주하며, 장면 콜백을 공통 텍스트 콜백 앞에 유지한다. 프레임마다
  공통 간접 디스패처를 추가하지 않았다. 차가운 진입/이탈 함수만 ROM 뱅크 15로 옮겼다.
- 인계 전에 새 작업을 중단하고 필드/전투 pending 및 공통 텍스트 전송을 비운다.
  창이 열렸거나, WRAM 복사 중이거나, 마법이 빌린 자원을 복구하지 않았으면 거부한다.
  기본 OAM DMA를 끄고 전투 LCD 래스터 콜백도 제거한다. 전투 동결·미러 캐시는
  무효화한다. 같은 콜백을 재등록해도 중복 실행하지 않는다.

`scene-video.c`는 표시 소유권만 담당한다. 필드 문맥 저장, 조우 결과, 승리나 보상,
새 자산의 적재를 수행하지 않는다. `field.request=12/13`, `party_request=2/3`은
검증용 중단/재부착 요청이며 정상 게임 동작으로 세지 않는다.

## 통합 준비 중 드러난 필드 오류

열 전송에서 타이머 우선 배치가 남긴 인덱스 30에 VBlank 첫 배치가 4쌍을 더해
34로 넘어갔다. 완료 조건 32를 놓쳐 한 전송이 858ms까지 지속될 수 있었다.
첫 배치도 남은 2쌍으로 제한한다. 숫자·그림·타일을 생략하지 않는다.

또한 기존 오디오 협력 양보는 `prepare()`를 한 번 더 실행한 뒤 검사했다. 방향을
전환하고 화면을 준비해야 할 때도 무거운 오디오 틱 하나가 추가됐다. 원작 일반맵
`3F/E1E1..E201`은 VBlank/OAM/스크롤 후 한 번의 사운드 갱신을 실행한다. GBC는
타이머 소비용 선행 큐가 필요하지만, 두 틱 이상 준비됐고 논리 갱신 기한 또는 미표시
그림이 있으면 추가 생산 전에 양보할 수 있다. 원작 논리 틱, 명령, 출력 패킷,
기본 세 틱 선행 목표와 타이머 소비기는 유지한다. 이 수정은 탐색 빌드에만 적용한다.

## 재현과 검증 범위

```powershell
npm run build:exploration
npm run build:battle-effects
npm run verify:scene-video
npm run verify:scene-endpoints
npm run verify:exploration
npm run verify:battle-effects
node tools/verify-battle-magic.mjs --smoke
npm run audit:scene-link
```

- 공통 API 진단: 1,481개 검사, 128번 해제, 실제 pending 전송 거부 64번.
  원작 음악/효과음 7,200틱의 소비 해시와 underrun/late 0을 확인한다.
- 실제 표시기: 별도 필드 ROM 2회, 전투 ROM 4회 중단/재부착. 중단 중 VRAM 불변,
  오디오 진행, GameState 보존, NPC 보존 또는 전투 상주 VRAM 재현을 검사한다.
  필드 열의 마지막 2쌍을 64번 직접 시험한다. 플레이어 좌표·NPC를 조작하는 검사가 아니다.
- 기존 탐색 검사는 입력/이동 논리·NPC·한글 대사·화면 픽셀·APU 버스와 성능 기준을
  그대로 검사한다. 효과/마법 검사는 기존 도트·피해 숫자·복구·오디오 회귀다.
  음질 개선 또는 새 정상 전투 기능의 완료로 해석하지 않는다.
- 원본 ROM, 생성물, 캡처와 실행 로그는 로컬에만 둔다. 배포에는 변환/검증 소스만 포함한다.

현재 실행 결과: 탐색 7,191개 관찰 프레임과 원작 오디오 7,200틱 통과. 실제 스크롤
반영 최대 30.436ms(기준 35ms), 이동 중 동일 스크롤 최대 3프레임(기준 3),
열/행 전송 최대 41.348ms(기준 55ms)다. 논리 시간 오차는 96.317초 동안 +7.621ms이며
원작 이동/NPC 판정과 화면 픽셀을 유지했다. 오디오 생산의 한 호출 최댓값 38.809ms는
직전 실패 빌드의 32.775ms보다 크지만, 필요한 화면에 양보하는 순서를 고쳐 화면 정체
기준을 충족했다. 모든 비용이 줄었다는 주장은 하지 않는다.

표시기 재진입은 필드 163회 관찰/164틱, 전투 327회 관찰/330틱에서 통과했다.
효과 회귀는 6개 경우/198프레임, 마법 smoke는 1개 경우/27프레임·35개 화면을
검사했다. 두 검사 모두 원작 오디오 7,200틱, 불법 VRAM/OAM 접근 0, 복구 차이 0이다.

## 실제 합친 링크와 다음 단계

`audit:scene-link`는 두 진단의 main을 각각 다른 이름으로 바꾸고 공통 모듈을 한 번만
링크한다. 기존 필드·전투의 생성 뱅크도 실제로 함께 넣는다. 비활성 진입점을 사용하며
충돌한 ROM을 실행하거나 배포하지 않는다. 링커 종료 코드 0만으로 성공 판정하지 않는다.

114개 입력 소스를 합친 현재 배치의 고정 RAM 끝은 `$D381`로 `$D000`을 897바이트,
고정 ROM/초기화 데이터 끝은 `$4C3B`로 `$4000`을 3,131바이트 초과한다. 자산을 포함해
링커가 기록한 중복 쓰기 경고는 69개다(고유 뱅크 개수가 아니다). 이것은 기존 두
진단의 배치를 그대로 합칠 수 없다는 증거이며 GBC 이식 자체가 불가능하다는 뜻이 아니다.

다음 순서는 (1) 지속 상태와 장면별 작업 RAM의 명시적 오버레이, 비 IRQ 코드·자산의
공통 뱅크 재배치, (2) 원작 일반맵 복귀 문맥 실제 추적, (3) 단일 부팅/오디오 아래
조우→전투 적재→진단 종료→필드 복귀와 두 번째 조우다. 그 뒤 원작의 결과/승패/이벤트
연결을 완료한다. 별도 ROM 재부착 검사를 단일 ROM 왕복으로 대신하지 않는다.

R2 0/8·제품 0/3은 유지한다. 전체 우선순위는 [로드맵](implementation-roadmap.md)에 있다.

추가 검증: 기존 테스트 189개, 메모리 계약 변조 거부 75개, 공통 전송 경계 17개,
원작 인계 512사이클/3,072호출을 통과했다. 링크 실험의 초과는 의도적으로 노출한
통합 차단 사유이며, 실행 ROM의 용량 검사를 완화하지 않았다.
