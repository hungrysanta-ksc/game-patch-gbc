# 원작 이벤트의 NPC 이동·대기

일반 탐색과 한글 대사 사이에 프레임 단위 이벤트 실행기를 연결한다. 개발 진입
맵 10의 NPC 30이 선택하는 원본 이벤트 118을 사용한다. 초기 배치·표시 플래그,
대사·이동·대기 순서는 ROM에서 읽으며 진단용 이야기를 작성하지 않는다.
새 게임부터 이 맵까지 진행하거나 전체 이벤트가 완성됐다는 뜻은 아니다.

## 원작 계약

| 주소 | 이식한 동작 |
|---|---|
| `3E/C72C..C74F` | 원작 포인터로 시작, 반복 카운터만 초기화 |
| `3E/D219..D277` | 프레임별 명령 읽기, 직전 명령 반복, PC 증가 |
| `3B/ACD1..AD4A` | 12개 슬롯의 이동·방향·표시·숨김·연속 애니메이션 |
| `3B/AFDD..B0C4` | 방향별 목적지 예약·서브픽셀·포즈·대기 카운터 |
| `3B/B110..B17B` | 이벤트 강제 이동의 지형 높이 갱신과 충돌 우회 |
| `3B/B775..B79C` | FC 대기, 8비트 감소와 PC 되돌리기 |
| `3B/B6BF..B6E7`, `B7A3` | 대사/플래그 명령과 이벤트 종료 |
| `3F/E32E..E37D`, `E229..E249` | 입력 대신 이벤트 실행, 대화 후 NPC 픽셀 처리 |

지원 범위는 NPC 명령의 하위 값 `0..9,C,D`, `F0..F3,FC,FE,FF`다.
점프·원운동·회전, 플레이어 강제 이동, 차량, 전투·맵 전환 등은 이벤트 전체를
실행하기 전에 거부한다. 지원하지 않는 명령을 성공한 것으로 처리하지 않는다.
기존 대사 전용 진단 ROM의 실행기는 그대로 유지하며 탐색 빌드만 확장한다.

- NPC가 이미 이동 중이면 `$17`을 증가시켜 같은 명령을 재시도한다. 숨겨진
  슬롯도 원작 명령 대상이며, 표시된 NPC만 매 프레임 픽셀 이동을 한다.
- 이벤트 강제 이동은 일반 이동과 달리 플레이어/NPC 예약 충돌과 지형의
  거부 carry를 무시한다. 지형 루틴이 실제로 바꾼 높이 층은 보존한다.
- `FE n`은 **직전 명령**을 반복한다. FE 자체도 한 프레임을 쓰며 `n-1`을
  8비트로 저장한다. 다음 명령을 반복하는 새 문법으로 바꾸지 않는다.
- `FC n`은 감소 전 값이 0일 때 끝난다. 따라서 n+1번 실행되며, 실행 중
  PC를 2바이트 되돌린다. 대기 임시값 `$74/$75`는 새 이벤트 진입 시 지우지 않는다.
- 원작은 1바이트 명령에서도 다음 바이트를 `$71`로 읽는다. `BFFF`의 FF는
  고정 은행 `3E/C000`을 미리 읽으므로 해당 1바이트도 원본에서 공급한다.
- 대사 값 0은 “대기 중인 대사 없음”이며 문자열 0을 여는 명령이 아니다.
- 이벤트 중 새 무작위 이동은 예약하지 않는다. 기존 이동·애니메이션은 진행하고,
  한글 창이 열린 동안에는 멈춘다. 창을 닫으면 이벤트로 돌아가며 FF 뒤에 탐색한다.

추가 이벤트 상태는 `$17,$70,$71,$74,$75`에 대응하는 5바이트다. 탐색 상태
예약에는 읽기 전용 계측용 busy 표시 1바이트를 추가해 76/80바이트를 사용한다.
원작의 모든 임시 변수 공유나 전체 컷신 타이밍까지 완료한 것은 아니다.

이벤트에서도 논리 마감을 버리지 않고 최대 두 프레임을 처리한 뒤 OAM을
제출한다. 처음에는 매 프레임 화면을 합성해 실제 대기/이동이 약 0.33초 늦어졌다.
명령이나 픽셀 이동을 생략하지 않고 표시 제출만 묶었다. 원시 명령 관측의
프레임 카운터와 master clock을 함께 비교하며, 창이 열린 구간을 제외한 연속
명령 시계 오차와 단일 명령 점유를 각각 기존 정체 예산 55ms 안으로 제한한다.

## 재현과 검증

`local.json`의 `event`는 기존 `dialogue`와 같은 외부 입력 계약이며, 검수된
맵 10/NPC 30 설정과 문자열 546·547 대응을 사용한다. 제공된 한국어 문구를
수정하지 않고 페이지 표식만 기존 창의 줄 배치 제어에 연결한다. 대응표·번역·
폰트·ROM·원시 관측은 공개 소스에 포함하지 않는다.

```text
node tools/build-text.mjs --explore
node tools/build-text.mjs --event
node tools/build-exploration-verifier.mjs
node tools/verify-exploration.mjs --units
node tools/verify-exploration.mjs
node tools/verify-event-motion.mjs
```

`event-motion-source.mjs`의 기대값은 수정하지 않은 원작 `ACD1` 또는 `D219`를
실행해 만든다. 새 경계 검사 2,186건에는 모든 슬롯/지원 NPC 명령, 이동 중
재시도, 숨김, 지형 256값과 높이 층, 대기 256값, 실제 FC/FE 인자가 포함된다.
기존 8,640건과 합쳐 10,826건을 비교한다. 원본 이벤트 바이트는 새로 만들지 않는다.

통합 경로는 원작 초기 상태에서 맵에 개발 진입한 뒤 실제 A 입력으로 이벤트를
두 번 실행한다. 명령과 픽셀 갱신 경계의 관측은 메모리를 읽기만 한다. 전체
명령 상태/PC/객체 바이트를 원작과 비교하며, 표시 비교용 일시정지 캡처는
정상 플레이 타이밍의 증거와 구분한다. 기존 맵 29의 연속 이동/대화 및 7,200틱
음악·효과음·페이드 검사를 별도 회귀 경로로 유지한다.

## 통합 결과 (2026-11-23)

이벤트 ROM SHA-256은
`9370bcaec7aa5a9113f955f49682d4e57ecdf0540e70d11d4bf4d18be44ed0a3`다.
고정 Mesen core는
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.

- 실제 A 입력으로 이벤트 두 번 완료. 명령 전이 668회, 픽셀 갱신 668회가
  원작과 일치한다. 이동 중 명령 재시도 172회와 FC 실행 460회를 포함한다.
- 연속 이벤트 논리 시계의 최대 오차 28.060ms, 대사를 제외한 단일 명령 최대
  1.451ms. 이전 332.945ms 누적 지연을 수정했으며 55ms 기준을 완화하지 않았다.
- 원작 오디오 7,200틱/21,366이벤트, 실제 APU 쓰기 30,938회/해시 16366.
  보고된 지연·큐 부족, 잘못된 영상/OAM/스크롤 쓰기, LCD-off는 0이다.
  master clock 대비 오디오 타이머 오차는 -0.329..0.018ms였다.
- 체크포인트 7개, 161,280픽셀이 원작 데이터에서 만든 표시와 일치한다.
  한 줄 스프라이트 최대 6개다. 두 번째 대사 화면의 7×7 한글도 직접 확인했다.
- 정적 WRAM 끝 `CFCA`, 탐색 상태 76/80바이트, 스택 예약 848바이트.
  공개 허용 소스는 190개이며 원본/추출물/번역/글꼴은 별도의 로컬 입력이다.

위 시간은 이 개발 진입 경로의 측정값이다. 원작 창의 표시 속도, 전 이벤트의
성능, 전체 맵의 객체 우선순위 또는 실기 호환 완료를 의미하지 않는다.

## 다음 소비자: 동행 NPC

동행 NPC는 일반 12개 NPC 슬롯의 무작위 이동을 재사용하지 않는다.
`3D/B6DA..B714`는 플레이어가 이동을 시작할 때 방향·층 정보를 `$E1..$E4`
네 칸에 밀어 넣는다. `B716..B789`는 지연 거리·대기 상태·프레임 카운터에
따라 칸을 꺼내며, 속도 선택은 `$F4`를 소비하지 않고 `$F0`로 원작 난수 표를
읽는다. `B78A..B7F8`의 픽셀 이동과 `3E/DB58` 표시/우선순위를 함께 연결해야 한다.
다음 작업은 이 큐·대기·이동·그림/팔레트 공급을 원작과 대조하는 묶음이다.
그 뒤에 맵 전환에서 초기 진입/재진입 및 NPC RNG 수명을 연결한다.
