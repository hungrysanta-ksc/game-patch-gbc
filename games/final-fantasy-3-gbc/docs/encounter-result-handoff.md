# 공유 조우 카탈로그와 행동 결과 인계

2026-11-28. PR 113 병합 `3f5709a709510d4f69208d278819ead4a7314d03` 이후.

## 구현 범위

동굴 배경 8을 공유하는 일반맵 181·111·115·112·22·113의 그룹 0..3을
같은 카탈로그로 묶었다. 그룹별 8칸의 중복 편성을 그대로 보존하고, 자원은 편성
0..3의 합집합으로 한 번씩 생성한다. 인원 조합·정면/백어택을 합쳐 공간 키는
14개에서 44개로 늘어난다. 필드 경계는 생성된 맵 목록을 사용하며 월드맵·차량은
허용하지 않는다. 이 등록은 해당 맵 사이의 이동 이벤트 구현 완료를 뜻하지 않는다.

`battle-result`는 이미 이식한 물리 계산의 레코드 입력/출력을 전투 상태에 연결하는
코어다. 계산 직후 HP를 저장하되 상태는 원작 E0/F0 버퍼에 보류한다. 실제 손별
명중 수·피해 숫자·메시지는 `Ff3Fight` 전체 출력에 남기며 축약하지 않는다.
스크립트 0D/0E의 상태 확정과 승패·도주 판정을 별도 함수로 옮겼다.

**아직 정상 전투 완료는 아니다.** 이 코어는 독립 GBC 대조 ROM에서 실행한다.
통합 V6의 실제 명령 수집→계산 호출, 스크립트 0D/0E→사망 표시 소유자,
보상/성장/가방 반영→승리·도주 복귀/패배 분기는 이번 범위에 연결되지 않았다.
기존 `scene_request=2`는 계속 명시적 진단 복귀이며 승리로 해석하지 않는다.
미구현 사망 표시를 즉시 적 삭제나 성공 응답으로 대체하지 않았다.

## 원작 소비자와 수명

| 원작 | 유지한 구조 |
| --- | --- |
| 3D/BD4D, BDB9; 2E/92F0,94F0; 39/BC00 | 맵→그룹→편성 및 별도 배경 선택. 중복 슬롯은 확률의 일부이고 자원 중복과 구분 |
| 2F/A02A,A0B7,9FAA | 선택 편성의 인원 난수와 배치. 정적 자원 카탈로그만 확장 |
| 30/9E8A..31/A2B9 | 정본 64바이트 레코드→물리 계산→HP/상태 버퍼/손별 숫자 |
| 34/9369..93B6,9408,9474 | 숫자 이후 상태 확정. 아군/적 공격·대상 조합에 따른 버퍼 적용 순서, 빈사 판정 |
| 34/80C9..811C; 35/A458 | 행동 사이·턴 종료의 결과 검사. 도주 우선, 전원 사망/석화 패배, 살아 있는 파티가 있을 때 남은 적 0이면 승리 |
| 35/A8BF,A93B,A978 | 일반 도주·특수 도주·적 도주. 원작 RNG1 진행과 실패 메시지 |
| 34/811C..8184,8306; 35/BB49..BF7B | 미통합 종료 호출 순서: 메시지/종료 그림, 승리 보상·성장, 캐릭터/장비·가방 반영과 복귀 |

상태 버퍼는 OR로 합쳐지며 적의 `E8` 마스크 뒤 죽음 처리에서 다른 비트가 지워지는
원작 동작도 유지한다. 아군 사망 시 상태 2의 추가 적용을 건너뛴다. 포격의 0E는
일반 0D와 달리 빈사 갱신을 호출하지 않는다. 승리는 HP 0 개수를 세어 조기 확정하지
않고 사망 표시 소비자가 갱신하는 `$7DD2`를 기다린다.

일반 도주는 `(도주 능력치 + 25)`의 8비트 넘침을 유지하고 남은 적의 평균 레벨을
뺀다. 선제공격으로 확률 실패를 우회해도 원작 난수 호출은 발생한다. 특수 도주는
확률 난수를 소비하지 않지만 도주 금지 플래그와 파티 네 슬롯의 혼란 검사를 유지한다.
적 도주는 전체 전투 결과를 도주로 바꾸지 않고 해당 적의 상태 버퍼/탈출 마스크만
설정한다. 없는 적에 대한 평균 계산 등 미지원 입력은 명시적으로 거절한다.

원작 `$7575..7874`의 전투 레코드는 전투 내내 상주하는 구조다. 새 코어의 828바이트
구조체는 그 레코드와 상태/결과 메타데이터의 ABI다. **통합 ROM에 이 크기의 전역을
추가하지 않았다.** 현재 고정 RAM 여유는 43바이트이며, 통합 시 WRAM5의 기존 아군
레코드 영역을 확장하고 제한된 작업 공간으로 연산해야 한다. 스택이 WRAM1에 있으므로
SVBK를 바꾼 채 C 연산을 하는 설계는 금지한다. 숫자/사망/복구 중 사용하는 작업 공간과
동시에 매핑해서도 안 된다. 정적 원작 자원을 변환하되 상태·계산을 빌드 시 프레임으로
구워 넣지 않는 원칙을 유지한다.

## 검증

전체 `npm test` 212개 통과. 아래 코어/통합 ROM 검증은 각각 별도로 실행했다.

- 원작 코드 실행과 컴파일된 GBC 코어 **5,226건** 대조: 상태 순서 2,048,
  포격 상태 257, 빈사 경계 100, 승패 2,048, 도주 480, 네 슬롯 혼란 24,
  거절 5, 원작 속성으로 초기화한 22직업 양방향 물리 계산 인계 264.
- 마지막 264건은 HP·상태만이 아니라 `Ff3Fight` 175바이트 전체와 난수 커서까지 대조.
  첫 기대 바이트를 고친 음성 대조 ROM은 사례 0 / 바이트 0에서 실패한다.
- 4편성 × 256 시작값의 원작 인원·슬롯 소비자 검사. 44개 배치의 타일·두 팔레트
  평면·잔여 OBJ를 다시 디코딩해 모든 적 도트를 비교한다. 잔여 OBJ 최대 8,
  단일 자원 뱅크 최대 15,343바이트. 기존 아군·숫자/효과 자원은 공유한다.
- 새 통합 ROM에서 자연 조우·명시적 복귀 3회, 확률 호출 114회, 실제 화면 8장,
  원작 오디오 2,740틱 / 실제 APU 쓰기 15,346회 대조. 언더런·늦은 오디오·잘못된
  VRAM/OAM 접근·WRAM 뱅크/IRQ 오류 0. 타이머 오차 범위 310.421µs.
- 별도 마을 시작 통합 ROM도 새로 빌드해 실제 실행했다. 7회 조우/복귀, 무기/숫자
  원작 프레임·효과음 및 복귀 후 이동/대화, 화면 589장, 오디오 7,200틱 / APU 쓰기
  34,152회를 대조했다. 관련 오류 0, 타이머 오차 범위 332.832µs. 이 경로의 조우
  타일/확률은 통제된 진단이며 자연 조우 검사와 구분한다.
- 같은 ROM의 장면 메모리 검사 650건 / 64회 교환 / 오디오 7,200틱.
  고정 RAM 43바이트, 고정 ROM 1,373바이트 여유. 필드 보존 4,050/4,096바이트.
  자연 조우 적재 1.016–1.030초로 0.5초 목표에는 아직 미달한다.

   후에만 필드로 복귀. 이때 같은 부팅 두 번째 조우와 이동·대화까지 재검증.
