# 아군 사망과 일반 패배의 재시작 화면 경계

기준은 PR 116 병합 `bc06c5c31d6ca340d83ea9e0479bd2a93b314a96`이다.
기존 자연 조우 ROM의 실제 물리 명령을 사용한다. 정상 명령 수집기나 턴 스케줄러를
새로 만든 것으로 세지 않는다. 검증은 1 HP와 높은 공격력을 명시적으로 주입한다.

## 원작 소비자와 순서

| 원작 | 유지하는 역할 |
| --- | --- |
| `34/9369`, `9D06`, `2F/B3D3`, `9E80` | 숫자 뒤 상태 확정, 정규화 상태 전달 |
| `2F/B5B8..B7CB` | 네 명 순회, 그래픽 종류 캐시, 숨김→필요한 타일 교체→자세/위치 갱신 |
| `35/A458..A486` | 탈출 우선, 네 명 모두 사망 또는 석화인지 검사, 이후 적 수 검사 |
| `34/811C..8184` | HP, 메시지 `1C`, 행동 스크립트 2, 종료 그래픽 `11`, 가방 정리 |
| `2F/B260..B283` | 레퀴엠 `13`, VBlank마다 A 입력/반복 검사, `0179` 대기 예외 |
| `31/BEBF..BF16` | 8비트 합산, 수량 99 제한, 아이템 ID 역순 정리 |
| `3F/FA5B..FA80` | 20회 VBlank와 4회 간격의 팔레트 감소, 패배 carry |
| `3E/C058..C0C6`, `3D/B9F6..BA54` | 필드 복귀 대신 소프트 재시작, 프렐류드와 불러오기 메뉴 |

메시지 창은 원작 스크립트가 닫는다. 별도 GAME OVER 문구나 부활 규칙을 넣지 않는다.
원작의 재시작 메뉴를 실제 실행하여 PPU, 다섯 창 호출, 문자열 ID `22/23`, 손 커서를
관찰한다. 처음부터/메시지 속도 및 세 저장칸의 구성을 160×144에 맞게 배치한다.
문자열은 비공개 번역 입력, 글자는 승인된 7×7 폰트, 창과 손은 원작 타일을 사용한다.

## 자원과 전송

아군 갱신은 기존 `Ff3EntryTail`과 상주 직업 그래픽을 쓴다. 사망 종류로 바뀔 때
원작의 여섯 타일만 교체하고 나머지 여덟 타일은 보존한다. B304의 선택 화면 준비나
적 재집계, 초기 등장, 음악 초기화를 반복하지 않는다. 액션 도중 상태 아이콘도
임의로 다시 켜지 않는다. 바뀐 객체와 공유된 동결 캐시는 무효화한다.

종료 소유자는 액션이 완전히 끝난 뒤에만 시작한다. `D800..D80A`의 종료 코어와
`D80C..D80E`의 페이드 시계, `D840..D8BF`의 원래 팔레트는 이 단계에서만 유효하다.
팔레트 준비 후 `D600..D7FF`를 네 단계 전송원으로 사용한다. 공용 전송 스테이징
`D950..DA4F`, OAM, 오디오 큐와 겹치지 않는다. 사망/마법의 이전 scratch는 이때 종료됐다.
타이밍 구간에는 색 계산을 넣지 않고 전송과 음악 처리를 수행한다.
초기 구현은 한 단계 팔레트 전송에 9프레임이 걸려 중간 단계를 건너뛰고 28프레임으로
늘어났다. 바이트 루프만 줄였을 때에도 23프레임이었으므로 공용 전송을 연속된 최대 8개
팔레트(64바이트) 묶음으로 바꾼다. 8바이트 본체를 펼친 SM83 루프로 CPU 비용과
인터럽트 마스킹 구간을 제한한다. 기존 VBlank 검사와 묶음 사이의 타이머 서비스,
모든 128바이트 색 데이터는 유지한다.
종료 소유자가 원작처럼 전체 대기 구간을 맡아 유휴 루프를 반복하지 않는다.

NES 색 번호의 명도 감소를 CGB RGB555의 네 단계 감소로 적응한다. 원작의 최종 검정과
대기/갱신 순서를 유지하지만 중간 팔레트의 아날로그 색 일치를 주장하지 않는다.
오디오 엔진과 타이머는 유지하며 음악 요청을 전환한다. GBC에서는 재시작을 위해
공유 IRQ/오디오 큐를 다시 초기화하지 않는다.

재시작 시 필드 보존 이미지의 유효성을 폐기한다. 같은 좌표의 필드로 돌아오거나
게임 상태에 임의 HP를 넣지 않는다. 배경 지도와 손 커서를 준비한 후 새 지도를 공개한다.
지도는 8행 단위로 묶어 16바이트 DMA 정렬을 유지한다. 기존 저장이 유효한 경우
빈 칸으로 잘못 표시하지 않도록 아직 미지원인 저장 미리보기 경계에서 오류 5로 멈춘다.

## 검증과 남은 경계

`tools/verify-party-defeat.mjs`는 한 번 부팅한 실제 던전 조우에서 네 차례 치명적 공격,
원작 계산·난수·숫자·메시지, 사망 OAM과 그래픽, 입력 대기와 재시작 화면을 검사한다.
모든 실제 APU 쓰기, 원작 오디오 누적 해시, 타이머, 전송 버스와 스택을 따로 대조한다.
원본 ROM·번역·폰트·추출 화면·생성 GBC 및 관찰 JSON은 모두 비공개다.

아래 경계는 이번 일반 물리 공격 경로와 구분한다.

- 석화/사망의 모든 조합에 대한 패배 **판정**과 원작 상태 코어는 대조되어 있지만,
  석화 BG 소유자는 통합 효과 표시기와 아직 공존하지 않는다. 해당 화면 경로는 실패를
  명시한다. 상태를 정상 자세로 바꾸거나 석화 캐릭터를 누락해 성공 처리하지 않는다.
- `0179`는 A 대기와 재시작을 건너뛰는 이벤트 복귀다. 종료 코어의 예외를 유지한다.
  현재 일반 조우 공급자는 이 이벤트의 9비트 전투 ID/이벤트 재개를 공급하지 않는다.
- 빈 저장 상태의 재시작 **화면 경계**까지이며 저장칸 선택, 저장 데이터의 초상/상태,
  새 게임과 저장 재개의 필드 시작 소비자는 다음 통합 항목이다. 고정 이름 정책은 유지한다.
- 승리 보상/파티 반영, 정상 행동 큐 및 전편 완성은 이 검증에 포함하지 않는다.

실측 결과는 비공개 `evidence/party-defeat/report.json`에 ROM 해시와 함께 기록한다.

## 검증 기록 (2026-11-28)

최종 통합 ROM SHA-256은
`19c686de1f5a0e98d45cb62ff3cdf1ee2bc37706ef5d5d465c4dcfbc2f8c6152`이다.
호스트 원작 비교 226건과 최종 소유권/배치/패배 계약 14건을 통과했다.
같은 ROM의 공유 메모리 검사 650건·64회 보존/복구·원작 오디오 7,200틱을 대조했다.
고정 전투 DATA는 1,393바이트, 잔여 15바이트이며 추가 종료 상태는 3바이트다.

기존 자동 적 사망 회귀는 37개 사망 그림, 이후 생존 적 공격과 54개 마법 그림,
세 번의 필드 복귀를 유지했다. 타이머 편차 범위는 272.751µs로 기존 500µs 기준을
통과했다. 음악·효과음의 실제 쓰기와 원작 누적 해시 대조는 음색 청취 승인과 구분한다.

아군 패배 경로는 실제 명령 4회, 전체 화면 8장, 20 VBlank와 네 팔레트 단계를
검증했다. 원작 오디오 3,407틱과 실제 APU 쓰기 20,872회가 일치했고 underrun 0,
타이머 편차 327.110µs, 메모리 전송 오류 0이었다. 스택 sentinel 133바이트와 guard를
보존했다. 완료 프레임을 기다린 뒤 메시지 창을 캡처하여 마지막 글리프 전송과 직전
프레임을 혼동하지 않도록 했다. 캡처를 확인한 결과 사망 자세·0 HP·패배 문구와
원작 구성의 빈 저장 메뉴가 표시된다.
