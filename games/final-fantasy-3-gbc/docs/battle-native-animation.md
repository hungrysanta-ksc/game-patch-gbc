# 공통 애니메이션 호출자와 숫자 생성기

기준은 PR 73 병합 `cce3464f086479a22aae21189ceede405962fc87`이다.
이번 변경은 원작 `34/8411` 호출자와 `33/AD2B` 숫자 본체의 네이티브 이식이다.
**요청한 무기·마법·숫자·사망의 실제 V6 화면 통합은 아직 완료되지 않았다.**
이 코드들은 현재 독립 GBC 함수 대조 ROM에만 연결된다. 기존 상주 화면의
`battle-script-video.c`는 그래픽 요청을 계속 보류한다. 이 보고서를 실제 전투,
새 화면의 픽셀 일치, 음악·효과음 동시 재생, 원작 속도 완료로 해석하지 않는다.

## 원작 구조와 유지한 부분

`34/83F8`의 25개 효과→17분기, `83A0`의 88개 소리 선택, `8739`의
10개 편성 행 표를 원본 ROM에서 읽는다. `34/8411..8738`의 아군/적 구분,
선행 점멸, 양손 명중 수 보존, 아군 간 공격, 마법 후속 변형, 소환,
대상/시전자 숫자 버퍼 순서, 사망/새 몬스터의 순서를 C 상태 머신으로 옮겼다.
`3F/FA0E`의 실제 묘화 호출은 완료 티켓을 가진 외부 요청으로 보존한다.
그림을 그리지 않고 티켓을 성공 처리하는 경로는 제공하지 않는다.

원작 `86AB`의 마스크 조회는 `3F/FD24`부터 8비트 Y로 탐색한다.
FF 전체 대상 마스크는 첫 번째 비트 선택으로 바꾸지 않는다. 전체 256바이트를
대조한 조회표를 만들며, 찾지 못하면 원작처럼 Y=0으로 돌아온다.
소환의 대상 집합과 마법의 hit/target mask는 이 조회 결과와 별도로 남긴다.

숫자는 원작의 16비트 표시값에서 14비트 값과 miss/recovery 비트를 분리한다.
3FFF는 다른 플래그보다 우선해 숨긴다. 0, 네 자리, 미스, 회복색과
원작이 받는 10000..16382의 몫도 임의로 잘라내지 않는다.
`10/9A80`의 사인 표, `33/AC43`의 적별 높이 차이, 정면/백어택 좌표,
앞 16프레임 진폭 64와 뒤 16프레임 진폭 16을 유지한다.
32개 대기는 중복 화면이어도 합치지 않으며 마지막 OAM은 호출자가 정리할 때까지 남는다.
AD2B가 첫 16바이트 전부 FF로 판단하면 OAM을 건드리지 않고 끝난다.

OAM 초기화의 실제 명령을 대조하면서 `A42B`가 Y만이 아니라 160바이트 전체를
F0으로 채운다는 차이를 발견해 수정했다. 아군의 `02A0..02FF`는 이 출력 범위 밖이다.
이 생성기는 원본 40개 임시 OAM 바이트를 산출한다. 그것을 GBC 40개 OAM에
아군·잔여 색상·효과와 함께 넣는 자원 배치 문제까지 해결한 것은 아니다.

## 자원 수명과 비용

공통 호출자는 109바이트, 숫자 상태는 96바이트다. 각각 bank 47/48에 둔다.
숫자 출력 160바이트는 호출자 소유이며 재진입하지 않는다. 새 숫자 세트의
십진수 변환은 시작할 때 한 번, 프레임마다 좌표/OAM만 갱신한다.
작은 반복 뺄셈으로 십진 몫을 구해 bank 0의 나눗셈 라이브러리 유입을 피했다.
원작 표는 불변 자산이고 실행 결과 OAM/프레임은 제품 ROM에 저장하지 않는다.

테스트 ROM에만 원작 함수 결과를 오라클로 넣는다. 실제 V6에 연결할 때는
고정 WRAM 여유, 기존 D200 작업 공간과 임시 OAM, bank 0 74바이트 여유를 다시
검사해야 한다. 별도 함수 ROM의 크기를 합산해 화면 ROM에 들어간다고 주장하지 않는다.
프레임 생성/전송/오디오 비용은 아직 측정하지 않아 성능 개선 수치도 제시하지 않는다.

## 검증 범위

- 원본 ROM SHA-256: `262a98737975df25fff80ad91090c3da039d2828035c6253140d2c5f3b176ea2`.
- 공통 호출자: 364입력, 876개 요청/종료 관측. 17개 분기, 네 가지 공격 측/대상 측,
  아군 간 양손 명중 보존, 전체 대상, 편성별 소환 행, 사망 순서와 두 숫자 버퍼.
- 숫자: 36입력, 932개 프레임/종료 관측. 정면/백어택, 아군/적,
  빈 슬롯, 0/9999/경계값, 미스/회복/숨김 우선순위와 좌표 래핑.
- 독립 원작 실행은 공통 호출자의 묘화 함수에서 멈춰 반환하며 숫자 본체는
  리소스 업로드/팔레트 전송/대기만 경계로 두고 실제 원작 연산을 실행한다.
  이 경계를 건너뛴 검사를 묘화나 사운드 검증으로 세지 않는다.
- GBC 실제 컴파일 결과의 상태/OAM 바이트를 전부 대조한다. 오래된/틀린 완료 티켓은
  상태와 출력 불변을 검사한다. 각 오류 주입 ROM은 첫 관측 바이트를 바꿔
  case 0/index 0에서 검증 실패를 확인한다.
- 호스트 회귀 169/169가 통과했다. 공개 허용 소스 554파일과 로컬 비공개 입력 설정을
  별도 디렉터리에 복사해 두 양성/오류 주입 ROM 및 보고서 6개를 바이트 단위로 재현했다.
  이번 코드에는 화면/오디오 연결이 없으므로 기존 음악 재생 결과를 새 검증 결과로 재사용하지 않는다.
