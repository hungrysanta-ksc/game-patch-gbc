# 원작 오디오 생산자 내부 비용

기준은 PR 51 병합 `8f0c5ce4695da443efdc378bb7e8e7a0884432f8`, 브랜치는
`ff3-audio-producer-costs`다. 이전 [화면 호출 비용](battle-opening-costs.md)을 다시
나누되, 원작 틱·출력 패킷·진단 바이트를 생략하지 않는다. 음색 조정은 포함하지 않는다.

## 원본 ROM을 바꾸지 않는 계측

고정 SDCC의 `audio-native` listing과 링크 심볼로 CALL 직전/복귀 주소를 찾고,
실제 ROM의 CALL opcode와 목적지를 대조한다. 롤링 해시의 직선 구간도 compiler
형태를 확인한다. 불명확한 형태는 실패한다. 관측기는 CPU 주소에 실행 콜백을 걸 뿐
ROM이나 게임 상태를 수정하지 않는다. 중첩 호출은 스택으로 짝지어 비용을 중복하지 않는다.

원작 명령·엔벌로프·NES 출력 생성, GBC 출력 변환/스윕, 패킷 카운터·해시 기록,
진단 스냅샷, 나머지 패킷 처리, 서비스 루프를 구분한다. IRQ가 끼어든 시간은 해당
호출 구간에 포함되므로 순수 CPU 명령 비용으로 해석하지 않는다.

초기 별도 시계는 요청 주입 뒤 더 이른 명령 콜백에서 시작해 첫 구간을 16.809ms
더 셌다. 게임 ROM이나 대기 판정을 바꾸지 않고 외부/내부 비용의 요청 경계와 시계를
공유하도록 수정했다. 내부 비용 합계는 외부 오디오 서비스와 0.001ms 이내로 같아야 한다.

기준 ROM의 첫 정면 생존 요청은 15.554초이며, 내부 오디오 합계는 10.344초였다.
기준 계측은 1,200프레임의 제한 실행으로 음악 전체 합격을 주장하지 않는다.
명령 처리 5.035초, 출력 변환 1.892초, 카운터·해시 기록 1.104초,
기타 패킷 처리 1.154초, 서비스 루프 1.158초였다. 진단 스냅샷은 0초였다.
스냅샷은 이미 `scene_request`가 끝날 때까지 미뤄지므로 그것을 줄이는 수정은 하지 않는다.

## 변경과 보존 조건

- 엔벌로프의 16비트 포인터가 NES `$8000..9FFE`에 있으면, 같은 GBC bank 8에
  검증된 bank 36 사본에서 두 바이트를 한 번에 읽는다. `$9FFF`의 은행 경계,
  `$BFFF`, `$FFFF`의 범위/주소 래핑은 기존의 두 순차 읽기로 처리한다.
- 이미 범위를 확인한 bank 36 단일 바이트 읽기도 중복 검사/호출을 피한다.
  곡 선택 은행, 반복 명령, 엔벌로프 계산·원작 오류 동작은 유지한다.
- 패킷의 틱/이벤트 카운터 8바이트와 두 해시 4바이트를 기존 위치에 직접 복사한다.
  비활성 큐 슬롯만 쓰고 완료 뒤 tail을 게시한다. 타이머 ISR은 이 원본 값들을 바꾸지
  않으며 레지스터를 보존한다. 12바이트, 해시 갱신, 소비 메타데이터 모두 유지한다.
- 변경은 현재 검증하는 `FF3_OPENING_VIDEO` 소비자에 한정한다. 출력 변환표와 음색,
  선행량·조기 복귀 조건, 숫자 전용 스케줄러, DMA/게시 규칙은 그대로다.

## 검증

`verify-audio-reads.mjs`는 통합 후보의 실제 control/channel/music/engine object를
별도 GBC ROM에 다시 링크한다. 다섯 곡 선택 구간에서 16비트 주소 전체를 비교해
327,680개 단어 값·오류 상태와 부수 상태 보존을 검사한다. 기준 읽기는 별도 은행에
복사한 원작 ROM 바이트를 직접 매핑한다. 사용하지 않는 출력 callback이 호출되면 실패한다.

```text
npm test
npm run build:battle-opening-video
node tools/verify-audio-reads.mjs
npm run verify:battle-opening-video
node tools/audio-producer-performance.mjs <PR51-baseline-folder>
```

최종 통합은 같은 8요청, 251개 그림, 32프레임 숫자, 원작 최소 대기와 21,600 오디오
틱으로 검사한다. 전체 원작 속도·일반 편성·정상 게임 진행·음색·실기 합격과 구분한다.
원본/생성 ROM·번역·추출 자산·raw 관측은 공개 소스 목록에 포함하지 않는다.

기록 구간의 호출 수 감소에는 패킷당 복사 함수 4회를 1회로 합친 효과가 포함된다.
해시 갱신이나 기록 바이트를 생략한 것이 아니다. 출력 변환의 호출당 비용은 이번에
개선하지 못했으며, 누적 시간 감소만으로 변환 코드가 빨라졌다고 해석하지 않는다.

전체 8경로는 2.30~5.13% 빨라졌지만, 선행 준비 마감 초과는
1158/1496 → 1162/1496, 최대 지연은
252.197 → 269.531ms로 증가했다.
오디오와 화면 준비의 실행 시점이 달라졌지만 최대 지연 증가의 세부 원인은 후속 계측 대상이며,
모든 개별 프레임의 개선을 주장하지 않는다. 원작 대기는 줄이지 않았고 늦은 그림도 버리지 않았다.
**전체 원작 속도 관문은 여전히 미통과**다. 평균 요청 시간 개선과 최악 지연을 별도로 추적한다.

- 호스트 테스트 128/128 통과. 실제 통합 object 4개를 재사용한 별도 GBC 검사 327,680건 통과.
- 표시 1784장, 41,103,360픽셀, 행동 단계 1520개, 원작 상태 경계 348개 일치.
- 숫자 원작 속도 관문 통과. 원작 최소 대기·전체 도트·OAM·창·선택 복귀 보존.
- 원작 오디오 21600틱, 동적 효과음 12회, 실제 APU 쓰기 144515회 대조.
  언더런/오디오 지각/잘못된 VRAM·DMA/활성 OAM 재작성/메모리 가드 오류 0.
- 429개 공개 허용 파일만 복사한 깨끗한 빌드가 같은 ROM과 report를 생성했고,
  그 복사본에서 최종 전체 검증을 실행했다. 계측 시계 수정 전후 요청 시간·표시·소비 상태도 일치했다.
  공용 `text_cells` 진단 뷰의 뒤 64바이트는 이 소비자에서 쓰지 않는 초기 RAM이므로
  이 추가 비교에서 제외했다. 실제 D800 캐시 256바이트와 모든 표시 픽셀 검사는 유지했다.

다음은 남은 원작 VM의 채널 상태 접근과 출력 변환의 호출당 비용을 나누고,
최악 준비 지연이 생기는 오디오 보충 구간을 줄이는 작업이다. 원작 틱/쓰기를
생략하거나 출력 패킷을 버리는 방식은 사용하지 않는다. 현재 제한된 등장·포격 4구성의
검증이며 일반 편성·정상 게임 진행·음색·독립 에뮬레이터/실기 완료는 아니다.
