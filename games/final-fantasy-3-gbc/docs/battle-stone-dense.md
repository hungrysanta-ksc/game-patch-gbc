# 혼란 석화와 밀집 숫자의 동시 표시

기준: PR 122, `70089e78f676e7edf1745d6ade614d1a92848189`.
작업 브랜치의 구현과 실제 에뮬레이터 검증 기록이다.

## 원작 구조

`2F/B5B8 → B5C3`의 네 명 갱신 순서를 유지한다. `B6AB`는 혼란 상태의
전진/복귀를 먼저 요청하고, `B72B`가 사망 우선순위·일반/개구리/소형 석화와
행 위치에 맞는 지도 요청을 만든다. `B6C8`은 그 지도를 BG에 쓴다.
혼란은 저장 캐릭터의 비트 하나를 임의로 바꾸어 만들지 않는다. 검증에서는
실제 공통 연출 22번에 정규화 상태 `0x48`을 명시적으로 입력하여 이 경로를 실행한다.

숫자는 `33/AD2B..ADA5`가 한 번 읽은 글리프를 유지하며 `AC4B..AD09`의 배치,
`10/9A80`의 사인 값과 `33/AC43`의 지연 표로 움직인다. `AD91/F8C5`에서
매 화면을 게시하고 총 32번 기다린다. 값, 자리 수, 글리프, 원작의 각 대기와
진행 순서는 그대로 둔다. 완성 프레임을 게임 ROM에 추가하지 않는다.

## GBC에서 달라져야 하는 부분

GBC는 총 40개, 한 주사선에서 10개의 OBJ를 표시한다. NES의 총 64개 OAM을
그대로 복제할 수 없다. [Pan Docs OAM](https://gbdev.io/pandocs/OAM.html).
등록된 편성의 혼란 석화를 RGB555로 조사하면 한 칸에서 최대 7색이 필요하다.
따라서 모든 것을 4색 BG로 합치거나 숫자 32개 뒤에 잔여 OBJ를 단순 추가하는
방법으로는 도트와 색을 보존할 수 없다.

석화와 적이 겹친 칸은 현재 사망/점멸 지도를 기준으로 합친다. 기존 BG 팔레트에
있는 석화 색은 BG에, 없는 색은 잔여 OBJ에 둔다. 적의 색 경계 OBJ에도 동일한
석화 마스크를 적용한다. 두 배우가 같은 칸을 쓰면 원작 배우 순서로 합친 뒤
기존 공통 셀 풀에서 정확히 같은 글리프만 공유한다. 아직 VRAM 전송을 기다리는
사망 타일도 WRAM의 현재 셀 사전에서 읽으므로 옛 원본 그림을 되살리지 않는다.
빈 화면 전체를 순회하지 않고 현재 석화가 소유한 열만 처리한다. 팔레트 검색과
합성 행 사이에서 오디오를 보충한다. 픽셀별 가변 시프트 대신 세 가지 원작 색상의
비트면 마스크로 한 행을 처리하여 두 비트면을 모두 보존한다.

숫자 32개는 고정 OAM 0..31에 둔다. 남은 논리 OBJ가 8개를 넘으면 OAM 32..39를
주사선 구간에 따라 재사용한다. 기존 그림의 8줄이 모두 끝난 뒤, 새 그림의 첫 줄보다
앞선 HBlank에 한 레코드 4바이트를 쓴다. 프레임 교대나 도트 생략은 없다.
겹치는 객체의 우선순위도 보존할 수 있는 슬롯만 고른다. 불가능한 일정과 늦은 IRQ는
명시적으로 실패하며, 이를 정상 표시로 인정하지 않는다.

일정은 숫자 시작 때 한 번 만든다. 갱신 사이에 최소 네 주사선을 확보하고,
다음 LYC를 먼저 예약한 뒤 새 HBlank 시작에서 4바이트를 쓴다. 레코드 선택과
다음 예약도 고정 명령어 경로로 실행하여 C 포인터 계산이 주사선 하나를 소비하지 않게 한다. 다음 VBlank에서는
예약한 갱신을 전부 실행했는지도 확인한다. 숫자 준비는 대상별로 오디오를 보충하여
여덟 대상을 모두 처리할 때까지 오디오 보충이 밀리지 않게 한다.
HBlank 대기 중에는 TIMA만 허용하고, 실제 4바이트 쓰기 직전에 다시 차단한다.
타이머 선점 후에도 새 그림의 첫 줄 이전인지 다시 검사한다. 첫 줄 바로 앞 HBlank는
안전한 교체 시점에 포함하며, 첫 줄의 OAM 검색이 시작된 뒤에는 실패한다. VBlank의 초기 32바이트
복구도 640 CPU 사이클의 고정 복사로 줄이며 오디오 소비를 허용한다.
유지되는 각 화면의 VBlank에서 첫 8개를 복구하고,
원래 지형 경계의 LYC 11 이후 필요한 갱신 시점만 예약한다. 연출 종료는 복구 OAM을
게시하는 VBlank에서 이 소유권을 반납한다. 필드에서는 이 LCD 콜백을 사용하지 않는다.

## 메모리 수명

| 자원 | 범위 | 소유 기간 |
|---|---|---|
| 사망·석화 가변 패턴 | 기존 두 페이지의 bank 1 셀 풀 | 해당 BG 페이지 |
| 현재 셀 사전 | WRAM 6 `[192,1056)` | 한 지도 구성 트랜잭션 |
| 석화 잔여 목록 두 개 | WRAM 6 `[1056,1312)` | 해당 BG 페이지 |
| 숫자 OAM 원형·그룹 배치 | WRAM 1 `D200..D2BF` | freeze 합성 종료부터 숫자 종료 |
| HBlank 일정·초기 8 OBJ | 기존 battle DATA overlay | 숫자 소유권 중 IRQ와 공유 |

숫자 원형을 합성이 끝난 작업 공간으로 옮겨 고정 RAM을 확보한다. 필드 정지 이미지,
음악 큐와 캐릭터 영구 데이터는 그대로 유지한다. CGB에서 사용하지 않는 OBJ 속성
비트 4를 석화 잔여의 내부 표식으로 써서 같은 팔레트/타일 범위의 적 점멸 조각과
구분한다. 하드웨어 색상·반전·우선순위 비트는 바꾸지 않는다.

## 검증

- `node tools/verify-stone-dense.mjs`: 같은 부팅에서 필드→밀집 전투→필드, 정면/백어택,
  원작 상태 갱신으로 혼란 석화, 적 8명의 `9999`, 32개 화면 각각의 전체 RGB 대조,
  화면 복구, 같은 상태의 자동 재생 각 32그림, 실제 OAM/VRAM/APU 쓰기,
  오디오 해시·타이머·WRAM/스택 검사. LCD가 켜진 실제 표시 구간에서 OAM 쓰기를
  판정하며, LCD를 끈 자원 적재는 주사선 위반으로 세지 않는다.
- 편성 3/난수 시작값 22, 두 번째 진입의 백어택 방향, 상태 및 숫자는 **명시적 진단 입력**이다.
  정상 턴 처리로 이 결과가 발생했다거나, 전원 석화 시 패배 판정을 우회하는 제품 동작이라고
  주장하지 않는다. 원작 계산·원래 조우의 회귀는 별도 `verify-dungeon --stone`으로 유지한다.
- `battle-dense-oam-audit.mjs`는 슬롯 선택 알고리즘과 별도로 모든 논리 그림의 8줄이
  실제 슬롯의 수명에 포함되는지 검사한다. 실제 출력 픽셀은 에뮬레이터 PNG와 비교한다.
- 혼란 석화 네 명과 모든 마법의 조합은 이번 숫자 소유자와 별개다. 마법의 기존
  잔여 OBJ 18개 제한을 임의로 풀지 않으며, 이 조합의 검증을 다음 단계로 남긴다.

2026-11-28 실제 실행:

| 항목 | 결과 |
|---|---|
| 같은 부팅 | 정면 밀집 전투 → 필드 → 백어택 밀집 전투 → 필드 → 원래 조우 → 필드/이동 |
| 숫자 | 각 방향의 32개 원작 화면 전체 RGB 일치, 별도 자동 재생도 각 32그림 완료 |
| 그림 생략 | 없음. 숫자 OBJ 32개 + 잔여 논리 OBJ 25개를 물리 슬롯 40개 안에서 표시 |
| 주사선 | 실제 조합 최대 8 OBJ, 잔여 슬롯 갱신 17회/화면, 프레임 교대 없음 |
| 공통 셀 풀 | 각 방향 최대 17패턴 |
| 화면 캡처 | 76장, 원작 석화 색 픽셀 1,624개와 모든 숫자·적 픽셀 대조 |
| OAM 쓰기 | 134,160회 중 금지 구간 0회, 표시 구간의 44,880회는 잔여 슬롯의 HBlank 쓰기 |
| VRAM/팔레트·DMA | 금지 구간 쓰기 0회 |
| 오디오 | 원작 진행 5,663틱, 실제 APU 쓰기 34,811회와 원작/변환 해시 일치, 효과음 요청 6회 |
| 연속성 | 큐 언더런·늦은 이벤트 0, 활성 타이머 드리프트 범위 308.037µs |
| WRAM·스택 | 매핑 10,858회 오류 0, 최장 매핑 79.632µs, 스택 가드 보존·미사용 129바이트 |

오디오 시간 검사는 기존 던전 검사처럼 첫 소비 패킷부터 계산한다. 타이머를 켜기 전의
초기 큐 준비 시간까지 재생 시간으로 잘못 더하지 않는다. 검증 ROM SHA-256은
`1dbd3103fc95abcdb860d768699d221fbc098f913d4b5a8c87a195a667a147e8`,
고정 MesenCore는 `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`이다.
ROM·캡처·원시 로그는 비공개 로컬 `evidence/stone-dense`에만 둔다.

자동 재생은 원작의 모든 그림을 순서대로 게시하지만 **원작 속도 달성은 아니다**.
첫 그림과 마지막 그림 사이 31개 간격은 정면 평균 58.972ms/최대 83.877ms,
백어택 평균 51.285ms/최대 70.557ms다. 각각 1.828초/1.590초이며 초기 준비와 복구 시간은
이 수치에 포함하지 않는다. 현재 화면의 자원·오디오 공존을 확보한 결과이고,
남은 숫자 준비·오디오 보충 비용과 혼란 석화+마법의 18 OBJ 제한은 후속 항목이다.

같은 최종 ROM으로 `verify-dungeon --stone`의 자연 조우 3회·사망 37그림·마법 54그림·
상태 해제/재석화/사망 우선순위·필드 복귀를 통과했다(타이머 범위 332.355µs).
`verify-party-defeat --mixed`의 사망/석화 복합 상태·실제 패배·빈 저장 슬롯 재시작도
통과했다(오디오 2,067틱, 언더런 0, 타이머 범위 314.236µs).
전체 호스트 검사 236개, 최종 관련 검사 20개와 자원 계약 재검사 11개가 통과했다.
공개 허용 목록 772개 파일의 해시와 `git diff --check`도 확인했다.
