# 정본 파티의 전투 진입

2026-11-27. PR 108의 조우 선택 다음 단계. `state_start=5` / `scene_mode=2`는
같은 부팅의 필드 상태에서 현재 파티를 읽어 전투 표시기에 공급한다. 적은 아직 기존
진단 편성이고, 호출은 명시적인 `scene_request=1`이다. 자연 조우를 이 편성으로
바꾸지 않는다. 기존 mode 4는 고정 입력의 마법/오디오 회귀 검사로 남는다.

## 원작 소비자와 순서

`34/9CE3`의 초기화에서 파티 측 경로를 연결한다.

1. `31/A400..A43F`, `A482..A4F5`: `$6100` 캐릭터에서 레벨, 지속 상태,
   현재/최대 HP, 직업 레벨, 현재 MP를 별도의 64바이트 전투 레코드에 옮긴다.
   `39/BB1A`의 직업별 치명타·도주·수면·숙련도 배율도 공급한다.
2. `34/9474..94D5`: 살아 있는 멤버의 HP가 `floor(maxHP/4)` 이하면 빈사 비트를
   설정한다. 저장된 지속 상태는 변경하지 않는다. 사망 시에는 원작처럼 이 계산을 건너뛴다.
3. `34/9D06..9D9D`: 표시용 두 상태 바이트와 우선순위가 가장 높은 상태 아이콘을 구한다.
   전투 중 일시 상태를 이전 전투에서 가져오지 않는다.
4. `31/AA16..AF76`: 기존 검증된 장비 능력치 소비자를 사용한다. 캐릭터 레벨과
   **직업 레벨**을 구분하고 원작의 바이트 덧셈·carry 동작을 유지한다. 정본 캐릭터/장비의
   파생 능력치와 별도 전투 레코드를 갱신한다.
5. `2E/9E64`, `9E01`: 전열, 직업, 상태와 직업별 팔레트 번호를 공급한다.
   양파검사는 슬롯별 팔레트를 사용한다.
6. `2F/AA00..AA67`: 현재 직업/상태의 14타일을 상주시킨다. 사망 시 정상 타일의
   앞 6타일을 사망 그림으로 바꾸는 원작 결과를 보존한다. 개구리/미니도 실제 로더를 실행해
   얻은 14타일이다. 뒤쪽 바이트를 임의로 0으로 채우거나 8타일로 생략하지 않는다.
7. 실제 파티 자원 준비 뒤 `2E/9D84`의 음악 요청, 기존 등장/전열 정착/상태 표시 흐름을
   실행한다. `2F/B304,B52A` 시점에 현재 아이콘을 로드하고 정착한 좌표를 상태 OAM에 넘긴다.
8. HP 창은 같은 정본 HP를 사용한다. `32/95E1`의 네 자리 표시와 앞쪽 공백 처리를
   원작 실행과 대조한다. 승인된 V6 숫자 글꼴·한글 이름·창 모양은 유지한다.

`34/87BE`의 조우 종류/선제·백어택 난수와 전열 반전은 아직 이 어댑터의 입력 경계 밖이다.
진단에서 공급한 전투 방향을 실제 난수 결과라고 주장하지 않는다. 향후 실제 조우 호출자와
연결할 때 행 반전을 이중 적용해서는 안 된다.

## 자원 수명과 GBC 변경 이유

- 정본 1,024바이트 상태는 공통 RAM, 전투 레코드 4개는 WRAM 5 `[0,256)`에 둔다.
  필드 보관 영역인 WRAM 7과 분리해, 복귀 사본이 새 파생 능력치를 되돌리지 못하게 한다.
- 합성 작업 영역의 64바이트를 초기화 중에만 빌린다. 장면 전체에 256바이트를 고정 RAM으로
  추가하는 방식은 현재 여유를 넘는다. 기존 은행 복사기는 16바이트마다 은행 1과 IRQ 상태를
  복원하며 오디오와 스택을 저장용 은행에 두지 않는다.
- 정상/사망 22직업과 작은 형태 2개의 재사용 자원 10,304바이트, 아이콘 512바이트,
  팔레트 ID 26바이트, 직업 배율 110바이트를 ROM 은행 78에 둔다. 장비 표 1,216바이트는
  그 표를 읽는 기존 코드와 같은 은행 15에 둔다. 프레임별 완성 화면은 ROM에 넣지 않는다.
- 사망형을 정상 14타일+사망 6타일의 별도 조각으로 보관하면 ROM 2,816바이트를 줄일 수 있다.
  현재는 초기 로더가 완성한 14타일 변형을 보관해 사망 멤버마다 입구에서 96바이트를
  다시 전송하는 비용을 없앴다. 원작과 같은 상주 패턴/캐시 종류를 사용하며 매 프레임 합성은
  없다. 현 은행 용량 안에서 선택한 ROM/전송 절충이며 전체 진입 시간 개선의 증거는 아니다.
- 고정 시안의 아군 그림을 먼저 전송했다가 다시 덮어쓰지 않는다. 공용 범위와 파티 범위를
  분리해 현재 파티 896바이트를 직접 전송한다. 명령 진입의 고정 상태 아이콘도 건너뛰고
  현재 상태의 아이콘만 공급한다. 다른 적/배경 자원은 이번에 임의 변경하지 않는다.
- 직업 그림은 원작 크기이며, 적 28×28/V6 배치와 피해 숫자의 자원에는 변경이 없다.

## 검증과 한계

실행 명령: `node tools/build-scene-layout.mjs`,
`node tools/verify-scene-roundtrip.mjs --live-party`, 기존
`node tools/verify-scene-roundtrip.mjs`, `node tools/verify-scene-layout.mjs`.
원작 실행 오라클은 `tools/live-party-source.mjs`이며 게임 규칙을 스텁으로 대체하지 않는다.
표시 오라클만 기존과 같이 NMI 대기·래스터 지연·음악 요청을 관찰 경계로 처리한다.
이는 NES 실시간 실행 속도 측정과 구별한다.

통합 ROM SHA-256:
`439d56934c50fa17e1b381d8e70d51dfb8a6c87e5666024b4ba588ad307026a5`.

- 단일 부팅에서 6회 진입/복귀, 총 24슬롯으로 22직업 모두 확인했다. 직업 레벨 1/99,
  두 전열과 양쪽 전투 방향, 정상·빈사·사망·암흑·침묵·개구리·미니를 포함한다.
- 실제 GBC의 전투 레코드 256바이트와 정본 파생 능력치가 원작 코드 실행과 일치한다.
  파티 좌표/자세/팔레트, 상주 타일, 상태 아이콘과 실제 OAM, HP 창도 대조했다.
  필드 25장과 전투 6장, 총 31장의 에뮬레이터 캡처를 픽셀 단위로 검사했다.
- 매번 복귀 후 컨트롤러 이동과 한글 NPC 대화를 통과했다. 마지막에는 미지원 실제
  편성 요청이 고정 시안으로 우회되지 않는 기존 경계도 확인했다.
- 범위 밖 직업, 석화, 범위 밖 무기를 마지막 슬롯에 각각 넣어 오류 81/82/83을 확인했다.
  앞 슬롯을 포함한 정본 상태/전투 레코드가 불변이며 오디오가 진행했다. 이후 정상 파티를
  다시 로드하고 필드로 복귀했다.
- 원작 음악/SFX 일정 7,200틱, 관찰 6,998회, 실제 APU 쓰기 30,065회의 내용/순서가
  오라클과 일치한다. underrun/late 0, 금지 구간 VRAM/DMA 쓰기 0,
  타이머 편차 범위 343.800µs이다. 음색 개선을 완료했다는 의미는 아니다.
- 은행 복사 13,122회, 위반 0, 저장 은행 매핑 최장 79.632µs. 이 진입 경로에서는
  마법의 resident DMA를 사용하지 않았다. 그 경로는 기존 mode 4 검사로 별도 확인한다.
- 스택 사용 217/512바이트, 잔여 295바이트와 가드 보존. 통합 고정 RAM 잔여 51바이트,
  고정 ROM 잔여 30바이트, 필드 보존 4,050/4,096바이트다.
- 진입 자원 준비 975.571–1,095.516ms. 0.5초 목표는 미달이다. 원작에 대응하는
  파티 로딩을 연결한 수치이며 준비 시간이 개선되었다고 주장하지 않는다. 마지막 왕복의
  10.750초는 의도적인 거부 3회와 정상 재적재를 포함하므로 전투 연출 시간으로 비교하지 않는다.
- 원시 기록: 비공개 `evidence/live-party-roundtrip/{config,result,report}.json`,
  실제 버스 관찰 `result.json.audit.log`, 빌드/실행 로그. 영상/ROM/번역은 게시하지 않는다.
- 동일 ROM의 mode 4 회귀: 2회 왕복, 79장, 원작 마법 54프레임과 전처리 플래시 16장,
  오디오 7,200틱/관찰 7,105회/실제 APU 쓰기 30,435회 통과. resident DMA 14회,
  최장 1,076클럭이며 타이머 편차 340.939µs, 스택 사용 223바이트다.
- 메모리 경계 64사이클/650검사와 오디오 7,200틱 통과. Node 회귀 194검사 및
  최종 소유권/링크 계약 11검사 통과. 원본에서 생성한 128개 전투/오디오 배열의 링크 바이트와
  227개 빌드 입력 해시도 확인했다. 소스 게시 목록은 686파일이며 생성 자산은 제외한다.

현재 제한:

- 석화 BG 소유자가 통합되지 않아 석화 입력은 오류 82, 직업 범위 밖은 81,
  장비 표 범위 밖은 83으로 거부한다. 네 명 모두 검사한 뒤에만 파생 능력치를 쓴다.
- 기존 행동 자원이 고정 파티 입력에 의존하므로 이 모드의 행동·메시지 요청은 오류 85다.
  mode 4 회귀의 무기/마법 실행을 현재 파티 전투의 완료라고 세지 않는다.
- 한국어 이름은 루네스·아르크·레피아·잉구스로 고정한다. 후속 사용자 결정과 제공된
  한글 NES판 새 게임 확인에 따라 이름 입력·일본어 이름 인코딩 연결은 구현 대상이 아니다.
- 필드의 독 피해 처리가 미지원이어서 독을 보존한 복귀 뒤 이동은 기존 오류 5에 멈춘다.
  이 경계는 첫 통합 검사에서 실제 확인했으며 성공한 이동으로 처리하지 않았다.
- 실제 편성 자원 조립, 전체 전투 계산·메뉴·승패/도주 결과, 필드 직업/상태 그림 갱신,
  자연 재조우와 특수 전투는 다음 통합 대상이다. 제품 진행 관문 수치를 올리지 않는다.
- 빈사 비트는 검증된 전투 레코드에 있다. 원작의 전체 전투 전역 상태(예: `$7CEC`의
  빈사 멤버 집계 마스크)까지 연결한 것은 아니며 행동/계산 호출자 통합에서 별도로 공급해야 한다.
