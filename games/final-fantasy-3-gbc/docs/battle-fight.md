# 대상 확정 후 물리 공격 호출자

현재 후속은 [전투 진입·주변 규칙](battle-entry-context.md)을 따른다. 도주 중 피격은 지원하며,
원작 대조 입력은 3,532건으로 확장했다. 대상 재지정·분열은 별도 준비 함수를 확보했지만
이 호출자와의 연결은 남아 있어 해당 입력 거부를 유지한다.

## PR 45 당시 검증 기록

아래 수치·해시·지원 범위는 PR 45 당시 기록이며 현재 후속 수치는 위 문서에 있다.

2026-11-25. PR 44 병합 `138b48e0e307c0d7fbc799470d6b768fa007ad69` 기준.
`ff3_fight_resolved`는 원작 `30/9E8A..31/A2B9` 중 **이미 살아 있는 대상으로 확정된 물리 공격**을
GBC C 코드로 옮긴다. 기존 bank 15의 명중/피해 산술과 bank 10의 전투 난수를 실제 호출한다.
원작 기계어 실행은 개발용 기대값 생성에만 사용한다.

## 이번에 연결한 것

- 원작 64바이트 공격자/대상 레코드와 장비 ID에서 손 수·처리 순서를 결정한다.
- 암흑·전후열·원거리 예외·대상 회피를 거쳐 손별 순 명중 수를 구한다. 앞 손의 진열 작업 값이
  뒤 손에 남는 동작도 원작대로 유지하며 임의의 “후열 피해 절반” 공식으로 바꾸지 않는다.
- 약점/흡수 속성 배수, 무기 추가 공격값, 방어 명령, 미니/개구리, 크리티컬, 점프/모으기를 처리한다.
- 각 손의 피해를 HP에 적용하고 흡혈·언데드 역흡혈, 사망 카운터, 상태 부여와 면역/우선순위를 반영한다.
- 결과를 원작 메시지 큐, 실패/회복 숫자 플래그, 공격자/대상 상태 버퍼, 실제 명중 수와 연출 인계 값으로 낸다.

**실제 명중 수에 검의 4회 연출 상한을 적용하지 않는다.** 이번 원본 속성 로더 입력의 양파검사는
캐릭터 레벨 33 고정에서 숙련도 1/99가 각각 2/3명중을 낸다. 고정 레벨 99·숙련도 99 입력은
7명중을 계산/연출 인계에 그대로 남긴다. 이것은 PR 44의 비공개 세이브/RNG 상태에서 얻은 6명중과
다른 실험이다. 연출 소비자가 별도 카운터에 검의 최대 4회 제한을 적용해야 한다.

`Ff3Fight`는 175바이트의 명시적 호출 계약이다. 모든 포인터는 현재 접근 가능한 WRAM이어야 하고
IRQ에서 호출하지 않는다. 같은 진영/슬롯이면 대상은 공격자와 같은 레코드로 취급한다.
공격자와 대상의 HP는 결과 레코드에 갱신되지만, 원작처럼 상태 변화는 별도 상태 버퍼에 남긴다.
이 버퍼를 다음 행동 시점에 확정하는 외부 스크립트까지 구현한 것으로 세지 않는다.

| 원작 경계 | C 코드에서 보존하는 내용 |
|---|---|
| `31/A2BA..A2E8`, `30/9ED5..9F68` | 슬롯·상태 버퍼 초기화, 이전 HP 저장, 양손 수 및 공격/방어/직업 보정 복사 |
| `30/9F6A..9FEE`, `31/A397..A3FF` | 손별 명중/회피, 암흑·진열·원거리 예외, 실패 시 모으기 제거 |
| `30/9FF1..31/A0C6` | 속성 배수, 추가 공격값, 방어·변신·크리티컬, 원작 정수 폭/곱셈 순서와 최소 1 피해 |
| `31/A0C8..A138`, `BCD2..BD02`, `BD24..BDBB` | 손별 HP 차감/회복·역흡혈·사망 및 상태 부여로의 분기 |
| `31/BE14..BE42`, `BBF3..BCD1` | 명중/면역 판정, 상태 우선순위·부분 석화·혼란의 명령 해제와 메시지 |
| `31/A139..A261`, `A290..A2B9` | 손별 실제 명중, 실패/회복 숫자와 공격자 HP 변화 메시지, 하프/활 등의 연출 인계 |

주석의 의도보다 실제 명령을 따른다. 예를 들어 언데드 역흡혈의 `BD72`는 공격자 포인터를 선택하고
`BD89`의 회복에서도 그 포인터가 남는다. 이를 임의로 대상으로 고치지 않았다. HP 회복의 16비트 합,
모으기 배수의 8비트 증가, 부분 석화 메시지의 큐 인덱스 증가 여부도 원작과 대조한다.

## 아직 연결하지 않은 경로

다음 입력은 **상태와 RNG를 바꾸기 전에 0을 반환**한다. 호출자는 성공한 공격으로 진행하면 안 된다.

- 사망·석화·점프/HP 0인 대상: 먼저 원작의 자동 대상 재지정이 필요하다.
- 도주 중 공격: `9F09..9F19`, `A264..A285`의 임시 페널티와 복원/메시지 소비가 필요하다.
- 분열 공격 ID `0x4F`를 가진 적: `BF53..BFF9`와 새 몬스터 슬롯/그림·행동 등록이 필요하다.
- 유효하지 않은 슬롯, 사망/석화/점프 표시 또는 HP 0이 남은 공격자, 메시지 큐 여유 부족.

입력 거부는 게임 규칙의 변경이 아니라 현재 이식 함수의 지원 범위다. 분열 가능 적은 조건부로
분열하지 않는 경우까지 보수적으로 거부한다. 이런 적을 완성 게임에서 공격할 수 없게 두지 않는다.
행동 정렬·예약 명령 디스패치·표시 스크립트·V6 공격/피격 프레임과 음악/효과음은 아직 이 함수와
연결 전이다. 기존 화면/오디오 실행 파일과 원본 아군 도트·숫자를 변경하지 않았다.

## 검증

```text
node --test tests/battle-fight.test.mjs
npm run build:battle-fight
npm run verify:battle-fight
npm run verify:battle-fight -- --negative
```

원본 참조는 지원 입력에 대해 `9E8A`부터 복귀까지 모든 계산·HP·상태 관련 원작 코드를 실행한다.
누락된 계산을 가로채거나 미지원 분기를 성공 no-op으로 만들지 않는다. 전투 RNG 표도 원작 초기화로
생성하고, 결과 175바이트 및 RNG 카운터 3개를 컴파일된 GBC 함수와 비교한다.

| 입력군 | 건수 |
|---|---:|
| 아군/적·자기 대상·진열·양손/무기 타입 | 448 |
| 공격자/대상 상태·속성·HP·흡혈/역흡혈 | 648 |
| 상태 부여·기존 상태·보스·면역 | 364 |
| 큐 사용량·추가 공격값·크리티컬·모으기·방어 | 256 |
| 정수 폭과 혼합 경계 | 512 |
| 미지원/무효 입력 무변경 거부 | 13 |
| 원본 속성 로더의 22직업×3레벨×2숙련도×양방향 | 264 |
| 합계 | 2,505 |

마지막 264건은 원본 초기 상태와 편성 3에서 `31/A400` 캐릭터/몬스터 로더와 `AA16` 장비 계산을
실행한 데이터다. 양파검사 오른손 검 `0x1E`, 다른 직업은 맨손 조건이다. 직업·레벨·숙련도는
검증을 위해 바꾼 상태이므로 자연 성장·장비 획득·정상 플레이를 증명하지 않는다. 다른 경계 입력은
계산을 엄격히 검사하기 위한 조합이며 실제 조우 장면으로 표시하지 않는다.

GBC **2,505/2,505**가 일치했다. 기대값을 한 바이트 바꾼 음성 ROM은 첫 입력의 첫 상태 바이트에서
실패했다. 정상 ROM의 데이터/링크/은행/WRAM 경계는 빌더가 검사한다.
bank 15는 산술을 포함해 5,109바이트, 진단의 정적 WRAM 끝은 `$C270`이다.
이는 전체 전투·음악·렌더러를 합친 상주 예산 승인 수치가 아니다.

- 정상 ROM SHA256: `cc88bc2e77c6f3ccef3d6a74b13b406f02814154a3dbf20b52f6d419aa26587a`
- 음성 ROM SHA256: `c5ef5d7e2d09dc1ac4170c3bc494b2a6ed75e0608237f7fc2716a3c29b19da19`
- 입력/기대값 SHA256: `8abda0c10edb009decee65741bcdc02b20ba3b7d95341b74aaa63029f4887c3d`

결과는 `build/battle-fight/report.json`, 실제 GBC 실행 기록은 `evidence/battle-fight/`에 보관한다.
전체 호스트 회귀 **113/113**을 통과했다. 공개 허용 소스 **395파일**만 새 디렉터리로 복사하고
비공개 원본/도구 경로 설정을 공급해 빌드·신규 4시험·매니페스트 검사를 다시 실행했다.
정상/음성 ROM과 입력/기대값 해시, 빌드 보고서가 모두 일치했다. 재현 이후 변경은 이 검증 기록뿐이다.
원본/생성 ROM, 추출 속성, 기대값, 분해 자료와 번역 입력은 공개하지 않는다.
R2 통합 0/8과 제품 관문 0/3은 유지한다. 다음은 대상 재지정·도주·분열을 같은 전투 상태에 연결한 뒤
원작 행동 실행기가 이 결과를 숫자·메시지·손별 무기/피격 연출로 소비하게 하는 작업이다.
