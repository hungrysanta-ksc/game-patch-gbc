# 일반 마법의 동결 합성과 배경 패턴 사본 재사용

## 원작의 수명과 GBC에서 추가된 비용

원작 `2F/B15E → AF14 → 33/B68D/B589`는 행동의 진입에서 그래픽 07/08을
적재한다. `B696` 이후 시퀀스를 고르고 `B6DD/B6F3`에서 대상별 커서를 시작한다.
`B765..B797`의 36셀과 `B7A9`의 대기를 반복하지만, 전투 배경과 아군 전체를
대상마다 다시 합성하는 구조는 아니다. 숫자는 `2F/B175`의 별도 그래픽 06 소유자다.

GBC에서는 40 OBJ·주사선 10개 한도 때문에 일부 정지 아군을 BG로 빌려 주는
기존 경로가 있다. 이는 NES의 상주 객체 구조와 다른 어댑터 비용이다. 일반
마법 타일 풀은 이미 상주하지만, 행동마다 동결 셀을 재합성하고 서명 있는 BG
주소에 필요한 동일한 패턴 사본을 재전송했다. 따라서 타일 로드만의 병목은 아니다.

이번 변경은 런타임의 실제 자원을 비교해 이전 합성을 재사용한다. 사전 합성한
검증 이미지를 런타임의 정답 데이터로 읽거나 같은 직업/마법 ID만으로 판단하지 않는다.
시퀀스·도트·숫자·소리 요청·대기와 오디오 큐 목표량은 바꾸지 않는다.

## 재사용·무효화·복구 계약

- 장면 안의 마지막 합성 한 개를 보관한다. 원래 OAM 160바이트, BG 0..3과
  OBJ 팔레트, 실제 참조 셀의 타일/속성, 실제 참조 패턴 16바이트가 모두 같아야 한다.
  해시 충돌이나 세대 번호 누락을 허용하지 않고 실제 바이트를 비교한다.
- 다른 자세·상태·팔레트·참조 타일·셀은 다시 합성한다. 장면 적재 시 캐시를 비운다.
  저장할 때 고유 패턴 기록은 네 개씩 묶고, 셀별 입력 기록은 사용이 끝난
  멤버십 공간에 압축한 뒤 한 번에 보낸다. 작은 기록마다 뱅크 전송하지 않는다.
- WRAM3의 합성 패턴 `[2816,4096)`을 유지한다. WRAM4에는 OAM `[0,160)`,
  입력 팔레트 `[160,256)`, 출력 셀 키 `[256,416)`, 출력 팔레트 `[416,448)`,
  입력 셀 `[448,608)`, 고유 패턴 기록 `[1408,3280)`을 둔다. 기존 마법 잔류
  패턴 백업 `[1152,1408)`과 겹치지 않는다. 새로운 WRAM 뱅크는 요구하지 않는다.
- VRAM1 `$9000..97FF`의 정본 사본은 장면 내에서 한 번 만들고 재사용한다.
  해당 영역을 덮는 공통 WRAM/ROM 전송은 유효 표시를 먼저 지운다. 장면 적재도
  무효화한다. 살아 있는 창 글꼴의 VRAM0 `$8700..87FF` 미러는 매번 갱신한다.
- 합성 결과와 복구 백업은 수명이 다르다. 현재 OAM·원래 BG 팔레트·비활성
  지도 차이 블록은 행동마다 새로 보존한다. HP/UI 변경이나 서로 다른 두 지도
  페이지를 이전 시점으로 되돌리지 않는다. 캐시가 맞아도 지도/패턴 게시와
  원래 지도 복구는 수행한다.

이 구조는 effects 장면의 독점 WRAM 소유를 전제로 한다. 다른 소유자가 해당
영역을 쓰는 새 경로를 연결할 때는 장면 전환 또는 명시적 무효화가 필요하다.
정지 아군 자세가 매번 바뀌면 합성 캐시의 이익도 줄어든다.

## 측정·검증

기준은 PR 96 병합 `d57cddde8c279ce281f12b0831be128943457c31`이다.
기존 ROM도 같은 장면에서 두 번 시전했다. 각 행동은 35게시이며 두 번째 행동
사이에 장면을 재적재하지 않는다. 다음 값은 GBC 에뮬레이터의 실제 DMA/행동 시간이다.

| 동일 장면 | PR 96 | 이번 변경 | 변화 |
|---|---:|---:|---:|
| 첫 시전 전체 | 2,026.470ms | 2,093.463ms | 66.993ms 증가 |
| 두 번째 시전 전체 | 1,859.316ms | 1,540.944ms | 17.1% 감소 |
| 첫 시전 최대 게시 간격 | 1,054.585ms | 1,104.780ms | 50.195ms 증가 |
| 두 번째 시전 최대 게시 간격 | 920.851ms | 585.978ms | 36.4% 감소 |

다른 첫 시전도 확인했다. 최대 30쌍 마법은 2,059.955→2,126.941ms,
아군 네 명 대상은 3,852.188→3,919.173ms다. 이들 역시 약 67ms 증가했다.

두 번 합친 시간은 3,885.787→3,634.408ms다. 원작 속도나 초기 0.5초 기준을
달성했다고 보지 않는다. 처음 만드는 비용은 여전히 늘며, 자세가 자주 바뀌면
이 이득이 보장되지 않는다. 같은 장면의 재시전을 기존 첫 시전 2.026초와만
비교해 개선율을 크게 표시하지 않는다.

새 ROM의 동결 구간은 첫 971.409ms, 재사용 452.194ms다. 첫 합성/기록은
419.405ms이고 재사용 때는 건너뛴다. 기록을 묶기 전 같은 구간은 448.492ms였지만,
묶은 뒤에도 전체 시전 시간은 VBlank·오디오 보충 배치 때문에 사실상 같다.
패턴 사본/미러 구간은 85.211→18.560ms다. 현재 지도 준비는 247.622/212.630ms,
출력 패턴·팔레트 게시도 약 100ms씩 남고 마지막 게시 이후 복구는 285.288ms다.
이 단계 시간은 내부 오디오 보충과 대기를 포함하며 순수 CPU 감소량이 아니다.
초기 이후 최대 게시 간격은 약 33.5~33.6ms로 유지됐다.

최종 ROM SHA-256은
`4950b9116478555a26cd89fe34d79c9891de7b3e33ae19c2a21fc863f37de023`다.
고정 RAM 끝은 `$CF96`으로 106바이트 여유다. 원작 ROM·추출 자원·번역·캡처는 공개하지 않는다.

`node tools/verify-battle-magic.mjs --repeat --skip-build`는 장면을 다시 적재하지
않고 두 번 시전해 원작 OAM·전체 화면·복구·7,200틱 오디오를 확인한다.
`--auto --repeat`는 실제 게시 간격과 행동별 시간을 측정한다. 여러 행동의 계측
로그는 각각 보존한다. 에뮬레이터의 제한된 로그 버퍼에서 첫 행동 기록이 밀려난
것을 비용이 없어진 것으로 처리하지 않는다.

`node tools/verify-battle-freeze-reuse.mjs KIND`는 `same`, `oam`, `palette`,
`map`, `glyph`, `inactive`를 각각 실행한다. 재사용 후보와 강제 재합성을 같은
입력 변경 아래 비교한다. 각 140개 하드웨어 캡처, 70개 대응 프레임, 각 시전의
지도 복구를 검사한다. 전투 시작의 비활성 지도는 재적재마다 다를 수 있으므로
다른 장면의 비활성 지도와 같다고 가정하지 않는다. 이 검사는 RAM 개입과 부분
오디오 일정이며 정상 플레이/완전한 오디오 검증에 합산하지 않는다.

자동 공격 회귀 중 검증기가 부팅 전 WRAM의 우연한 `$A5`를 준비 완료로 읽은
실패가 한 번 있었다. 오디오 틱 0·일반 속도에서 보호 영역이 아직 초기화되지
않은 네 관측값만 실패했고, 그 외 런타임 오류는 없었다. 검증기는 이제
`battle-party-video.c`가 준비 표식보다 먼저 쓰는 16바이트 보호 영역도 확인한다.
`node tools/verify-battle-freeze-reuse.mjs same --early-ready`는 부팅 전 표식을
의도적으로 위조하고 보호 영역을 지워, 실제 초기화까지 기다리는지 검사한다.
이 진단도 정상 플레이 수치와 분리한다. 실패 기록은 비공개 증거로 보존한다.

최종 검증은 기존 940캡처·11회 전체 오디오 일정에 정면/상태 백어택 반복 시전
140캡처와 자동 반복 시전을 더해 **1,080캡처·14회 × 7,200 = 100,800틱**이다.
원작 OAM·전체 픽셀·동적 소리 요청·NES/GBC 소비 해시가 일치하며 오디오 부족,
늦은 처리, 불법 VRAM/OAM 접근은 0이다. 별도 여섯 RAM 변경 검사는 840캡처·
420대응 프레임, 초기 표식 회귀 검사는 140캡처를 통과했다. 의도적으로 바꾼
주사선 점유 10은 허용, 11은 오류 7로 거부했다. 호스트 테스트 11개도 통과했다.
양손 지팡이는 83게시·2,110.162ms, 최대 실제 DMA 간격 83.956ms로 유지됐다.

635개 공개 소스만 별도 폴더에서 재빌드해 ROM 3개를 포함한 12산출물이
바이트 단위로 일치했다. 검증에 사용한 고정 MesenCore SHA-256은
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.
실기나 정상 전편 진행의 합격을 뜻하지 않는다.

## 남는 범위와 다음 순서

원작 소환은 `2F/AF18 → 32/8CEF`, 선행 연출은 `2F/AF20 → 33/AFB0`,
24개 디스패치는 `32/80DA`의 별도 경로다. 일반 마법의 측정으로 소환의 속도나
자원 공존을 보증하지 않는다. 소환 연결 전에 이 호출자의 로드/해제 경계를
등록하고 일반 마법 캐시를 빌릴 수 있는지 확인해야 한다.

다음은 첫 합성 비용과 현재 지도 비교/보존/복구의 잔여 비용이다. 원작처럼
변경 소유자가 갱신한 자원만 준비할 수 있는지 검토하되, 잘못된 무효화 때문에
이전 HP·상태·도트가 보이는 최적화는 허용하지 않는다. 아군 시전/발사·적 대상·
반사·특수/소환·정상 계산/메뉴 통합은 아직 별도다. R2 0/8·제품 0/3을 유지한다.
