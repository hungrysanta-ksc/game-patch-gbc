# 전투 진입 상태·인빈시블 포격·물리 공격 주변 규칙

2026-11-25. PR 45 병합 `0a345c1fd31b3a44d8477413c49c3ba875a5fc05` 기준 후속.
원본 ROM의 기계어로 기대값을 만들고 GBC C 함수의 전체 결과와 난수 소비를 대조한다.
현재 단계는 공통 전투 실행기에 연결할 규칙 이식이다. 정상 게임의 전투 진입이나 포격 화면을
완성한 것으로 세지 않는다. 원본 그래픽·번역·생성 ROM과 검증 자료는 비공개로 유지한다.

## 전투 시작에 이미 존재하는 상태

`31/A400,A482`는 파티의 영구 상태 `$6102`, HP, 직업 숙련도 등을 전투 레코드로 읽는다.
일시 상태 두 번째 바이트는 초기화되며 이전 전투의 수면·혼란 등을 임의로 이어받지 않는다.
`34/9CE3`의 초기화 이후 `9D06→9D1D`가 표시 상태와 아이콘을 정하고,
`2E/9D5F`의 그래픽 초기화 및 `2F/B469`의 등장 처리가 이를 소비한다.

`ff3_status_view`는 이 상태 변환, 아이콘 우선순위와 `B607/B5F2/B651`의 자세·그림 종류를 옮겼다.
사망, 석화, 개구리, 미니 및 중첩 상태에 같은 그림을 강제로 적용하지 않는다.
석화는 원작의 배경 표시 경로를 요청한다. 그림 종류 값은 원본 자산 공급 요청이며 대체 도트가 아니다.

호스트 시험은 상태를 **등장 전에** 원작 영구 상태에 넣고 `A400→9D06→9D5F→B469`를 실행한다.
정방향/백어택 각각 혼합 상태 3종과 전원 사망 상태, 총 8구성/32멤버의 자세·CHR 종류·OAM을 검사한다.
이는 강제 입력의 소비자 검사다. 전원 사망 상태의 정상 조우 가능성이나 실제 PPU 화면 검증은 아니다.
NMI/래스터 대기와 음악 요청은 호스트에서 가로채므로 실제 프레임·음질 증거로 사용하지 않는다.

## 인빈시블 포격의 순서

| 원작 경계 | 보존할 동작 |
|---|---|
| `34/87BE..8807` | 필드 탑승 ID `$74C6 == 7`일 때 포격 예약. 비트 회전 뒤 `$7ED8 & $20`. 보스/포격에서는 선제·기습 난수 판정 생략 |
| `34/8074..807E`, `35/A487` | 명령 수집 전 적 8슬롯의 포격 피해·숫자·상태 버퍼를 준비 |
| `34/990A..9934` | 첫 턴 등장 처리 후 포격 분기로 이동 |
| `35/A50B` | 그래픽 `$0F`, 원작 메시지 ID `$3D`, 포격 예약 비트 해제, 행동 스크립트 `$03` 실행 |
| `35/A528..A53E` | 전멸 검사. 승리면 `811C`로 나가고, 생존 적이 있으면 그래픽 `$0E` 후 명령 수집 복귀 |

`ff3_entry_rules`는 탑승·월드·보스 플래그와 원작 선제/기습/백어택 판정 및 진열 반전을 옮긴다.
파티 평균에서 사망 여부를 임의로 제외하지 않으며 원작처럼 레벨 0만 제외한다.
`ff3_cannon_prepare`는 이미 사망 표시된 적을 건너뛰고, 나머지 각각에 `250 + random(0..62)`를 계산한다.
이 경계에서는 HP 뺄셈의 언더플로를 그대로 남기고 사망 상태를 기록한다. 정확히 HP 0이 되는 경우는
이 루틴에서 사망 비트를 세우지 않는다. 이후 상태 확정/소멸 소비자가 필요하므로 여기서 임의로 보정하지 않는다.

원작 `A50B`의 호출 순서와 승리 분기도 별도 검사한다. 이 순서 시험은 그래픽/행동/승패 소비자를
가로채므로 **포격 애니메이션·효과음·실제 승패 계산의 통합 검증은 아니다**.
다음 연결에서는 단발 포격 예약이 명령 수집 재진입 때 반복되지 않는지도 검사해야 한다.

## 대상 재지정·분열·도주

- `ff3_retarget`: `31/A300`의 사망·석화·점프 대상 제외와 난수 재선택, 대상 마스크/이름 인계를 옮겼다.
  원작은 적 8슬롯일 때도 앞 4슬롯의 방문으로 실패를 판정한다. 슬롯 4의 방문 표시가 실패 바이트와
  겹치는 동작도 보존한다. 무효 limit는 거부하고, 난수의 한 주기 256회 안에 종료하지 않는 입력은
  상태와 난수 카운터를 복원하고 미지원으로 반환한다. 실패 마커와 함수의 입력 거부 반환값은 별개다.
- `ff3_split_prepare`: `31/BF53`의 분열 공격 ID, 상태·명중·무기 조건과 앞 6슬롯의 빈자리 탐색을 옮겼다.
  원본 64바이트 레코드 복사·사망/상태 예약·제거 마스크·분열 ID·메시지 `$6F`를 준비한다.
  원작처럼 여기서는 새 적 종류 등록과 메시지 인덱스 증가를 하지 않는다. 그래픽/종류 확정은 다음 소비자의 책임이다.
- 기존 `ff3_fight_resolved`에는 `30/9F07..9F19`, `31/A264..A285`의 도주 중 피격을 연결했다.
  임시 회피/방어 페널티, 해제와 메시지 `$55`, 8비트 래핑을 보존한다. `A275`의 `SBC #1` 앞에는
  `SEC`가 없으므로 명중 실패/흡혈 등의 경로에서 넘어온 캐리까지 보존한다. 큐 여유는 도주 시 한 칸 더 요구한다.

재지정·분열은 아직 물리 공격 외부 호출자에 연결하지 않았으므로 기존 함수의 해당 입력 거부를 유지한다.
준비 함수만 호출하고 새 적이나 상태 확정이 끝난 것처럼 진행하면 안 된다.

입력 거부 6건은 원작 게임 동작이 아닌 이식 API의 무변경 계약 검사다. 나머지는 원작 실행과 결과/RNG를 비교한다.
도주 확장은 256개 임시 보정 바이트 × 일반/실패/흡혈/언데드 역흡혈 4종과 진영 조합 4건이다.
진입/주변 함수 bank 16은 2,495바이트, 물리 호출자 포함 bank 15는 5,419바이트다.
진입 진단의 정적 WRAM 끝은 `$C43B`, 물리 진단은 `$C270`이며 전체 통합 상주 예산을 뜻하지 않는다.

## 다음 통합 경계

공통 파티/적 상태에서 진입·표시 초기화 → 포격 예약/피해 준비 → 등장 → 포격 스크립트와
상태 확정/소멸/승패 → 명령 수집의 한 수명을 연결한다. 이어 물리 대상 재지정·분열을 같은 상태에 연결하고
예약 명령/행동 정렬을 실행한다. V6 원본 크기 아군·적 축소안, 전체 숫자와 원작 창 구성을 유지한다.
직업 숙련도별 손 동작/효과음 반복과 긴 연출 중 음악·효과음·VBlank 연속성은 실제 화면 연결 시 다시 측정한다.
현재 진단은 음악이나 화면을 실행하지 않으므로 오디오 무중단이나 포격 프레임/OAM 한계 통과를 주장하지 않는다.
R2 통합 0/8, 제품 관문 0/3은 유지한다.
