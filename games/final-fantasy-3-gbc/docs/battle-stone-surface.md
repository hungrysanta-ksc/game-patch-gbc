# 석화·현재 창의 실제 팔레트와 셀 합성

2026-11-28. 순수 석화 통합의 자원 계약과 합성 커널 단계다. **통합 ROM의 순수 석화
지원 검사는 아직 해제하지 않았다.** 같은 부팅의 석화·사망·마법·필드 왕복 완료로 세지 않는다.

## 원작 소비자와 기존 판단 정정

`2F/B5B8`은 네 캐릭터에 `B5C3`을 호출한다. `B651`의 그래픽 캐시, `B6AB`의 혼란 위치,
`B607/B5F2`의 자세·방향, `B72B`의 석화 지도 선택 이후 OAM을 공개하고 `B6C8`이 지도에
쓴다. 프레임마다 별도 석화 그림을 만드는 구조가 아니다. `B72B`는 `(status & C0)==40`일 때만
석화 지도를 선택한다. 사망 동반 상태는 빈 지도로 정리한다. `B6C8`의 지도 쓰기는 검은
픽셀까지 포함한 교체이므로, 공통 커널을 단순 OR 또는 무조건 투명색 합성으로 만들면 안 된다.

이전 [소유권 감사](battle-stone-ownership.md)의 “회색 BG 팔레트 3과 UI가 충돌한다”는
판단은 잘못됐다. 팔레트 번호만 보고 내용 변경을 가정했다. 원작에서 읽은 석화 팔레트와
현재 생성한 메시지 창 팔레트의 **8바이트 전체가 같다.** 모든 현재 조우 배치에서도
생성된 팔레트 바이트를 대조하도록 통합 빌드에 검사를 추가했다. 추가 팔레트, 주사선별
팔레트 교환, 색 변경은 필요하지 않다. 이는 두 소비자에 한정한 결론이다.

UI 지도는 y=104부터지만 실제 프레임/문자는 y=106부터다. UI 참조기는 소유하지 않는
앞 두 줄을 FF로 표시하고 native render는 해당 타일을 0으로 초기화한다. 석화 발끝은
y=104..105에만 있으므로 같은 팔레트의 첫 행 타일에 합성할 수 있다. 정면/백어택 각각
일반 25픽셀, 개구리 9픽셀, 소인 10픽셀을 보존하며 창 도트와 충돌하지 않는다.
현재 생성하는 모든 창 상태와 원작의 세 가로 위치를 검사한다. 위쪽 머리는 y=14..15에
있어 y=10까지인 지형 도트와 직접 겹치지 않지만, 그 **셀의 서로 다른 팔레트**는 별도 문제다.

## 구현한 경계

- `ff3_cell_paint`는 같은 팔레트의 두 bitplane을 명시적인 행 마스크로 교체한다.
  지정한 0 픽셀은 지우고, 지정하지 않은 픽셀은 그대로 둔다. 기존 mask 커널과 같은
  unchanged/blank/changed 반환 규약을 사용한다. 고정 DATA, IRQ, 오디오 호출은 추가하지 않는다.
- 은행 124의 일반 호출과 외부 BANKED 진입점을 함께 제공한다. 현재 적 사망 경로는
  기존 mask를 유지한다. 새 paint 커널은 SM83 진단에서 실행하며 실제 석화 공개 경로는 미연결이다.
- 원본의 서로 다른 석화 글리프 80개 × 두 가지 소유 범위와 모든 픽셀 위치·색 조합을
  독립적인 픽셀 단위 oracle과 대조한다. 단순 합성 함수를 같은 식으로 다시 써서 기대값으로
  삼지 않고, 색 인덱스를 개별 픽셀로 읽고 쓴다.
- 통합 빌드는 실제 생성 UI의 팔레트·프레임·내용을 검사한다. 팔레트 변경, 첫 두 줄에
  내용 추가, 프레임을 위로 이동하는 변형은 명시적으로 실패한다.

## 남은 자원 결정과 다음 연결

한 방향의 정상/개구리/소인 석화 글리프는 중복 제거 후 40타일이다. bank 0의 현재 UI는
112..211, 피해 숫자는 223..255를 사용하므로 사이의 11타일에는 들어가지 않는다.
212부터 40타일을 예약하면 숫자를 덮는다. 이 검사 결과를 “예약 가능”으로 오해하지 않는다.
기존 bank 1의 페이지별 변경 풀도 사망/점멸과 공유하므로 각각의 최대치를 더해선 안 된다.

다음은 현재 제거 마스크와 석화를 **동일한 페이지 합성**에 공급하는 연결이다. 빈 셀은
완성 글리프를 재사용하고 혼합 셀만 교체한다. 각 상태에서 실제 중복 제거 후 타일 수와
잔여 OBJ/주사선 상한을 먼저 계산해야 한다. UI 첫 행은 별도 창 덮어쓰기로 지우지 않도록
창 갱신 소비자에도 연결하고, 머리의 지형 혼합 셀은 현재 잔여 OBJ와 함께 계산한다.
마법의 signed BG 전환에서 물리 주소가 바뀌는 타일과 복구 소유권도 함께 검증한다.

대안인 별도 상주 40타일은 숫자 재배치/복구 비용을 먼저 요구한다. 전부 OBJ로 옮기는
방법은 원작의 BG 석화 구조를 버리고 OAM을 늘린다. 아직 어느 대안도 전체 동시 상태에서
우월하다고 증명하지 않았다. 이번 결과는 불필요한 팔레트 교환과 발끝 삭제를 계획에서
제거하고 공통 합성에 필요한 정확한 연산을 검증한 것이다.

## 검증

통합 GBC SHA-256: `d3a7a51cec21a2d85ec488ad1cc3faae4087827d4ac65da2175efa133c65aeeb`.
고정 DATA 여유 8바이트, 고정 ROM 여유 894바이트로 기존 배치를 유지한다.

- 기존 호스트 전체 230건, 새 surface 검사 4건, 영향 계약 18건 통과.
- 원작 지도 소비자의 유색 셀 368개에서 실제 attribute 팔레트 3 확인. 원작 상태
  분기 4,096건도 다시 대조했다. UI 101상태 × 두 방향 × 세 형태 × 세 위치의
  경계 합성 1,818건에서 발끝 26,664픽셀과 나머지 창 내용을 보존했다.
- native SM83 13검사군 통과. 새 paint의 픽셀/색/소유 조합 2,048건과 원본 글리프
  160입력을 포함한다. 기대값을 틀리게 한 별도 ROM은 첫 검사에서 예상대로 실패했다.
  초기 probe 실패는 새 fixture 이후 이전 풀 검사의 임시 글리프 초기화를 빠뜨린
  진단 코드 문제였으며 초기화 후 전체를 재실행했다.
- 통합 ROM: 적 사망 37그림, 생존 적 점멸/공격, 마법 27그림과 정확한 복구,
  같은 부팅의 필드 진단 복귀 3회. 원작 오디오 4,032틱 / 실제 APU 쓰기 23,909회,
  타이머 편차 326.157µs, 메모리 복사 4,572회 / 오류 0, underrun 0.
- 복합 상태 사망/패배 회귀: 20 VBlank 페이드와 재시작 메뉴, 오디오 2,065틱 /
  APU 쓰기 12,024회, 편차 294.685µs, 메모리 오류/underrun 0.

뒤 두 경로는 **기존 표시 소비자의 회귀 검사**다. 새 paint를 실제 석화 상태에서 실행한
통합 검사가 아니다. 합성 커널 통과를 석화 전투 표시 완료나 음색 청취 승인으로 바꾸지 않는다.
원본·추출 글리프·참조 fixture·화면·관찰 JSON은 `build/`, `evidence/`에만 둔다.
