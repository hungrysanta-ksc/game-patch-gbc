# 마법 주사선 검사와 오디오 보충 분리

기준은 PR 95 병합 `4101dd24bdb59271866291e892401c3f470b145c`과
[대상 경계 비용](battle-magic-boundaries.md)이다. 기존 적→아군 보통 마법의
표시 경로만 최적화한다. 새 마법·정상 전투·음질 개선 완료로 세지 않는다.

## 원작과 GBC의 차이

원작 `2F/B15E → AF14 → 33/BAFD`의 보통 마법은 `B6DD`에서 대상을 순회하고
`B6F3`에서 대상 효과음을 요청한다. `B765..B797`은 6×6 고정 격자의 원작 OAM을
복사한다. `B7A9..B7B4`의 네 번 대기는 `3F/F8C5 → FB80/F8AA`의 VBlank/OAM
게시 경계를 유지한다. `3F/FB52 → FAF2`는 IRQ 경로에서 원작 소리 요청을 전달해
`36/8003`을 실행하고, `8011/8014`에서 효과음·음악, `801F/8022`에서 출력을 갱신한다.

GBC는 40 OBJ/한 주사선 10개 한도와 전역 OBJ 높이 때문에 원작 36개 8×8 셀을
그대로 동시에 유지할 수 없다. 기존 방식대로 모든 도트를 8×16 쌍으로 보존하면
효과는 서로 겹치지 않는 세 개의 16px 행이다. 움직이지 않는 잔류 OBJ 최대
8개는 행동 동안 동일하다. 원작에 없는 GBC 한도 검사는 이 고정 구조를 활용한다.
원작보다 적은 도트를 표시하거나 원작 대기를 줄이는 변경은 없다.

이전에는 그림마다 전체 주사선 표를 지우고 모든 효과/잔류 객체의 16행을
다시 세었다. 이제 잔류 객체의 실제 잘린 16px 범위를 `borrow()`에서 한 번
세고, 그림마다 효과 세 행의 객체 수를 더해 검사한다. 각 행의 모든 16줄을
확인하므로 비정렬 잔류 객체, 빈 효과 셀, 수평/수직 반전·백어택을 포함한다.
객체 수가 10을 넘으면 기존 오류로 중단한다. 빈 그림은 기존 최대 8개 보증을 유지한다.

점유표는 기존 scratch `[0..143]`, 다음 원작 OAM은 `[144..303]`, 세 행의
Y/개수는 비어 있던 `[304..309]`, 잔류 OAM은 `[576..607]`이다. 점유표는 동결
완료 뒤 만들고 `release()`까지 쓰며 다른 소유자가 scratch를 쓰기 전에 끝난다.
추가 RAM 은행이나 프레임 그림 자산은 없다. 고정 RAM 끝은 `$CF91`로 1바이트
줄었고 여유는 111바이트, 은행 65 코드는 `$0EEC`다.

## 비용 분리

읽기 전용 콜백으로 준비 단계 3→4 구간을 관찰한다. `native_irq_busy` 시간을
먼저 분리하고 나머지 `native_busy` 시간을 오디오, 나머지를 일반 CPU 처리로
분류한다. 합계가 구간 벽시계와 정확히 맞는지 검사한다. 같은 대상 첫 그림의
동기 호출에서는 이 구간이 검사와 그 호출 경계다. 선행 준비에서는 이전 그림의
대기/호출자 비용도 들어가므로 그 값을 순수 검사 함수 시간이라고 해석하지 않는다.
IRQ 항목은 계측 플래그 안의 타이머 처리다. 나머지 작은 VBlank 콜백·호출 경계는
일반 CPU 분류에 포함된다.

| 전체 대상의 첫 검사 | PR 95 | 이번 |
| --- | ---: | ---: |
| 일반 CPU | 13.959ms | 1.338ms |
| 오디오 서비스(IRQ 제외) | 27.339ms | 0.191ms |
| 계측된 타이머 IRQ | 4.311ms | 0.103ms |
| 합계 | 45.609ms | 1.632ms |
| 해당 구간의 서비스 호출 | 20회 | 3회 |

후속 세 대상의 검사도 40.918/28.759/28.343ms→1.632/2.244/1.632ms다.
효과 한 행마다 같은 오디오 서비스를 호출하며 타이머 소비·큐 목표량·음표/
반복/엔벌로프·요청 순서·출력 변환은 바꾸지 않았다. 서비스가 다시 필요할 만큼
검사 자체가 오래 걸리던 구조를 줄인다.

전체 행동의 오디오 전용 분류는 1,640.809→1,632.192ms로 거의 같다.
전체 서비스 호출 수는 오히려 4,875→5,574회다. 빠른 검사 이후의 대기/호출자에서
큐를 확인하는 호출도 포함되기 때문이다. 검사 안의 27ms가 사라진 것을 오디오
엔진 전체가 그만큼 빨라졌다고 주장하지 않는다. 실제 DMA 간격과 전체 시간을
함께 평가한다.

전체 대상의 실제 첫 그림 간격은 83.721→33.484ms, 세 대상 전환은
83.681/66.940/66.948→33.486/33.465/33.485ms다. 142게시 전체는
4,036.408→3,852.188ms(약 4.6% 감소)다. 초기 이후 최대 간격은 33.486ms다.
잔류 표를 한 번 만드는 비용으로 초기 포함 최대 간격은 1,037.834→1,054.585ms로
약 한 프레임 늘었다. 초기 0.5초/원작 전체 속도는 아직 달성하지 못했다.

| 자동 재생 | 게시 수 | PR 95 전체 | 이번 전체 | 이번 초기 이후 최대 DMA 간격 |
| --- | ---: | ---: | ---: | ---: |
| 대표 마법 29 | 35 | 2,093.459ms | 2,026.470ms | 33.484ms |
| 최대 30쌍 마법 36 | 35 | 2,126.942ms | 2,059.955ms | 33.484ms |
| 아군 4명 대상 마법 0 | 142 | 4,036.408ms | 3,852.188ms | 33.486ms |

최대 30쌍 사례의 초기 포함 최대 간격은 1,054.585→1,071.295ms다. 대표와 전체
대상의 초기 최대는 1,054.585ms다. 이 일회 준비 증가를 전체 개선 수치에 숨기지 않는다.

## 검증과 범위

`battle-magic-grid-audit.mjs`는 실제 비활성 OAM의 40개 객체를 144주사선마다
직접 세어 캐시/세 행 합계와 비교한다. 런타임의 단축 계산을 기준 답안으로
사용하지 않는다. 기존 원작 OAM/전체 픽셀/오디오/자원 복구 검사는 유지한다.

`verify-battle-magic-grid.mjs`는 별도 진단 실행에서 첫 그림의 점유표 한 줄을
의도적으로 바꿔 10개는 허용하고 11개는 오류 7로 거부하는지 검사한다. 허용
사례는 표를 즉시 복구하고 35게시를 끝낸다. 이 RAM 개입은 한도 분기 검증이며
정상 플레이나 완전한 오디오 일정의 증거로 합산하지 않는다.

최종 ROM `e95ee37c194e99989ed0224023bd868e5af05a4b4657a4032066540ad1518ec2`에서
940개 화면·11회 × 7,200 = 79,200오디오 틱을 통과했다. 원작 OAM·전체 픽셀·
동적 소리 요청과 소비 해시를 대조했으며 오디오 부족·늦은 처리·불법 VRAM/OAM
접근은 0이다. 171개 그림의 24,624주사선에서 새 점유표와 실제 OAM 집계가 일치했다.
상주 풀 593회, 지도/캐시/정본 복구 13회, 선행 준비 140회의 현재 그림/대기 경계
560회와 호스트 테스트 11개도 통과했다. 양손 지팡이는 83게시/2,110.162ms,
실제 DMA 최대 간격 83.956ms로 유지됐다.

공개 소스 632개를 별도 폴더에서 재빌드하여 ROM 3개를 포함한 12산출물이
바이트 단위로 일치했다. 고정 MesenCore SHA-256은
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.

재현은 [기존 전체 검증 명령](battle-magic-next-picture.md#검증-경계)에 이어
`node tools/verify-battle-magic-grid.mjs`를 실행한다. R2 0/8·제품 0/3,
아군 시전/발사·적 대상·반사·
특수/소환·정상 계산/메뉴 통합의 미완료 경계는 유지한다. 원본 ROM·번역·추출
자산·캡처는 공개하지 않는다.
