# 석화 BG의 부분 갱신·복원과 그래픽 캐시 교체

2026-11-25, PR 60의 상주 적 BG·아군 OBJ·상태 아이콘 후속.
32×32 적은 28×28로, 일반 아군은 무축소 OBJ로 유지한다. 석화는 원작부터 BG다.
정면/백어택의 정규 진열에서 원작 상태 소비자와 실제 GBC 표시·오디오를 연결한다.
보스, 혼란 이동, 창·포격·숫자의 같은 화면 통합은 이 진단의 완료 범위가 아니다.

## 원작 실행과 게시 경계

- `2F/B651`의 그래픽 캐시 ID가 다르면 `AB0D`가 해당 배우의 OAM 24바이트를
  `F0`로 지우고 `F8C5`에서 게시한다. `B489`가 앞서 준비한 정규 진열의 shadow OAM은
  `F8BC`에서 아직 게시되지 않았으므로, HIDE 때 다른 배우까지 이전 물리 OAM으로
  되돌리면 안 된다. 백어택 캡처로 이 차이를 대조한다.
- `F987/F9D3`의 64/32바이트 LOAD는 CHR만 교체하며 물리 OAM은 유지한다.
  STATUS의 `B5E3` 대기 뒤 `F8AA`가 OAM을 게시하고 `B6C8`이 석화 맵을 갱신한다.
  원작의 정상 직업/사망/개구리/소인 캐시 분기, 전송 순서와 작은 마지막 블록을 보존한다.
- 직업 그림은 `$28/8000`부터 22×672바이트, 개구리/소인은 `$29/BF80`, `$29/BF00`의
  각 128바이트다. 원본 블록을 고정 자원으로 링크하고 요청된 범위만 NES→GBC 2bpp로
  바꾸어 VRAM bank 0에 쓴다. 관측한 프레임의 완성 그림을 실행 ROM에 넣지 않는다.
- `B72B/B6C8`, `B7BB..B834`의 두 열 석화/지우기 맵을 소비한다. 배우별 원작 높이
  32/24/32/24픽셀과 일반·개구리·소인의 도트를 유지한다. V6 배우 좌표와 8픽셀 경계가
  어긋나므로 native에서는 배우마다 5/4/5/4개 타일 행에 걸친다.
- 상태 갱신 API는 `B5B8`을 따로 실행한다. 좌표·자원 캐시를 유지하며, 전체 진입
  `B479..B4A9`와 달리 `B909`의 적 수 재계산을 하지 않는다. 검증에서는 적 수를
  별도 값으로 설정해 이 함수가 바꾸지 않는지 대조한다. private chunk의 상위 비트로
  복귀 경로를 구분하며 75바이트 ABI와 원작 논리 상태는 유지한다.

석화 해제 검사는 입력 상태 비트를 0으로 바꾼 뒤 실제 원작 `B5B8`과 GBC 함수를
실행한다. 이는 상태 변경 이후 표시 검사다. 치료 아이템·부활 마법의 사용 조건이나
전투 효과 계산을 구현했다는 뜻이 아니다. 강제 캐시 불일치도 자원 교체 검사를 위한 입력이다.

## GBC 자원 수명과 변경 이유

초기 지형/적 자원에서 작은 셀만 읽어 석화가 차지하는 영역을 구성한다. 파티 원본 도트와
지형의 색이 한 8×8 타일에 섞이는 경우, 기존 팔레트로 표현 가능한 색은 BG에 남기고
나머지는 원작 색의 보조 OBJ로 표현한다. 이번 경로는 상단 지형 접점에서 2개가 필요했다.
일반 아군을 항상 BG에 합성하는 구조로 되돌리지 않는다.

정규 진열 이후에는 OAM 게시 페이지와 BG 맵 페이지를 맞춘다. 페이지별로 초기 맵을
한 번 적재하고, 변경된 석화 상태의 작은 패턴과 이전/새 영역을 포함하는 행만 비활성
페이지에 쓴다. 지울 때는 검은색으로 덮는 대신 원래 타일 ID와 팔레트 속성을 복원한다.
두 페이지의 descriptor 캐시가 같으면 합성·VRAM 쓰기 없이 기존 패턴/보조 OBJ를 재사용한다.
앞으로 지형·적 자체가 바뀔 때는 해당 기반 자원 세대도 무효화하는 계약이 필요하다.

현재는 상태 하나가 바뀌어도 **활성 석화 셀의 합집합**을 다시 구성한다. 이 방식은
버퍼별 할당과 복원을 단순하게 하지만 최종 최적화가 아니다. 검증에서 최대 BG 24셀과
보조 OBJ 2개, 한 페이지 416바이트를 사용했다. 40셀+8보조 패턴을 상한으로 검사한다.
변경 배우만 갱신하는 안정된 타일 할당과 좁은 열 전송을 후속 비용 후보로 남긴다.
동일한 동작/색/게시 순서로 CPU·전송·메모리를 비교하기 전에는 원작보다 효율적이라 하지 않는다.

- VRAM bank 1: 적 0..129, 두 지형 페이지 130..149, 두 석화 페이지 150..245.
  석화 페이지당 48패턴을 예약하고 초과는 실패시킨다.
- 석화 staging `D600..D8FF` 768바이트, `D900` 가드 16바이트.
  기존 맵/지형/전송/OAM/스택 영역과 분리한다.
- 원작 22직업과 작은 그림 고정 자원은 bank 29에 15,040바이트다.
  석화 glyph 1,920바이트와 팔레트 매핑 16바이트는 각 진단 프로필의 고정 자원이다.
- 실제 OAM 총수/한 줄 제한에 맞지 않으면 도트를 버리지 않고 실패시킨다.
  이번 결과를 최대 몬스터·마법·숫자·창 동시 한도로 확대하지 않는다.

화면 작업이 끝난 뒤에도 `party_work`가 켜져 있어 오디오 보충이 두 틱에서 계속
양보하는 문제가 드러났다. 이제 준비 중에만 두 틱 양보를 적용하고, 유휴/게시 대기에는
기존 세 틱 큐를 채운다. 원작 음표·반복·페이드·효과음 내용과 소비 마감은 바꾸지 않았다.
검사 중 발견한 부족은 숨기지 않고 실패시켰고 수정한 아티팩트 전체를 다시 검사했다.

## 검증 범위와 재현

정면/백어택 × 두 상태 구성으로 초기 등장부터 정규 진열, 캐시 교체, 석화/해제,
명령 아이콘까지 317화면을 비교한다. NES 실제 소비 코드의 상태·물리 OAM·PPU를
기준으로 하며 native OAM, bank 0 전체 4 KiB 그래픽, 석화 타일/맵, 팔레트 속성,
지형·적·가드와 실제 캡처 RGB를 검사한다. 원작 전송 28블록 중 6개는 32바이트다.
별도의 JS 픽셀 참조와 C 비트플레인 합성을 비교해 동일한 구현식의 재사용을 피한다.

최종 검증 결과:

- 호스트 148검사 통과. 후반부 C/SM83 180건, 15,258개 상태/대기,
  자원 출력 428,512바이트 일치. 기대 상태를 변조한 ROM은 첫 케이스 첫 바이트에서 실패한다.
  추가 네 상태 갱신 경로는 적 수를 별도 값으로 설정해 B5B8의 보존 동작도 검사한다.
- 최종 표시 ROM의 317화면 전부 일치. 일반/소형 석화·해제와 정면/백어택을
  실제 캡처로 확인했다. 관측 한 줄 최대 OBJ는 5개, 메모리/전송/표시 오류는 0이다.
- 같은 아티팩트에서 원작 음악·효과음·페이드 7,200틱 소비 해시 일치,
  지연/버퍼 부족 0, 타이머 오차 +0.072ms. 음색의 청취 합격을 뜻하지 않는다.
- 네 프로필의 석화 패턴 전송 합계 5,504바이트, 맵/속성 12,672바이트.
  뒤이은 자동 명령 대기에서는 패턴/맵을 포함한 VRAM 쓰기 0,
  OAM DMA 1,461회, 잘못된 DMA/래스터 변경 0, 최대 DMA 시작 LY=149.
  앞의 전송 합계와 뒤의 대기 구간 계측은 서로 다른 범위다.
- **전체 수동 진행 검증의 최대 준비 601.563ms**가 남았다. 자동 명령 대기의
  최대 게시 간격은 6프레임, 지연 게시 1,460회다. 상태 교체 구간의 최대 준비와
  자동 대기의 간격을 혼동하지 않는다. PR 60보다 많은 일을 수행하는 검사이며,
  이 결과를 속도 개선으로 표시하지 않는다. 변경 셀/전송 행/오디오 보충별 비용
  분리가 후속 과제다. 원작 속도 관문은 여전히 미통과다.
- 코드 bank 11은 2,145바이트, bank 12는 3,282바이트, bank 16은 6,817바이트,
  정적 WRAM 끝은 `CD80`이다. 고정 버퍼와 가드는 별도 주소로 검사했다.
- 기존 비석화 경로 회귀도 최종 소스로 다시 빌드해 268화면과 7,200오디오 틱이
  일치했다. 지연/버퍼 부족 0, 타이머 오차 +0.145ms, 자동 대기 VRAM 쓰기 0,
  최대 준비 126.465ms, 최대 게시 간격 6프레임이다.
- 공개 허용 소스 494개만 복사한 환경에서 표시/함수 검증/오차 주입 ROM 세 개와

혼란의 겹침/우선순위를 다음에 연결한 뒤 창·포격·피해/대상 숫자를 통합한다.
