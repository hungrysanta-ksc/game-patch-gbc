# 필드→전투→필드 자원 수명 재점검

2026-11-27. 기준: PR 102 병합 `489fe7cfda39a043cbe7ac0ed9fb4ea6fd7f4f3c`.
결론: 기존의 전투 내부 최적화는 유효하지만, 다음 우선순위는 같은 ROM에서의
장면 왕복이다. 독립 마법 진단의 시간을 더 줄이는 것을 통합의 선행 조건으로 삼지 않는다.
이번은 원작 명령/현행 소스의 정적 감사와 계획 수정이다. 실제 왕복을 구현하거나
NES/GBC 정상 플레이에서 새로 관측한 결과가 아니다.

## 최근 측정은 무엇을 뜻하는가

PR 102의 첫 시전 1.792초/재시전 1.357초는 **이미 전투가 올라온 상태**에서의
일반 마법 행동이다. 713ms도 그 마법의 정지 아군 합성·지도 준비 합계다.
필드에서 인카운터가 성립해 명령 입력이 가능해지는 시간으로 쓰면 안 된다.
별도 전투 로더 검증도 부팅 후 진단 요청으로 시작했으며 자연스러운 필드 진입이 아니다.
과거의 독립 화면/오디오 합격을 장면 왕복의 증거로 승격하지 않는다.

## 원작은 그래픽을 교체하면서 문맥을 보존한다

| 경계 | 확인한 원작 소비자 | 확인한 동작 |
| --- | --- | --- |
| 조우 | `3D/BC5B`, `BDB9`, `BD4D` | 월드/일반맵, 차량·지형·확률·편성 선택을 구분 |
| 진입 요청 | `3E/C19D..C1AB`, `3F/E26A..E280` | 필드 플래시→지형 결정→공통 전투 호출→각 필드 복귀 |
| 공통 연결 | `3E/C049..C060` | 가방 형식 변환→편성/배경/플래그 전달→패배 분기→가방 형식 복원 |
| 실행 문맥 | `3F/FA26..FA80`, `FB17`, `F83B`, `FAB5/FADD` | 일부 제로페이지와 인터럽트 진입 코드를 저장/교체/복원; 원작 20프레임 종료 페이드 |
| 초기 그래픽 | `2E/9D5F..9D87` | 현재 직업/상태→팔레트→아군/메뉴→적/배경→전투곡 요청 |
| 아군·메뉴 | `2F/A9ED..AA65`, `A9AC` | 직업·개구리/소인 상태별 그래픽과 메뉴 그래픽을 PPU에 공급 |
| 일반맵 복귀 | `3F/E7F8..E8FD` | 맵 데이터·그래픽·색·표시를 재구성하고 맵/조건부 음악을 요청 |
| 월드 복귀 | `3E/C8E6..C8F4` | 방향을 보존하고 월드 로드·표시·루프로 복귀 |

일반맵의 새 진입 `E7EC`은 NPC 로더 `E811`을 호출하지만, 전투 후 재로드 `E7F8`은
그 호출을 건너뛴다. 복귀 때 무조건 새 맵/새 NPC 초기화를 호출하면 안 된다.
다만 이 차이만으로 모든 NPC/맵 바이트의 보존을 증명한 것은 아니며, 동적 타일·
이벤트 PC·NPC 이동 잔여량의 정확한 유지/재초기화 범위는 실제 왕복 추적으로 확정한다.

따라서 원작도 필드 그래픽 전체를 그대로 보여 줄 수 있는 채로 전투를 진행하는
구조는 아니다. 그렇다고 게임 상태까지 처음부터 만드는 것도 아니다. ROM 자산,
지속 게임 상태, 화면의 임시 패턴/맵, 장면 문맥의 수명을 구분한다.
전투 중에는 메뉴/아군/적 자원을 상주시켜 쓰고, 마법 등은 필요한 자원만 빌려
게시·복원한다. 모든 마법/소환 그래픽을 조우 전에 미리 적재한다고 가정하지 않는다.

## 현재 GBC 구현: 재사용은 있지만 통합 계약은 없다

| 자원/경로 | 현재 구현 | 통합 전에 필요한 것 |
| --- | --- | --- |
| 원작 추출·28×28 변환·글꼴·음원 변환 | 빌드 도구가 GBC ROM 자산으로 만듦 | 전투마다 원본 NES ROM을 다시 분석/축소하는 비용은 없음 |
| 탐색 조우 | `exploration.c`에서 확률이 성립하면 `field.error=4` | 실제 편성/지형/호출 문맥 전달과 전환 |
| 화면 실행 | `exploration-viewer.c`, `battle-party-video.c`가 별도 `main()` | 한 부팅·한 스케줄러 아래 enter/update/leave 계약 |
| 전투 적·아군 패턴 | `load()`가 적/맵을 초기화하고 아군 4,096바이트를 다시 공급 | live 파티/편성 조회; 장면 간 상주 여부는 별도 검증 |
| 마법 합성·지도·패턴 캐시 | 같은 장면에서 정확한 의존성이 같을 때 재사용 | `ff3_resident_load()`에서 초기화됨; 장면을 넘는 캐시 아님 |
| 전투 HP/메시지 초기값 | `ff3_live_ui_reset()`이 `live_ui_seed`를 복사 | 실제 파티 HP/상태/이름으로 공급; 진단 seed를 게임 상태로 쓰지 않음 |
| 음악/효과음 엔진 | 두 진단 `main()` 모두 `ff3_native_begin()` 호출 | 엔진은 한 번 시작, 전환 때는 원작 음악/페이드/효과음 요청 전달 |
| 그래픽 게시 | 필드/전투에 각 VBlank 게시 함수 | 이전 요청 배출·소유자 교체·미완료 DMA/창/스크롤 처리 |
| 보스·석화·마법 | 현재 일부 동시 빌드는 명시적 오류로 차단 | 계약 미완성의 표시이며, 모든 전투 조합이 합쳐진 상태가 아님 |

전투 캐시 초기화는 현재의 안전한 동작이다. 단순히 그 초기화를 없애면 다른 맵,
파티 상태, 덮어쓴 VRAM을 이전 전투 자원으로 오인할 수 있다. 동일 자산의 장면 간
재사용은 소유 범위·버전·무효화 조건이 확보된 뒤에만 검토한다.

## 지금 합치면 문제가 될 구체적인 지점

1. **WRAM 1 겹침**: 탐색 맵 작업 공간은 `D000..D7EE`; 전투 합성/공유 작업
   공간 `D200..D4BF`, 애니메이션 원본 `D600`, 기준 OAM `D6A0` 등이 겹친다.
   이는 다른 시간에 쓰면 가능한 오버레이지만 현재 저장/재구성 인계가 없다.
   필드 `DC00` OAM과 전투 `DC00/DD00` 이중 OAM도 한 게시 소유자로 관리해야 한다.
2. **은행 예약 문서의 충돌**: `tools/memory-layout.mjs`의 탐색 검사는 WRAM 3을
   필드 중단용 예약, 4를 미할당으로 기록한다. 현재 마법은 3을 지도/합성/복구,
   4를 의존성 캐시와 임시 패턴 백업에 사용한다. 예전 예약대로 필드를 복사하면
   전투에서 덮일 수 있다. 탐색용 보고서를 전역 메모리 계획으로 사용하지 않는다.
3. **고정 RAM/스택 계약 차이**: 전투 진단의 고정 RAM 끝은 CFA0, 여유 96바이트다.
   탐색 메모리 검사는 256바이트 여유를 요구한다. 두 실행기의 스택/정적 배치는
   따로 링크됐으므로 그대로 합쳐 들어간다는 증거가 없다. 새 링크 맵과 실제 최저
   SP를 측정하고, 임시 데이터를 모드별로 공유해야 한다. 검사 한도만 낮추지 않는다.
4. **콜백과 큐**: 탐색의 `add_VBL(publish_irq)`와 전투의 `add_VBL(publish)`는
   현재 각각 부팅에서 등록된다. 둘을 그대로 호출하면 등록 중복과 이전 화면의
   요청/주소가 살아남을 위험이 있다. 공통 디스패치 또는 명시적 등록 해제가 필요하다.
5. **상태/자산 공급**: 진단 편성과 HP seed를 버리고 동일 GameState와 가방·장비·
   상태·편성 입력을 사용해야 한다. 필드 복원용 사본이 전투 후 HP/가방 결과를
   덮어쓰지 않도록 지속 상태와 장면 문맥을 분리한다.

지금 확인한 것은 **별도 진단 간 계약 불일치와 미구현 경계**다. 이미 통합한 제품에서
메모리 파손을 재현했다는 뜻은 아니다. 그러나 지금 통합 설계를 우선할 충분한 근거다.

## 수정한 실행 순서와 통과 조건

1. **원작 경계·메모리 수명 통합**: 원작 인카운터 전부터 진입/종료/복귀까지 추적하고
   지속 GameState·오디오, 보존 문맥, 재생성할 표시 자원, 임시 공간을 하나의 등록부로
   묶는다. WRAM 1..7/고정 RAM/스택/VRAM/OAM/전송 큐를 동시에 점검한다.
   필요량을 모른 채 6/7번 은행을 또 예약하거나 필드 전체를 무조건 복사하지 않는다.
2. **단일 ROM의 자원 왕복**: 독립 `main()`의 부팅 처리를 분리한다. 실제 탐색
   인카운터 입력으로 전투를 적재하고, 필드 표시와 상태를 되돌리는 경계를 먼저 검증한다.
   임시 진단 종료가 필요하면 테스트 전용 중단으로 명시하며 승리/보상 구현으로 세지 않는다.
   복귀 때 `ff3_state_init()`이나 오디오 엔진 재시작으로 결과를 지우지 않는다.
3. **원작 결과와 재진입 연결**: 이미 이식한 계산/선택/행동 소비자를 같은 상태에
   연결하고, 원작 도주/승리/패배/이벤트 복귀를 순서대로 확장한다. 가방 형식,
   지속/일시 상태, HP·장비·보상·이벤트 PC의 commit/cancel 규칙을 대조한다.
   자연스러운 왕복과 테스트 개입 왕복의 증거를 분리한다.
4. **전체 경로에서 성능 판단**: 조우→첫 전투 그림→명령 가능, 첫 행동/재행동,
   종료→첫 필드 그림→이동/대화 가능 시간을 따로 측정한다. 이때 실제 병목이
   확인된 로드/합성/전송만 최적화한다. 기존 전투 단독 회귀는 계속 유지한다.

공통 검증 시나리오는 같은 맵의 연속 조우, 다른 편성, 직업/장비/상태 변화,
전투 후 이동·NPC 대화, 이벤트 대화 직후 전투, 도가→우네 연속전의 호출 문맥,
인빈시블 차량 문맥, 도주·승리·패배·강제 결과의 구분이다. 첫 통합에서는 구현된
일반맵 경로를 기준으로 시작하되, 월드/차량/특수 이벤트를 통과한 것처럼 표시하지 않는다.
같은 부팅에서 두 번째 전투까지 실행해 초기화 누락과 낡은 캐시를 검사한다.
음악/효과음은 전환 구간을 포함해 검사하고, 원작의 곡 변경/재시작은 끊김 오류와 구분한다.

## 선행 로딩에 대한 결정

현재 재사용 중인 ROM 정본·변환 자산·전투 내부 상주는 유지한다. 다음 후보는 공통
프레임/폰트의 불변 부분, 현재 파티 직업에 필요한 자료, 현재 지역의 적 그룹처럼
식별 가능한 작은 자원이다. 이는 채택 완료가 아니라 인계 계약 확정 후 비교할 후보다.
ROM에 이미 있는 데이터를 RAM으로 옮기는 것 자체가 이득은 아니다. VRAM 공간,
오디오/이동 부하, 폐기율과 지역·직업·상태 변화의 무효화 비용까지 합쳐 비교한다.
전환 효과 동안 적재하는 경우도 필드/전투의 같은 타일 주소를 동시에 덮지 않도록
실제 표시 종료와 전송 완료 경계를 먼저 확보한다.
