# 원작 공통 마법 프레임과 진행 커서

2026-11-27, 기준 PR 88 병합 `28fc8963867a3d345d35b0c81b7c9304ca6cb0cc`.
이번 변경은 실제 마법 화면 연결에 앞서는 공통 소비자 경계다. 원작의 압축 그림을 읽는
C 코드와 진행 커서를 옮겼으며 **실제 V6 마법·소환 화면 및 오디오 연결은 아직 남았다.**
독립 함수 대조 ROM을 전투 화면 구현 완료로 세지 않는다.

## 원작 호출과 자원 수명

|---|---|---|
| `2F/B15E` | 아군 전진·직업 그림 → 마법 본체 → 복귀 → 숫자 그림 재적재. 적 시전은 별도 선행 점멸 | 호출·소유권 확인, 실제 실행기 연결은 후속 |
| `33/BAFD`, `BC2B` | 마법 종류별 19개 포인터 슬롯. 보통 마법은 `B937`에서 시전→발사→정리→명중 | 19슬롯 등록, 특수 본체 완료 아님 |
| `32/8115`, `80DA` | 소환 종류×변형의 24개 포인터 슬롯 | 등록만. 기존 대상 조건 대조와 그림 구현을 구분 |
| `33/AF6F`, `B589` | `2E/91D0` 속성 3바이트와 그래픽 요청 07/08. 속성 40비트가 그림 기준 주소 선택 | 88속성 추출, 그래픽 소유권 연결은 후속 |

| `33/B6F3` 종료 | 해당 대상 완료 후 앞 160바이트 전체 F0 정리와 1대기 | 원작 관측, 실제 게시/정리 호출은 후속 |

공통 명중 효과는 **대상마다 시퀀스를 끝까지 실행**한다. 전체 선택이라고 같은 효과를
8개 동시에 복제하지 않는다. 전체 화면 특수 효과와 소환은 별도 분기이므로 이 규칙을
일괄 적용하지 않는다. `B64F`는 반사 비트를 이동하고 대상 편·슬롯을 잠시 바꾼 뒤
복원한다. 이 경로를 일반 단일 대상 실행으로 대체하지 않는다.

적 대상은 원작 중심에서 X−24/Y−16, 아군 대상은 X−16/Y−12가 기준이다.
아군은 속성 20비트에 따라 Y−12가 추가되고, 마법 종류 5이면 X−8을 추가한다.
백어택은 최종 X를 `247−X`로 바꾸며 수평 반전을 뒤집는다. 모든 산술은 8비트 순환을
유지한다. 여기서 출력하는 좌표는 **NES 좌표**다. GBC 적 28×28의 중심으로 옮기는
작업과 화면 가장자리의 전체 그림 이동은 실제 어댑터의 책임이며 아직 적용하지 않았다.

적 대상에서는 첫 96바이트와 아군 OAM 96바이트를 교환한 상태로 4번 대기하고,
그 뒤 다시 교환해 복원한다. 원작 주석만으로 앞뒤 순서를 추정하지 않고 대기 시점의
256바이트 전체를 대조했다. 아군 대상에서는 교환하지 않는다.

## 구현과 비용

ROM의 `00/9708` 128포인터가 가리키는 **16KiB pair 00**의 압축 자료를 사용한다.
일부는 A000 이후이므로 물리 bank 00만의 8KiB 주소 마스크로 읽으면 잘못된 그림이 된다.
원작이 복사하는 36바이트씩 4,608바이트를 보존하고, 실제 압축 해제 결과가 정확히
36슬롯인지 빌드 때 검사한다. 원작 88시퀀스는 총 530바이트, 오프셋은 176바이트다.
이 범위는 현재 지원 호출자의 88 ID이며 물리 포인터 표의 나머지 슬롯 도달성을 뜻하지 않는다.

원작은 36바이트를 RAM에 복사하고 144바이트 템플릿을 채운 뒤 OAM으로 옮긴다.
GBC 코드는 불변 압축 자료를 bank에서 읽어 좌표·속성을 한 번에 호출자 소유 160바이트에
쓴다. 별도 압축 복사본/144바이트 템플릿을 런타임에 만들지 않는다. 빈 슬롯도 위치와
속성을 보존하며, 이어지는 아군 96바이트는 교환 함수 외에는 건드리지 않는다.
정적 결과 프레임이나 6502 실행기는 제품 자산에 넣지 않는다.

진행 커서는 3바이트다. FF는 다음 코드의 수직 반전 접두사이며 그 자체가 한 프레임은
아니다. 라이프 계열 호출자가 쓰는 길이 16 감소도 접두사를 절단하지 않는 범위만
허용한다. 이는 입력 경계 시험이며 모든 마법에서 길이 감소가 정상 도달한다는 뜻은 아니다.
잘못된 ID·길이·커서는 상태/출력을 바꾸지 않고 실패한다. 커서 반환값 1은 4대기짜리
그림, 0은 종료, 255는 잘못된 상태다. 효과음과 실제 대기는 외부 호출자 소유다.

별도 대조 ROM의 bank 8 코드·표는 6,612바이트다. 실제 전투 ROM에는 bank 8을
예약하지 않았으며 현재 고정 WRAM/ROM에 그대로 들어간다고 주장하지 않는다.
전송·오디오와 결합한 총 CPU 비용은 아직 측정하지 않아 속도 개선 수치도 제시하지 않는다.

## 표시 예산과 다음 연결

원작 공통 프레임 128개 중 비어 있지 않은 타일 슬롯이 16개를 넘는 것이 25개이고,
최대 36개, 한 타일 행 최대 6개다. **이는 타일 슬롯 수이지 실제 불투명 픽셀 점유가 아니다.**
아군 24 OBJ와 합치면 최대 60이라 모든 슬롯을 그대로 GBC OAM에 넣을 수 없다.
GBC 한도는 전체 40/줄당 10이며, 8×16은 두 타일의 속성을 공유한다.
[Pan Docs OAM](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md)

다음 실제 연결에서는 효과의 그래픽 07/08과 아군/잔여 색상/숫자/창의 수명을 같은
프레임에서 관측한다. 전체 화면 합성으로 돌아가거나 넘친 도트를 버리지 않는다.
상주 패턴과 OAM을 우선 사용하고, 부족한 효과 부분에 대한 국소 BG 합성과 8×16
타일쌍 재배치를 비교한다. 후자는 전역 OBJ 크기·공유 속성·줄당 한도·기존 무기/숫자
경로까지 영향을 주므로 단순히 개수가 줄어든다는 이유로 채택하지 않는다.
대상별 효과가 끝날 때 원래 타일/속성/팔레트가 복구되는지까지 비용과 함께 검사한다.

순서는 공통 보통 마법의 시전·발사·명중과 GBC 좌표/게시 → 전체 대상·반사 →
특수 19분기와 소환 24슬롯의 공유 기능군이다. 공통 프레임 커널로 소환 전체를 완료
처리하지 않는다. 상태 확정/사망, 정상 메뉴·계산·창 연결은 이후 통합 관문으로 유지한다.

## 검증

- 실제 원작 `B711`의 4대기 시점 OAM을 기대값으로 생성했다. 128그림×반전×
  아군/적×백어택×일반/0/255 좌표 등의 **6,132개** 배치를 GBC 코드와 대조했다.
  코드 FF는 스트림 접두사이므로 수직 반전 없는 독립 그림 코드 FF 입력은 제외했다.
- 실제 `B6F3`의 88시퀀스와 유효 길이 감소 경계에서 **544개** 진행/종료 입력을
  대조했다. 원작의 그림당 4대기·대상 종료 1대기와 소리 pending 1을 별도로 관측했다.
- 총 **6,676개**가 고정 MesenCore에서 통과했다. 잘못된 상태의 무변경 실패와 출력
  가드, 아군 OAM 복원을 검사했다. 기대값 1바이트를 바꾼 부정 ROM도 검출한다.
- 호스트 검사는 압축 자료의 두 물리 은행 범위, 실제 대기 시점 순서, 모든 시퀀스의
  접두사와 128프레임 참조를 확인한다. 이것을 모든 마법의 정상 플레이 도달성으로 세지 않는다.
- 새 호스트 4검사와 기존 공통 호출자/숫자 3검사, 총 7검사가 통과했다.
  공개 허용 소스 613개를 별도 폴더에 복사해 빌드한 ROM·부정 ROM·보고서·원작 관측·
  시험 기대값·생성 헤더 6개 산출물이 바이트 단위로 일치했다. 비공개 입력은 로컬 설정으로 참조한다.

실행: `node tools/build-battle-magic-frames.mjs`,
`node tools/verify-battle-select.mjs --magic-frames` 및 `--negative`,
`node --test tests/battle-magic-frames.test.mjs`.
원작 관측·생성 헤더·시험 기대값·ROM·증거는 모두 로컬에만 남긴다.

양성 ROM SHA-256: `003b4e843eaebeb9df25b4d73924d642bccad484c56d36b0a8a96b5a8029c84c`.
음악/효과음 코드와 실제 화면 ROM은 이번 변경 대상이 아니므로 PR 88의 오디오 결과를
이번 마법 검증 결과로 재사용하지 않는다. 실제 화면 연결 때 다시 공존 검증한다.
