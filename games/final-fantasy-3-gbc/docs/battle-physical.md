# 물리 공격 계산과 원작 연출 연결 계약

2026-11-25. 기준은 PR 42 병합 `647f513945a628ee38bfe588b73f426ff44d3479`.
원본 SHA-256 `262a98737975df25fff80ad91090c3da039d2828035c6253140d2c5f3b176ea2`.
설치된 NES 역분석·한글패치 스킬의 함수 경계 대조를 사용하며, GBC는 고정 GBDK/Mesen 경로로 검증한다.

## 이번에 구현한 범위

`src/battle-physical.c`는 원작 `31/BB28..BB43` 명중 횟수와 `31/BB44..BBE1`
피해량 산술을 bank 15의 재사용 함수로 옮긴다. 기존 `ff3_battle_random`을 bank 10에서 호출하며
RNG 1의 결과와 세 카운터를 원본 실행과 대조한다. 자체 난수나 단순 공격력−방어력 공식으로 대체하지 않는다.

- 시도 횟수마다 0..99 난수를 뽑고 `< 명중률`로 판정한다. 0회는 난수를 소비하지 않는다.
- 공격값의 절반을 상한으로 난수를 더하고, 원작 정수 폭/곱셈 하위 16비트/나눗셈 순서를 보존한다.
- 속성 배수, 치명타 보너스, 방어력, 순 명중 수와 대상 수를 입력받는다. 아군→아군은 이 함수에서
  방어력 차감을 건너뛰는 원작 분기도 유지한다. 결과 상한은 9,999다.
- 0 피해는 이 함수에서 정상 값이다. 물리 효과 호출자의 최소 1 보정은 `31/A0C0`에 따로 있다.
  대상 수 0은 지원하지 않는 호출로 명시적으로 실패하며 RNG와 출력값을 보존한다.
- 입력은 장비/상태 처리가 끝난 값이다. 진열·암흑·치명타 확률·양손·흡수·상태 부여·HP 반영을
  이 함수 하나가 처리했다고 세지 않는다. IRQ에서 호출하지 않으며 활성 WRAM 포인터만 받는다.

숙련도가 연출 순서를 직접 바꾼다고 가정하지 않는다. 현재 확인된 무기 제어 함수의 분기는
무기 종류/손/혼란/명중 카운터다. 직업 특수기·숙련도에 따른 간접 명중 변화와 전용 연출은
각 명령의 실제 소비자를 통해 추가 확인한다. 무기 종류만 보고 모든 직업을 같은 동작으로 처리하지 않는다.

## 다음 연결 및 누락 방지 조건

1. 실제 예약 명령과 행동 순서에서 물리 효과 호출자를 이식한다. 동일 초기 상태/RNG로 양손 결과,
   HP·상태·메시지 큐·숫자 플래그·난수 카운터 전체를 비교한다. 진열/백어택/감싸기 보정의 복원도 포함한다.
2. 그 결과를 원작 행동 스크립트와 V6 화면에 연결한다. 아군 전진→손별 무기→복귀,
   적 공격 점멸→아군 피격/감싸기→숫자→사망/대기 자세→창 복원→다음 선택을 연속 관측한다.
   기존 영상의 정상 경로와 원작 실행 화면을 함께 대조하고, 표시 함수 가로채기만으로 완료하지 않는다.
3. 기존 [전체 장면 계약](battle-scene-contract.md)의 22직업 커맨드·마법·소환·아이템을 같은
   결과 계약에 확장한다. 사용 조건·비용·단일/전체 선택·대상 위치·상태별 자세·전용 연출을 개별 등록한다.
   전체 선택을 임의 허용하거나 전용 효과를 성공 no-op으로 만들지 않는다.
4. 진입/선택/행동/숫자/소멸/승패/복귀의 전체 수명에 대해 스프라이트/VRAM/전송/은행/스택과
   음악·효과음을 동시에 검증한다. 숫자·원작 도트 생략 없이 R2의 8개 통합 시나리오를 닫는다.

신규 호스트 6시험: 능력치 528, 명중 1,536, 산술 4,096, 무기 제어 1,000, 점멸 1,024,
피격/감싸기 80입력. 산술 시험은 독립 정수식과 원본 실행을 비교한다. 표/분기 감사와 픽셀 검사는 구분한다.
GBC에서는 원본 코드가 생성한 **4,720건(명중 1,536 + 피해 3,184)**과 세 난수 카운터가 일치했다.
256바이트 난수 표는 원작 초기화로 생성하며 결과 기대값에 사용하는 RNG/곱셈/나눗셈은 가로채지 않는다.
기대값 첫 바이트를 변조한 음성 시험은 case 0/index 0에서 실패했다. 대상 수 0의 명시적 거부도 실행했다.

ROM SHA-256 `256e5a25e9bb04874a717b21e1502b95ff118c879e7f72bd5ffecd62caef288a`.
음성 ROM `1b5b0c6b99959c9464a1156a118ddbec60e17cad5566cf529743bd45b392d75c`.
fixture SHA-256 `3a4297b0f3b7d071f05709baa64936f15ab0ef65a05d73c2e5417425f021485d`.
계산 코드 bank 15는 564바이트이며 진단의 정적 WRAM 끝은 `$C1CB`다. 실제 전투 상주 배치의 승인 수치가 아니다.
보고서는 `build/battle-physical/report.json`, 실행 증거는 `evidence/battle-physical/`에 비공개로 보관한다.

전체 호스트 회귀 **107/107**을 통과했다. 공개 허용 소스 **380파일**을 새 폴더에 복사하고
비공개 원본 경로 설정만 공급해 재빌드했으며 정상/음성 ROM 두 해시가 일치했다.
그 복사본에서도 신규 6시험과 매니페스트 검사를 통과했다. ROM 재현 뒤에는 이 검증 기록만 추가했다.

이번 진단은 계산 전용이며 음악/화면 동시 실행을 주장하지 않는다. 기존 화면·오디오 실행 파일을 수정하지
않았고 PR 42의 1,110장/오디오 무결성 결과는 이전 기준선이다. 전체 전투 구현·통합 시나리오 0/8,
제품 관문 0/3은 유지한다. 원본/생성 ROM·추출 난수/기대값·분해 자료는 공개하지 않는다.
