# 네 명의 원작 명령 수집과 HP 행동명

PR 36 병합 `0c46f6973ad1230e4b896a103c217152fa85b779` 뒤의 후속 작업이다.
V6의 아군 원본 크기·배치와 원작 파란 창/프레임을 유지한다. 글꼴 선정과 음질 개선은 후순위다.

## 연결 범위

- A로 공격 대상을 확정하거나 막기/도주를 예약하면 다음 아군을 준비한다.
- 명령창에서 B는 원작 조건에 맞는 이전 아군으로 돌아가며 해당 명령을 다시 준비한다.
  첫 아군에서 B는 같은 아군을 다시 준비한다. 대상창의 B는 현재 아군 명령으로 돌아간다.
- 원작 HP 소비자처럼 예약한 행동명이 최대 HP 자리를 대신하고, 재선택 시 최대 HP가 복구된다.
  HP 숫자만 승인된 작은 글꼴이고 행동명은 기존 한글 7×7이다.
- 네 명의 예약 뒤에는 실행 준비 경계에서 멈춘다. 후속으로 아이템/장비 소비자와
  [진열 화살표·예약·취소](battle-row.md)를 연결했다. 실제 진열 이동은 행동 실행부의 후속 범위다.
  실제 피해·방어 상승·도주 난수·아이템 소비·마법 실행을 임의로 수행하지 않는다.

현재 화면 공급은 첫 편성/양파검사 4명, 이름 0~3과 HP 32/32의 진단 입력이다.
새 게임의 현재 파티에서 모든 상태를 읽는 정상 전투 통합은 아니다. 실제 원작에는 상태/점프/
자동 행동/소모 아이템 복구가 끼어들며 이들을 단순히 다음 캐릭터로 건너뛰지 않는다.

## ROM 근거와 검증 분리

| 원작 위치 | 소비 내용 |
|---|---|
| `34/986F..990A`, `35/A433` | 선택 초기화, 명령 대상 초기화, 조작 가능 아군 확인, 방어력 복구, 사망/석화/점프와 자동 행동 분기 |
| `34/9A42` | 이전 아군 탐색, 점프 및 표시 상태 제외, 되돌아갈 아군이 없을 때 원래 위치 유지 |
| `34/99D0..99E1` | 슬롯과 명령 ID 저장 |
| `35/A853..A86C`, `A877`, `A8AB`, `AA56` | 공격 대상 마스크/플래그와 막기/도주 예약, 다음 아군 인덱스 |
| `34/9BA2..9CE0`, 특히 `9C39..9C47` | HP 행 및 명령명 문자열 `$0620 + command` |
| `2F/B3CD` | 현재 아군의 원작 전진 위치를 읽어 진단 그림 공급 |

`Ff3Party` 55바이트는 위 함수가 읽고 쓰는 원작 상태의 압축 투영이다. 게임 상태의 별도 복제본을
제품에 추가하는 설계가 아니다. 자동 행동은 `AUTO`, 예약 아이템 복구는 `RETURN_ITEM`에서
소비자에게 반환하며 성공한 빈 동작으로 취급하지 않는다.

핵심 비교는 ROM의 6502 코드를 실제 실행한 결과와 GBC C 결과를 대조한다. 선택 진입 중
PPU 호출 두 개만 별도 소비자로 분리한다. 상태 입력에는 비정상 조합도 포함되므로 모든 상태가
정상 플레이에서 도달한다고 주장하지 않는다. 화면 근거는 별도의 정상 첫 전투 NES 조작 관찰이다.

실제 NES에서 공격 예약 뒤 아군 1→2, B로 2→1→0을 관찰했다. 고정된 RAM/PPU/OAM과
스크린샷 4개에서 하단 UI 76,800픽셀, HP 오른쪽 64타일 및 두 번의 이전 아군 상태 전이가
원작 소비자 실행과 일치한다. ROM·덤프·원문·번역·폰트·스크린샷은 비공개 로컬 자료다.

## GBC 표시와 메모리

기존 선택 진단은 보존하고 `--party-commands`를 별도로 빌드한다. 정면/백어택 각각
아군 0~3 전진 상태와 선택 완료의 원위치 상태를 공급한다. 이는 최종 전투 애니메이션 타이밍을
구현했다는 의미가 아니다. 활성 페이지를 수정하지 않고 준비된 BG/OAM을 함께 게시한다.

HP 오른쪽 40×40 영역의 25타일을 예약한다. 파란 창/경계 기본 타일에 네 행의 글자 마스크를
합성하고, 나머지 창과 전투 도트는 그대로 둔다. 타일은 UI 예약 80개 안에 들어가며
VRAM 뱅크 0/1의 `$9670..97FF`를 쓴다. 페이지별 상태가 같으면 글자 전송을 생략한다.
400바이트 글자 임시 버퍼는 맵 버퍼의 일부와 겹치므로 **전송 완료 후** 맵을 만든다.
합성 루프 중에도 오디오 생산자를 자주 호출해 음악/효과음 큐를 유지한다.

실제 버튼으로 공격→막기→B 복귀→도주 재예약→남은 두 공격→완료도 확인했다.
UI 합성 루프의 오디오 점유를 짧은 80바이트 마스크 합성으로 줄이고 아군 변경 뒤 두 페이지를
준비하여 다음 커서 입력에 업로드 비용이 붙지 않게 했다. 그러나 **아군 전환의 준비 시간은
아직 길며 원작 전진/후퇴 애니메이션의 속도 완료가 아니다.** 후속 통합에서 실제 원작의 대기
시간과 구간별 공급 비용을 측정하여 준비를 분산해야 한다. 이 비용을 커서 67ms로 표현하지 않는다.

GBC 표시 ROM SHA-256: `2800b410c6eacdeac8195114a5d8a939c9c17ba297cdbf7c709a8446a48aa075`.
커널 정상: `8d3d3d49c4318df34b7071d9820dc87898a2a2e5faa9d9625c8694858614ce97`.
커널 변조: `3ec42c5706fb6872114e05b121f67b3b4a952c24a1053f70a3ade021a68f9627`.

## 실행

```powershell
npm run build:battle-party
npm run verify:battle-party
node tools/verify-battle-select.mjs --party --negative
npm run build:battle-party-commands
npm run verify:battle-party-commands
node tools/audit-battle-party-observations.mjs --observations PRIVATE_DIRECTORY
npm test
node tools/export-source.mjs --check
```

조작 ROM은 `build/battle-party-commands/ff3-battle-party-commands.gbc`, 실제 GBC 캡처 갤러리는
같은 디렉터리의 `index.html`이다. 방향키/A/B를 사용한다. 실행 준비/미지원 호출자에서 멈춘
뒤 다른 경로를 확인하려면 ROM을 재시작한다. 커널의 실패 대조군은 기대값 하나를 변조하여
첫 사례에서 실패하는 것을 확인한다.

## 남은 연결

후속 [공통 가방·아이템 선택 경계](battle-items.md)에서 이전 아군 복귀의 예약 반환을 연결했다.
이 문서의 해시/측정은 PR 37 기준 기록이며 최신 빌드의 반환 시험/해시는 후속 문서를 따른다.
아이템 창의 실제 스크롤·취소 복원·예약 생산자·장비 교체는 다음 단계다.
이후 마법 목록/MP/시전 조건, 단일·집단·전체 대상 플래그, 공유 효과 계산을 같은 호출자에
연결한다. 전체 대상 소환과 적 개별 마법, 아군 물리/아이템 이펙트의 기준 위치도 기존
[전투 전체 계약](battle-scene-contract.md)에 따라 검사한다. 제품 관문과 R2 전체 8개 시나리오는
이번 함수/화면 검증만으로 통과 처리하지 않는다.
