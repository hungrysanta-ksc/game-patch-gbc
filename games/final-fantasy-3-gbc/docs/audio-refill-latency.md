# 오디오 계산과 보충 집중 구간 최적화

기준은 PR 52 병합 `b72057354e79b1f3faaa4695e7f74e89321f06a5`와 ROM
`8c34e84dfd538f351b704e5bbf9a420b055180ccbba77105d5ad0426bb39f130`다.
이전 작업은 8요청 총시간을 줄였지만 최대 준비 지연은 269.531ms로 증가했다.
사용자 요청의 필수 성능 목표는 최대 준비 지연 감소다. 총시간과 마감 초과 수도
함께 추적하며, 추가 탐색 목표로 마감 초과 수 감소를 시도했다.

## 변경

- `audio-channel.c`의 원작 bank 36 고정 표만 직접 읽는다. `8805/8815`는 4비트
  색인, `872D/872E/87BD/8825`는 8비트 색인이어서 모든 주소가 같은 검증된
  `8000..9FFF` 사본 안에 있다. 음표·반복·엔벌로프의 동적 포인터는 기존 검사와
  은행 매핑을 유지한다. RAM 상태·캐리·정수 폭·읽기 순서는 바꾸지 않는다.
- 제품의 단일 엔진을 직접 참조하는 정적 헬퍼에서는 사용하지 않는 상태/콜백 포인터
  인자를 제거한다. 공개 함수 ABI와 다중 인스턴스용 일반 경로는 그대로다. 고정 SDCC
  listing에서 `volume/pitch` 호출마다 사용하지 않는 두 포인터를 다시 읽고 전달하던
  비용을 확인했다. 명령·엔벌로프 계산이나 원작 데이터는 바꾸지 않는다.
- 출력 변환과 스윕의 pulse 0/1을 고정 채널로 컴파일해 배열 주소·레지스터·비트 마스크의
  반복 계산을 줄인다. 파형/주파수표·스윕·재트리거·쓰는 바이트와 순서는 유지한다.
  일반 채널 함수는 비대상 빌드와 대조 기준으로 보존한다.
- 오디오 보충 루프의 `full()`과 완료된 전송/게시 대기 판정을 하나의 원자적 시계
  표본으로 처리한다. 선행량을 먼저 검사해 불필요한 상태 읽기도 줄인다.
  기존 세 틱 기준과 **작업 완료 후에만** 두 틱에서 복귀하는 조건을 보존한다.
  패킷 중간 중단, 틱/출력 생략, 명령 대기·숫자 일정·IRQ 소비 규칙 변경은 없다.

이 변경들은 `FF3_OPENING_VIDEO`에 한정한다. 음악·효과음의 원작 처리 결과와 출력
변환의 음색은 그대로 유지하며 다른 소비자의 스케줄 기준을 바꾸지 않는다.

### 폐기한 접근

후보 `8d1e94f00eddb67db1d6e86d6536491a02bd10a043d6b526554dfa021ef567ef`는
아직 진행 중인 전송/게시 대기에서도 두 틱에서 복귀하도록 했다. 첫 요청의 서비스
루프 비용이 1346.585→2217.568ms로 늘었고 7362프레임에서 언더런 6건이 발생했다.
전송 뒤 다음 화면 계산까지 포함한 여유를 보장하지 못했으므로 폐기했다. 검사 기준을
완화하지 않았으며, 이 ROM은 검증 성공이나 배포 후보에 포함하지 않는다.
최종안은 보충량을 줄이는 대신 기존 안전 조건의 검사 비용을 줄인다.

안전 기준을 복원한 중간 후보
`469089973eea51dde6d2c11ccf52773890afbdb971b26e3642be5737474680e2`는
전체 화면/오디오 검사를 통과했고 최대 준비 지연 259.277ms, 최대 서비스 호출
55.740ms를 기록했다. 하지만 늦은 준비 횟수는 1162회로 같아 이번 추가 성능 기준을
충족하지 못했다. 이 계측에 근거해 스윕의 두 채널도 고정 색인으로 컴파일했다.
추가로 생성 기계어에서 확인한 정적 헬퍼의 불필요한 인자 전달을 제거했다.

## 비용 관측과 검증

기존 명령·출력·진단 비용 관측에 서비스 호출별 시간을 추가한다. 진입 시 화면 단계와
전송 대기 여부, 최대 호출의 profile/step, 큐 마지막 패킷의 잔여 시간을 기록한다.
IRQ가 포함된 경과 시간이며 순수 CPU 시간은 아니다. 외부 디버거 콜백은 ROM이나
게임 메모리를 수정하지 않는다. 요청별 호출 시간의 합은 기존 오디오 서비스 합계와
0.001ms 이내로 일치해야 한다. 타이머 값은 signed 16비트 차이고 빈 큐는 -32768로 구분한다.

기준 ROM은 10,000프레임 제한 계측으로 같은 8요청 시간을 재확인한다. 이 제한 실행은
음원 전체 검증으로 세지 않는다. 후보는 21,600 원작 틱을 끝까지 실행하고 전체
픽셀·도트·숫자·원작 대기·상태 경계·효과음 요청·실제 APU 쓰기를 대조한다.

출력 대조 ROM은 후보의 실제 `11.o`를 재사용하고 일반 채널 경로를 별도로 컴파일한다.
같은 실제 변환표와 8,192개 연속 입력에서 모든 register/value 쌍을 직접 비교한다.
리셋, 24개 입력 레지스터, 두 pulse 채널, 스윕, 캐시된 볼륨/주파수, 노이즈 복구와
pop 플래그를 포함한다. 이는 임의의 모든 내부 상태에 대한 전수 증명이 아니다.
일반 빌드와 `FF3_SINGLE_ENGINE + FF3_BANKED_RUNTIME` 빌드의 채널 코드는
고정 컴파일러의 전처리 결과를 PR 52와 비교했다. 줄 지시자/공백을 제외한 내용은
두 구성 모두 동일해서, 비대상 소비자의 상태·콜백 경로가 바뀌지 않았음을 확인했다.

```text
npm test
npm run build:battle-opening-video
node tools/verify-audio-output.mjs
npm run verify:battle-opening-video
node tools/audio-refill-performance.mjs <PR52-baseline-folder>
```

원본/생성 ROM·번역·추출 자산·raw 관측은 공개 소스 목록에서 제외한다. 일반 편성의
실시간 전투·정상 게임 진행·음색·실기는 별도 관문이다.

최대 준비 지연과 총시간 감소는 달성했지만, 추가 탐색 목표였던 늦은 준비 횟수
감소는 달성하지 못했다(1회 증가). 초기 분석 도구의 두 목표 동시 감소 판정도 실패했다.
최종 비교는 사용자 요청의 최대 지연 감소를 필수 검사하고, 횟수 감소는 별도 결과

프레임의 개선을 주장하지 않는다. 픽셀·숫자·원작 대기·오디오 부족/지각·출력 대조 검사는
기존 기준 그대로다. 원작의 전체 속도 관문 역시 통과로 바꾸지 않았다.

원작 명령 호출당 5270.715 → 4496.815μs,
출력 변환 호출당 409.516 → 267.322μs다. 서비스 루프 누적 비용은 증가했으므로
명령·변환 개선을 모든 비용 항목의 개선으로 일반화하지 않는다.

- 호스트 기존 128개 전체와 새 비용 집계 1개 통과(129개).
- 후보 출력 object를 재사용한 GBC 대조 8,192건 통과. 65,536회 입력 쓰기와 각 단계의 순서 있는 출력 바이트를 검사했다.
- 1784장 / 41,103,360픽셀, 1520행동 단계, 348원작 상태 경계 일치.
- 21600원작 오디오 틱, 12효과음 요청, 144362실제 APU 쓰기 대조.
- 언더런·오디오 지각·잘못된 VRAM/DMA·활성 OAM 재작성·가드 오류 0. 숫자 원작 속도와 최소 대기 보존.
- 436개 공개 허용 소스만 복사한 빌드가 최종 ROM/report와 일치했다.

8경로 전체 시간은 3.62~6.28% 줄었다. 준비 지연은 아직 남으므로
**전체 장면의 원작 속도 관문은 미통과**다. 같은 4개 등장·포격 구성의 두 반복에 대한
개선이며 일반 편성·정상 게임 진행·음색·독립 에뮬레이터/실기 완료가 아니다.
다음은 가장 긴 보충 호출의 원작 틱별 작업량과 화면 준비 단계별 비용을 함께 추적한다.
음원 선행량을 낮추는 대신 계산/중복 작업을 더 줄이고, 그림·출력·원작 대기는 계속 보존한다.
