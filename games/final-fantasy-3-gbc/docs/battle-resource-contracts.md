# 전투 창 수명과 이벤트 전투 등록

기준: PR 68 병합 `6dd6c54e506abebd8b74df1a984f7e8166c24875`, 2026-11-26.
사용자의 메시지/상태 창 및 특수 전투 요청에 따라 보스 상주 화면 연결의 선행 계약을 추가한다.
이번 변경은 원작 소비자를 실행하는 분석 도구·회귀 검사다. GBC 실행기나 새 화면을 완성한 변경이 아니다.

## 초기 로딩과 창 호출은 구분한다

원작 `2E/9D5F`는 팔레트 → 아군/메뉴 그래픽 → 적/지형 순서로 준비한다.
`2F/A9ED → A9AC → A1B3`는 메뉴 글꼴·테두리 2,304바이트를 NES PPU
`$1700..1FFF`에 올린다. 해당 내용은 사용자 ROM의 `$1B710..1C00F`와 직접 일치한다.
메뉴 팔레트는 `2E/9DCF..9DD6`, 손 커서 팔레트는 `9DF7..9DFE`에서 준비한다.
초기 준비 후 보스 시프트가 쓰는 `$0700..0FFF`와 별개이며, 창이 닫혀 있어도 글꼴을 버리지 않는다.

| 창/표시 | 원작 호출 시점과 소비자 | 상주 어댑터의 의무 |
|---|---|---|
| 적 이름·명령 선택 | `34/986C → 9D9E`, 직업 명령 `9B21` | 원작 선택/취소 상태에 따라 맵 갱신, 임의 메뉴 구성 금지 |
| 이름·HP·상태·예약 행동 | `34/989E`, 행동 루프 `80CC`, 종료 `811C`, `35/B9C9 → 9BA2` | 네 행과 갱신 플래그 `$7CE8`, 예약 행동 `$78CF..D2` 보존 |
| 행동자·행동명·대상·추가 메시지 | `34/8FF7` 스크립트, `909A/90CA/9171/91C8/91F8/925C/931C → 8D1B` | 원작 5개 창 레코드 `8E83`와 밑그림 저장/복원 `8E14` 유지 |
| 아이템·무기 교체·마법 목록 | `35/AE53/AE65/AE77/B2E7/B3A0/B7A2/B824/B85D → 34/8B38` | 두 열/가로 이동, 선택된 긴 이름만 스크롤, 대상 조건/취소 복원 |
| 선제·기습·백어택 | `34/82CE..8305` | 편성 메시지 큐를 원작 행동 스크립트 2로 표시 |
| 승패·보상·성장 | `34/811C..8184`, `35/BB49` 이후 | 특수 종료 분기 먼저 적용, 공통 승리창을 무조건 호출하지 않음 |
| 상태 아이콘·피해/대상 숫자 | `2F/B304` 선택 준비, `B2EB` 행동 준비 | 원작의 표시 게이트 및 그래픽 교체 순서와 창 수명 공존 |

도구는 직접 호출 지점 19곳의 실제 ROM 명령/목적지를 검사한다. 이는 모든 메뉴의 실행 커버리지가 아니다.
실행 대조는 기존 원작 행동 소비자의 정면/백어택 × 아군 아이템/적 메시지 4경로다.
총 766개의 원작 대기 관측에서 HP 행과 창 열기/닫기 순서를 기록하고, 다음 선택 전
열린 창이 0개임을 검사한다. 이 표본에서는 창 3을 열지 않으므로 5창 전체 조합 검증으로 세지 않는다.
화면 구성의 시각 기준은 기존 [실제 NES 화면 대조](battle-ui-observation.md)를 유지한다.

## 특수 전투는 ID·데이터·이벤트·계산을 연결한다

전체 편성 512개는 `2F/A02A..A0B7`, 몬스터 256개는 `31/A4F6..A65D`의
원작 로더로 읽는다. HP·속성·특수 행동 확률·8칸 AI 목록과 출처/해시를 로컬 등록부에 남긴다.
이름은 전투 소비자의 문자열 기준 `$0520 + 몬스터 ID`로 연결한다.
제공된 번역의 이름 번호를 NES 몬스터 ID로 직접 쓰지 않는다.

이벤트 포인터 254개를 명령 경계로 해독해 F7 호출 40곳과 복귀 주소를 등록한다.
`3B/B70F`는 편성 **하위 바이트**와 요청 상태만 설정한다. 상위 바이트는
`2E/9E8E`에서 호출 문맥에 따라 정한다. 등록부에는 두 후보와 미검증 문맥을 모두 남긴다.
같은 몬스터가 다른 편성에 존재한다고 정상 플레이에서 모두 등장하는 것으로 세지 않는다.

| 대상 | 확인한 원작 연결 | 다음 통합에서 확인할 것 |
|---|---|---|
| 가루다 | 몬스터 `$D5`, 이벤트 `$9E`의 `F7 $69`, 상위 후보 편성 `$169`; 약점 비트 `$20`, AI 목록 별도 로드 | 장비 속성→명중/방어→약점→점프, 공중 대상 제외, 적 마법 대상/효과·메시지까지 한 턴 검증 |
| 도가 → 우네 | 몬스터 `$D7/$D8`, 같은 이벤트 `$6A`의 `F7 $6B` 후 대사, 이어 `F7 $80`; 상위 후보 `$16B/$180` | 첫 전투 결과/지속 HP·상태와 이벤트 대사를 유지한 채 두 번째 전투 진입·복귀 |
| 도가/우네 공통·차이 | 저항 비트 `$FE`, 서로 다른 8칸 마법 목록; 보스 AI 성공 시 순차 포인터 1..8 순환 | 이름별 임의 피해 보정 대신 실제 속성/AI/마법 공식을 사용; 실패 대상에서의 포인터 처리 포함 |
| 하인·아몬 | 몬스터 `$D2/$B4`만 주기 값 2에서 배리어 체인지 `$4D`; 로더의 최초 약점 설정도 실행 | 약점 변경·메시지·색/효과와 다음 공격의 일관성 |
| 초반 바하무트·어둠의 구름 | 편성 `$055/$179/$190`만 적 행동 직전에 현재 HP 상위 바이트를 최대 HP 상위 바이트로 복원 | 하위 바이트까지 회복시키는 구현으로 바꾸지 않음 |
| 잔데·최종 구름 | 승리 경로의 `$173/$178`은 일반 메시지/종료 연출/보상 호출을 건너뜀 | 이벤트 복귀, 최종 구름 전용 소멸 `2F/BE97 → BF93` |
| 강제 패배 구름 | `$179`만 종료 시 패배 상태를 지움 | 일반 게임오버와 구분하여 원작 이벤트 재개 |

점프 시작 1,024입력과 착지 256입력을 원작으로 실행했다. 개구리/소인 거부와 메시지,
점프 상태, 다음 명령 9, 배율 필드 2(후속 물리 계산에서 3배)를 확인한다.
속성 약점의 내부 배율은 일반 2에서 4로 바뀐다. 이를 최종 피해에 다시 4배 하거나,
가루다 전용 고정 피해로 해석하면 안 된다. 이 검사는 전체 점프 피해/회피/연출 완료가 아니다.
도가/우네/가루다는 이번에 검사한 편성별 HP 복원·보상 생략·패배 해제 분기에 해당하지 않는다.
다른 전용 분기가 없다는 전수 증명으로 확대하지 않는다.

추가 필수 추적: 분열 `31/BF53`의 대상 상태/암흑 속성/빈 슬롯, 몬스터 소환 `B4F4`,
언데드 회복·흡수 `BBE2/BD6B`, 자폭 `B51F`, 전체/개별 대상 마법과 소환,
보스 상태 면역, 도주 금지, 특수 지형, 보물상자 전투 및 비 F7 호출.
원작 코드와 기존 물리/문맥 검사에 연결하되 아직 전체 전투로 통합됐다고 표시하지 않는다.

## 보스 화면 구현에 반영할 결정

실제 편성에 연결된 20종 보스 그래픽 × 정면/백어택 40프로필에서
4,720회의 64바이트 시프트 요청 동안 메뉴 글꼴/프레임이 유지되는지 실행 검사했다.
한 프로필 최대 288단계이므로 기존 8비트 화면 진단 번호를 그대로 쓰면 넘친다.
편성 연결이 없는 그래픽 4종은 기존 함수 검사만 있으며 이번 40프로필에 포함하지 않는다.

1. 한글 글리프·프레임·메뉴 팔레트의 예약 수명을 보스 부분 갱신/석화와 함께 설계한다.
   NES 주소를 GBC에 그대로 복사하지 않고 타일 은행·인덱스별 소유권과 최대 사용량을 측정한다.
2. 원작 64바이트 블록에 영향을 받는 GBC 셀만 재합성한다. 큰 보스 전체 프레임의
   사전 렌더링/상시 재전송이나 글꼴 영역 임시 차용으로 문제를 덮지 않는다.
3. 정규 진열 전 `$98` 반전 게이트와 BG/보조 OBJ 게시를 연결하고,
   원작 창을 실제로 열고 닫는 동안 숫자·아군 원본 도트·오디오를 함께 검증한다.
4. 선택→AI/계산→행동/숫자→결과→이벤트 복귀를 연결한다. 도가/우네 연속전과
   가루다 점프, 강제 패배/승리 생략을 별도 시나리오로 둔다.

V6 배치, 아군 원본 크기, 일반 적 28×28, 원작 창 구성은 유지한다.
500ms 초기 진입 목표, 전투 중 준비 지연, 채널 충돌/음질 개선은 미해결 상태 그대로다.
전체 제품 관문 0/3, R2 통합 0/8을 유지한다.

## 재현과 범위

`npm run audit:battle-resources`는 로컬 `evidence/battle-resource-contracts/report.json`을 만든다.
추출된 이름/AI/이벤트 및 관측 데이터는 배포 allowlist에 넣지 않는다.
새 회귀 검사 5개는 원작 주소 경계·ID 조합·메뉴 보존·AI 포인터와 부정 조건을 검사한다.
전체 호스트 160/160 검사가 통과했다. allowlist 517파일만 복사한 환경에서 분석 보고서를
재생성해 바이트 단위 일치를 확인했다. 보고서 SHA-256은
`99c3fd16b8c08b329bbe690a74b27459cf6c8489254143eb2c9bafb5b5d12bde`다.
원작 NMI/렌더 대기는 호스트 관측으로 치환한다. 이번에는 GBC 코드/ROM을 변경하지 않았으며
새 실기 속도·오디오 연속성·정상 진행 통과를 주장하지 않는다.

원작 참조는 [고정된 역분석 소스](https://github.com/everything8215/ff3/tree/1acef8117120ff891003de249b1a74bc8d94d674),
최종 판정은 지원되는 사용자 원본 ROM의 실제 명령 실행이다.
