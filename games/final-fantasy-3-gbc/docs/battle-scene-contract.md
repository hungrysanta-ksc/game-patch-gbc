# 전투 전체 표시 계약: 영상·원작 소비자·동시 자산

2026-11-24. 기준은 PR 27 병합 `86400869078b92294ae66c10411fda582b0df70a`와
사용자가 제공한 `battle.avi`다. [현재 순서](implementation-roadmap.md)의 R2를 보완한다.
**개별 편성의 OBJ 실패를 먼저 고치는 순서에서, 전투 전체의 표시 수명과 통합 부하를 먼저 정하는 순서로 변경했다.**
기존 [배치 검사](battle-placement.md)의 실패 60상태와 공급 문제를 없어진 것으로 처리하지 않는다.

이번 결과는 원작 표시 호출의 등록·실행 검사와 다음 통합 검사의 계약이다. 새 GBC 전투 화면이나
전체 전투 프레임 예산을 완성한 결과가 아니다. GBC 런타임은 변경하지 않았다.

후속 [적 등장·상태·아이템 표시 수명](battle-transitions.md)에서 등장/상태/아이템의 원작 본문 실행과
복원 검사를 추가했다. 아래 PR 28의 수치·해시는 당시 기록이며, 후속 계약의 검사 해시는 해당 문서에 기록한다.

## 영상에서 확인한 범위

입력은 99,967,488바이트, 256×240, MS Video 1, 영상 스트림 60fps·5,382프레임(89.7초)이다.
SHA-256: `c1a1d955655aa6b5dfeb84a72c2e13453a5084d10fc2f0eb5a8464be8c486d8a`.
Windows AVI 디코더로 1초 간격 90장과 진입/공격/회복/종료 부근의 추가 63장을 로컬에서 추출·확인했다.
아래 시간은 파일의 시간축이며 원작 PPU의 정확한 틱이나 입력 로그가 아니다.
한국어판 영상과 지원 일본판 ROM은 서로 다른 입력이다. 영상은 관찰/누락 탐지에 사용하고,
일본판 ROM의 수치·조건·순서는 해시가 고정된 기계어로 검사한다. 영상의 번역/배치를 그대로 추출하지 않는다.

## 원작 호출과 수명 검사

`tools/battle-scene-source.mjs`는 기존 제한형 6502 분석기를 사용한다. ROM 테이블의 주소를 읽고
원작 선택 명령을 실행하여 목적지와 비교했다. 표 개수는 함수/동작의 중복을 포함한다.

| 분기 표 | 원작 표 주소 | 슬롯 수 | 이번 실행 범위 |
|---|---|---:|---|
| 전투 그래픽 | `2F/AF74` | 38 | 선택부 `AF4E..AF64` |
| 애니메이션 함수 | `32/800F` | 26 | 선택부 `8000..800C` |
| 무기 애니메이션 | `33/A080` | 10 | 선택부 `A094..A0BD` |
| 마법 전용 연출 | `33/BC2B` | 19 | 선택부 `BAFD..BB0C` |
| 소환 변형 | `32/80DA` | 24 | 선택부 `8115..812D` |
| 행동 스크립트 명령 | `34/954D` | 15 | 선택부 `9037..904E` |
| 행동 스크립트 | `34/950D` | 6 | 선택부 `8FF7..9016`, 아래 순서 검사 |
| 행동→공격 연출 | `34/843E` | 17 | 행동 ID 25×소환 플래그 2=50입력, 17목적지 도달 |

총 **155포인터 슬롯**이며 155개 연출 본문을 실행한 수치가 아니다.
`tools/battle-scene-contract.mjs`에서 그래픽 38슬롯을 16기능군으로 빠짐없이 연결하고,
별도 은행의 최종 보스 `10/8A00`과 필드 복원/문자 치환/사운드 호출자 미해결을 따로 남긴다.

행동 스크립트 6개는 명령 가져오기·분기·다음 명령 진행을 실제로 실행했다. 개별 명령 본문을
모두 실행하지는 않았다. 일반 공격은 사용자→대상→연출→명중→숫자→상태→소멸→결과 순서를,
마법 계열은 사용자→행동→대상→연출→숫자→상태→결과→소멸 순서를 가진다. 조건에 따라 창이 생략된다.
무기와 숫자가 항상 동시에 필요하다고 합산해서도, 연출 함수가 반환했다고 자원을 즉시 반환해서도 안 된다.
`34/94E7`의 대기 메시지 반복 4조건, `9450`의 속도/버튼 대기 18조건도 따로 실행했다.
메시지 속도 0..8 전체 바이트 경계 시험이며 이 값 모두가 설정 메뉴에서 선택 가능하다는 주장은 아니다.

### 메시지 창은 화면 상태를 소유한다

원작의 사용자/행동/대상/상태/결과 **5종 논리 창**을 순서에 맞게 열고 닫았다.
`34/8D1B`가 가려질 타일을 저장하고 `8E14`가 복원한다. Japanese ROM의 `8E83`을 읽으며,
참고 어셈블리에 함께 적힌 영문판 표를 사용하지 않는다.

- 작은 창 4개의 백업 40바이트씩, 결과 창 76바이트로 총 **236바이트**.
- 강제로 5창을 모두 연 공격/마법 두 프로필에서 최초 밑그림을 정확히 복원.
- 프로필당 열기 40·닫기 20회의 대기 함수 호출, PPU 읽기 256회·쓰기 472회.
- 이는 NES 타일맵·시험 입력의 수치다. GBC 한글 백업량이나 실제 걸린 프레임 수로 복사하지 않는다.
  대기 호출은 대체했으며 `34/8185` 내부의 상태/대상 번호 갱신은 이 시험에서 실행하지 않았다.
- 실제 스크립트에서 5창이 모두 의미 있는 내용으로 동시에 열리는 도달성은 아직 별도 확인이 필요하다.

이 검사에서 분석기 `Driver6502`가 `STA` 목적지를 불필요하게 읽던 문제를 발견했다.
`STA $2007` 앞의 가짜 읽기가 PPU 주소/버퍼를 전진시켜 복원이 깨졌다. 쓰기 명령의 가짜 읽기를 제거하고,
읽기 부작용 회귀 시험과 기존 전체 호스트 시험을 수행했다. 이 수정으로 분석기가 사이클 단위 NES
에뮬레이터가 된 것은 아니다. 버스 더미 사이클·IRQ·PPU 래스터는 여전히 모델 범위 밖이다.

### 피해 숫자는 독립적인 최대 부하다

원작 `33/AD2B` 전체 루프를 8개 적·네 아군 정상 자세와 강제 피해값 1234로 실행했다.
팔레트 준비 대기 1회와 숫자 표시 대기 **32회**를 분리하고, 매 표시 경계에서 OAM을 검사했다.
숫자 **32조각 + 아군 24조각 = 56개의 비영 타일 조각**이 공존하며 아군 OAM은 유지됐다.
원작의 사인 조회/RAM 트램펄린·숫자 변환·배치를 실행했고 하드웨어 대기는 대체했다.
이 수치는 원작 8×8 조각의 직접 복사 후보이며 8개 적에게 그 피해가 발생하는 정상 게임 계산 검증은 아니다.
GBC 최적 배치의 필요량이나 게임 전체의 최댓값이라고도 말하지 않는다.

GBC는 전체 40 OBJ, 한 줄 10 OBJ 제한이 있다. 8×16 병합은 전역 크기와 타일 쌍 정렬/투명도/순서를
검사해야 하며, 가로로 놓인 숫자를 두 배 높이로 바꾼다고 개수가 자동으로 절반이 되지 않는다.
[Pan Docs OAM](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md).
전체 VRAM 768타일과 특정 BG/OBJ 주소 방식에서 동시에 참조 가능한 타일은 구분한다.
[Pan Docs Tile Data](https://raw.githubusercontent.com/gbdev/pandocs/master/src/Tile_Data.md).
직접 사이트 접근 실패 후 같은 Pan Docs의 GitHub 원문을 확인했다.

## 합쳐서 검증할 8개 시나리오

실행 가능한 등록부의 `integrationScenarios`를 기준으로 하며 **현재 통합 통과는 0/8**이다.
선택부/메시지/숫자 시험 통과를 아래 통합 성공으로 승격하지 않는다.

| 무기·결과 | 양손·무기군·투사체와 대상별 기준점, 행동 창, 숫자/미스, 사망, 공유 효과 슬롯 해제 |

각 묶음의 보고서는 원작 조건/출처와 **활성 요소·다음 요소·교체 시점**을 함께 남겨야 한다.
필수 측정은 총 OBJ/144개 모든 줄, BG/OBJ 타일과 팔레트의 활성+다음 최대, 지도/속성/한글/백업,
WRAM 은행 소유권과 복귀, 준비 시간과 최초 가능한 VBlank, 원작 순서/기간과 복원 픽셀,
음악·효과음의 버퍼 부족/IRQ 지연이다. 관측되지 않은 비용을 0으로 쓰지 않는다.

## 구현 결정과 다음 단계

1. **먼저 전체 자원 계약을 닫는다.** 위 기능군의 CHR/팔레트/지도/OAM·문자 저장 공간을
   로드→사용→다음 준비→명시적 지우기/복원 순으로 추적한다. 특히 메시지 대기 중 갱신, 무기→숫자,
   소환→아군/숫자 복원, 전투→필드의 경계가 우선이다. 미실행 본문은 별도 부하 종류로 남긴다.
2. **공통 합성기에서 통합 후보를 만든다.** 지형·적·일부 아군/효과의 BG 합성과 OBJ, 한글 창을
   같은 예산에 넣고 활성/다음 타일을 준비한다. 지속되는 배경과 변경 셀을 분리하되 단일 마법의
   유한 그림 전체를 미리 생성한 방식을 전편 조합으로 확대하지 않는다. 8×16/합성/팔레트 분할을
   같은 장면에서 비교한다. 이전 실패 편성 13/47/234와 편성 3의 공급량은 이 단계의 회귀 입력이다.
3. **기존 GBC 표시 시계에 연결해 경계 전체를 재생한다.** 첫 세로 경로는 진입→선택→물리 공격→
   명중/숫자/소멸/메시지 복원→다음 선택으로 잡고, 소환·전체 피해·종료/필드 복원 스트레스를 추가한다.
   규칙 미구현 동안은 원작에서 얻은 상태/호출을 공급하고, 임의 보상/포션 규칙으로 게임을 만들지 않는다.
4. **R2 통과 뒤 R3 계산으로 간다.** 모든 연출을 제품 수준으로 완성할 필요는 없지만, 서로 다른
   자원 수명을 가진 모든 종류에는 통합 측정 또는 그 측정이 포괄한다는 보수적 상한 근거가 필요하다.
   한 종류라도 자원/기한 상한이 미해결이면 전투 전체가 맞는다고 선언하지 않는다. 이후 새 기능은
   같은 계약과 회귀 시나리오에 추가한다. 원작의 정상 도달성은 R3/R5/R6에서 계속 확장한다.

NES의 다섯 창을 160×144에 그대로 축소하면 현재 하단 UI에 들어가지 않는다. 원작 논리 창/순서/내용은
유지하고 화면상의 배치와 겹침만 조정해야 한다. 7×7 한글·HP·숫자·커서까지 보이는 통합 비교안을
만든 뒤 공간과 가독성을 판단한다. 임의 메시지 생략, 발표 순서 변경, 아군 축소, 깜박임 도입은 하지 않는다.
기존 아군 원본 크기·상단 축소·하단 제목 생략 컨셉은 유지하며, 일반 7/8·보스 96×64의 전 적 적용은
아직 아트 승인으로 간주하지 않는다. 음질 개선은 계속 후순위다.
