# R2 후속: 밀집 NPC의 색 보존 합성 후보

2026-11-23. 기준은 PR 18 병합 `496277a57c9e9ee66870afd9156681c2f4dd5d3d`.
[앞선 표시 예산 조사](render-budgets.md)에서 실패한 정지 입력 **637개 모두를 RGB555 색 변경 없이
GBC 타일/OAM 예산 안에 넣는 후보**를 확보했다. 22개 원작 상태로 만든 GBC 검사 ROM도 표시·복원을 통과했다.
**제품 실행기의 동적 합성·오디오 동시 전송은 아직 미구현이며 R2는 열려 있다.**

## 합성 방식과 보존 조건

단순 BG 합성은 NPC와 지형의 색이 한 타일에 모여 4색을 넘는다. 이번 후보는 다음처럼 처리한다.

1. 원작 NPC 그림·반전·배치 순서로 픽셀의 OBJ 우선순위를 먼저 결정하고, 원래 지형 색 번호에 따라
   앞/뒤 판정을 적용한다. 뒤에 가려진 첫 OBJ를 건너뛰어 나중 OBJ를 드러내지 않는다.
2. 각 8×8 셀의 최종 RGB555 색 집합을 만든다. 실제 색을 바꾸지 않고 색 번호만 다시 배정한다.
3. 최대 8개 BG 팔레트 후보를 결정적인 탐욕 탐색으로 선택한다. 한 BG 팔레트에 포함되지 않는
   픽셀은 원작 OBJ 팔레트의 투명 색+3색으로 별도 8×8 OBJ에 담는다.
4. 같은 BG 패턴은 공유한다. BG 패턴 256개, 전체 OBJ 40개, 줄당 OBJ 10개를 넘거나
   색을 모두 담지 못하면 오류다. 색 근사·픽셀 생략·깜박임으로 통과시키지 않는다.

탐욕 탐색이 실패해도 모든 가능한 배치가 불가능하다는 뜻은 아니다. 새 입력의 실패는 기록하고
그 입력에서 다른 배치를 검증해야 한다. 최종 소프트웨어 합성 결과는 RGB555 단위로 대조하고,
별도 원작 픽셀 계산기와 GBC 캡처로도 확인한다. NES의 줄당 OBJ 드롭/깜박임을 기대 영상에 넣지는 않는다.

BG에는 최종 가림 결과가 들어가므로, 이후 플레이어/동행 OBJ를 단순히 얹는 것은 안전하지 않다.
원작의 플레이어 우선순위와 기존 BG의 색 번호 0 의미를 포함해 다시 합성하거나 별도 마스크를
검증해야 한다. 이번 숫자를 플레이어/동행/한글 창까지 포함한 완성 예산으로 사용하지 않는다.

사양 근거는 [Pan Docs Tile Maps](https://raw.githubusercontent.com/gbdev/pandocs/master/src/Tile_Maps.md)의
BG 색 번호·우선순위와 OBJ 우선순위 처리다. signed/unsigned BG, VRAM 공유 영역과 OBJ 제한은
[앞선 조사](render-budgets.md)에 연결했다. 검사 ROM은 unsigned BG를 은행 0, 잔여 OBJ를 은행 1에 두어 분리한다.

## 정지 입력 전수 결과

대상은 PR 7의 총 OAM 초과 592개와 줄당 초과 45개의 합집합 **637개**다.
PR 18 전수 조사에서 나온 정확한 `(world,map,x,y)` 집합의 해시도 검사한다.
새 8×16 후보 때문에 추가로 실패했던 5,230개를 이 후보의 모집단으로 부풀리지 않는다.
모든 NPC 표시 플래그를 켠 정지 입력이며 원작 초기 상태/정상 플레이 도달성과 구분한다.

| 항목 | 결과 |
|---|---:|
| 검사 입력 / 실패 | 637 / 0 |
| BG 패턴 최대 | 74 / 256 |
| BG 팔레트 최대 | 7 / 8 |
| OBJ 최대 | 29 / 40 |
| 줄당 OBJ 최대 | 6 / 10 |

대상 프로필은 world 0/map 139, world 1·2/map 86·87이다. 기준 카메라에서
world 1/map 87은 74 BG 패턴·7 BG 팔레트·29 OBJ·줄당 6개,
world 2/map 86·87은 26·2·16·4, world 0/map 139는 34·3·4·2다.
전수 입력에서 정확한 RGB555 대조와 독립 원작 픽셀 대조를 모두 통과했다.
움직이는 모든 NPC 조합이나 모든 방향/포즈의 전수 검사는 아니다.

## 실제 소비 경로를 더 좁힌 근거

새 게임 NPC 플래그는 원작 `3A:8E76`을 실행한 `$6080–60BF`와 대조한다.
`8EB7`은 **8KiB bank 0을 A000에 매핑**한 뒤 B600을 읽으므로 파일 오프셋은 `1610`이다.
주소의 B600만 보고 `3610`으로 바꾸지 않는다.

맵 속성과 원작 레이아웃을 넣고 `3A:918A`를 실행해 트리거 번호 부여 및 `$0720` 목록을 얻었다.
원시 `$60` 타일을 이벤트 번호로 간주하지 않는다. 이후 `3F:E6C6→E6D7`, `EA1B`, `3C:9319`로
포인터 선택·64바이트 복사·조건 판정을 실행하고 관련 플래그의 모든 조합과 대조했다.

- world 2/map 86·87의 (10,3) 트리거는 ID 52다. 이벤트 플래그 `$47`이 꺼져 있으면
  이벤트 81(`$51`), 켜져 있으면 0을 선택한다. 맵 87의 world 1 레이아웃 선택 조합에는
  다른 트리거도 있으므로 이를 같은 정상 진행으로 취급하지 않는다.
- 이벤트 81은 전투 명령 뒤 슬롯 4–11을 차례로 숨기고 NPC ID 34의 영속 플래그를 지운다.
  이번 검사에서는 **전투가 반환했다는 명령 경계 입력**에서 원작 `3B:ACD1`의 숨기기 8개를 실행했다.
  전투 성공이나 그 이전 플레이어 이동을 구현/검증한 것으로 세지 않는다.
- world 0/map 139에는 이 방식의 타일 트리거가 없다. 해당 NPC 조건은 앞선 조사에 보존했다.
  이벤트 98(`$62`)에 있는 슬롯 0 우측 이동을 명령 경계에서 실행하고 `B17C/B1EE`로
  1/4/8/12/16틱의 좌표·포즈를 얻었다. 전체 이벤트를 재생하거나 맵 139에서 정상 실행된 것으로 주장하지 않는다.

따라서 “밀집 상태는 모두 도달 불가능하므로 제외”라는 처리는 하지 않는다.
맵→조건→이벤트의 국소 연결은 확인했지만 새 게임부터의 world 전환·영속 플래그 이력은 계속 미해결이다.

## GBC 검사 범위

`build/npc-composition/ff3-npc-composition.gbc`는 A/B로 원작 상태 22개를 전후 이동한다.
다섯 기본 장면, 순서 반전 스트레스 두 장면, NPC 숨기기 여덟 단계, 원작 이동 다섯 중간 상태와
두 재로딩을 포함한다. 자동 검사는 0→…→21→0의 23회 로딩에서 실제 OAM/영상 **529,920픽셀**을 비교한다.
원작 이동/숨기기 상태는 빌드 시 6502로 계산하며 GBC에서 게임 로직을 실행하는 것이 아니다.

프레임별 생성 데이터를 각 ROM 은행에 넣고, 실제 GBC 코드가 은행을 선택해 읽어 VRAM/팔레트/OAM에
적재한다. 메타데이터는 은행 1에서 로컬 구조체로 복사한 뒤 데이터 은행으로 전환한다.
VRAM 갱신은 LCD를 끄고 수행한다. 이는 **색·가림·자산 공급의 가능성 검사**이며 게임 중 갱신 시간이나
VBlank 예산·오디오 연속성의 증거가 아니다. 프레임 사전 생성 방식을 제품의 전체 맵 저장 방식으로 채택하지 않는다.

고정 MesenCore에서 OAM/화면이 일치했고, 캡처 001(밀집), 014(숨기기 완료), 019(이동 중)를 육안 확인했다.
공통 검사기 변경 후 기존 PR 18의 실패 재현 ROM도 3화면/69,120픽셀 회귀를 통과했다.
독립 에뮬레이터/실기 검증은 아직 아니다. 제품 탐색·음악 코드는 변경하지 않았다.

반복 검사에서 기본 프레임 혼합 때문에 정지/재개 시 한 캡처의 RGB 바이트 69,120개가 전부
기대값의 절반이 되는 문제가 드러났다. 고정 코어의 `GbDefaultVideoFilter`는 혼합 상태가 바뀌면
이전 프레임을 0으로 지운다. 검사기는 기존 `VerifyExploration/Audit.ConfigureVideo`의 ABI 검사를
재사용해 프레임 혼합을 끄고 색 보정을 고정했다. 실패 영상은 로컬에 보존했고 픽셀 허용 오차는 늘리지 않았다.
수정 후 새 검사와 기존 실패 재현 검사를 다시 통과했다. 호스트 회귀는 총 36건 통과했다.
공개 허용 소스 217개만 복사한 별도 폴더에서도 같은 ROM과 정지 입력 조사 결과가 재생성됐다.

- 검사 ROM SHA-256: `8af69af164b83318b967d6892d93c5bc4da740c18f19379adb5ead25c4c15e4e`
- 정지 입력 조사 SHA-256: `88a7e88ef3b3023e3b4a041e6ac8aea8fe00222bba0da02ea522b8089dc900a5`
- MesenCore SHA-256: `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`

## 다음 R2 완료 조건

1. 이 색 보존 후보를 기준으로 플레이어/동행·카메라 경계·원작 가림을 포함한 변경 타일 갱신을 설계한다.
   정지 장식의 사전 변환과 동적 영역의 합성을 분리하고 실제 GBC 준비 시간/WRAM/VRAM 상주량을 측정한다.
2. 기존 VBlank 전송과 오디오 경로에 연결해 숨기기·이동·창·재진입 중 복원과 음악 연속성을 검사한다.
   이번 PC 탐색 알고리즘을 그대로 매 프레임 GBC에서 수행할 수 있다고 가정하지 않는다.
3. 남은 적 색 초과, 보스 206 외부 타일, 원본 아군+대형 마법과 한글 창의 공존 예산을 계속 검증한다.
   이 조건들을 닫기 전에는 R3에 들어가지 않는다.
