# 같은 부팅의 필드 → 전투 표시 → 필드

2026-11-27. PR 106의 통합 링크에 실제 화면 왕복을 연결한다.
`state_start=4`는 한 번 부팅한 세션에서 필드 문맥과 원작 오디오를 유지한다.
`scene_request=1`은 지원하는 전투 표시 프로필 진입, `2`는 표시 진단 종료 요청이다.
이 요청은 승리·도주·보상 처리나 자연 조우를 대신하지 않는다.

## 원작 구조와 구현 범위

- `3F/E1E1..E201`: 필드 VBlank/OAM/스크롤 뒤 사운드 갱신과 프레임 진행.
- `3F/E37E..E3B2`, `3D/BDB9`: 이동/통과 판정에서 조우를 검사하고
  전투 번호 `$6A`, 트리거 `$AB=$20`을 설정한다. 판정 즉시 화면을 빼앗는 구조가 아니다.
  `3F/E26A..E280`의 프레임 루프가 전환과 전투 호출·필드 복귀를 수행한다.
- `3F/FA26..FA80`: 필드 문맥 보관(`FB17`), 표시 IRQ 교환(`FAB5`), 전투 자원 준비와
  실행, 종료 페이드, IRQ 복구(`FADD`), 문맥 복구(`F83B`). 보관 대상에서 사운드 DP는 제외된다.
- `3F/E7EC`의 새 맵 진입은 `E811`에서 NPC를 초기화한다. **전투 복귀 `E7F8`은
  `E803`과 `E81B`를 호출하며 `E811`은 호출하지 않는다.** 복귀 시 NPC를 새로 만드는 것은 오류다.
  `E81B`는 맵 그림과 팔레트를 다시 올리고 방향을 보존하며 입력/표시 상태를 정리한다.
- `2E/9D5F..9D87`: 직업·상태, 캐릭터/메뉴, 적/배경 준비 뒤 전투곡을 요청한다.
  일반곡 `$20`, 보스 `$2A`, 최종 보스 `$28`은 구별된다. 현재 표시 프로필은 일반 전투만 지원한다.
  필드 복귀곡은 `E8CE..E8FD`의 맵 음악 경로에 해당한다. 현재 맵 29는 곡 `$0C`다.

원작의 문맥 보존, 표시 소유권 교환, 자원 준비 후 음악 요청을 유지한다. GBC에서는
WRAM 은행 7에 필드 DATA와 은행 1 작업 영역을 보관한다. 현재 최악 사용량은 4,050바이트다.
GameState와 오디오 큐/생산기/타이머는 이 이미지 밖에 있어 복귀 이미지로 덮어쓰지 않는다.
장면을 넘길 때는 전송과 콜백을 먼저 배출하고 새 소유자만 VRAM/OAM을 구성한다.

필드 복귀는 RAM의 맵·충돌·NPC 위치와 실행 문맥을 재사용한다. 맵 그래픽·글꼴·NPC 그래픽은
전투가 VRAM을 덮어썼으므로 ROM에서 다시 올린다. 256바이트 단위 업로드와 맵 행 구성 사이에
오디오를 생산한다. 기존의 새 맵 로더를 재호출하는 방식은 NPC 초기화와 오디오 공백을
일으킬 수 있어 사용하지 않는다. 별도 VRAM 사본을 유지하는 방식보다 보관 RAM이 적고,
기존 원작 구조와 대응된다. 모든 전투 변형의 최적 방식이라는 주장은 하지 않는다.

## 같은 부팅 검증

`npm run verify:scene-roundtrip`은 원본 ROM의 음악/마법/필드/NPC 소비 코드로 만든
독립 기준과 실제 Mesen 출력을 비교한다. 테스트 세션의 7,200틱 오디오 스케줄을 한 번 시작한
후에는 장면 전환에서 재시작하지 않는다. 게임의 초기 오디오 초기화 횟수도 1회여야 한다.

1. 실제 필드에서 버튼으로 NPC 앞으로 이동한다.
2. 필드 문맥을 보관하고 전투 자원과 원작 등장 경로를 실행한다.
3. 원작 일반 마법의 모든 프레임을 캡처한다. 마법 도중 복귀 요청은 완료까지 보류한다.
4. 필드 복귀 후 위치·방향·NPC·맵·GameState 보존을 대조한다.
5. 실제 버튼으로 한글 NPC 대사를 열고 닫은 뒤 이동한다.
6. 백어택 표시 프로필로 다시 진입해 같은 검사를 반복한다.

프레임 단위 캡처는 누락 도트 검사 용도이며 자연 속도 측정이 아니다. 진입 자원 준비 시간과
검증을 위해 멈춘 마법 포함 전체 왕복 시간은 구분한다. 기존 숫자·필드·메모리 검증도
같은 최종 ROM의 별도 부팅 회귀로 실행한다.

최종 통합 ROM SHA-256은
`c9332f0844d779a9e0cf1a33cc5b6f7c4cb88cf24aca293e41dad0a920009065`다.
원작 ROM은 `262a98737975df25fff80ad91090c3da039d2828035c6253140d2c5f3b176ea2`,
검증 코어는 `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`로 고정했다.
실제 캡처·원본 데이터·생성 ROM은 로컬에만 보관한다.

추가 검증에서 기존 16바이트 CPU 복사의 100μs 기준을 256바이트 상주 DMA에도 적용한
관측기 분류 오류를 발견했다. 전송 루틴의 실제 23바이트 기계어와 진입/종료 주소를 대조해
두 경로를 나눴다. CPU 기준을 완화하거나 DMA를 관측에서 빼지 않았으며, 두 경로 모두
은행 1·SP·IE/IME 복원 및 잘못된 은행에서의 인터럽트 금지를 검사한다. 게임 코드는 이
관측기 수정 때문에 변경하지 않았다.

전투 자원 준비 완료까지는 각각 **1,057.542ms / 1,015.800ms**다. 등장 완료나 첫 입력
가능까지의 측정은 아니며, 0.5초 진입 목표는 아직 미달성이다. 필드 복구 구간은 프레임
표본 기준 약 0.49–0.52초다. 모든 전투의 최대값으로 확대하지 않는다. 필드 회귀의 실제
이동 화면 최대 간격은 50.442ms, p95 상한은 34ms로 기존 55/35ms 기준을 유지한다.

공통 DATA 끝은 CA78, 장면 arena는 CA80, 고정 RAM 끝 CFCB(53바이트 여유),
고정 ROM 끝 3FE2(30바이트 여유)다. 필드 보관은 4,050바이트로 WRAM7에 46바이트가
남는다. 219개 빌드 입력과 원작에서 변환한 36개 필드 자산 은행·123개 전투/오디오 배열도
동일성을 확인했다. 이 작은 여유를 새 기능의 무조건 사용 가능한 공간으로 간주하지 않는다.

## 남은 연결

현재 필드 진단 맵의 조우율은 0이다. 전투 프로필의 파티/편성/HP는 기존 표시 진단 입력이다.
자연 조우 선택 → 현재 파티/직업/장비/상태 공급 → 실제 행동/계산 → 승리·패배·도주 결과
반영은 후속 작업이며, 진단 종료를 그 결과처럼 취급하지 않는다. 원작의 전환 플래시·종료
페이드 전체도 이번 자원 왕복 자체와 별개의 남은 표시 경로다.
보스·석화·아이템 atlas 등 별도 진단 변형을 추가할 때도 동일 메모리 수명 검사를 적용한다.
