# 진열 변경: 원작 선택·예약·실행 경계

2026-11-25. 규칙 커널과 여백 수정은 PR 41까지의 결과이며, 그 병합
`1d04d42e85fba454cc3558dd1d300863f7508b82` 뒤에 **화살표·취소·예약·수집기 복귀**를 연결했다.
실제 열 이동과 행동 실행 순서는 아직 미연결이다. 예약 완료를 진열 변경 전체의 완료로 세지 않는다.

## 원작 호출과 이식 경계

| 원작 코드 | 확인한 동작 | 이번 소비자 |
|---|---|---|
| `35/A71C..A7A4` | 장비 레코드 `+0F`의 bit 0을 읽어 같은 열로의 변경을 거절. 정상 입력이면 `5D` 화살표를 준비 | `ff3_row_begin` |
| `35/A823..A842` | 아군 4명 × 두 방향, 보통/백어택 화살표 좌표. 백어택은 X·반전 속성·반대 방향 취소 키를 바꿈 | 원본 ROM에서 32바이트 추출, 생성 C 배열은 비공개 |
| `35/A7AA..A7CA` | 정확히 A이면 확인음·다음 아군·행동 ID 예약. B 또는 반대 방향이면 취소. 복합 입력과 다른 키는 계속 대기 | `ff3_row_key` |
| `35/A7DF..A822` | 행동 실행 때 이름 `3B/3C`, 스크립트 `01`; 전투 `+33` 및 정본 장비 `+0F`의 bit 0을 각각 뒤집음 | `ff3_row_execute` |
| `34/99FD` 이후 | 선택한 아군을 되돌린 뒤 수집기 복귀 | 수집기/HP/다음 아군 경계 연결. 중간 이동 프레임은 후속 |
| `2F/B42A`, `B443`, `B45C` | 후퇴/전진의 표시 좌표·행 상태·이동 액션 | 후속 화면 관찰 및 GBC 연결 |

선택/확인은 두 row 값을 바꾸지 않는다. 실제 행동 순서가 왔을 때 변경한다.
두 값의 상위 7비트는 각각 보존하며 하나를 다른 하나로 복사하지 않는다.
원작 실행은 명령에 따라 bit 0을 고정 대입하는 방식이 아니라 두 명령 모두 toggle이다.
원작 효과음 요청 값은 확인 `05`, 오류 `06`으로 반환한다. 커널 자체가 재생기를 소유하지 않는다.

원작 oracle은 ROM의 6502 명령을 실행하고 대기/외부 수집기 경계에서 멈춘다.
실행의 `91CE` 대상 메시지 지우기만 반환 처리하며 이를 화면 검증으로 세지 않는다.
좌표는 NES 좌표 그대로 대조한다. 새 GBC 좌표를 임의로 추가하지 않는다.
공개 소스에는 원본 테이블이나 ROM 바이트를 포함하지 않는다.

## 검증

`npm run build:battle-row`, `npm run verify:battle-row`:

- 선택 진입 4,096건: 4명 × 장비 row 바이트 256종 × 보통/백어택 × 두 명령.
- 대기 입력 4,096건: 4명 × 보통/백어택 × 두 명령 × 입력 바이트 256종.
- 실행 2,048건: 4명 × row 바이트 256종 × 두 명령. 전투 row도 별도의 순열로 전 범위 검사.
- 합계 **10,240건**, GBDK로 컴파일한 SM83 커널과 원작 결과 16바이트 일치.
- 기대 결과를 1비트 훼손한 음성 대조 ROM은 첫 사례/첫 바이트에서 실패.

정상 ROM SHA-256: `bb90d8862409fb694fa537ac801666e2a8d4e2be7f38308bd8959f0a4266fe48`.
원작/GBDK/Mesen 버전은 기존 고정 입력을 그대로 사용한다.
이 검사는 함수 경계 비교이며 실제 버튼→화살표→행동 순서→이동 영상의 완주 검사가 아니다.

## 이번 UI 조정

사용자 요청대로 하단 선택/아이템/장비 창의 내부 글자와 HP 숫자를 **1px 아래로** 옮겼다.
상단 좌표 103, 높이 41, 행 간격 8, 손 커서 좌표와 원본 도트는 유지한다.
2px 안은 정적 선택 UI가 예약보다 1타일 늘어났고, 요청 범위인 1px 안은 기존 예약 안에 들어간다.
HP 행동명 마스크도 같은 기준으로 옮겨 선택 전후에 기준선이 달라지지 않게 했다.
동적 아이템 글자와 독립 픽셀 참조도 같은 내부 기준선으로 검사한다.
이전 행동 표시 진단의 별도 레이아웃은 변경하지 않는다.

UI 후속 검증: 아이템/장비 창 1,005요청·762장·17,556,480픽셀, 명령창 405요청·208장.
원작 오디오 각각 21,600/7,200틱에서 underrun·late·잘못된 영상 전송 0.
아이템 OAM 최대 20개/한 줄 6개, 스택 미사용 263바이트, IRQ 최대 238.895µs.
열 이동은 원작 6프레임 유지. 준비 포함 최대 535.767ms, 창 열기 602.737ms,
기타 입력 1,037.913ms, 별도 명령 진단의 아군/HP 전환 736.679ms다.
기존보다 빨라졌다는 주장이 아니며 준비 비용 최적화는 남아 있다.
아이템 ROM: `6c509f87b74499ec0f9c12db66dc0f48c6241f093e8b018ec0b7b7ea150942c9`.
명령 ROM: `6436e80d1db8d2ae8b0b4abb406622df6a97c6443d9b51c048bc52739e21372e`.
공개 allowlist 373파일과 로컬 입력만으로 세 ROM 해시를 재현한다.

## 화살표와 실제 명령 수집기 연결

정면 NES 저장 상태에서 실제 방향키/A/B 입력으로 화살표, 취소 후 명령창,
예약 후 다음 아군과 HP 행동명 표시를 확인했다. 진단 이름/HP가 들어 있는 기존 상태이며
새 게임부터의 정상 진행 검증으로 세지 않는다. 화살표 캡처 SHA-256은
`8165b51ae8533326cdbbc0ce4d05afac644a9df988382d61d056fb38028a3613`이다.
원본 `5D` 타일의 8×8 실루엣 64픽셀이 실제 NES 캡처와 일치한다. 도트와 네 색을 보존한다.
메모리 관찰에서도 예약 뒤 행동 ID만 바뀌고 정본 장비의 열은 유지됐다.
백어택/전진의 실제 NES 이동 영상까지 관찰했다는 주장은 하지 않는다.

GBC에서는 기존 명령/아이템 실행기에 같은 `ff3_row_begin/key`를 연결한다.
원작처럼 좌/우의 연속 입력을 받아 화살표를 표시하고 A로 예약, B/반대 방향으로 취소한다.
복합 입력을 A 확정으로 오인하지 않으며 같은 열 요청은 원작 오류 요청 값을 반환한다.
확인 뒤 HP 오른쪽에 원작 문자열 ID `0622/0623`의 한글 행동명을 표시한다.
이전 아군으로 돌아오면 최대 HP가 복구된다. 마스크와 행 상태는 원작 수집기 경계를 따른다.

화살표는 손 커서의 첫 타일 슬롯을 빌려 쓰며 캐시를 손/화살표 두 종류로 구분한다.
취소 후 명령 손, 예약 후 다음 아군 손, 아이템 창 손을 복원한다. 비활성 페이지에서만
타일/OAM을 준비하고 함께 게시하며, 새로운 아군 축소나 숫자 생략은 없다.
현재 화면 공급은 기존의 네 명 전열 진단 편성이다. 후열을 포함한 모든 조합의
실제 이동/선택 자세는 행동 소비자와 함께 연결해야 한다.

명령 진단 최종 ROM:
`80ea2e55464ef7129e4ea1304ed18876b8d46cb43e39335dd71753530deaac11`.
430요청·304장·7,004,160픽셀, 네 아군×정면/백어택 8위치의 화살표를 원작 결과와 비교했다.
대기 50건·예약 26건·취소 12건·같은 열 거절 6건, 16바이트 규칙 상태와 전체 OAM 일치.
원작 오디오 7,200틱·21,366이벤트·30,938 APU 쓰기에서 underrun/late/잘못된 영상 전송 0.
최대 OAM 16개/한 줄 5개, 스택 미사용 296바이트. 일반 입력 최대 50.378ms,
아군/HP 전환 최대 736.679ms로 준비 비용은 여전히 남아 있다.
오디오 수치는 기존 원작 음악/SFX 부하 계획과의 공존 검증이며 새 게임의 모든 사운드 호출자 검증은 아니다.

아이템/장비/진열 왕복 최종 ROM:
`72ab17811401aab591a95c69ae44f6882c0a72129fd296f881c05fa5ac16d97c`.
1,002요청·806장·18,570,240픽셀과 원작 오디오 21,600틱을 검증했다.
underrun/late/잘못된 영상 전송 0, 최대 OAM 20개/한 줄 6개,
스택 미사용 265바이트, 오디오 IRQ 최대 238.895µs.
아이템 창 열기 최대 719.936ms, 스크롤 준비 포함 585.995ms, 기타 입력 1,004.562ms다.
스크롤 이동 자체는 기존 6프레임을 유지한다. 요청 순서가 달라 이전 수치와 직접적인
속도 개선 비교를 하지 않으며, 공급 준비 지연은 후속 최적화 대상으로 남긴다.
긴 이름의 끝 도달/역방향 이동과 선택한 이름만 움직이는 픽셀을 대조한다. 고정 360프레임
캡처가 원점 복귀 순간과 겹친 초기 실행은 픽셀 증거 관문에서 실패했다. 검증기를 수정해
최소 대기 뒤 120프레임 이내의 안정된 비영점 위치를 요구하며, 게임 코드는 바꾸지 않았다.
모든 픽셀/상태/오디오 관문을 다시 통과한 위 최종 실행만 승인 근거로 사용한다.
공개 허용 목록 373파일과 기존 비공개 입력을 복사한 두 ROM의 해시도 일치한다.
최종 소스 복사본에서 물리 전후열 회귀를 포함한 호스트 검사 **101개가 모두 통과**했다.

## 물리 공격의 전후열 효과: 필수 후속 소비자

사용자 지적에 따라 진열의 물리 방어 효과를 완료 조건에 명시한다. 단순히 장비 방어력에
상수를 더하는 방식으로 구현하지 않는다. 원본 ROM 실행으로 아래 계산 경계를 고정했다.

- `30/9F7E..9FA6`: 예외가 없을 때 공격자 후열이면 명중률을 한 번 우측 시프트한다.
  대상도 후열이면 다시 시프트하고 추가 회피 표식을 세운다. 홀수의 절삭도 보존한다.
- `30/9FD2..9FE6`: 그 표식이 있으면 회피 성공 수를 한 번 증가시켜 총 명중 수에서 뺀다.
  바이트 증가/뺄셈과 0 하한은 원작 순서대로 처리한다. 피해를 일괄 절반으로 대체하지 않는다.
- `31/A397..A3FF`: 아군의 무기 타입/장비 ID와 현재 손 경로에 따른 원거리 예외.
  하프·활/화살 플래그, 화살 장비 플래그, 해당 장거리 무기 범위를 각각 구분한다.
  몬스터는 아군 장비 예외 검사로 들어가지 않는다.
- `35/A19E..A1A7`, `A224` 이후: 감싸기 대상의 열을 저장하고 잠시 전열로 취급한 뒤 복원한다.
- `34/88A4`와 진입/종료 호출자: 백어택 전후에 정본 장비와 전투 레코드의 열을 함께
  반전/복원한다. 화면의 좌우 반전만으로 방어 계산까지 맞았다고 간주하지 않는다.

`tests/battle-row.test.mjs`에 명중률 256종×공격자/대상 열×아군/몬스터 2,048경계,
명중/회피 결과 50경계, 원거리/손/몬스터 예외 44경계를 추가했다. 이는 **원작 계산의
회귀 기준**이며 GBC 피해 계산 이식을 완료했다는 뜻은 아니다. 실제 연결에서는 원작 RNG 소비,
양손 공격, 상태와 감싸기 복원, 진열 예약 전/후와 실행 후의 다음 물리 공격까지 검사해야 한다.

## 다음 연결 순서

1. 실제 NES의 전진/후퇴와 백어택 실행을 추가 관찰한다. 원작의 명령 선택 전후 이동과
   행동 차례의 진열 이동을 구분하고 좌표·자세·프레임 대기를 확인한다.
2. 원작 행동 순서가 row 실행을 호출하도록 연결한다. 정본 장비와 전투 레코드의 수명을 유지한다.
   `34/9777..986B`의 난수·정렬·제외와 `34/9FAC` 행동 분배를 기준으로 삼는다.
   아군 배열 순서나 모든 진열 우선 처리로 바꾸지 않는다. 정렬 루틴 `34/8F57`의
   동률 순서와 난수 소비도 대조한 뒤 활성 행동 기록을 표시 소비자에 전달한다.
   `B42A/B443/B45C` 이동 액션, 백어택 방향, 음악/효과음, 화면 예산을 함께 검증한다.
3. 위 물리 전후열 계산과 첫 효과 계산, 아이템 실행 전 예약 반환/실제 소비 호출자로 이어간다.
   전후열 공격/방어 소비자도 해당 계산 경계에서 비교한다. 22직업 명령과 마법 조건은 계속 필수 범위다.
