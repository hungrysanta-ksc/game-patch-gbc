# 원작 정규 진열과 상태 아이콘의 상주 표시

기준: 2026-11-25, PR 59의 지형·적 BG·아군 OBJ 경로 후속.
원작 ROM의 `B479` 이후 캐시 적중·비석화 진열과 `B304`의 명령 선택 준비를 연결한다.
32×32 적은 28×28, 아군은 무축소, 지형 11픽셀과 기존 V6 좌표를 유지한다.
전체 전투나 석화 표시가 완료된 것은 아니다.

## 원작 구조와 보존한 경계

- `2F/B489`는 정규 진열 좌표와 반전 허용 `$98`을 바꾸지만, `F8BC` 대기는
  OAM DMA를 하지 않는다. 실제 표시를 검사하려면 `$0200`의 작업 버퍼와
  `$4014`가 게시한 OAM을 구분해야 한다. 기준 실행기에 물리 OAM 추적과
  `F8CB` 복귀 시점의 PPU 관측을 추가했다. 백어택 반전을 한 대기 일찍
  게시하지 않는 회귀 검사를 포함한다.
- 후속 상태 복원 대기는 기존 `Ff3EntryTail` 실행기가 진행한다. 이번 실제
  표시 어댑터는 CANONICAL → 네 번의 STATUS → DONE인 캐시 적중 경로다.
  이 진단의 석화 맵은 처음부터 비어 있고, 원작의 clear 작업 후에도 비어
  있음을 독립 NES/GBC 픽셀로 대조한다. 석화·캐시 교체·보스 분기는 명시적으로
  거부한다. 이미 이식한 일반 후반부 실행기를 삭제하거나 성공 no-op으로 바꾸지 않는다.
- 상태 아이콘은 등장 중 항상 표시하지 않는다. `2F/B304..B330`이 상태 ID를
  복사하고 그래픽을 적재한 뒤 대상 마스크를 지우고 `$AC`를 켠다.
  `B52A`의 상태 그림은 `0D/B240 + id×64`에서 네 슬롯의 `1490/14D0/1510/1550`으로
  읽힌다. 명령용 시스템 그림도 원작 전송 범위를 사용한다. 일반 아군의
  `1010..138F` 패턴은 바뀌지 않는다. `B331`은 마지막 OBJ 팔레트만 교체한다.
- `32/9F11..33/A048`의 상태/대상 OAM 소비자를 C/SM83로 이식했다.
  표시 게이트, 상태별 팔레트·Y 오프셋, 백어택 반전, 8회마다 바뀌는 두 그림,
  `$B7`의 8비트 순환, 대상 숫자 소유자 순환과 마스크를 원작 바이트와 대조한다.
  대상 숫자의 **논리/OAM 생성 검증**과 **실제 V6 표시 연결**은 구분한다.
  이번 native 어댑터는 B304가 지운 대상 마스크만 허용한다.

## GBC 자원 수명과 비용

명령 시작 때 원작 그래픽을 NES 2bpp에서 GBC 2bpp로 바꾸어 같은 타일 ID에
적재한다. 이후 상태 아이콘은 매번 타일을 다시 만들지 않고 OAM만 변경한다.
실행 ROM에는 초기 상태와 자원 블록이 들어가며, 관측한 프레임별 좌표·OAM·
완성 그림은 검증 파일에만 남긴다. 현재 진단의 명령 준비 자원은 초기 상태에
종속된다. 상태 변화에 따른 재적재를 처리하는 일반 자원 공급기는 후속 범위다.

아이콘 8 OBJ를 아군 24 OBJ보다 먼저 배치해 원작 우선순위를 유지한다.
적 색 보정 OBJ까지 이번 편성에서 최대 38슬롯을 예약하며, 관측한 전체 경로의
한 줄 최대는 5개다. 한도가 부족하면 실패시키며 도트·숫자를 생략하지 않는다.
이 한도는 모든 편성·마법·피해 숫자·창의 동시 한도가 아니다.

새 소비자 코드 bank 11은 1,141바이트, 공유 bank 16은 6,693바이트,
정적 WRAM 끝은 `CB5D`다. 원래 배경을 캐릭터 전체 그림으로 다시 합성하는
경로를 추가하지 않았다. 반대로 석화는 원작부터 BG 소유이므로, 일반 OBJ처럼
옮기는 대신 작은 BG 영역의 갱신·복원과 타일 경계 색 보정을 다음에 연결한다.

초기 동시 부하 검사에서 그래픽 적재 후/프로필 교체의 팔레트 대기 구간에
버퍼 부족이 검출됐다. 오디오를 서비스하지 않는 VBlank 대기를 제거하고,
팔레트를 4색 단위로 안전한 VBlank 초반에 게시하며 그룹 사이 음악을 보충한다.
명령 시작은 실제 변경되는 팔레트 하나만 전송한다. 음표·반복·효과음 패킷과
소비 마감은 바꾸지 않았다. 이 변경은 이전 등장 경로에도 회귀 검사한다.

## 검증

- 기존 호스트 142검사와 추가 3검사 통과. 추가 검사는 비활성 보존/카운터 순환,
  물리 OAM의 지연 게시, 실제 B304 상태 ID·그래픽 소유권을 검사한다.
- 상태 OAM C/SM83 1,024건: 정면/백어택 × 256카운터 × 켬/끔.
  상태 0..7/FF, 좌표 순환, 다양한 대상 마스크를 포함한다.
  잘못된 상태 ID는 상태·출력 보존으로 거부하며, 기대 OAM을 변조한 ROM은
  첫 케이스 첫 바이트에서 실패한다.
- 최종 실제 GBC 화면 268장: 정면/백어택 × 정상/독·암흑·침묵·빈사.
  상태, 원작 OAM, native OAM, 지형, 적 패턴, 가드와 픽셀이 일치한다.
  상태 아이콘의 두 그림과 원작 자세를 확인했다. 하단 UI는 이 진단에 포함하지 않는다.
- 원작 음악·효과음·페이드 7,200틱 소비 해시 일치. 지연/버퍼 부족 0,
  타이머 누적 오차 +0.113ms. 음질의 청취 합격을 뜻하지 않는다.
- 자동 명령 대기 중 패턴/맵/전체 VRAM 쓰기 0. OAM DMA 2,038회,
  잘못된 DMA/래스터 변경 0, 가장 늦은 DMA 시작 LY=149.
- 최대 준비 126.465ms는 등장 전반부를 포함하고 오디오 보충과 겹친다.
  자동 명령 대기의 게시 간격은 최대 5프레임, 지연 게시 2,037회다.
  PR 59의 반복 등장과 작업량이 다르므로 이 수치로 속도 개선율을 주장하지 않는다.
  원작 속도 및 모든 전투 요소의 동시 통합은 여전히 미완료다.
- 공유 팔레트 변경의 기존 지형/혼합 상태 회귀: 123화면과 7,200오디오 틱 일치,
  지연/버퍼 부족 0, 오차 +0.182ms. 적 패턴 쓰기 0, 지형 100,160바이트와
  맵 200,640바이트의 합이 전체 VRAM 쓰기 300,800바이트와 일치한다.
  최대 준비 151.855ms, 게시 간격 최대 11프레임으로 이전 140.137ms/10프레임보다
  나쁜 관측도 남았다. 이번 수정은 오디오 안전성과 새 소비자 연결이며 전체
  등장 속도 개선으로 표시하지 않는다. 오디오와 화면의 작업 배치 비용은 후속 과제다.
- 공개 허용 소스 489개만 복사한 환경에서 표시/검증/오차 주입 ROM과 보고서를
  바이트 단위로 재현했다. 도구·원본 ROM 경로만 비공개 local.json으로 공급한다.

표시 ROM SHA-256:
`5d6e3b9db94c4d90280d7d3ca94966a891423fc40222de5a4214a5b8906cd176`.
상태 OAM 검증 ROM SHA-256:
`4e207649736ae5e57a2015f1ed62cf6e87b8ac886f766b8fdaa530ca9780f82c`.

재현: `npm run build:battle-status-oam`, `npm run verify:battle-status-oam`,
`node tools/verify-battle-select.mjs --status-oam --negative`,
`npm run build:battle-status-video`, `npm run verify:battle-status-video`, `npm test`.
원본 ROM·번역 파일·추출 그림·관측·캡처·생성 ROM은 공개하지 않는다.
