# 실제 전투의 석화·사망·마법 자원

2026-11-28. 기준은 PR 121 병합 `8566f4595a08622ed236b2063ef65a4a5b341a6c`.

## 원작 소비자와 수명

`2F/B5B8 → B5C3`는 네 명을 차례로 갱신한다. `B651`의 직업/상태 그래픽 캐시,
`B6AB` 위치, `B607` 자세, `B5F2` 반전, `B72B` 석화 지도 요청을 만든 뒤
`AEE8`, NMI/OAM 게시, `B6C8` 배경 지도 갱신을 실행한다. 전투 진입뿐 아니라
`34/8411` 공통 연출의 7번 호출자도 같은 소비자를 사용한다.
첫 배우가 그래픽 캐시 적중으로 곧바로 STATUS 요청을 내는 경우에도 첫 게시 전에
지도 요청을 준비한다. 기존 갱신 루프는 이를 준비하지 않고 다음 배우로 진행하여
첫 배우의 석화 해제가 누락됐다. 해제 상태/지도 대조가 실제 ROM에서 이 결함을 잡았다.

`(status & C0) == 40`일 때만 석화이며, 사망은 석화보다 우선한다. 석화 안에서는
개구리·소형·일반 순서로 원본 지도와 글리프를 선택한다. 석화를 위해 원래 직업
스프라이트를 덮지 않으며, 해제 때 기존 직업/상태 캐시와 원작 로더를 다시 사용한다.

## GBC 자원 배치

완성 프레임을 ROM에 추가하지 않는다. 방향당 40개 원본 석화 글리프를 처음 필요할
때 한 번 올리고, 상태 변경은 지도 ID를 바꾼다. 적 사망·점멸의 현재 지도 소비자가
석화 지도까지 함께 구성하므로 오래된 초기 적 지도로 돌아가지 않는다.
서로 인접한 석화 두 명이 같은 GBC 셀에 걸리면 두 원본 글리프를 공통 paint 커널로
합치고, 적 사망과 같은 현재 셀 풀에서 타일을 받는다. 별도 가변 풀은 만들지 않는다.

| 자원 | 실제 영역 | 수명 |
|---|---|---|
| 석화 글리프 | VRAM bank 0 `9400..967F`, signed BG 64..103 | 첫 석화부터 전투 종료 |
| 지형 경계의 머리 2조각 | bank 0 `8D40..8D5F`, OBJ 212..213 | 같은 전투 |
| 원작 피해 숫자 | bank 0 OBJ 223..255 | 기존 소유권 유지 |
| UI | bank 0 112..211 및 signed 112..127 사본 | 기존 창 소유권 |
| 마법의 임시 아군 BG | bank 0 signed 0..63, 석화가 없으면 기존 80개 한도 | 연출 준비부터 복구 |
| 적 사망·점멸 | 기존 bank 1 현재 셀 풀 | 해당 지도 페이지 |

첫 석화에서 원본 적의 signed 사본을 준비한다. 이후 석화가 모두 해제되어도 이 전투는
signed 주소 모드를 유지한다. 다음 조우에서는 상태와 캐시를 초기화하고, 필드 복귀는
기존 전송 배수·오디오 유지·필드 자원 재구성 경로를 사용한다.

상단 경계는 지형과 석화를 합치면 6색이 필요하므로 원본 석화 2조각을 OBJ로 남긴다.
아래쪽 발끝은 현재 UI와 원작 팔레트가 같고, 내용 앞의 빈 두 줄에만 공통 셀 paint를
적용한다. 창 프레임·글자·숫자·석화 도트를 자르지 않는다.

마법이 아군을 임시 BG에 고정할 때 석화와 같은 셀에 걸리는 아군 조각은 OBJ에
유지한다. 이를 무조건 BG로 합치면 실제 픽셀은 서로 겹치지 않아도 셀당 4색을 넘는다.
상주 석화의 signed 타일 읽기는 OBJ의 unsigned 타일 읽기와 구분하며, 상태 변경은
마법 합성 캐시를 무효화한다.

## 검증과 남은 범위

`node tools/verify-dungeon.mjs --stone`은 원본 맵의 자연 조우·현재 파티 입력을 사용한다.
석화 상태와 강제 공격/HP는 명시적인 진단 입력이다. 치료 아이템이나 석화 마법의
계산을 새로 만든 것이 아니다. 원작 효과 22의 표시 갱신도 진단 입력으로 호출한다.

정면/후열의 일반·개구리·소형 석화를 연결한다. 혼란으로 전진한 석화는 축소 적의
셀/보조색 OBJ와 섞이므로 아직 명시적으로 거부한다. 밀집 8적의 네 자리 숫자 32개와
석화 경계 OBJ가 동시에 필요한 최악 조합도 별도 통합 과제다. 기존 OAM/색/셀 용량
검사를 낮추거나 픽셀을 생략해서 통과시키지 않는다. 전투 전체 지원 완료로 세지 않는다.

정적 전투 RAM은 1,406바이트이며 고정 RAM 여유는 2바이트다. 다음 상태 추가는 이
여유를 넘겨 적재하지 않고 기존 단계별 작업 공간과 수명을 다시 검토해야 한다.
이 수치와 별도로 실제 실행의 스택 가드·여유와 WRAM/IRQ 전송을 검사한다.

재현 명령:

```text
node tools/build-scene-layout.mjs --dungeon
node tools/audit-live-stone.mjs
node tools/verify-dungeon.mjs --stone
node tools/verify-dungeon.mjs --death
node tools/verify-party-defeat.mjs --mixed
npm test
node tools/export-source.mjs --check
```

## 최종 결과

- 현재 카탈로그 44편성, 일반/후열 1,056배치에서 석화 본체와 원본 적 지도 충돌 없음.
  방향별 종류/열/해제 조합 8,192건에서 두 배우의 공통 셀은 최대 6개이며 세 배우가
  한 칸을 함께 쓰지 않는다. 이는 호스트 자원 검사이며 백어택 실기 검증과 구분한다.
- 같은 부팅의 자연 조우 3회, 적 사망 37그림, 생존 적 점멸 8회, 마법 27그림씩 2회,
  석화 해제→네 명 재석화→사망/석화 동시 상태 갱신 3회와 필드 복귀/이동 통과.
  석화 원본 픽셀과 두 마법의 전체 화면·복구 픽셀이 일치한다.

  오디오 지연/버퍼 부족 0, 타이머 오차 범위 0.313ms 미만. 음색 청취 승인과는 별개다.

- 일반 사망/마법 회귀: 4,032음원 틱, APU 쓰기 23,919회, 메모리 오류 0.

  2,065음원 틱, 메모리 오류/오디오 버퍼 부족 0.
