# 원작 피해·회복 숫자: 같은 전투 장면의 공급·표시·복원

최신 기준: 2026-11-24, PR 32 병합 `869d7eece81e1e0dd04438541572ff8500a9df67` 이후.
아래 PR 32 기준선과 문서 마지막의 전체 피해 해결을 구분한다.
기존 등장→상태 변화→아이템→다음 선택 장면에 숫자 표시를 연결했다.
피해 계산/HP 변경을 새로 만든 것이 아니다. 개발 입력으로 원작 표시 함수를 실행하고
같은 VRAM/OAM의 결과를 기존 GBC 전송 경로에 공급한다.

## 원작 소비자와 입력 계약

| 소비자 | 연결·검증한 책임 |
|---|---|
| `2E/9F5E..9F6B` | 원작의 36바이트 RAM 코드 복사 실행. 숫자 사인 함수의 은행 전환 코드 거주 확인 |
| `2F/B32B → BDBA` | 적의 중심/하단 좌표 초기화. 적 그림을 그리는 호출과 별개이므로 생략할 수 없음 |
| `33/AD2B` | 팔레트 `BE`, 그림 `0D` 로드, 원작 사인·진폭 변화와 32회 표시 대기 |
| `33/AD0A → ADF4` | 16비트 입력, 선행 0 생략, 0/MISS/회복/미표시의 원작 타일 변환 |
| `33/AC4B → ACAA` | 대상 슬롯별 배치, 적 8/아군 4그룹, 그룹당 4개의 8×8 원작 OBJ |
| `2F/B5B8 → AEE8 → 32/90D8 → 33/A42B` | 다음 아군 갱신 시 숫자 OAM 삭제·복원. AD2B 반환 자체가 삭제 경계는 아님 |

입력의 상위 `40` 비트는 MISS, `80` 비트는 회복이며 `FFFF`는 미표시다.
호스트 시험은 0/9/10/999/9999, MISS, 회복 56, 미표시를 실제 원작 함수와 대조한다.
모든 입력이 미표시면 32프레임 본문에 들어가지 않는다. 피해·회복량 산출, 대상 마스크를
만드는 명령/마법 호출자, 합법적인 전투 도달성은 아직 연결하지 않았다.
MISS는 의미 구분을 검증한 원작 그림이며 해당 그래픽 문구의 한글화는 남아 있다.

## 좌표와 그림 보존

아군 숫자는 해당 아군 슬롯의 원본 자세·행 좌표를 기준으로 옮긴다. 적 숫자는 원작 중심 X와
하단 Y를 해당 편성의 7/8 배치·후방 이동에 맞춰 변환한다. 숫자 글리프와 사인 이동량은 축소하지 않는다.
백어택에서도 숫자 문자열은 좌우 반전하지 않는다. 뷰포트 가장자리에서는 32픽셀 숫자 묶음을
통째로 안쪽으로 옮겨 유효 자리수를 자르지 않는 후보 규칙을 사용한다. 위쪽 경계에서는
8픽셀 글리프 묶음의 Y를 0 이상으로 제한한다. 맨 위 아군의 상승 정점에서는 원작 곡선이
경계에 머무는 차이가 있지만 글리프를 자르지 않는다. 모든 비투명 숫자 픽셀이 뷰포트에 들어가는지 검사한다.
이 좌표 정책은 이번 편성의 표시 후보이며 모든 보스·소환 위치 정책의 승인으로 일반화하지 않는다.

같은 장면에서 원작 호출 전후의 아군 OAM 96바이트를 보존하고, 숫자를 지운 뒤에는
기존 장면의 RGB555 픽셀과 OAM 해시가 복원되는지 검사한다. 원작은 사용했던 숫자 CHR와
효과 팔레트를 남겨 두므로, 미사용 CHR/팔레트까지 호출 전 바이트로 덮어쓰지 않는다.

## PR 32 기준선: 단일 대상 통과와 전체 피해 실패

GBC 진단 입력은 적 슬롯 3의 피해 1234, 아군 네 슬롯의 0/MISS/회복 56/미표시다.
정면·백어택 각각 원작 숫자 본문 32+32회와 초기 팔레트 대기·반환·삭제를 관측한다.
같은 그림의 연속 관측만 합쳐 장면은 각 113개, 총 226개다. 32프레임 실행 기록은 별도로
전부 보존한다. GBC는 요청 완료 기준으로 이 관측을 재생하므로 원작 32프레임의 실제 시간 보증은 아니다.

**PR 32에서 적 8명 모두 피해 1234인 최악 입력은 실패했다.** 기존 합성기로 정면 16상태,
백어택 18상태가 OAM/스캔라인 한도를 초과한다. 보고서는 모든 실패를 보존하며 통과한
상태만 추려 완성된 전체 피해 연출로 내보내지 않는다. 제한 회귀 시험의 통과는
이 실패가 제대로 검출된다는 뜻이지 하드웨어 예산 통과가 아니다.

로컬 탐색에서는 셀 빈도 가중 팔레트, 팔레트 교환, 원작 8개 중 잔여 OBJ 팔레트 4개 선택,
잔여 픽셀의 8×8 재배치를 시험했다. 일부 실패를 줄였으나 전체를 해결하지 못해 채택하지 않았다.
이는 GBC에서 불가능하다는 증명이 아니라 현재 합성 정책의 실패다. 원작 OAM 수 56개를
GBC 한도와 단순 비교해 결론 내리지 않고, 배경에 합성할 부분과 움직이는 숫자의 소유권을 함께 풀어야 한다.

## 후속: 숫자 계층을 분리해 전체 피해 한도 해결

문제는 모든 픽셀을 먼저 합친 뒤 8×8 배경 칸마다 남는 색을 OBJ로 만드는 정책이었다.
대표 실패 관측에는 5색 이상인 칸이 44개 있다. 칸 단위 잔여 OBJ 방식의 하한부터 40개를
넘으므로 같은 방식에서 팔레트 선택만 반복해 해결할 수 없다.

새 소비자는 같은 원작 VRAM/OAM에서 두 결과를 얻는다. 하나는 숫자를 제외한 배경·아군 픽셀,
다른 하나는 원작 순서·대상·좌표·색 인덱스를 보존한 숫자 8×8 조각이다. 배경·아군의 잔여 색은
원작 팔레트 0/1/4/7을 GBC OBJ 네 팔레트에 배정해 8개로 합성하고, 숫자 팔레트는 마지막을 쓴다.
숫자 32개를 OAM 앞에, 잔여 8개를 뒤에 놓아 원작의 가림 순서를 보존한다. 필요한 그림을
사후에 지우거나 숫자를 번갈아 표시하지 않는다. BG 팔레트 7은 계속 한글 창에 남겨 둔다.

기존 평면 합성 경로는 `layeredNumbers:false`로 회귀 시험에 남아 정면 16·백어택 18실패를
재현한다. 새 경로는 같은 226관측을 모두 합성하며 숫자 32개+잔여 8개, 줄당 최대 8개다.
모든 최종 RGB555 픽셀을 원작 입력을 기존 좌표 정책에 맞춘 기준 그림과 대조한다.
8개의 서로 다른 네 자리 피해/회복과 0/MISS/미표시 조합도 별도 원작 함수 입력으로 검사한다.
이전 지형 자르기·적 7/8 축소·후방 이동·화면 경계 보정은 그대로이며 추가 축소나 색 대체는 없다.

숫자가 움직이는 동안 배경 타일·지도와 OBJ 패턴은 변하지 않고 OAM 좌표만 달라진다.
이는 현재 원작 숫자 본문의 자산 수명에 따른 결과다. 한글 창이 VRAM 은행을 빌린 뒤에는
기존 무효화·재공급 경로가 동작하며 이 비용을 0으로 취급하지 않는다. 런타임 C·오디오·DMA 코드는
바꾸지 않고 기존 40개 OAM 제출 경로로 공급한다. 관측 수를 늘려 해결한 것도 아니다.

해결 범위는 편성 3의 원작 32프레임 숫자 본문에 대응하는 관측과 같은 장면의 삭제·복원이다.
모든 편성/상태/효과 동시 조합, 원작 시계의 자율 재생과 정상 피해 계산으로 일반화하지 않는다.
특히 전체 피해에서 OBJ 40개를 모두 쓰므로 상태 아이콘·행동 창·다른 연출을 추가할 때 같은
활성 자산 계약을 다시 검사해야 한다. 전체 통합 0/8·제품 0/3과 후순위 음질 개선은 유지한다.

## 후속: 원작 32프레임 자동 재생

기준은 PR 33 병합 `6a4136ccfcdaa69d0f76a3ae3e18ae371d01834b`다.
`33/AD2B`의 숫자 본문은 `AD59..ADA5`에서 좌표를 만들고 `F8C5`로 한 번 기다리는 일을
32회 반복한다. 그림이 같은 관측을 합쳐도 이 32개 대기는 합치지 않는다. 추출 결과에 각 관측의
원작 프레임 목록을 남기고, 누락/중복이나 움직임 중 패턴·배경·팔레트 변경은 빌드 오류로 처리한다.

기존 `build:battle-scene`의 요청 6에 정면 적/아군, 백어택 적/아군의 네 구간을 연결했다.
`scene_page=0..3`으로 구간을 선택한 뒤 요청을 한 번 보내면 ROM이 끝까지 재생한다.
검증기는 시작 요청만 보내며 중간 숫자 프레임이나 시계를 쓰지 않는다. 요청 1의 정지 관측 검사는
기존 전송/한글 창 회귀를 위해 남겨 두었다. 준비 시간과 본문 재생 시간은 별도다.

- 첫 그림의 BG/OBJ 패턴·팔레트·OAM을 준비한 뒤 첫 VBlank 진입을 시간 원점으로 잡는다.
- 이후에는 배경과 OBJ 패턴 페이지를 고정하고 `$DC00/$DD00`의 OAM 160바이트만 교대로 준비한다.
  OAM 버퍼 번호와 그림 저장 페이지를 분리해 숫자 도트의 타일 번호가 바뀌지 않도록 한다.
- 기존 4096Hz 오디오 시계에 `floor(원작 프레임 × 4096 / 60.0988)`의 절대 기한을 투영한다.
  첫 가능한 GBC VBlank에 각 프레임을 게시한다. 같은 그림인 프레임도 시간과 게시 순서를 보존한다.
- 32프레임 후에는 `B5B8 → AEE8 → 32/90D8`가 지운 기준 그림을 OAM만으로 재현한다.
  **이 즉시 인계 시점은 진단 조건이다.** AD2B 자체가 숫자를 지우는 것은 아니며 실제 행동 호출자와
  메시지 대기까지 구현한 것으로 세지 않는다. 이후 일반 장면/창 소유자는 캐시를 무효화하고 다시 공급한다.

32프레임의 원작 기준 길이는 약 532.46ms다. GBC 화면 주기가 달라 매 프레임의 시각은 VBlank에
맞춰 양자화하며 숫자를 건너뛰어 따라잡지 않는다. 준비가 늦으면 오류로 중단하므로 누락으로 숨기지 않는다.
현재는 원작 실행으로 만든 네 유한 입력의 OAM 공급 검증이다. 실시간 피해 계산, 모든 편성의 배치,
행동 창/HP/상태 아이콘과 동시 점유, 다른 연출과의 연결은 별도 통합 관문으로 남아 있다.

### 시계와 관측 경계의 수정

첫 실행은 APU 출력 순서가 맞고 큐 고갈도 없었지만, 타이머 시계가 약 31.66ms 늦어져 실패했다.
OAM DMA와 스케줄러의 장부 갱신을 연속해서 인터럽트 차단 상태로 실행한 것이 원인이었다.
DMA 직후만 타이머를 허용하는 중간 수정에서도 누적 지연이 남아, 최종 경로는 기한 계산/장부 갱신 중에도
타이머를 허용하고 DMA와 16비트 시계 스냅샷만 짧게 보호한다. DMA 중 IME가 꺼져 있는지는 실제 버스로 검사한다.
하드웨어 근거는 명세 계층인 [Pan Docs의 인터럽트](https://gbdev.io/pandocs/Interrupts.html)와
[OAM DMA](https://gbdev.io/pandocs/OAM_DMA_Transfer.html)다. 웹 접근 제한으로 같은 문서의
[GitHub 원문](https://github.com/gbdev/pandocs/blob/master/src/OAM_DMA_Transfer.md)을 확인했다.

첫 팔레트 게시만 작업량이 크므로 이를 끝낸 시각을 다음 프레임의 기준으로 삼지 않는다.
첫 VBlank 진입의 타이머 값을 기준으로 삼고, 1틱 미만의 반올림 불확실성에는 내림을 사용한다.
검증은 게시 명령 시각과 실제 표시 프레임을 구분한다. 전자는 기한·준비 완료·VBlank 내부 작업을 검사하고,
후자는 PPU의 프레임 번호로 32개 원작 대기가 연속한 32개 GBC 프레임을 차지하는지 검사한다.
첫 팔레트 처리 시간으로 실제 표시 오차가 왜곡되지 않으며 프레임 생략이나 늘어난 대기를 허용하지 않는다.

기존 에뮬레이터 관측은 상대 154줄 실행 뒤 IRQ 종료까지 더 실행했다. 이 추가 시간이 누적돼 일부
캡처가 다음 그림으로 기록되고 두 엔트리를 한꺼번에 읽었다. 숫자 검증은 매번 주사선 10에서 관측하고,
현재 OAM과 다음 관측에서 얻는 완료 화면을 PPU 프레임 번호로 짝지었다. 160바이트 OAM과 모든 픽셀을
기준과 대조하는 조건은 유지한다. 실패 원시 로그/ROM, 중간 시도와 짧은 500프레임 수정 검사는 로컬에 보존한다.

### 자동 재생 최종 검증

최종 ROM SHA-256은 `3626d4ca4123350b5ca82ac4b4b3377ef9cae98d604f759500e87c71411c875d`다.
호스트 73/73, 공개 소스 304파일의 별도 폴더 동일 ROM 재현과 관련 11/11 검사를 통과했다.
기존 마법 타임라인 ROM은 재빌드해 이전 SHA-256
`5d6d11e7d4ae344773be0362d4516fa9e2d31a5f70101b592f31ac27304e5b7d`와 같음을 확인했다.
이 동일 ROM의 기존 원시 증거(84회·588엔트리)를 다시 검사했다. 새로 실행한 증거로 세지 않는다.

고정 MesenCore의 새 실행은 총 779요청, 828장·19,077,120픽셀을 대조했다.
자동 재생은 네 구간을 세 번씩, 총 12회·396엔트리다. 처음 두 순회의 모든 엔트리를 촬영하고
264회 OAM 전체 160바이트와 실제 표시 프레임 번호를 대조했다. 정면·백어택·아군 숫자의 실제 캡처도 시각 검사했다.

| 자동 숫자 구간 | 결과 |
|---|---:|
| 원작 32프레임 / GBC 32프레임 길이 | 532.457 / 535.767ms |
| 실제 표시 간격 | 16.743ms, 32프레임 모두 연속 |
| 실제 표시 오차 최대 | 3.310ms |
| 기한 전 준비 여유 최소 | 4.395ms |
| VBlank 게시 작업 최대 | 0.737ms |
| 준비 지연 / 잘못된 OAM DMA | 0 / 0 |
| 숫자 재생 중 VRAM·지도·팔레트 쓰기 | 0 |
| OBJ / 한 줄 OBJ 최대 | 40 / 8 |

원작 오디오 7,200틱·21,366이벤트에서 지연/큐 고갈 0, APU 30,938쓰기·해시 16,366이
기준과 같고 시계 드리프트는 +0.023ms다. 655회 일반 장면 게시의 OAM/지도 불일치,
영상/DMA·활성 그림 덮어쓰기·LCD 끄기·가드 오류도 0이다. 고정 WRAM 끝은 `$CE0B`,
스택 미사용 284바이트, 기존 VRAM DMA 임계 구간 최대 162.60µs다. 음색 품질 승인은 별도다.

초기 준비를 포함한 요청 6의 중앙값/최대는 703.19/753.42ms다. 원작 본문 시간과 혼동하지 않는다.
정지 관측 변경 최대 301.37ms, 한글 창 열기 최대 502.28ms도 남아 있다. 관측 위상을 고정하고
자동 재생/창 인계를 추가한 실행이므로 PR 33 수치와 동일 입력의 순수 성능 비교를 하지 않는다.
실제 행동 호출자가 숫자 자산을 언제 선행 준비하고 언제 창을 지우는지 다음 통합에서 연결해야 한다.
전체 장면 관문 0/8·제품 관문 0/3은 유지하며 이번 통과는 숫자 본문 시계의 제한된 통과다.
