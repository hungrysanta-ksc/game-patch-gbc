# 원작 피해·회복 숫자: 같은 전투 장면의 공급·표시·복원

최신 기준: 2026-11-24, PR 32 병합 `869d7eece81e1e0dd04438541572ff8500a9df67` 이후.
아래 PR 32 기준선과 문서 마지막의 전체 피해 해결을 구분한다.
기존 등장→상태 변화→아이템→다음 선택 장면에 숫자 표시를 연결했다.
피해 계산/HP 변경을 새로 만든 것이 아니다. 개발 입력으로 원작 표시 함수를 실행하고
같은 VRAM/OAM의 결과를 기존 GBC 전송 경로에 공급한다.

## 원작 소비자와 입력 계약

| 소비자 | 연결·검증한 책임 |
|---|---|
| `2E/9F5E..9F6B` | 원작의 36바이트 RAM 코드 복사 실행. 숫자 사인 함수의 은행 전환 코드 거주 확인 |
| `2F/B32B → BDBA` | 적의 중심/하단 좌표 초기화. 적 그림을 그리는 호출과 별개이므로 생략할 수 없음 |
| `33/AD2B` | 팔레트 `BE`, 그림 `0D` 로드, 원작 사인·진폭 변화와 32회 표시 대기 |
| `33/AD0A → ADF4` | 16비트 입력, 선행 0 생략, 0/MISS/회복/미표시의 원작 타일 변환 |
| `33/AC4B → ACAA` | 대상 슬롯별 배치, 적 8/아군 4그룹, 그룹당 4개의 8×8 원작 OBJ |
| `2F/B5B8 → AEE8 → 32/90D8 → 33/A42B` | 다음 아군 갱신 시 숫자 OAM 삭제·복원. AD2B 반환 자체가 삭제 경계는 아님 |

입력의 상위 `40` 비트는 MISS, `80` 비트는 회복이며 `FFFF`는 미표시다.
호스트 시험은 0/9/10/999/9999, MISS, 회복 56, 미표시를 실제 원작 함수와 대조한다.
모든 입력이 미표시면 32프레임 본문에 들어가지 않는다. 피해·회복량 산출, 대상 마스크를
만드는 명령/마법 호출자, 합법적인 전투 도달성은 아직 연결하지 않았다.
MISS는 의미 구분을 검증한 원작 그림이며 해당 그래픽 문구의 한글화는 남아 있다.

## 좌표와 그림 보존

아군 숫자는 해당 아군 슬롯의 원본 자세·행 좌표를 기준으로 옮긴다. 적 숫자는 원작 중심 X와
하단 Y를 해당 편성의 7/8 배치·후방 이동에 맞춰 변환한다. 숫자 글리프와 사인 이동량은 축소하지 않는다.
백어택에서도 숫자 문자열은 좌우 반전하지 않는다. 뷰포트 가장자리에서는 32픽셀 숫자 묶음을
통째로 안쪽으로 옮겨 유효 자리수를 자르지 않는 후보 규칙을 사용한다. 위쪽 경계에서는
8픽셀 글리프 묶음의 Y를 0 이상으로 제한한다. 맨 위 아군의 상승 정점에서는 원작 곡선이
경계에 머무는 차이가 있지만 글리프를 자르지 않는다. 모든 비투명 숫자 픽셀이 뷰포트에 들어가는지 검사한다.
이 좌표 정책은 이번 편성의 표시 후보이며 모든 보스·소환 위치 정책의 승인으로 일반화하지 않는다.

같은 장면에서 원작 호출 전후의 아군 OAM 96바이트를 보존하고, 숫자를 지운 뒤에는
기존 장면의 RGB555 픽셀과 OAM 해시가 복원되는지 검사한다. 원작은 사용했던 숫자 CHR와
효과 팔레트를 남겨 두므로, 미사용 CHR/팔레트까지 호출 전 바이트로 덮어쓰지 않는다.

## PR 32 기준선: 단일 대상 통과와 전체 피해 실패

GBC 진단 입력은 적 슬롯 3의 피해 1234, 아군 네 슬롯의 0/MISS/회복 56/미표시다.
정면·백어택 각각 원작 숫자 본문 32+32회와 초기 팔레트 대기·반환·삭제를 관측한다.
같은 그림의 연속 관측만 합쳐 장면은 각 113개, 총 226개다. 32프레임 실행 기록은 별도로
전부 보존한다. GBC는 요청 완료 기준으로 이 관측을 재생하므로 원작 32프레임의 실제 시간 보증은 아니다.

**PR 32에서 적 8명 모두 피해 1234인 최악 입력은 실패했다.** 기존 합성기로 정면 16상태,
백어택 18상태가 OAM/스캔라인 한도를 초과한다. 보고서는 모든 실패를 보존하며 통과한
상태만 추려 완성된 전체 피해 연출로 내보내지 않는다. 제한 회귀 시험의 통과는
이 실패가 제대로 검출된다는 뜻이지 하드웨어 예산 통과가 아니다.

로컬 탐색에서는 셀 빈도 가중 팔레트, 팔레트 교환, 원작 8개 중 잔여 OBJ 팔레트 4개 선택,
잔여 픽셀의 8×8 재배치를 시험했다. 일부 실패를 줄였으나 전체를 해결하지 못해 채택하지 않았다.
이는 GBC에서 불가능하다는 증명이 아니라 현재 합성 정책의 실패다. 원작 OAM 수 56개를
GBC 한도와 단순 비교해 결론 내리지 않고, 배경에 합성할 부분과 움직이는 숫자의 소유권을 함께 풀어야 한다.

## 후속: 숫자 계층을 분리해 전체 피해 한도 해결

문제는 모든 픽셀을 먼저 합친 뒤 8×8 배경 칸마다 남는 색을 OBJ로 만드는 정책이었다.
대표 실패 관측에는 5색 이상인 칸이 44개 있다. 칸 단위 잔여 OBJ 방식의 하한부터 40개를
넘으므로 같은 방식에서 팔레트 선택만 반복해 해결할 수 없다.

새 소비자는 같은 원작 VRAM/OAM에서 두 결과를 얻는다. 하나는 숫자를 제외한 배경·아군 픽셀,
다른 하나는 원작 순서·대상·좌표·색 인덱스를 보존한 숫자 8×8 조각이다. 배경·아군의 잔여 색은
원작 팔레트 0/1/4/7을 GBC OBJ 네 팔레트에 배정해 8개로 합성하고, 숫자 팔레트는 마지막을 쓴다.
숫자 32개를 OAM 앞에, 잔여 8개를 뒤에 놓아 원작의 가림 순서를 보존한다. 필요한 그림을
사후에 지우거나 숫자를 번갈아 표시하지 않는다. BG 팔레트 7은 계속 한글 창에 남겨 둔다.

기존 평면 합성 경로는 `layeredNumbers:false`로 회귀 시험에 남아 정면 16·백어택 18실패를
재현한다. 새 경로는 같은 226관측을 모두 합성하며 숫자 32개+잔여 8개, 줄당 최대 8개다.
모든 최종 RGB555 픽셀을 원작 입력을 기존 좌표 정책에 맞춘 기준 그림과 대조한다.
8개의 서로 다른 네 자리 피해/회복과 0/MISS/미표시 조합도 별도 원작 함수 입력으로 검사한다.
이전 지형 자르기·적 7/8 축소·후방 이동·화면 경계 보정은 그대로이며 추가 축소나 색 대체는 없다.

숫자가 움직이는 동안 배경 타일·지도와 OBJ 패턴은 변하지 않고 OAM 좌표만 달라진다.
이는 현재 원작 숫자 본문의 자산 수명에 따른 결과다. 한글 창이 VRAM 은행을 빌린 뒤에는
기존 무효화·재공급 경로가 동작하며 이 비용을 0으로 취급하지 않는다. 런타임 C·오디오·DMA 코드는
바꾸지 않고 기존 40개 OAM 제출 경로로 공급한다. 관측 수를 늘려 해결한 것도 아니다.

해결 범위는 편성 3의 원작 32프레임 숫자 본문에 대응하는 관측과 같은 장면의 삭제·복원이다.
모든 편성/상태/효과 동시 조합, 원작 시계의 자율 재생과 정상 피해 계산으로 일반화하지 않는다.
특히 전체 피해에서 OBJ 40개를 모두 쓰므로 상태 아이콘·행동 창·다른 연출을 추가할 때 같은
활성 자산 계약을 다시 검사해야 한다. 전체 통합 0/8·제품 0/3과 후순위 음질 개선은 유지한다.

### 전체 피해 최종 검증

영상/오디오 실행 결과를 바꾸거나 한도를 완화하지 않았다. 원시 실패와 최종 검사 로그는 로컬에 보존한다.
