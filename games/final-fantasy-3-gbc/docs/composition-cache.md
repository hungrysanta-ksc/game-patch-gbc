# 원작 NPC 화면의 변경 타일 캐시와 VBlank 전환

기준: PR 20 병합 `44c2b9e4ecd871d4e7ff5033dcd85d508d84f770`.
R2의 [타일 합성 핵심 루틴](composition-kernel.md)을 실제 전체 화면 공급에 연결한다.
진단 입력은 기존 원작 상태 22개다. 현재 게임의 플레이어 이동·동행·카메라 실행기를 교체한 것은 아니다.

## 자산에서 실제 화면까지

원작 `B2FD/B1EE`, `ACD1`, `B17C` 소비자가 만든 NPC 초기/역순 겹침/숨김/이동/재로딩 상태를
같은 출처와 전제 조건으로 사용한다. 이벤트 81의 전투 후 조건은 전투 실행 완료를 뜻하지 않는다.
22개 표본 안에서 같은 world/map의 팔레트를 공유해, NPC 하나가 바뀔 때 전체 팔레트가 다시
배치되는 문제를 없앤다. 다른 모든 원작 상태까지 이 팔레트가 충분하다고 일반화하지 않는다.

225개 고유 셀 입력 중 OBJ가 없는 80개는 빌드 단계에서 변환한다. 나머지는 원작 BG/OBJ 인덱스와
상대 위치·가림 순서를 GBC에 공급하고 캐시 미스 때만 기존 SM83 커널을 실행한다.
완성된 동적 화면은 ROM에 넣지 않는다. 입력 ID는 이 진단의 불변 데이터 식별자이며,
실제 이동/NPC 상태에서 이 키와 입력을 만드는 생산자는 아직 연결하지 않았다.

128개 캐시 슬롯은 BG 패턴과 연결된다. 현재 화면 또는 준비 중인 화면이 사용하는 슬롯은
교체하지 않는다. 미사용 슬롯만 순환 교체하며 이전 키의 인덱스도 지운다. 핀으로 보호된 슬롯밖에
남지 않으면 명시적으로 실패한다. 각 표본과 인접 표본의 합집합은 빌드 시에도 용량을 검사한다.

변경된 셀만 새 슬롯을 찾고, 이전과 같은 입력/속성은 다시 합성하지 않는다. 두 BG 타일 지도를
번갈아 준비하고 변경 마스크가 표시한 블록만 전송한다. 잔여 OBJ 패턴과 OAM도 두 영역을 교대로
사용하며, 각 OBJ 영역에 남아 있는 그림의 키가 같으면 패턴 전송을 생략한다.
준비가 끝난 뒤 VBlank에서 OAM·팔레트·BG 지도 선택을 함께 바꾼다.
그동안 이전 화면이 참조하는 타일과 지도는 유지한다. 동일한 화면 재요청은 내용 비교 후
합성·VRAM 전송·화면 전환을 생략한다.

## 부하와 검증 경계

첫 선형 키 검색/작은 전송 반복 구현은 오디오 큐 고갈과 큰 지연을 재현하여 채택하지 않았다.
직접 인덱스와 묶음 전송으로 수정했다. 오디오 생산기는 탐색에서 이미 사용하던 두 틱 선행량의
협력적 양보를 이 진단에도 적용하며, 충분히 앞선 경우 다음 패킷 준비 전에 돌아온다.
화면 준비 중에는 개발용 스냅샷 발행을 뒤로 미룬다. 같은 행은 입력과 속성을 묶어서 비교해
셀별 처리를 건너뛰며, 잔여 OBJ가 없는 셀도 두 팔레트를 다시 검사하지 않는다.
원작 음악 이벤트·타이머 소비·음색 변환은 바꾸지 않는다. `FF3_COMPOSITION_CACHE`를 정의하지
않는 기존 빌드에는 새 조건을 적용하지 않는다.

실제 VRAM 쓰기를 별도 Lua 관측기로 검사한다. 활성 BG 슬롯, 활성 타일 지도, 활성 OBJ 패턴
영역에 쓰면 실패한다. 팔레트/VRAM/DMA 시점, LCD 유지, WRAM 은행 복원·스택 가드와
원작 기준의 실제 APU 쓰기도 함께 검사한다. 초기 상태뿐 아니라 캐시 교체 후의 두 번째 순회도
캡처하고, 원작 기대 이미지와 모든 픽셀을 대조한다. 같은 화면 재요청은 전송 0건을 요구한다.

전체 화면 전환 시간에는 입력 조회·합성·오디오 서비스·VRAM 준비·VBlank 대기가 포함된다.
맵 변경/차가운 캐시와 같은 맵 안의 변화, 완전히 같은 화면은 분리해서 해석한다.
표본의 부하 검증을 원작 프레임 속도의 정상 이동이나 실기/독립 에뮬레이터 합격으로 바꾸지 않는다.

현재 탐색/한글 창 작업 공간과 겹치므로 그대로 합쳐 사용할 수 없다. 다음 작업은 원작 플레이어·
동행·카메라 상태에서 입력/변경 영역을 생성하는 경계와 실제 작업 공간 배치다.
두 BG 지도를 쓰므로 한글 창이 열릴 때 지도 소유권 전환과 닫힌 뒤 복구도 검증해야 한다.
매 프레임 전체 셀을 검사하는 진단 호출 구조를 제품의 이동 경로로 그대로 채택하지 않는다.
이어 적 색 보존·206 외부 타일·원본 아군/큰 마법/한글 동시 예산을 마무리해야 R2를 닫는다.

## 재현

```powershell
node tools/build-composition-cache.mjs
node tools/verify-composition-cache.mjs
node tools/verify-composition-cache.mjs --idle
```

`build/composition-cache/report.json`은 출처/프레임 입력·고정 팔레트·링크 예산·해시,
`evidence/composition-cache/load.json`과 Lua 로그는 실제 페이지·VRAM·OAM·오디오·시간 관측이다.
비채택 구현의 원시 관측·보고서는 `rejected-linear/`, `full-refill-baseline/`,
`shadow-scan-baseline/`, `dirty-block-baseline/`에 로컬로 보존한다.
공개 소스만 별도 폴더에 복사하여 외부 원본 ROM과 고정 도구로 재현한다. 생성 그림·ROM·관측과
번역 파일은 공개하지 않는다. 음질 개선은 [후순위 계획](audio-backlog.md)을 유지한다.

이 ROM은 검증기가 원작 상태 ID를 요청하는 자동 진단용이다. 일반 조작으로 플레이하는
새 게임 빌드가 아니며, 기존 탐색 ROM을 대체하지 않는다. 같은 프레임 재요청의 시간에는
검증기의 프레임 단위 완료 관측 간격도 포함된다.

사양 근거: CGB 팔레트의 인덱스/자동 증가·접근 제한은 [Pan Docs 팔레트 문서](https://github.com/gbdev/pandocs/blob/master/src/Palettes.md),
VRAM/OAM 접근 가능 구간은 [접근 문서](https://github.com/gbdev/pandocs/blob/master/src/Accessing_VRAM_and_OAM.md)를 따른다.
사이트 직접 열기와 curl이 실패해 같은 문서의 GitHub 원문으로 확인했다. 실제 전송 시간과
원자적 화면 전환의 판정은 고정 Mesen 관측으로 제한한다.
