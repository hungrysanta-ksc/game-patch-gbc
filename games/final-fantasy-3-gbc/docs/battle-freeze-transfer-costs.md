# 합성·지도 준비와 복구 비용 분리

## 원작 구조와 변경 범위

원작 `33/B68D → B589`는 시전당 그래픽과 시퀀스를 적재하고,
`B6DD/B6F3`에서 대상·프레임을 순회한다. `B765..B797`은 타일 번호·속성·좌표를
갱신하며, `B7A9..B7B4 → 3F/F8C5`는 준비된 OAM을 NMI에 맞춰 게시한다.
`33/A42B`와 마지막 대기는 연출 OAM 수명을 끝낸다.

GBC의 40 OBJ/주사선 10 OBJ 제약 때문에 밀집 마법과 숫자에서는 정지한 아군을
기존 signed BG 임시 영역으로 합성하는 어댑터가 필요하다. 이번 작업은 이
어댑터의 준비·복구를 줄이며 원작의 대상·프레임·4회 대기·소리 요청 순서를
변경하지 않는다. 적 축소·아군 원본 도트·피해 숫자·한글 HP 표현도 그대로다.

## 계측 방법

`tools/profile-battle-freeze-costs.mjs`는 고정 컴파일러의 목록을 실제 링크된
기계어와 대조하고, Mesen 읽기 전용 콜백으로 비용을 배타적으로 나눈다.
DMA 명령/설정, 인터럽트 벡터→RETI, 오디오 생산, 전송 HALT 대기, VRAM STAT
폴링, 나머지 VRAM 읽기, WRAM 복사, 대기 중 디스크립터 처리, 나머지 전경
처리의 합은 각 단계의 실제 에뮬레이터 클록과 같아야 한다. STAT 폴링에는
최초 확인 비용도 포함되며 DMA 수치는 버스 전송만의 시간이 아니다.

이는 자동 첫 시전·같은 장면 재시전의 진단이다. 전곡 7,200틱 검증과
일반 전투 전체 진행을 대신하지 않는다. 합성된 장면의 수와 ROM의 주소 수를
전체 게임의 검증률로 환산하지 않는다.

## 구현

- 셀 수집은 기존 선형 목록 검색 대신 정확한 20×13 위치 조회표를 쓴다.
  기존 `text_staging` 256바이트와 아직 glyph cache 수명이 시작되지 않은
  `seen` 4바이트를 빌린다. 별도 RAM 또는 해시를 추가하지 않는다.
- 같은 준비 단계에서 정렬·단일 팔레트 가능 여부를 키의 미사용 비트에 보존한다.
  합성은 이 결과를 다시 검사하지 않고 소비한다. 완성된 키에는 기존 출력
  팔레트만 남으며, 4개를 초과한 객체가 겹치면 기존 전체 OAM 검사 경로를 쓴다.
- 지도 팔레트 검사는 같은 금지 조건 `(attribute & 7) >= 4`를 연속 바이트의
  bit 2 검사로 수행한다. 셀 배치는 unsigned 상대 위치 한 번으로 범위를 검사한다.
- 복구는 WRAM 3의 상주 백업을 직접 DMA 원본으로 사용한다. 임시 bank-1
  버퍼로 다시 복사하지 않는다. 변경 구간 목록을 한 수명으로 게시하고,
  VBlank 소비자가 다음 구간으로 이어 간다. 지도 두 은행의 실제 원본 바이트와
  변경하지 않은 구간은 그대로 보존한다.
- 일반 작업 버퍼 전송은 128바이트를 유지한다. 상주 백업 전송만 기존 ROM
  상주 자원 전송과 같은 최대 256바이트를 사용한다. 고정 ROM의 마스킹된
  leaf가 SVBK를 바꾸고 DMA가 끝나면 즉시 bank 1로 돌린다. 이 구간에는
  스택 접근·호출·인터럽트가 없다. 원래 스택과 IE/IME, VRAM 은행도 복원한다.
  호출자는 동기 완료까지 백업과 변경 목록을 소유하며 다른 소유자에게 넘기지 않는다.

128바이트 이중 버퍼 및 두 디스크립터 후보는 복사 CPU 시간을 줄여도
실제 첫 복구를 줄이지 못했다. 추적 결과 전송 구간 사이의 VBlank 경계와
오디오 보충이 절약분을 흡수했다. 개별 CPU 수치만으로 성공으로 판정하지 않는다.

같은 재사용 검사 CPU는 30.532→30.404ms로 감소했으나 오디오 보충은

범위가 다르다. 복구 성능 비교는 같은 마지막 게시→행동 완료 경계를 사용한다.

## 수명과 하드웨어 근거

상주 백업은 WRAM 3 [0,1152), 마법의 retained OBJ 백업은 WRAM 4
[1152,1408)이다. 원래 OAM 게시를 확인한 뒤에만 복구 목록을 만들며,
사용이 끝난 membership 영역에 최대 75바이트(36개 지도 구간·타일 구간·끝)를
쓴다. ISR은 목록을 읽고 256바이트 이하로 나누며, 구간 탐색은 하지 않는다.
숫자 연출은 지도만 복구하고 마법만 retained OBJ 백업도 소비한다.
고정 RAM 추가는 4바이트로 끝주소 CF9A, 남은 공간 102바이트다.
은행 51 코드는 7254→7060바이트다.

[Pan Docs VRAM DMA](https://raw.githubusercontent.com/gbdev/pandocs/master/src/VDMA.md)는
현재 선택된 WRAM/VRAM 은행이 전송 원본/목적지를 결정하고 GDMA 완료까지 CPU가
멈춘다고 설명한다. [WRAM 은행 명세](https://raw.githubusercontent.com/gbdev/pandocs/master/src/CGB_Registers.md)에
따라 bank 1 스택을 선택한 채 고정 ROM leaf에 진입하고, IE를 저장·마스킹한 뒤
은행을 전환한다. bank 1 복귀 후에만 스택에서 IE를 복원한다. 코드 바이트와
실행 중 SP·IME·은행·소스/목적지·VBlank·IRQ 진입을 각각 검증한다.

## 검증 범위

- 호스트 테스트 12개와 에뮬레이터 작업 31개 통과.
- 일반 검증 화면 1,080장, 독립 실행 14회 각각 오디오 7,200틱(합계 100,800틱).
  VRAM/OAM 접근, 원작 출력·효과음 요청, 오디오 지연·underrun, 메모리 가드 검사 통과.
- 주입 상태 13종의 화면 1,820장과 강제 재합성 비교 910프레임. 이 중 좌우 오프셋,
  4개 초과 객체 중첩, 위치 디렉터리 끝의 독립 OBJ→BG 전체 화면 비교 16쌍 통과.
  중첩 검사에서 전체 OAM fallback 셀 4개가 실제로 실행됐다.
- 초기 준비 표식 회귀 검사 140장. 지도 금지 팔레트 4·5·6·7과 셀 0·255·256·575는
  모두 기존 오류 8, 5색 셀은 오류 4, 주사선 10 OBJ 허용/11 OBJ 오류 7을 확인했다.
- PR 99와 동일한 frozen pattern 480바이트 × 2회 비교, 모든 활성/비활성 지도와
  원본 패턴 소유권 검증 통과. 수량이나 도트를 줄이는 fallback은 추가하지 않았다.
- 새 resident DMA leaf는 최대 1,172클록(8,388,608Hz에서 약 139.7µs)이다.
  전체 구간은 기존 1/4096초 오디오 IRQ 주기보다 짧으며 타이머 연속성은 별도 실행으로
  검증했다. 실제 장치 청취/음질 승인이나 소환/반사/전체 게임 검증을 대신하지 않는다.
- 허용 목록 642개로 만든 깨끗한 빌드의 산출물 12개가 검증 작업 공간과 일치한다.
  두 OAM 테스트 ROM과 자산/원작 oracle은 기준과 동일하다. 변경된 video ROM SHA-256:
  `6e5b5c5816c1eebe12a254e1d352e9b2e552b94925696e9fd2539b029c1d5f10`.

개별 원시 실행 기록은 비공개 `.local/transfer-final-*.log`, 합산 검증은
`.local/transfer-final.json`, 처리 분리는 `.local/transfer-spans-summary.json`과
`.local/transfer-final-baseline-cost-summary.json`에 보존한다. ROM/번역/추출물/
스크린샷/로그는 배포 허용 목록에 넣지 않는다.

새 경계 검증과 처리 계측은 다음 순서로 재현한다(기존 `local.json` 및 고정 도구 필요).

```powershell
node tools/build-battle-party-oam.mjs --effects
node tools/verify-battle-magic.mjs --repeat --skip-build
node tools/verify-battle-magic.mjs --auto --repeat --skip-build
node tools/profile-battle-freeze-costs.mjs
node tools/verify-battle-freeze-reuse.mjs overlap
node tools/verify-battle-freeze-reuse.mjs directory-tail
node tools/verify-battle-freeze-map-limit.mjs
```

전체 31개 작업에는 기존 일반/반복/자동/백어택·상태/반전 마법 10종, 무기·피해·숫자
4종, 재사용 주입 13종, grid/color/map 한계와 early-ready 회귀 검증이 포함된다.
R2 0/8·제품 0/3은 그대로다.
