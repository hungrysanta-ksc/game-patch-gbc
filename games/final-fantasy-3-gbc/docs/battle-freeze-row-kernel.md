# 최초 합성 행과 지도 셀 배치 비용

## 원작 구조와 변경 범위

기준은 PR 101 병합 `7b8387261950c7a072121404e3254e1edfdd497c`다.
원작 `33/B68D → B589`가 그래픽·시퀀스를 준비하고, `B6DD/B6F3 → B711`,
`B765..B797`이 상주 패턴의 타일·속성·좌표를 대상별로 소비한다.
`B7A9..B7B4 → 3F/F8C5`의 OAM 게시/네 번 대기와 `33/A42B`의 해제 순서를
유지한다. GBC OBJ 한도 때문에 정지 아군을 정확히 합성하는 어댑터는 필요하지만,
원본 인덱스와 자원 수명을 유지하며 매번 RGB로 확장하지 않는다.

- 검은 배경·동일 팔레트·X 정렬·무반전의 기존 경로에 40바이트 SM83 행 루프를
  적용한다. 2bpp 색 0은 투명, 나머지 도트는 그대로다. 먼저 나온 OBJ의 우선순위,
  위/아래 잘린 행과 원본 패턴을 보존한다. 반전·혼색·X 비정렬은 기존 경로다.
  두 포인터의 소유자는 합성 함수 하나이며 ISR에서 접근하지 않는다. 은행,
  VRAM, IE/IME와 오디오 서비스 호출 간격을 바꾸지 않는다. BC를 보존한다.
- 지도 키의 기존 비트 구성을 직접 소비한다. 낮은 바이트는 256바이트 조각 안의
  위치, 높은 바이트의 하위 2비트는 지도 페이지, 나머지는 출력 팔레트다.
  매 셀의 16비트 차감/범위 검사를 없앤다. 256/256/64바이트 조각과 마지막
  64바이트 경계, 활성/비활성 지도 보존 및 실제 전송 바이트는 그대로다.
- 캐시 유효 조건과 준비된 미러/패턴/팔레트 전송 목록은 PR 101 그대로다.
  미지원 색이나 OBJ 한도를 성공으로 넘기거나 숫자·원본 도트를 생략하지 않는다.

## 비용과 한계

원시 함수 진단은 은행 51 진입 라벨별로 비오디오·비IRQ 시간을 분류했다.
라이브러리/호출 스텁 시간은 마지막 라벨에 포함되므로 순수 leaf 함수 시간이라고
부르지 않는다. 지도 배치의 두 시전 합계는 31.611→10.745ms, 일반 행 합성은
호출부 포함 13.928→6.787ms다. 공개 재현 도구의 배타적 단계 계측과 전체 시간을
함께 판단한다. 계측 콜백은 읽기 전용이며 컴파일 기계어와 ROM을 대조한다.

소환/반사/특수 마법과 정상 전투 통합은 미완료이며 R2 0/8·제품 0/3은 그대로다.
다음은 남은 최초 합성의 타일 조회/변환과 지도·복구의 오디오/전송 위상이다.

후자는 기존 전체 대상 진단이며 소환/모든 마법의 속도를 보장하는 수치는 아니다.

고정 RAM 끝은 CF9C→CFA0(4바이트 증가, 96바이트 여유), 은행 51 코드는
7059→7037바이트다. video ROM SHA-256은
`3fd76a0a28bf5c9f6166440bd66f30629919bba371d9e95f1bc6e93d35a240f9`다.

## 검증과 재현

최종 video ROM에서 호스트 테스트 12개와 에뮬레이터 41종이 통과했다.
일반 화면 1,080장과 14회 × 7,200틱 = 100,800틱의 완전한 음악/효과음 일정을
원작 참조와 대조했다. 오디오 지연/부족, VRAM/OAM, 은행/가드/전송 오류는 0이다.
의존성·지도·좌표·중첩·세로 경계 주입 23종은 3,220장과 강제 재합성
1,610프레임이 일치했다. 독립 OBJ→BG 전체 화면 44쌍과 early-ready 140장도 같다.
반복 시전과 첫 세로 경계는 동일 최종 ROM으로 먼저 끝낸 결과를 재사용했다.

일반/반복과 세로 경계에서 실제 행 커널 1,592회·6,340행을 확인했다.
길이 1..8의 마스크는 255, 입력 색 0..3은 15로 모든 분기를 포함한다.
합성 업로드 19회·38청크·9,120바이트와 미러/팔레트는 원본 WRAM 및 실제
VRAM과 일치했다. 복구 포함 resident DMA 131청크는 최대 1,172클록이며
SP·IME·IE·은행·VBlank 계약을 유지했다. 기존 주사선 10/11, 5색, 지도 팔레트
4..7의 거부 경계도 통과했다. 기준 frozen pattern 480바이트 × 2회가 같다.

허용 소스 645개를 새 디렉터리에 복사한 빌드가 산출물 12개를 재현했다.
기존 두 OAM ROM과 추출 자산은 변하지 않았다. 고정 Mesen 코어 SHA-256은
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.
집계는 비공개 `.local/row-final.json`, `.local/row-extra.json`, 전체 실행 상태와
원시 로그는 `.local/row-final-batch-status.json`, `.local/row-final-*.log`에 보존한다.
이는 실기 청취/음질 승인이나 소환·전편 검증을 뜻하지 않는다.

연결된 행 루프의 실제 바이트·포인터 로드를 확인하고 매 호출의 전체 16바이트를
독립적인 픽셀 색 계산과 비교한다. 입력 원본, BC/SP, IE/IME, bank 1도 검사한다.
세로 좌표를 1..7px 바꾼 경계는 캐시 시도와 강제 재합성을 쌍으로 실행하고,
합성 전 OBJ 화면과 합성 후 BG 화면도 독립 렌더러로 비교한다.

```powershell
node tools/build-battle-party-oam.mjs --effects
node tools/verify-battle-magic.mjs --repeat
node tools/verify-battle-magic.mjs --auto --repeat --skip-build
node tools/verify-battle-freeze-reuse.mjs row-offset-1
node tools/verify-battle-freeze-reuse.mjs row-offset-7
node tools/profile-battle-freeze-costs.mjs --settle-frames 2
```

비용 계측은 정상 음악/효과음 검증을 대신하지 않는다. 전체 오디오 일정, 각 실제
화면과 원작 그림, 지도/패턴 복구, 기존 색·주사선·지도 경계는 별도로 검증한다.
위상 비교는 `--settle-frames 1/3`, 기준 소스/ROM은 `--source-root`, `--video`로
지정한다. 빌드/원시 로그와 입력·번역·ROM·캡처는 비공개로 보존한다.
