# 원작 맨손·클로 연출의 실제 화면 연결

기준은 PR 84 병합 `d2a4cf3158c3bb389e0f536a45f88ea8bc53ec38`이다.
맨손(kind 0)과 클로 5종(ID 1..5, kind 9)을 기존 상주 화면에 연결한다.
장비 적합성·피해 계산·정상 선택을 포함한 게임 통합 승인은 별도다.
상태 이상·치명타·아군 피격·활/화살·투척·마법·사망은 미지원 경계를 유지한다.

## 원작 실행 구조

- `2F/B24F..B258`: 전진, 직업 그림 `A9CF`, 양손 자원/속성 `A8EA`,
  공통 무기 연출 `AEF0`; `B25B → B38B`에서 복귀한다.
- `33/A0C0..A119`: 일반 양손은 오른손→왼손, 하프 혼합은 오른손 명중을 왼손에
  복사한 뒤 각 손의 상한을 적용한다. `A2F2..A2FA`의 맨손 경로는 상대 손에 무기가
  있으면 아무 그림 없이 반환한다. **양손 모두 kind 0일 때는 두 손 모두 연출한다.**
- `33/A094..A0BD`: kind를 `A077,Y`에 사용한다. 주석의 9바이트 표 다음은
  점프 표 `A080`의 `$F2`다. kind 9는 실제로 이를 읽어 최대 241회를 허용한다.
  맨손 6회, 검/봉/하프 4회와 구분하고 임의의 공통 상한을 만들지 않는다.
  이 경계 동작은 정상 게임에서 241명중이 발생한다는 주장이 아니다.
- `33/A2FB → A11C`: 반복 수·현재 손 타격 팔레트·자세를 준비하고 독립 아군 OAM을
  초기화한다. `A303..A308`에서 매 8프레임 반복마다 `$8A` 효과음을 한 번 요청한다.
- `A30B..A34D`: scratch 초기화 → actor pose(오른손 5/왼손 6) → RNG 0 두 바이트의
  `&1`로 주먹 x/y 떨림 → frame 4/13 → 명중 시 hit kind 2 순서다.
  주먹은 `32/9374..937C`에서 **아군 팔레트/override**를 쓰며, 타격은 팔레트 3이다.
- `32/98D1 → 98E8`: 짝수 프레임에 대상점 RNG 2회, 홀수는 같은 점을 유지한다.
  모양은 frame 18/19다. 매 프레임의 주먹 RNG 두 번이 그보다 먼저 소비된다.
  빗나감도 주먹 RNG를 소비하며, 0명중은 8프레임을 한 번 재생한다.
- `A350`에서 VBlank, `A353..A360`에서 8프레임 반복을 진행하고
  `A362 → AC35/AC3A`가 효과음 `$FF` 요청·자세·scratch를 복구한다.

## GBC 구조와 검증 경계

기존 직업·양손 타일 상주, actor OAM, 공유 RNG 커서, VBlank 게시 및 복구를 재사용한다.
주먹/타격의 원본 크기·도트를 보존하고 타격점만 기존 적 7:8 좌표 투영을 적용한다.
완성 OAM 프레임을 ROM에 추가하지 않는다. 난수가 매번 달라지므로 맨손/클로에는
입력 pose/weapon만 같은지 보는 기존 그림 재사용 조건을 적용하지 않는다.
검/봉/하프의 같은 그림 재게시 경로는 유지한다.

상한 10바이트는 원본에서 추출해 링크 후 확인한다. 주먹 떨림과 타격 종류 2는
실제 6502 소비자와 컴파일된 GBC 코드로 비교한다. 원작 `B24F` 전체 실행에서
`33/A350` 직전의 OAM·아군 상태·타일·팔레트와 효과음 요청을 수집하며, GBC 투영은
별도 검사한다. 주입 입력은 연출 호출 경계의 진단이며 정상 플레이로 세지 않는다.

```powershell
node tools/build-battle-party-oam.mjs --effects
node tools/build-battle-motion-sprites.mjs
node tools/verify-battle-select.mjs --motion-sprites
node tools/verify-battle-select.mjs --motion-sprites --negative
node tools/verify-battle-strike.mjs --claw --skip-build
node tools/verify-battle-strike.mjs --claw --back --skip-build
node tools/verify-battle-strike.mjs --claw --positions --skip-build
node tools/verify-battle-strike.mjs --claw --numbers --skip-build
node tools/verify-battle-strike.mjs --claw --auto --skip-build
node tools/verify-battle-strike.mjs --claw --auto --ceiling --skip-build
```

`--ceiling`은 한 손 255 입력의 241회 반복을 관측 게이트 없이 실행한다.
장시간 진단의 로그 한도 때문에 프레임별 비용 로그는 수집하지 않으며, 완료 프레임 수,
명중 상한, 공유 RNG 최종 상태, 전체 효과음 요청 순서 및 7,200틱 오디오를 검사한다.
일반 `--auto`는 프레임별 실제 DMA와 90ms 최대 간격 회귀 검사를 그대로 유지한다.
원작 241회 비교 실행은 5,413,491개 명령이 필요했다. 이 진단에만 기존 원작 실행기의
6,000,000명령 예산을 선택하며 일반 검사의 3,000,000명령 예산은 바꾸지 않는다.

## 최종 검증

최종 ROM SHA-256은 `cb05dc2e1714691880d7c02d4d1aa048b8844cd3f1ed308c089f7ca2fd021294`다.
모든 아래 화면/오디오 검사는 이 ROM 하나에서 실행했다.

| 검사 | 결과 |
|---|---|
| 맨손/클로 정면·백어택 | 각 9조건·601장 |
| 아군 4명·적 8칸 대상 위치 | 16조건·680장 |
| 맨손→9999 숫자 연결 | 2조건·134장 |
| 기존 검·봉·하프·공통 숫자 회귀 | 4,372장 |
| 전체 화면 대조 | 6,388장; 원작 OAM·타일·팔레트와 GBC 투영/픽셀 일치 |
| 원작 음악·동적 효과음 | 18회 각각 7,200틱, 총 129,600틱; 소비/변환 해시 일치 |
| 안전 검사 | 오디오 부족·지연 및 잘못된 VRAM/OAM 접근 0 |
| 컴파일된 스프라이트·난수 소비자 | 2,560조건 통과, 오류 주입 ROM은 첫 잘못된 바이트 검출 |
| 호스트 검사 | 12개 통과; 원작 명중 상한 2,560입력과 전체 타격점 범위 포함 |
| 소스 전용 재빌드 | 공개 허용 594파일에서 ROM/보고서 등 9산출물 바이트 일치 |

일반 최대 맨손은 96본체+19이동/정리 = 115게시·14사운드 요청을 유지했다.
별도 클로 상한 진단은 1,928본체+18이동/정리 = 1,946게시·242사운드 요청,
최종 명중 `[241,0]`, RNG 카운터 `[151,23,197]`이 원작과 일치했다.
이 장시간 진단은 전체 프레임 캡처로 세지 않는다. 모든 도트의 비교는 일반 조건의
프레임 대조와 개별 생성기의 원작 비교에 근거한다.

| 자동 실행 | 전체 행동 ms | 최초→최종 실제 DMA ms | 최대 DMA 간격 ms |
|---|---:|---:|---:|
| 맨손 양손 최대 | 3098.483 | 3013.688 | 83.955 |
| 기존 검 | 2110.178 | 2025.867 | 83.956 |
| 기존 봉 | 2110.180 | 2025.866 | 83.956 |
| 기존 하프 | 3282.701 | 3197.889 | 83.955 |

검/봉은 약 2.110초를 유지한다. 하프는 PR 84의 3249.265ms보다 **33.436ms 증가**했다.
현재 기능 확장으로 인한 총 비용 증가를 기록하며, 모든 경로가 빨라졌다고 주장하지 않는다.
최대 실제 DMA 간격은 모두 기존 90ms 회귀 기준을 통과했다. 하프 전체 비용 증가와
첫 칼질 약 84ms 간격은 후속 소비자 통합 때 함께 추적한다. 원작 속도 달성·음질 승인은 별도다.

bank 52 코드 크기 `0xA60`(2,656바이트), bank 55 `0xFC5`(4,037바이트),
고정 WRAM 끝 `0xCEF8`로 264바이트 여유를 유지한다. 원작 상한 10바이트 외에
완성 프레임 자산이나 고정 RAM 버퍼를 추가하지 않았다.
로컬 `mesen-strike-GnY58k/Screenshots/ff3-battle-effects-video_065.png`는 최종 ROM의
맨손 타격 장면으로, 아군 원형과 적 위치에 맞춘 타격점·하단 HP 창을 시각 확인했다.
R2 0/8·제품 0/3은 유지한다.
