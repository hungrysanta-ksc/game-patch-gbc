# 첫 마법의 색 대응과 지도·패턴 전송 묶음

## 원작 호출자와 변경 이유

원작 `2F/B15E`는 적 시전이면 `AF14`를 바로 호출하고, 아군이면 `B38E` 이동과
`A9CF` 그래픽 적재 뒤 호출한다. `33/BAFD..BB15`는 마법 종류를 디스패치한다.
일반 명중의 `B68D/B589`는 그래픽 07/08과 시퀀스를 행동당 한 번 적재하며,
`B6DD/B6F3`는 대상 커서, `B765..B797`은 36셀의 타일·속성·좌표를 갱신한다.
종료의 `BB0F/A42B`는 연출 OAM을 정리하고 `BB12/F8C5`가 기다린다. 이후
`2F/B175`가 숫자 그래픽 06으로 넘긴다. 배경 전체를 재합성/복구하는 경로가 아니다.

GBC에서는 현재의 40 OBJ·주사선 10개 한도 대응 때문에 정지 아군 일부를 BG로
빌리는 어댑터가 필요하다. PR 97은 그 합성 결과를 재사용했지만 첫 기록 비용으로
첫 시전이 2,026.470→2,093.463ms로 늘었다. 이번에는 그 첫 경로의 반복 색 검색과
전송 완료 대기를 줄인다. 원작 타일 선택·대기·음악/효과음 요청은 그대로다.

## 실제 구현과 자원 수명

혼합 셀의 최종 RGB를 만든 뒤 64픽셀 각각에 대해 같은 팔레트를 다시 찾던 코드를
바꿨다. 사용된 RGB를 최대 네 개로 모으고, 각 색에 대해 한 번만 대응 인덱스를
찾는다. 기존과 같은 첫 일치 팔레트·첫 색 인덱스·색 등장 순서를 유지한다.
네 색으로 표현할 수 없는 셀은 오류 4로 거부하며 근사하거나 픽셀을 버리지 않는다.

소비가 끝난 16비트 RGB 영역의 앞부분에 8비트 색 인덱스를 압축하고, 마지막 원본 글리프
임시 공간을 색 목록/대응표로 사용한다. 실제 글리프 캐시와 원본 패턴 기록은
덮지 않는다. 새 고정 RAM이나 WRAM 뱅크는 추가하지 않는다.

지도 비교는 128→256바이트 단위로 묶는다. 합성 이후 더 쓰지 않는 멤버십 영역을
현재 비활성 지도 256바이트의 임시 보관소로 쓴다. 활성 지도와 오버레이를 실제
비활성 지도와 비교하고, 변경 범위의 원래 바이트를 WRAM3에 저장한다. 이전
시전의 지도 백업을 재사용하지 않는다. 합성 패턴의 게시 요청도 256바이트로 묶는다.

**하드웨어 DMA의 128바이트 제한과 VBlank 시작/종료 검사는 변경하지 않았다.**
기존 전송기가 같은 VBlank의 남은 여유를 사용하게 하며, 대기 중 오디오 보충과
전송 사이 타이머 IRQ는 유지한다. 복구 알고리즘은 준비 때 기록한 변경 블록 집합을 사용하되
더 연속적인 범위를 한꺼번에 돌려놓는다. 지도 준비·게시·복구의 전체 비용을
함께 측정한다. 대표 장면의 지도 백업은 704→752바이트로 조금 늘었다. 짧은
변경 없는 틈도 함께 보내 완료 대기를 줄인 것이며, 전송 바이트 수 감소로
오해하지 않는다. 보이지 않는 열과 두 지도 페이지의 원래 값도 정확히 복구한다.

## 측정

기준은 PR 97 병합 `0e955667b817339a4474d3ee5853d10703de77b6`, 동일 장면에서
원작 마법 29를 두 번 시전한 35게시/행동이다. 아래는 실제 GBC DMA/행동 시간이다.

| 구간 | PR 97 | 이번 변경 |
|---|---:|---:|
| 첫 시전 전체 | 2,093.463ms | 1,959.527ms |
| 재시전 전체 | 1,540.944ms | 1,423.890ms |
| 첫 시전 최대 게시 간격 | 1,104.780ms | 1,021.067ms |
| 재시전 최대 게시 간격 | 585.978ms | 519.026ms |
| 첫 합성/기록 | 419.405ms | 400.055ms |
| 첫 지도 준비 | 247.622ms | 228.113ms |
| 재시전 지도 준비 | 212.630ms | 176.741ms |
| 첫 합성 패턴/팔레트 게시 | 99.383ms | 66.420ms |
| 재시전 마지막 게시 이후 복구 | 285.288ms | 218.096ms |

첫 시전은 PR 97 대비 6.4%, 재시전은 7.6% 감소했다. 캐시 기록을 추가하기 전
PR 96의 첫 시전 2,026.470ms보다도 빨라졌다. 두 시전 합계는
3,634.408→3,383.418ms다. 동결 단계 전체는 첫 971.409→885.786ms,
재사용 452.194→396.557ms다. 이 세부 시간에는 내부 오디오 보충과 대기가
포함되며 순수 CPU 시간으로 표시하지 않는다. 초기 이후 최대 게시 간격은
약 33.5ms로 유지됐다. 첫 준비와 재시전 모두 초기 0.5초 기준에는 아직 못 미친다.

다른 첫 시전도 최대 30쌍 마법 2,126.941→1,993.012ms, 아군 네 명 대상
3,919.173→3,768.544ms로 줄었다. 대표 첫 시전의 마지막 게시 이후 복구는
283.626→238.704ms다. 위 표의 218.096ms는 같은 장면의 두 번째 시전 수치다.

고정 RAM 끝은 `$CF96`으로 유지되고 코드 bank 51만 6,961→7,182바이트로
221바이트 늘었다. 대표 첫 시전·재시전의 실제 합성 패턴 30셀(480바이트)은
PR 97의 실제 VRAM 결과와 바이트 단위로 같았다.

최종 검증 ROM SHA-256:
`cdb938cbeae089448b3070ee5f904873254bb1af944257a9c37db4a5b982f77e`.

## 검증과 재현

기존 [동결 재사용 검증](battle-freeze-reuse.md)의 원작 OAM·전체 픽셀·모든 숫자·
지도/팔레트 복구·음악/효과음 소비 해시 비교를 유지한다. 새 지도 검사는 다음과 같다.

```text
node tools/verify-battle-freeze-reuse.mjs inactive-ui
node tools/verify-battle-freeze-reuse.mjs active-ui
node tools/verify-battle-freeze-colors.mjs
```

앞의 두 검사는 화면에 보이는 UI 구역의 비활성/활성 지도 값을 각각 바꾼다.
같은 합성 결과를 재사용하면서도 바뀐 현재 화면과 복구 데이터가 보존되는지,
강제 재합성과 매 프레임 비교한다. 마지막 검사는 지형과 아군이 겹치는 셀을
의도적으로 5색으로 만든다. 원래 OBJ+BG 표시의 RGB를 독립적으로 세어 5색임을
확인하고, 새 ROM과 PR 97 ROM 모두 오류 4로 거부함을 확인한다. 이는 RAM 개입과
부분 오디오 검사이며 정상 플레이나 완전한 오디오 일정의 증거와 분리한다.

최종 25개 실행 작업과 호스트 테스트 11개가 통과했다. 정상 시나리오의 실제
화면 1,080장과 완전한 오디오 일정 14회(각 7,200틱, 총 100,800틱)를 검증했다.
원작 OAM/픽셀·숫자 비교, 음악/효과음 소비 해시, 전송 및 오디오 부족 검사는
모두 통과했다. 별도 8종 RAM 개입 검사는 1,120장/560쌍을 비교했고, 초기 완료
마커 회귀 검사는 별도 140장을 확인했다. 주사선 검사는 171그림/24,624줄이며
10 OBJ 허용·11 OBJ 거부 경계도 유지됐다.

공개 허용 소스 637개만 옮긴 깨끗한 디렉터리에서 빌드한 ROM 3개를 포함한
12개 산출물은 작업 디렉터리의 결과와 바이트 단위로 같았다. 에뮬레이터 코어는
기존 Mesen SHA-256
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.
ROM·번역·원작 추출 데이터와 캡처/실행 로그는 로컬에만 보관한다.

## 남은 작업

원작의 타일/팔레트 인덱스 갱신에 비해 최초 혼합 셀 합성과 실제 지도 보존의
어댑터 비용이 여전히 크다. 다음은 이 약 400ms 합성·228ms 지도 준비와 실제
원본 자원의 갱신 소유권을 비교하고, 변경된 범위만 처리하거나 중간 복사를 줄이는
대안을 전체 시간·메모리·IRQ 공존으로 평가한다. 재사용 조건을 느슨하게 만들거나
백업을 오래된 것으로 바꾸지 않는다. 소환/특수 마법은 별도 자원 경로이며 이번
일반 마법 수치로 성능을 보증하지 않는다. 아군 시전/발사·적 대상·반사·정상 계산/
메뉴 통합은 남고, R2 0/8·제품 0/3을 유지한다.
