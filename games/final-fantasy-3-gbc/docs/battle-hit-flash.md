# 원작 적 점멸·아군 피격·감싸기의 실제 화면 연결

## 원작 기준과 수명

`34/8613..8644`의 적→아군 물리 공격은 `8545`의 공격자 점멸 뒤 대상별
`2F/B201`을 호출한다. `2F/B024`는 플레어 웨이브(마법 9)에서 점멸을 생략한다.
그 외에는 `A738`의 선택된 적 속성 셀과 `A6B1`의 정상 속성을 번갈아 `AF34`로
게시하여 8회 기다린다. 전역 색상을 바꾸어 다른 적까지 점멸시키지 않는다.

`B201`은 명중 여부와 무관하게 `A9B1`으로 직업별 피격 그림 96바이트를
원작 PPU `1390..13EF`에 읽는다. 이 공유 그림은 반환 후에도 남는다.
감싸기 `7EDF/7EE0`이 있으면 감싸는 캐릭터를 보호 대상의 X−24/Y에 임시 배치하고
`B5B8`으로 네 명을 순서대로 갱신한다. 피격 후 원래 위치로 복귀하고 다시 갱신한다.

`B23C`는 `BB|BC`가 0이면 몸 흔들림을 생략한다. 명중 시 `33/A8B8`은
CB=0에서 X+8·SFX B0, CB≠0에서 X+16·SFX C6를 사용한다. 보통 피격 자세 4,
개구리/미니는 15이며 2회 대기 뒤 1px 왕복을 네 번 반복하고 원래 위치/자세로
복귀하여 2회 더 기다린다. 총 20회다. 효과음은 처음 한 번이고 임의 정지 요청을
추가하지 않는다. 명중 숫자 크기로 흔들림 횟수를 늘리지 않는다.

## GBC 구조

공통 애니메이션 호출자 owner 31/20을 별도 실행기에 연결한다. 현재 그림의 2회 대기는
같은 OAM을 다시 게시하며, 도트나 원작 대기를 제거하지 않는다. 파티 원본 상태와
화면 좌표 변환을 구분하고, 커버의 Y 압축은 보호 대상 행을 기준으로 한다.
가장자리의 피격은 전체 그림과 1px 흔들림이 들어오도록 고정 X 보정만 적용한다.
백어택의 원작 unsigned 좌표 래핑을 해석하고 그림 일부를 잘라내지 않는다.

축소된 적의 원작 16px 팔레트 경계는 GBC 8px 셀에 항상 맞지 않는다. 전역 팔레트
교환은 이웃 적을 바꾸므로 사용하지 않는다. 원작 속성 변경을 자원 컴파일 시 그대로
실행하여 필요한 셀 무늬를 기존 상주 무늬와 중복 제거한다. 검증 편성은 130→151타일,
추가 336바이트이며 각 적의 지도 704바이트와 잔여 색상 OBJ/원작 속성을 별도 ROM에
둔다. 시간별 완성 프레임 저장이 아니라 선택 마스크별 공간 자원이다.

실행 중 선택된 지도는 반대 BG 페이지에 한 번 전송하고 원작 8회는 페이지 교환한다.
양쪽 페이지의 UI와 지형 접두부 소유권을 유지한다. 종료 후 정상 페이지를 선택하고
변경된 페이지 캐시를 무효화한다. 숫자의 signed-BG 소유 기간에는 실행을 거절한다.
전체 OAM 40개/한 줄 10개를 검사하며 공통 VBlank·오디오 공급 경로를 유지한다.

## 범위와 미지원 경계

현재 원작 자원에서 구성하는 네 프로필(정면/백어택, 정상/상태 혼합)에 연결했다.
단일 공격자의 팔레트 3 점멸, 정상 및 허용 상태의 피격, 정상 네 명 사이의 감싸기가 범위다. 자기 자신을 감싸는 입력은 거절한다.
감싸기는 원작 그래픽 캐시 적중·정상 자세 2를 전제로 네 번씩 게시한다. 상태를 가진
감싸기와 그래픽 재로드, 혼란·석화·사망 피격, 복수 점멸 마스크, 스크롤 중 점멸은
명시적 미지원이다. 이 경계는 일반 전투 완료로 세지 않는다.

## 검증

`tests/battle-hit.test.mjs`는 양 방향의 적 8자리 전체 픽셀을 원작 PPU 관측과 대조하고
22개 직업의 피격 공유 그림을 확인한다. `tools/verify-battle-hit.mjs`는 원작 B041,
A923, B5E3 관측과 GBC의 매 게시 상태·원본 OAM·실제 OAM·VRAM·스크린샷을 대조한다.
피해 숫자, 회피, 플레어 웨이브, 정면/백어택과 자동 재생을 별도 조건으로 검증한다.
동적 효과음 요청을 원작 오디오 기준기에 다시 입력하여 7,200틱의 NES/GB 출력 해시,
오디오 큐·가드 및 잘못된 VRAM/OAM 접근을 검사한다. 실기/청취 승인을 뜻하지 않는다.
## 재현 명령과 메모리 경계

```text
node tools/build-battle-party-oam.mjs --effects
node --test tests/battle-hit.test.mjs tests/battle-animation.test.mjs tests/battle-resident-bg.test.mjs tests/battle-party-oam.test.mjs
node tools/verify-battle-hit.mjs --all --part 0
node tools/verify-battle-hit.mjs --all --part 1
node tools/verify-battle-hit.mjs --all --back --part 0
node tools/verify-battle-hit.mjs --all --back --part 1
node tools/verify-battle-hit.mjs --cover
node tools/verify-battle-hit.mjs --status
node tools/verify-battle-hit.mjs --miss
node tools/verify-battle-hit.mjs --numbers
```

각 장면 묶음을 `--back`으로도 검사한다. `--auto`는 묶음의 마지막 조건을 원작
대기마다 자동 게시하고 준비 완료·DMA·복귀 시각을 별도로 기록한다. 재사용은 같은
ROM 해시의 기존 관측에 한정한다. 원본 ROM·추출 데이터·스크린샷·오디오는 비공개다.

은행 63 실행기/서술자는 2,729바이트다. 자원 은행 59는 8,832바이트(직업 22개 포함),
60..62는 각 6,720바이트이며 16KiB 경계를 넘지 않는다. 고정 WRAM 끝은 CF3C로
D000까지 196바이트가 남는다. 별도 대형 프레임 버퍼를 추가하지 않고 기존 독점
애니메이션 작업 영역과 이중 OAM을 사용한다. 모든 편성에 이 자원 크기를 일반화하지 않는다.

백어택 후열의 원작 네 자리 피해 숫자는 V6에서 첫 글자가 X=−2가 된다.
원본 숫자 OAM·글리프·32회 재생은 유지하고 보이는 숫자 묶음 전체를 2px 안쪽으로
옮긴다. 다른 자리수도 실제 표시 글리프의 경계로 계산하며 숫자 축소/생략은 없다.
정면/백어택 각각 29조건을 15/14조건의 두 연속 묶음으로 실행하여 각 조건의 임시 위치/자세 복귀와 피격 공유 그림의 잔류도 확인한다. 각 조건 시작 시 프로필은 다시 적재하므로, 자원을 재적재하지 않는 연속 정상 전투 검증과는 구분한다.
## 비용과 남은 개선

자동 재생은 첫/마지막 표시 간격과 전체 호출 시간을 구분한다. 첫 게시에는 지도 준비,
오디오 공급과 IRQ가 포함된다. 일반 피격의 첫 게시 비용은 약 101.858ms이며 준비
50.375ms, 오디오 41.532ms, IRQ 9.660ms, 게시 대기 0.291ms로 나뉜다.
피격 전환(9번째 게시)이 이후 최대 간격이다. 이 결과를 원작 속도 합격으로 세지 않는다.

원작의 64바이트 속성 갱신보다 GBC의 반대 페이지 704바이트 준비는 크다. 현재는
점멸마다 합성/전송하지 않고 첫 준비 후 8회 교환하여 반복 비용을 줄였다. 후속에서는
정상 지도 페이지의 유효성을 보장한 상태에서 바뀐 셀만 전송하는 방법과 전투 진입 때
미리 준비하는 방법을 비교한다. 변경 셀 수·첫 지연·오디오 비용·페이지 복구 비용을
함께 측정해야 하며, 원작보다 효율적이라고 단정하지 않는다. 테스트 프로필 간 동일
공간 자원 중복도 제품 빌더의 편성 일반화 때 정리할 대상이다.

29조건을 한 번에 묶은 초기 시험은 고정 7,200틱 구간을 넘었다. 이후 효과음 요청이
시험 재생을 일반 재생으로 다시 시작하여 완료 대기가 끝나지 않았다. 이 관측은 합격
집계에서 제외한다. 검증 호스트는 이제 틱 감소/시험 종료 뒤 다음 조건 시작을 명시적으로
거절하며, 전체 조건은 두 묶음으로 나눠 각각 7,200틱을 끝까지 검증한다. 시험 길이를
늘리거나 종료 검사를 생략하여 실패를 숨기지 않는다.

## 최종 결과

최종 ROM에서 2,078개 화면(새 피격/점멸 1,880 + 공통 198), 11회 각각 7,200틱
오디오(총 79,200틱), 호스트 10검사가 통과했다. 공개 소스 606개를 별도 폴더에서
빌드하여 ROM·자원 보고서 등 10개 산출물이 일치했다. 일반 피격 0.838초, 백어택
감싸기 1.055초이며 최대 실제 DMA 간격은 약 67ms다. 검·봉 2.110초, 투척 2.663초,
활 1.809초의 기존 자동 재생도 유지했다. 원작 속도와 실기 합격을 뜻하지 않는다.
