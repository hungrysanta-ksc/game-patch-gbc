# 원작 행동 스크립트 실행기

PR 72의 메시지 생산자 위에 `34/8FF7..9058`의 실행기를 연결한다.
6개 스크립트는 원본 ROM의 `34/950D` 포인터로 읽는다. 런타임 C는 명령을
선택하고, 처리 완료 후 PC와 메시지 큐 인덱스를 이동한다. 빌드 때 관측한
화면 목록이나 완료 상태 목록을 재생하는 방식은 사용하지 않는다.

## 상태와 완료 책임

29바이트 `Ff3ActionScript`는 스크립트/효과/속도/결과/아이템 플래그,
공격자·우상단·대상·상태 메시지 번호, 10바이트 종료 표시된 메시지 큐,
PC·큐/변수 인덱스·대기 수·요청·완료·오류·16비트 티켓을 소유한다.
원작 가변 문자열 타입 0/1을 지원한다. HP 조사/수치/아이템 치환 타입
2/3/4는 오류 2로 멈추며 변수 큐를 처리한 척하지 않는다.

- `00..09`: 원작 메시지 생산자 호출. `03`은 큐가 남으면 PC를 4/5 되돌린 뒤
  공통 증가를 적용한다. 타입 1은 A 입력 뒤에 큐를 증가시킨다.
- `0A`: `(8 - 메시지 속도[6010]) * 8`개의 원작 프레임을 기다리고 A 입력으로 끝낼 수 있다.
- `0B..0E`: 애니메이션/숫자/사망/포격 **전체 처리자의 완료 요청**.
  `0C`에서 효과 ID를 23으로 바꾸고, 도주 결과의 `0D`는 원작처럼 생략한다.
  사망/포격 요청은 상태 확정 루틴까지 포함하므로 화면만 재생하고 완료하면 안 된다.
- `FF` 또는 효과 ID 0: 원작 그래픽 명령 37의 정리 요청을 완료한 뒤 반환한다.

티켓이 틀린 완료, 처리 중 재시작, 완료 뒤 재완료는 상태를 바꾸지 않는다.
검증용 큐가 원작의 등록된 10바이트 범위를 넘거나 종료 표시가 없으면 시작을 거절한다.
효과 ID 0은 원작처럼 스크립트 번호를 읽지 않고 정리로 간다.

## 실제 V6 연결과 미연결 경계

`battle-script-video.c`는 메시지 생성·창 갱신·시간 대기·정리를 실제로 수행한다.
메시지 생성 오류는 원인을 보존해 멈춘다. 입력의 새 누름/반복 규칙은
`3F/FBC6..FBEE`를 유지하며 GBC 버튼을 NES 비트 순서로 변환한다.
시간은 기존 4096Hz 시계와 원작 60.0988Hz 비율을 사용한다.
`40960000 / 600988 = 68 + 92816/600988`의 나머지를 누적하므로
매 프레임 소수부를 버리지 않으며 무거운 32비트 나눗셈도 필요 없다.

`2F/AFD8..AFE4` 정리는 NES OAM `0200..029F`의 임시 객체를 숨기고
VBlank를 기다린다. 아군은 `02A0..02FF`이므로 보존한다. 현재 GBC 어댑터는
상태 아이콘 8개가 앞쪽 OBJ 슬롯에 있고, 적 보조 OBJ는 원작 BG 도트를 나타낸다.
따라서 앞 8개만 숨긴 새 OAM 페이지를 VBlank에 게시하며 아군과 적 보조 OBJ는
보존한다. 이는 현재 검증된 상주 어댑터의 소유권 대응이다. 무기/숫자 등의 새
임시 OBJ 소유자가 합쳐지면 이 정리 범위도 소유권 표에서 확장해야 한다.

첫 실제 화면 검증은 첫 정리 직후 OAM 불일치를 검출했다. 고정 도구의 생성
기계어에서 두 조건식의 복사 주소 상위 바이트가 합쳐져 원본/대상이 같은 페이지가
되는 것을 확인했다. 페이지별 복사 방향을 두 분기로 명시해 수정하고, 종료 후 일괄
대조와 별개로 매 스크립트 관측/정리 직후 OAM을 즉시 검사한다. 기준 화면을 바꾸거나
남은 아이콘을 허용해 실패를 숨기지 않는다.

**실제 완료 연결은 메시지·대기·정리까지다.** `0B..0E`의 새 상주 화면 처리자는
아직 연결되지 않았으므로 요청을 보류하고 PC/큐/티켓을 진행시키지 않는다.
기존 `battle-action.inc`의 미리 구성된 화면 재생을 연결해서 이 경계를 숨기지 않는다.
스크립트 반환 뒤 정상 전투의 다음 선택/결과 처리자 연결도 남아 있다.

## 검증 방법

원작 CPU는 실제 분기·큐·PC·대기를 실행한다. 문자 그리기 말단과 입력을
관측하며, 그래픽 `0B..0E` 몸체는 외부 처리자 경계로 구분한다. 이 순서 검증은
그 몸체의 계산이나 렌더링 검증을 대신하지 않는다.

- 6개 스크립트 × 속도 0/4/8 × A 조기 종료 여부 × 큐 0/1/3개 × 도주 여부,
  효과 0의 스크립트 번호 우회: 217조건, 6,113단계.
- 실제 SM83 코드의 29바이트 상태 전체를 매 요청 대조하고 잘못된 티켓,
  재시작·재완료, A 없는 입력 대기, 범위 오류와 변수 타입 거절을 검사한다.
- 별도 부정 ROM은 첫 상태 바이트를 바꿔 첫 사례/첫 바이트에서 실패해야 한다.
- V6에서는 메시지 스크립트, 공격자+메시지 스크립트, 효과 0 정리, 관측 중단 없는
  32프레임 대기, 미연결 공격 애니메이션 보류를 검사한다.
- 관측 게이트는 진단 전용이며 요청 완료를 대신하지 않는다. 게이트 없는 대기는
  별도로 원작 시간 비율을 측정한다. 보류 사례의 종료는 검증기의 명시적 중단이며
  성공한 전투/애니메이션 완료로 세지 않는다.
- 기존 보스/상태 화면·711개 메시지 생산자 경계와 음악·효과음·페이드를 같은 ROM에서 검사한다.

## 자원과 재현

실행기 코드는 bank 45의 1,302바이트, 실제 화면 어댑터는 bank 46의
1,000바이트다. 정적 WRAM 끝은 `CDAC`이며 `D000`까지 596바이트가 남는다.
PR 72보다 57바이트 늘었다. 고정 bank 0의 끝은 `3FB6`으로 여유 74바이트다.
대기용 32비트 나눗셈은 정확한 나머지 누적으로 대체하고, 원시 UI 요청과
스크립트 요청의 공통 화면 처리를 bank 46에 모았다. VBlank 게시/오디오 경로는
고정 뱅크에 남긴다. 이 변경은 용량 문제를 해결한 것이며 전체 전투 속도 개선 주장과 구분한다.

542개 공개 허용 소스와 별도 로컬 입력 설정만 복사한 독립 폴더에서
화면 ROM/report, 실행기 양성·부정 ROM/report가 바이트 단위로 재현되었다.
ROM·글꼴·번역·추출 데이터·캡처는 공개 패키지에 포함하지 않는다.
기존 `--stone-overlap` ROM은 아래 SHA-256과 같아 기존 경로의 실행 바이트가 유지된다.

| 산출물 | SHA-256 |
|---|---|
| 실제 V6 ROM | `7ea1b2aa74600984cee212c2fa10821377daa46cf43a21c646350a4609bebe7a` |
| V6 report | `9ae35d3d70e9f3e7c2f79d11013d2ff5e7f1a891fc59f1c97cff00917e699490` |
| 실행기 양성 ROM | `0bf9c984e7ff07d422105d01109ff87b4ec583d3ab2f0a6eb94be47d16840a4e` |
| 실행기 부정 ROM | `bbf57773fd5776f44bc2c2af52369b35c5e5033508a7b268cd8d2124b51bf38f` |
| 기존 석화·겹침 ROM | `204b82ea0df2342b4867417f5df8bbb3e259a00c46569aa79cf1692afa9c6a76` |

호스트 검사 166/166과 실제 GBC 실행기 217조건/6,113단계가 통과했다.
부정 ROM은 첫 사례/첫 바이트에서 의도대로 실패했다.

실제 V6의 기존 988화면 + 메시지 59화면 + 스크립트 17화면, 총 1,064화면의
픽셀·상태·OAM이 일치했다. 원시 메시지 호출 경계 711개도 기존 오류/생략 규칙을 유지한다.
4개 실제 메시지/대기/정리 경로는 완료했고, 미연결 애니메이션 1경로는 10프레임 동안
상태를 진행시키지 않았다. 원작 음악·효과음·페이드 28,800틱이 일치하며
오디오 버퍼 부족·지연·잘못된 DMA·활성 보스 셀 쓰기는 모두 0이다.

관측 게이트 없는 32프레임 대기는 2181타이머 틱(532.471ms)으로,
원작 비율 532.457ms와 대조했다. A 조기 종료/타입 1 입력 대기는
실행기 검증에 포함되지만, 실제 번역 창에 대한 버튼 입력 검증 완료로 확대하지 않는다.
최대 present 준비는 330.078ms(PR 72: 330.078ms), 기존 711개
UI 호출의 최대 완료 시간은 703.564ms(PR 72: 737.275ms)다.
전체 속도 개선 완료를 주장하지 않는다. UI 패턴/맵 전송은 52800/2560바이트다.

## 다음 작업

`34/8411`의 공통 애니메이션 호출자와 원작 상태 확정 경계를 먼저 연결하고,
숫자/사망/포격 처리자도 같은 완료 계약을 사용하게 한다. 단일 공격부터 붙이더라도
전체 대상·직업/무기별 반복·상태 변화의 위치/수명을 보존한다.
고정 bank 0의 여유가 74바이트이므로 새 처리자는 별도 뱅크에 두고, IRQ에는
최소 게시 작업만 남긴다. 뱅크 호출 비용과 오디오 보충·표시 대기를 함께 측정한다.
상태 회복/명중 번역 바인딩, 변수 메시지 치환, 보스+석화+숫자 공존은 별도 미완료다.
제품 관문 0/3, R2 전체 통합 0/8은 유지한다.
