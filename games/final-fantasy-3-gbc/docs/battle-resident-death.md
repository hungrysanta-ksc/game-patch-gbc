# 상주 적 자원과 실제 사망 표시

## 원작 실행 경계

`34/8411`의 공통 애니메이션 호출자가 상태 확정 뒤 요청하는 그래픽 10은
`2F/B33E → BB0A → BB5E`로 이어진다. `BAEE`가 제거 전 종류별 처치 수를
증가시키고, `BAA2`가 선택 슬롯을 비운다. `BB13/A247`은 살아 있는 슬롯으로
지도를 재구성하고 `B909`가 남은 수를 센다. 화면 처리가 끝나기 전에 승리로
복귀시키지 않는다. 그래픽 13의 도주는 같은 표시 경로에서 처치 수를 올리지 않는다.

`BB94..BCCB`는 13개의 40비트 시프트 상태로 **37개 그림, 그림마다 NMI 2회**를
진행한다. `BD2A`의 61/62/63번 검은 마스크와 지도 한 열 쓰기가 함께 사용된다.
살아 있는 적의 지도 셀과 빈 공간 표식 1은 보호한다. 일반 방향과 백어택은
이동 방향과 수평 반전이 다르다. 피해 숫자 앞의 `33/BF1E` 그래픽 13 로드까지
포함한 자원 수명에서 관찰했다. 이전 BC84/BC87 관찰은 상태 비교용이고,
이번 화면 비교는 **DMA와 지도 쓰기가 끝난 BCB1**을 기준으로 한다.

## GBC에서 유지하는 구조와 달라지는 부분

원본 적 패턴은 계속 상주시킨다. 적 종류나 중복 제거된 타일 번호를 개체의
식별자로 쓰지 않는다. 실제 슬롯 제거 소비자를 실행해 얻은 공간별 소유권을
28px 배치에 대응시킨다. 축소 뒤 한 타일에 두 적이 걸쳐도 살아 있는 쪽의
도트를 보존한다. 사망 그림을 ROM에 연속 저장하지 않는다.

NES의 검은 마스크 OBJ를 그대로 추가하면 GBC의 전체/주사선 OBJ 한도와
아군·잔여 색상 OBJ가 경쟁한다. GBC에서는 일부만 지워지는 셀의 비트면을
별도 타일에 만들고, 완전히 지워진 셀은 빈 타일로 바꾼다. 변하지 않은 셀은
상주 원본을 그대로 참조한다. 마스크의 공간 투영 표는 원본 세 글리프와
가능한 열 좌표로 만들며, 애니메이션 시간으로 색인하는 화면 자료가 아니다.

임시 타일은 bank 1의 원본 패턴과 두 지형 페이지 **뒤**에 두 벌로 예약한다.
현재 보이는 쪽의 임시 타일을 다음 그림 준비로 덮지 않는다. 최대 편성은
페이지당 42개가 있고, 생존/제거/제거 중의 모든 조합에서 최대 39개가 필요하다.
44개 배치의 상태·그림 조합 1,136,196건을 빌드에서 검사한다. 점멸은 사망과
동시 소비자가 아니며, 제거 완료 후 혼합 셀의 두 층을 보수적으로 예약한다.

원작 마스크가 선택된 적의 점유 영역을 통과하지 않는 구간은 기존 화면을
재사용한다. 영역의 상한으로 거르는 검사여서 변화가 있는 그림을 생략하지 않는다.
고정 ROM의 작은 마스크 처리 함수가 lookup 뱅크를 한 번 선택해 처리한다.
최종 그림을 생존자 지도로 유지하며, 이후 점멸도 현재 제거 마스크를 적용한다.
마법은 이 실제 지도를 동결·복구하고, 임시 적 타일은 마법이 빌리는 0..127번
영역 밖에 있으므로 원본 prefix 복원으로 사망 상태를 덮지 않는다.

## 동굴 지형과 마법의 잔여 OBJ

같은 부팅의 사망 후 마법 검사에서 실제 동굴 화면의 (128,8), (136,8) 타일에
각각 6색이 필요함을 확인했다. 지형 3행과 축소하지 않은 아군 머리를 하나의
4색 BG 타일로 합칠 수 없다. 원작 33/B589는 마법 그래픽을 한 번 적재하고,
B711 이후 대상별 셀을 선택한다. 이 자원 수명을 유지하면서 GBC에서 필요한
부분만 바꾼다. 서로 다른 직업의 발과 다음 머리가 타일 하나에 걸치는 경계도
기존 한 개의 혼합 팔레트로는 모두 표현할 수 없다. 일반 마법에서는 상단 머리와
네 명의 발을 원래 OBJ로 보존하고,
나머지 아군의 정확히 표현 가능한 셀만 동결한다. 색 근사나 위치 변경은 없다.

하드웨어 기준은 [Pan Docs OAM](https://github.com/gbdev/pandocs/blob/master/src/OAM.md)과
[팔레트](https://github.com/gbdev/pandocs/blob/master/src/Palettes.md)다.
피해 숫자의 32 OBJ 경로는 기존 잔여 8개 한도를 유지한다. 일반 마법은 18개
효과 OBJ 옆에 최대 18개 잔여 OBJ를 허용하고, 실제 10개/주사선 한도도 검사한다.
머리 보존 모드는 동결 캐시의 별도 의존성이다. 마법 쌍 타일 백업은 WRAM4
[3280,3856), VRAM0 [74,110)이며 원본을 복원하고 나서 다른 소유자에게 넘긴다.
기존 글리프 캐시 [1408,3280) 및 필드 정본과 겹치지 않는다.

## 소유권과 검증 범위

- WRAM5 `[1020,1024)`는 전투별 종류별 처치 수다. 원작의 바이트 넘침과 중복
  제거 방지를 그대로 유지한다. 보상 소비자 연결은 별도 작업이다.
- WRAM6 `[0,192)`는 두 정상 지도와 점멸 지도의 잔여 색상 OBJ다. 각 페이지의
  임시 타일 번호를 서로 혼용하지 않는다. 전투 재진입 시 제거 상태와 캐시를 초기화한다.
- D600의 셀 임시값, D740의 잔여 OBJ, D7C0의 이전 열,
  D800의 사망 상태는 사망/정상 지도 준비의 배타적 임시 영역이다. 피해 숫자,
  다른 연출, 결과 계산과 동시에 쓰지 않는다. 명령 결과는 WRAM5에서 유지한다.
- 필드 정본과 중단 상태, 공통 오디오 큐는 이 소유권에 포함하지 않는다.

`npm run test:battle-death`는 실제 원작 PPU/OAM과 양방향의 각 도트를 대조하고,
같은 적의 타일 공유·혼합 셀·그림 재사용·마지막 그림의 완전 제거를 검사한다.
`npm run verify:dungeon-death`는 한 번 부팅한 통합 ROM에서 자연 조우 뒤
명시적으로 제출한 공격, 적 사망, 생존 적의 점멸/피격, 별도 표시 진단으로 요청한
마법의 동결/복구, 세 번의 진단 필드 복귀를 검사한다. 음악·효과음 요청과 실제
APU 쓰기, 타이머, VRAM/OAM 접근, 스택도 함께 대조한다.

HP/치명타 조작과 마법 표시 요청은 **진단 개입**이다. 정상 메뉴 선택·턴 수집이나
합법적인 마법 시전으로 세지 않는다. 게이트로 멈춘 모든 그림 대조와 자동 재생의
시간 측정은 분리한다. 보스 전용 사망(layout 9), 소환/분열, 아군 상태/사망 표시,
보상, 일반 승리 복귀와 게임오버의 시작 화면 복귀는 이번 완료 범위가 아니다.

- 통합 던전 ROM: 자연 조우 3회, 실제 명령에 의한 적 사망 37개 그림, 생존 적 점멸 8회, 마법 27개 그림과 전체 화면 복원. NES PPU/OAM의 원작 도트와 실제 GBC 화면을 대조.
- 기존 마을/백어택 ROM: 마법 54개 그림, 두 번의 필드 복귀 후 이동·한글 대화 회귀 통과.
- 원작 오디오 상태와 실제 APU 쓰기, 타이머/뱅크/IRQ, VRAM/OAM 접근, 동결 셀과 DMA 백업 복원 검사 통과. 두 던전 실행의 스택 미사용 여유 143/174바이트, 가드 정상.
