# 초기 그래픽 전송: 상주 자산 묶음과 제한된 ROM DMA

## 원작 구조와 GBC에서 바뀌는 부분

기준은 PR 65 병합 `ae40160dd824eb58f3c85c3131b6b3abffe38b8c`다.
원작 2F/B469..B479 → AD53..AD83은 초기 자산을 준비한 뒤 F8B0에서 게시하고
아군 이동을 진행한다. 3F/F8B0..F8B9의 NMI/OAM/팔레트/PPU 게시 경계를 유지한다.
프레임마다 완성 그림을 교체하지 않고, 한 번 올린 적 BG·아군 OBJ 자산을 이후 상태가 재사용한다.
원작 파티 자세·상태·28×28 적·11px 지형과 숫자 자산은 변경하지 않는다.

이전 GBC loader는 256바이트마다 ROM→WRAM 복사, 전송 완료 대기, 오디오 보충으로
전경에 복귀했다. 이제 아군 패턴 4096바이트와 적 패턴을 각각 한 descriptor로 요청하고,
VBlank 소비자가 ROM에서 직접 전송한다. 두 VRAM 은행의 맵 2048바이트씩은 기존 staging
256바이트를 한 번 0으로 채워 반복 전송한다. 팔레트·객체 숨김·첫 화면 게시 순서는 유지한다.
추가 프레임 캐시나 상태별 그림은 없다. ROM 은행 번호 1바이트만 늘어 정적 WRAM 끝은
0xCDD7, 0xD000 앞 여유는 553바이트다.

처음 시험한 128바이트 ROM DMA는 1020–1052ms로, PR 65의 987–1037ms보다 느렸다.
복사를 제거하는 것만으로는 은행 복원·짧은 DMA 반복과 대기 비용을 이기지 못했다.
채택한 경로는 **초기 bulk 요청만 최대 256바이트**로 전송한다. 일반 대사/전투 갱신은
최대 128바이트이며, 오디오 큐 크기·원작 명령·타이머·채널 배정은 바꾸지 않는다.

## 하드웨어 경계와 검증

[Pan Docs VRAM DMA](https://raw.githubusercontent.com/gbdev/pandocs/master/src/VDMA.md)의
16바이트 정렬, 활성 ROM 은행 수명, GDMA 중 CPU 정지 규칙을 따른다.
DMA 자체는 CPU 배속으로 빨라지지 않는다. 256바이트 전송에 더해 은행/레지스터 처리까지
포함해야 하므로, 이 API는 CGB 배속에서만 허용한다. 은행/주소/길이/ROM 끝을 검사하며
잘못된 요청은 fault로 거부한다. LCD를 끄거나 가시 구간까지 전송하지 않는다.

VBlank의 고정 ROM 함수가 한 critical section 안에서 ROM 은행을 선택하고 즉시 복원한다.
타이머 IRQ는 ROM 은행을 바꾸지 않는다. 이전의 “모든 IRQ가 은행을 바꾸지 않는다”는
계약에 이 제한된 예외만 추가한다. 중단된 BANKED 함수에 바뀐 은행을 노출하지 않는다.
owner가 전경/ISR의 descriptor 재진입을 막는다.

- ready 판정 LY 144–149, 실제 DMA 시작 LY ≤150은 그대로다. 전송 후 Mode 1/LY ≤152도 검사한다.
- ROM 은행의 하드웨어 쓰기와 shadow, SP, IME, 소스 범위·VRAM 은행·목적지를 함께 추적한다.
  로딩마다 ROM DMA 25회와 은행 복원 25회가 대응하며, 은행 변경 중 IRQ 진입은 0이다.
- 타이밍 표식은 실행 코드를 추가하지 않는 어셈블러 주소 별칭이다. 측정 구간 바깥의
  DI/ready/EI 지연 경로는 링크된 명령 바이트로 고정하고, 212 CPU clock 대신 보수적으로
  256 clock을 더한다. 최장 차단 상한 223.637µs < 4096Hz 타이머 주기 244.141µs다.
  CPU 배속/전체 전송 종료/IME를 함께 검사한다. 이 수치는 실기 검증을 대체하지 않는다.
- SM83 부정 검사 17건: 일반 속도 거부 2건, 은행/주소/정렬/경계 거부 13건,
  잘못된 맵 은행 1건, 0바이트 no-op 1건. 실제 DMA가 발생하지 않는지도 검사한다.

## 같은 음악 시점 비교

프로필마다 새 부팅 후 원작 소비 틱 96/224에서 요청한다. 오디오나 게임 데이터를
바꾸지 않는 기존 debugger 주입을 사용한다. 자연 탐색→전투 연결 완료를 뜻하지 않는다.

| 소비 틱 | 프로필 | PR 65 ms | 이번 ms | 감소 |
|---|---|---:|---:|---:|
| 96 | 0–3 | 986.701 | 702.518 | 28.8% |
| 224 | 0, 2 | 1022.574 | 768.180 | 24.9% |
| 224 | 1, 3 | 1036.979 | 768.180 | 25.9% |

로딩당 팔레트 128바이트, VRAM 11392/11584바이트는 기준과 같다. 모든 첫 화면 픽셀,
원작 상태/OAM, BG/OBJ 팔레트 RAM, 원작 APU·GBC 소비 해시와 이후 최소 120틱이 일치했다.
8회 최악 타이머 오차 절댓값은 0.151ms 미만이며, 은행/IRQ/소스/DMA 경계 fault는 0이다.
실제 오디오 생산자 경과는 약 461–476ms, 전송 함수 내 비오디오 경과는 약 183–236ms다.
작업이 빨리 끝나 오디오를 처리하는 구간도 짧아진 것이며, 오디오 한 틱 자체가 빨라졌다는 뜻은 아니다.

표시 ROM SHA-256: `f3ecc9a5a063497f193a821586c79840edca53f4f658fd68fc18aa0aa2212df4`.

## 전체 경로와 회귀

668개 실제 화면과 원작 상태/OAM/패턴/맵/픽셀, 음악·효과음·페이드 10,800틱이 일치했다.
석화 패턴/맵 전송은 18240/13632바이트, 잘못된 DMA·오디오 지연·버퍼 부족은 0이다.
자동 게시 최대 간격은 5프레임이다. **전투 중 present 최대 준비는 806.885→829.102ms**로
측정됐다. 초기 로딩 이후 음악 위상이 달라지는 전체 순회이며, 기존 상태 변화의 재합성 비용도
남아 있다. 이 증가를 숨기거나 초기 진입 개선을 모든 상태 갱신의 개선으로 확대하지 않는다.

기존 혼란 회귀도 642화면/10,800틱이 일치했다. 최대 present는 229.980→239.502ms,
자동 게시 최대 간격 5프레임, 잘못된 DMA·오디오 지연·버퍼 부족은 0이다.
회귀 ROM: `86ad4624af1475642a5c6ad8aaf58ac020a3d302cac1a5978f7b6bb17349c48a`.

공용 전송의 한글 대사 회귀는 7200틱, 실제 화면 82장, 한글 2350자를 통과했다.
요청 311회, 표시 268페이지, 최대 응답 603.067ms, p95 502.442ms다.
잘못된 VRAM/DMA 쓰기·오디오 지연·버퍼 부족·LCD 끄기는 0이다.
대사 ROM: `0abbd502093ef089a81fc9e5efcdccefcffb62ce33d136355f7adb20117dac24`.
호스트 검사 154건과 전송 부정 검사 17건을 통과했다.

## 다음 순서

약 500ms의 진입 목표는 아직 미달성이다. 초기에만 자산을 로드하고 이후에는 재사용하는
구조는 유지한다. 남은 대기와 오디오 생산 비용을 같은 음악 시점으로 분리하고, 탐색→전투
게시 수명과 겹칠 수 있는 준비 작업을 확인한다. 타이머를 늦추거나 효과음을 생략하지 않는다.
음질/CH4 차용 충돌은 후순위 검증에 남긴다.

전투 중 석화 상태 변화의 큰 준비 비용은 별개다. 원작의 변경 배우·맵 요청을 기준으로
고정 타일 할당과 변경 셀만 재합성/전송하는 경로가 다음 구현 대상이다. 이후 보스 블록 시프트,
창·포격·숫자의 자원 수명 통합으로 간다. 초기 로딩 개선을 전투 중 모든 프레임 개선으로 세지 않는다.
