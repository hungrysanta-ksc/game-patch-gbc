# 원작 아이템 창·가로 스크롤·대상 선택

기준: PR 38 병합 `3d73795fd366a4796ecc62b9931bcd272acead14`, 2026-11-24.
기존 V6 전투 선택기에 정본 가방을 읽는 아이템 창을 연결한다. 원본 크기 아군, 적의
승인된 축소/배치와 y=106 아래 38px는 유지한다. 원작 파란 팔레트, F7..FF 테두리,
연속된 두 열, 장비 열과 두 손 커서를 사용한다. 새 아이템 효과/보상은 만들지 않는다.

## 원작 근거와 연결

- 목록 입력/스크롤: `35/AE9D..AF9C`, `B198..B1AE`, `B2EA`, `B3A3`.
  장비 열 0, 가방 열 1..8, 열마다 4행이다. 처음 A는 표시를 고정하고, 같은 칸의
  다음 A가 사용으로 들어간다. B는 고정 표시를 해제한 뒤 창을 닫는다.
  고정한 두 번째 손은 원작처럼 4px 옆에 표시하고 겹침은 실제 OAM 순서를 따른다.
- 사용 가능성: `35/B8FD`, `30/9400` 무기 표와 `00/8900` 직업 비트 표.
  직업은 GameState+$100+actor×64, 장비는 +$200 영역이다. 두 영역을 혼동하지 않는다.
- 사용/HP 표시/대상 속성: `35/B4F7..B5BA`, `2E/91A0` 아이템→마법 ID,
  `30/98C0` 효과 표. 원작이 참조하는 FF 마법 ID도 실제 바이트를 읽는다.
  256 ID×22직업의 사용 가능성과 속성을 원작 기계어 실행 5,632건에 대조한다.
  수량은 `34/95E1`과 `35/B21E`의 원작 두 자리 출력 규칙을 0..255 전수 대조한다.
- `35/B9F0` 자동 전체 대상은 여덟 적 상태 레코드의 C0 비트를 읽는다.
  화면에 보이는 적 수로 임의 마스크를 만들지 않는다. 진단 편성의 빈 슬롯도 원작
  상태가 00이면 포함되며 이것을 실제 적 생존 판정으로 바꾸지 않는다.
- A6/A7/A8은 원작처럼 목록을 닫고 HP 창에서 아군을 고른다. 나머지 대상 지정 아이템은
  목록을 유지한다. 단일/집단·적/아군 속성은 기존 원작 대상 선택기를 호출한다.
- 대상 확정 후 `35/B5C6` 예약을 같은 GameState 가방에 적용한다. 이전 아군으로
  돌아가면 `34/9AE7` 반환이 같은 수량을 복구한다. 장착 무기 사용은 예약 표시만
  만들며 가방을 감소/증가시키지 않는다. 효과 계산과 실행 시 소비는 후속 소비자다.
- 장비↔가방의 다른 칸 선택은 E1 미지원 호출자에 명시적으로 멈춘다. 장비 교환을
  성공한 것처럼 넘기지 않는다. 상태/장비/능력치 변경은 다음 단계에서 함께 연결한다.

원본 NES에서 채워진 가방, 가로 이동, HP 대상, 예약 후 다음 아군, B 반환 화면을
직접 관찰했다. 원본 첫 전투의 가방에만 32쌍의 진단 입력을 넣은 관찰이며 정상 획득
경로의 검증은 아니다. 원본 목록의 포션 수량 7→6→7과 아이템 행동명/HP 창 전환을
확인했다. PNG/RAM/원본 상태는 `.local/item-original-*`에만 보관한다.
이전 빈 가방의 무주입 관찰은 [가방 경계 기록](battle-items.md)을 따른다.

## 한글과 화면 공급

사용자가 선택한 정책은 **현재 선택한 긴 이름만 좌우로 흐르게 전체 표시**하는 것이다.
7×7 글자 모양과 글자당 8px 폭, 원작 아이콘과 수량 숫자를 보존한다. 사용자 추가 요청에
따라 띄어쓰기만 8px→3px(1/3의 정수 픽셀 근사)로 줄이고 전투 메시지와 이름에 공통 적용한다.
HP 숫자의 정렬용 여백은 숫자 영역의 별도 규칙으로 유지한다. 80px 열에서 이름
뷰포트는 36px, 전체 이름 버퍼는 128px다. 이름을 줄임말로 바꾸거나 수량을 작은
글꼴로 바꾸지 않는다. 커서가 없는 이름은 처음 36px만 잘린 상태로 고정하고,
선택이 바뀌면 이전 이름을 처음 위치로 복구한다.

`local.json.text.itemNames`는 비공개 JSON 입력이다. schema=1, 256개 entries가 필요하며
각 항목은 id, 원본 문자열 sourceSha256, reviewed, ko, origin을 갖는다. sourceSha256은
추출 문자열 0x400+id의 해시다. 폰트 누락/길이 초과/원본 해시 변경은 빌드 실패다.
오른손·왼손은 제공된 system 번역의 288/289를 읽는다. 제공 번역에 없는 NES 항목의
로컬 초안은 origin으로 구분하며 사용자의 최종 번역 검수를 마쳤다는 뜻이 아니다.
원본/번역/대응표/폰트/생성 그림과 ROM은 공개하지 않는다.

아이템 글자 150타일은 VRAM bank 0의 unsigned 영역, 전투 상단은 bank 1의 기존
signed 영역을 사용한다. 세 개의 80px 열 중 두 열만 보여 주고 나머지 열에 다음
그림을 준비한다. 지도도 비활성 페이지에서 준비한 뒤 VBlank에서 OAM과 함께 게시한다.
가로 이동은 원작의 여섯 프레임을 유지하되 120px를 GBC의 80px로 대응한다.
여섯 SCX 단계를 VBlank가 직접 진행하므로 전경 음악 디코딩 지연이 이동 프레임을
반복시키지 않는다. 전경은 그동안 음악 큐 공급을 계속한다.
사전 로딩/창 열기 지연과 실제 여섯 이동 프레임은 별도로 측정한다.

LYC105에서 HBlank 인터럽트를 예약하고 즉시 복귀한 뒤 HBlank105에서 하단 SCX와
LCDC 타일 주소 모드만 바꾼다. 바쁜 대기로 음악 타이머를 막지 않는다. 은행 WRAM 복사는
104..105줄을 인터럽트가 켜진 상태로 기다려 이 분할을 침범하지 않는다. 원래 음악
레지스터 순서는 보존하며 최악 오디오 IRQ의 복사/쓰기 루프 비용을 줄인다.
이 변경은 `FF3_ITEM_WINDOW` 빌드에 한정한다. GBDK 자동 OAM 전송과 명시적 게시의
중복도 제거해 VBlank에서 음악 타이머가 오래 막히는 것을 방지한다.

## 검증과 남은 범위

```powershell
npm run build:battle-item-window
npm run verify:battle-item-window
npm test
node tools/export-source.mjs --check
```

검증기는 가방 64바이트를 명시적인 테스트 입력으로 주입한 뒤 실제 컴파일된 GBC를
실행한다. 제품 런타임에는 샘플 재고를 넣지 않는다. 원작 기계어 실행에 선택/취소,
대상/예약/반환 전체 상태를 대조하고 가방 밖 GameState 960바이트 불변을 검사한다.
전체 화면 픽셀, OAM 160바이트/줄당 개수, 활성 타일 쓰기, VRAM/DMA, 은행/스택,
실제 APU 쓰기와 누적 음악 시간을 함께 검사한다.

오디오는 원작 음악·효과음·페이드의 독립 스트레스 요청 계획이다. UI의 원작 사운드
요청 값은 대조하지만 버튼 효과음의 실제 게임 사운드 요청 중재까지 완료한 것은 아니다.
현재 원작 편성과 정상/백어택의 진단 경로이며 모든 여덟 대상 커서/편성, 실기,
실제 회복·마법 효과·전투 행동 실행·필드 복귀의 완료로 세지 않는다.
R2 통합 시나리오 0/8, 제품 관문 0/3, 후순위 음색 개선은 유지한다.

최종 GBC 검증 결과:

- 524개 요청 상태, 실제 화면 454장/10,460,160픽셀과 OAM 전체 일치.
  이름이 실제 이동한 화면 3장에서도 선택된 이름만 이동하고 다른 이름은 고정된다.
  커서 이동 직후 이름 오프셋 0, 전체 이름 끝 도달·반전 3회도 확인했다.
- 오른쪽 87회/왼쪽 43회가 모두 연속 6프레임. 프레임 간격 오차 최대 12.398µs.
- 원작 음악·효과음·페이드 10,800틱/32,044이벤트, 실제 APU 쓰기 46,407회 일치.
  큐 부족·늦은 출력·불법 VRAM/DMA·활성 타일 덮어쓰기·은행 오류는 모두 0.
  누적 타이머 오차 +0.0343ms, 스택 미사용 여유 273바이트.
- 하단 분할 6,066회 오류 0, 전체 raster ISR 최대 25.749µs,
  전체 오디오 IRQ 최대 243.187µs(주기 244.141µs), DMA 마스킹 최대 162.601µs.
  오디오 IRQ 여유는 작으므로 이후 연출 통합마다 같은 관문을 유지한다.
- 최대 24 OBJ/줄당 6개. 현재 편성에서의 관측이며 전체 전투의 상한은 아니다.
- 이름/열 준비를 포함한 지연은 창 열기 최대 652.966ms, 가로 이동 요청 최대
  485.670ms, 나머지 입력/창 복귀 최대 954.334ms다. 실제 이동 6프레임과 구분하며,
  다음 최적화에서 열/창 캐시와 준비 작업 분할을 다룬다. 응답 속도 완료로 세지 않는다.
- 호스트 테스트 92/92. 기존 가방 커널 18,497건과 의도적 오류 검출 유지.
  띄어쓰기 변경을 반영한 기존 네 명 명령 창도 479요청/208장/4,792,320픽셀과
  원작 오디오 7,200틱을 통과했다.
