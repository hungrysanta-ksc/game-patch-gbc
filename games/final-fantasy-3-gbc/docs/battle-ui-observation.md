# 원작 전투 UI 관찰과 V6 적용 기준

2026-11-24. 사용자의 V6·원작 화면 7장 및 기존 전투 영상이 화면 요구사항이다.
원작 스크립트의 창 열기 순서만으로 화면을 추정하지 않는다. **실제 NES 화면, 해당 시점의
PPU 타일맵·속성·CHR·팔레트·OAM, 이를 쓰는 원작 코드**를 함께 확인한다.

## 실제 ROM에서 확인한 화면

지원 일본어 ROM을 Mesen NES에서 새 게임부터 입력으로 진행해 첫 고블린 전투에 들어갔다.
이름은 조사용으로 입력한 6자 이름이며 원작 데이터/코드를 수정하거나 전투 RAM을 강제로 만들지 않았다.
아이템 화면 재관찰에는 같은 실행에서 저장한 상태를 복원했다. 아이템이 없는 첫 전투이므로
유효 아이템·긴 이름·사용 가능/불가의 표시 조건까지 검증한 것은 아니다.

| 장면 | 실제 화면/메모리에서 확인한 것 |
|---|---|
| 대기 | 왼쪽 적 이름 창 `(8,152)..(88,232)`, 오른쪽 이름/HP 창 `(88,152)..(248,232)` |
| 명령·대상 선택 | 명령 창은 `(32,152)..(88,232)`에서 적 이름 창을 일부 덮음. 대상 손 커서는 OAM |
| 선택 완료 | 오른쪽 HP 행에서 최대 HP 대신 선택한 행동명이 나타남 |
| 아이템 목록 | 아래쪽만 스크롤. 메뉴 스크롤 `$10=120`, 타일맵 경계를 가로지르는 2열 목록. 정지 전후가 다름 |
| 행동 | 행동자/행동과 대상 창이 HP 창 위에 겹침. 아래 창을 덮은 뒤 닫을 때 원래 타일맵 복원 |
| 결과 | 넓은 결과 창이 하단 왼쪽과 HP/이름 영역 일부를 덮음 |

실제 관찰 6장의 하단 240×80, 합계 **115,200픽셀**을 읽은 메모리에서 재구성해
NES 캡처와 대조했고 불일치는 0이다. 비교는 이 캡처 프로필의 NES 색표를 사용한다.
포트의 GBC 팔레트를 그 색표로 바꾸는 검사가 아니다.

아이템 창 전송 중간의 별도 캡처는 현재 PPU와 직전 완성 화면이 어긋나 830픽셀이 달랐다.
원시 실패를 보존했고 6장 통과에 포함하지 않는다. 전환 중간 프레임은 스캔라인별 쓰기와
화면을 정확히 짝지은 추가 관찰이 필요하다. 허용 오차를 늘려 통과시키지 않는다.

```powershell
node tools/audit-battle-ui-observations.mjs --observations PRIVATE_DIRECTORY
```

입력은 각 관찰의 `{ppu,ram,oam,sram}: {hex: ...}` JSON과 256×240 NES PNG다.
관찰/상태 저장/영상/스크린샷은 공개 패키지에 포함하지 않는다. 소스 ROM SHA-256은
`spec/source.json`에 고정되어 있으며 실행 ROM SHA-1은
`31A8397A4C33833AA8EEAA0E150E8F6F562FFD16`이었다.

## ROM 출처와 표시 계약

- 메시지 5종: `34/8E83`의 9바이트 레코드를 직접 읽는다. 각 창은 높이 32이고
  좌표/너비는 `(8,152,80)`, `(80,152,80)`, `(8,176,80)`, `(80,176,80)`, `(8,200,152)`다.
- 일반 메뉴: `34/8B38`의 좌/우·타일맵·테두리 비트, `8BCD..8C55`의 실제 전송을 따른다.
  창의 일부가 다른 창에 가려졌을 때 보이는 모서리를 원래 전체 크기로 오인하지 않는다.
- 이름/HP/상태/선택 행동명: `34/9BA2..9CE0`. `$7CE8`, `$78CF..78D2` 등의 조건을 보존한다.
- 직업별 명령: `34/9B21`의 22×4 목록. V6의 고정 ‘마법’ 명령을 모든 직업에 넣지 않는다.
- 적 이름: `34/9D9E`; 메뉴 이동/목록과 커서는 각각 실제 호출자와 PPU/OAM을 함께 확인한다.
- 테두리 `F7..FF`: ROM `1B710..1C00F`에서 공급되는 글꼴/메뉴 CHR.
  실제 메뉴 팔레트는 NES 인덱스 `0F 00 01 30`이다.

색상 확인: 원본 캡처의 파랑은 이 NES 색표에서 `#002A88`이다. 변환한 RGB555는
`0x44A0`이며 채널을 그대로 펼치면 약 `#00298C`다. 현재 Mesen GBC 기본 LCD 보정은
이를 `#0D4062`로 표시하므로 실제 GBC 검증 캡처는 청록색 기운이 있다. 팔레트를 잘못
선택한 현상은 아니며, 원본 색 인덱스를 임의의 보라색으로 교체하지 않는다. 보정 유무와
실기 표현을 별도 비교해야 하며, 사용자 첨부 이미지와 RGB까지 같다는 의미는 아니다.

## V6 보존과 조정

- 하단 시작 **y=106**, 높이 **38px**, 아군 **16×24 원본**, y=10/34/58/82를 유지한다.
- 오른쪽 이름/HP는 4행이며 제목 행을 다시 만들지 않는다. 승인대로 HP 숫자만 5×7로 표시한다.
- 원작 테두리의 회색·흰색·파란색과 둥근 모서리를 가져와 반복 여백을 줄인다.
  한글/캐릭터/피해 숫자 전체를 축소해 공간을 만드는 방식은 쓰지 않는다.
- 내부 BG 좌표에 6px를 더하고 `SCY=6`으로 표시한다. 화면상 캐릭터/창은 움직이지 않으며
  y=106 경계가 BG y=112에 정렬되어 아군 발끝과 UI 팔레트가 같은 타일을 공유하지 않는다.
- 적은 기존 7:8 도트를 유지한다. 공유 타일 격자에 맞춰 이 표시 입력의 적 기준 y를 16→18로
  2px 내린다. 피해 숫자는 이전 기준점을 유지한다. 상단 배경 높이는 11px다.
- 기존 y=96 시작/48px 높이와 아군을 위로 옮긴 중간 시안은 채택하지 않는다.

## 완료 범위와 다음 순서

이번 GBC 실행의 범위는 [행동 표시 연결](battle-action-flow.md)의 아이템/독 표시 4경로다.
명령 선택·아이템 목록에 대한 NES 관찰을 GBC 조작 구현 완료로 세지 않는다.

1. 원작 선택·대상·아이템·마법·선택 행동명/상태명 소비자를 실제 PPU 상태와 함께 연결한다.
   UI 단위의 임의 배치를 새로 만들지 않는다. 창 3·변수 메시지·복수 결과도 포함한다.
2. 취소/복원, 긴 이름, 아이템 수량/불가 표시, 페이지 이동, 전환 중간 상태를 검증한다.
3. 그 UI를 포함한 전체 전투 장면으로 상태 변경·소멸·전체/개별 대상 마법·소환·백어택 한도를 검사한다.
4. 준비 비용까지 포함한 전체 원작 속도 관문을 통과한 뒤 일반 전투 실행기와 정상 진행으로 확장한다.

음악/효과음 연속성은 각 단계에서 유지하고, 음색 개선은 기존 후순위 항목에 둔다.
