# 봉 계열의 원작 타격을 상주 화면에 연결

기준은 PR 79 병합 `4435ecb7dcbe0725ac09a64048adcfc68491a69e`다.
이번 범위는 그래픽 18의 무기 종류 2(쌍절곤·로드·스태프·망치)와 이미 연결한
종류 1의 혼합 양손이다. 활·투척·하프·맨손/클로, 치명타·특수 상태, 아군 피격·
감싸기·적 점멸, 마법·사망의 실제 연결은 여전히 별도다. R2 0/8·제품 0/3 유지.

## 원작 소비자와 공유 구조

- `2F/B24F`는 전진, 직업/양손 그림 로드, 무기 호출, 복귀, 공유 자원 복원을 소유한다.
- `33/A0C0..A119`는 오른손→왼손을 호출한다. `A094..A0BD`의 종류별 명중 상한은
  종류 1과 2 모두 5 미만, 즉 최대 4회다. 0명중도 무기 동작은 한 번 실행하며
  `32/97B2..97BA`에서 명중 이펙트만 그리지 않는다. 반대 손에 무기가 있으면 빈손은
  `33/A2F2..A2FA`에서 돌아온다. 양손 모두 빈손은 아직 지원하지 않는다.
- `33/A365`와 `A36F`는 명중 이펙트 종류만 0/1로 선택하고 `A379..A3DA`를 공유한다.
  한 번당 8프레임, 뒤 4프레임에 명중 이펙트, 매회 `$B6` 요청, 손 종료 `$FF`를 유지한다.
- 종류 2의 `32/98E0..991E`는 짝수 프레임에 RNG 0에서 두 값을 꺼내 각 `&31`을
  대상 중심에 더하고 홀수 프레임에는 이전 좌표를 재사용한다. `32/9357`의 프레임
  16/17을 손에 따라 선택한다. 단순히 임의 위치의 불꽃을 반복하지 않는다.
- 난수는 `33/A44F→3F/FBEF`의 0..255 범위다. 원작 반올림 곱셈 결과가 표의 값과
  같음을 256값 전부 실행 대조한 뒤 직접 조회한다. 다른 범위의 난수 연산은 바꾸지 않는다.

기존 칼질의 전진/복귀·양손·자원 수명·변경 아군만 OAM 구성·동일 그림 재게시·
비동기 효과음 요청 경로를 공유한다. 새 완성 화면이나 프레임별 관측 OAM을 ROM에
넣지 않는다. 원작의 무기 88개/직업 22개 불변 로더 자원도 재사용한다.

## 타격점과 메모리 수명

원작 좌표의 생성과 GBC 투영은 분리한다. NES OAM은 원작과 정확히 대조하고,
GBC에서는 대상 중심과 난수 오프셋 0..31을 적의 7:8 비율로 투영한다. 이펙트
16×16 도트 자체는 축소하지 않는다. 양손·백어택과 모든 난수 위치의 합집합을
기준으로 한 번 정한 보정점만 사용한다. 프레임마다 클리핑하거나 도트를 지우지 않는다.

봉 계열 합집합은 정면 `[-24,19)`, 백어택 `[-18,25)`, 세로 `[-15,28)`이다.
검류의 합집합과 다르므로 각 손을 시작할 때 종류에 맞는 기준점을 읽는다.
0명중이면 난수를 소비하지 않고, 홀수 프레임은 좌표도 카운터도 유지한다.

`strike_rng`는 기존 `FF3BattleRng` ABI(표 256바이트+카운터 3개)를 사용한다.
원작처럼 표는 전투 동안 유지하고 카운터 0만 진행한다. 초기화하지 않은 상태의
종류 2 요청은 상태를 바꾸기 전에 보류한다. 검증기는 원작 `3F/FC27`에서 만든
두 표와 명시한 카운터를 행동 경계에 넣는다. 이는 정상 전투 초기화→피해 계산→
연출의 공통 RNG 연결을 입증한 것이 아니다. 향후 통합 시 이 상태를 공통 전투 RNG에
연결해야 하며 계산용/연출용 표를 중복 소유하거나 매 공격마다 재시드하면 안 된다.

고정 WRAM 끝은 `CFF7`(9바이트 여유)이다. 기존 한계 검사와 런타임 가드를 유지한다.
새 지속 상태를 더하기 전에 전투 공통 상태의 배치를 정리해야 한다. 일시 작업 공간에
난수 표를 넣어 다음 그림/숫자 준비에 덮어쓰이게 하지 않는다.

## 검증

```powershell
npm run build:battle-motion-sprites
npm run verify:battle-motion-sprites
node tools/verify-battle-select.mjs --motion-sprites --negative
npm run build:battle-effects
node tools/verify-battle-strike.mjs --impact
node tools/verify-battle-strike.mjs --impact --positions
node tools/verify-battle-strike.mjs --impact --numbers
node tools/verify-battle-strike.mjs --impact --auto
npm run verify:battle-strike
npm run verify:battle-strike-auto
npm run verify:battle-effects
npm test
```

생성기 대조는 기존 1,568조건과 새 448조건(두 난수 표, 짝/홀, 양손, 백어택,
좌표 바이트 넘침, 난수 카운터 255→0)을 포함한다. 실제 화면 검증은 원작
`2F/B24F` 전체 호출에서 OAM·직업/양손 타일·팔레트·명중 상한·효과음 순서와
난수 카운터를 수집한다. 최종 GBC OAM, 실제 캡처 전체 픽셀, 자원 복원도 검사한다.
화면 입력은 기존 편성 3의 적 8칸과 아군 4명이며, 모든 편성/보스의 승인으로 확대하지 않는다.
명시한 개발 입력의 `result=2`로 미구현 상태 확정을 건너뛰는 경계는 그대로다.
원작 오디오 소비 해시·부족·지연 검증과 자동 속도 측정은 화면 관측 게이트와 분리한다.

## 최종 결과와 남은 성능 회귀

최종 효과 ROM: `bd98e6c2cad9f322c62a42f9962ef838fdc66f9623f8400dc5e797b92638fd85`.

- 봉 계열/혼합 양손 10조건 636장, 아군 4명·적 8칸·백어택 16조건 688장,
  봉→9999 숫자 2조건 116장: 새 경로 총 1,440장이 원작 OAM·패턴·팔레트·
  명중 상한·난수 소비 및 실제 GBC 픽셀과 일치한다.
- 기존 검류 368장과 밀집 8체 네 자리/회복/미스 숫자 198장 회귀도 통과했다.
  최종 ROM에서 검사한 전체 화면은 **2,006장**이다.
- 위 5실행과 두 자동 실행, 각각 7,200틱의 소비 오디오를 원작 VM/변환 출력 해시와
  대조했다. 부족·지연·잘못된 VRAM/OAM 접근·메모리 가드 손상은 0이다.
- GBC 생성기 2,016조건과 오류 주입 검사, 호스트 175검사가 통과했다.
- 공개 허용 소스 587파일만 복사한 디렉터리에서 효과/생성기 ROM과 보고서 등
  9산출물을 바이트 단위로 재현했다. 원본/번역/추출 자원/캡처는 공개하지 않는다.

**기존 검류의 약 67ms 증가와 최대 간격 증가는 미해결 성능 회귀다.** 추가 분기를
매 OBJ마다 검사하지 않고 같은 종류 양손의 기준점을 재사용해도 전체 시간은 거의
같았다. 최종 검류의 준비 719.235ms, 오디오 1,064.755ms, 게시 대기 242.423ms,
IRQ 211.668ms를 후속 기준으로 남긴다. 원인을 분리해 입증하기 전까지 특정 코드나
RAM 배치 때문이라고 단정하지 않는다. 이번을 속도 개선이나 원작 속도 승인으로 세지 않는다.

다음 우선 과제는 고정 RAM/공통 난수 상태의 배치와 이 회귀의 원인 대조·해소다.
그 뒤 남은 무기와 피격·점멸의 실제 화면 연결을 이어간다. 정상 플레이·정밀한
소리/화면 위상·음질·실기 승인도 여전히 남아 있으며, 이번 ROM은 개발 검증 산출물이다.
