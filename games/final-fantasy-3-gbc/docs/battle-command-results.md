# 실제 행동 호출과 사망·종료 경계

기준: PR 114 병합 `237b986e864bd197b08228375887552777008b7b`.
이 문서는 계산, 원작 연출 순서, 실제 GBC 표시, 정상 게임 진행을 구분한다.

## 원작 호출과 연결 범위

`34/80C9 → 9DE4 → 35/A104 → 30/9E8A`는 큐에서 선택한 행동자와
64바이트 전투 레코드의 `$2E/$2F/$30` 명령·대상·대상 편을 읽는다.
피해 코어만 호출하지 않고 `35/A229..A2B9`의 명중 횟수(8비트 합산 후
32회 표시 제한), 부분 상태 진행, 처치 문구, 스크립트 선택까지 연결했다.
공격 표시용 무기는 `35/A1AC..A212`를 따라 계산에 쓰는 장비와 구분한다.
방어 `A881`, 도주 `A8BF`, 탈출 `A93B`도 같은 명령 디스패처로 전달한다.

현재 소비자는 **깨어 있고 대상이 확정된 일반 물리 공격·방어·도주·탈출**이다.
재지정, 기사 감싸기, 화살/수리검 소비, 마법/특수 기술, 수면/마비/사망한
행동자 등 연결되지 않은 호출 문맥은 계산/RNG 전에 거부한다.
이것을 전체 명령 디스패처의 완료로 세지 않는다. 네 명의 선택 종료만으로
임의 순서의 공격을 실행하지 않으며, 기존 명령 수집기와 원작 행동 큐 연결은 남는다.

실제 통합 ROM에서는 현재 파티의 레코드를 WRAM 5에 유지하고 같은 공간에
선택된 적 편성의 초기 레코드와 사망 슬롯 상태를 확장한다. 원작 `31/A400,
A4F6..A65D`로 생성한 **초기 속성**만 ROM 자원으로 공급한다. 선택 행동이나
피해 결과, 연출 프레임을 빌드 시 계산해 넣지 않는다. 빈 슬롯의 `$7EC4`도
원작의 `80|slot` 값을 유지한다. 이를 0으로 초기화하면 사망 처리기가 빈 슬롯을
소환 대상으로 오인한다.

`command_request=actor+1`은 실제 턴 소유자의 호출 경계이다. 0은 대기이며
자동 공격으로 해석하지 않는다. 계산 결과는 원래 스크립트와 애니메이션의
명중 수·메시지·양쪽 숫자·무기 입력으로 전달된다. 숫자를 표시한 뒤 스크립트
`0D/0E`에서 상태를 확정한다. 사망 표시 요청이 남으면 스크립트와 필드 복귀를
완료시키지 않는다. 무사망 행동은 계산→연출→숫자→상태 확정→다음 호출 대기로
이어진다. 결과가 생긴 경우 아직 구현되지 않은 보상/종료 소유자 앞에서 대기한다.

## 사망 표시와 자원 수명

원작은 상태 확정 후 `34/8411`에서 아군 상태 재표시(그래픽 7), 적 사망(10)을
공격 편에 따른 순서로 요청한다. `2F/BB0A`는 죽은 적의 원래 타입별 보상 수를
먼저 올리고, `BAA2`가 슬롯을 지운다. `B909`의 남은 적 수 갱신은 지우기 연출
**시작 전**이지만, 호출자는 연출이 반환된 뒤에야 다음 `35/A458` 승패 검사를 한다.
도망친 적은 `BB5E`로 들어가므로 경험치를 주지 않는다. 카운터의 8비트 순환도 유지한다.

일반 적 사망의 `BB94..BCCB`는 13개의 40비트 이동 레지스터와 37개 그림,
그림마다 2회 NMI 대기이다. 정면은 소스 열 25→0, 백어택은 6→31로 진행한다.
GBC 사망 순서 코어는 원작의 레지스터·좌표·74회 대기를 그대로 보존한다.
도트 61/62/63의 검은 마스크와 네이티브 지도 전송은 별도 표시 소유자의 일이다.

**아직 실제 사망 그림이 통합 ROM에 연결된 것은 아니다.** 현재 적 상주 지도,
점멸 지도와 마법 복구는 원래의 불변 지도/패턴을 재사용한다. 화면에서 적만
지우면 다음 점멸·복구 때 다시 나타난다. 따라서 다음 표시 작업은 다음 계약으로 진행한다.

1. 원작처럼 현재 적 슬롯에서 유도되는 정본 지도 상태를 두고 사망/도주/소환이
   같은 소유자를 갱신한다. 초기 ROM 자원은 계속 원본으로 유지한다.
2. 공유 타일을 직접 지워 살아 있는 동형 적을 손상시키지 않는다. 바뀐 셀에만
   복사한 타일을 배정하고, 두 지도 페이지와 잔여색 OBJ를 함께 처리한다.
3. 원래 37개 그림의 검은 마스크를 28×28 좌표 투영에 적용한다. 적/아군 도트와
   숫자를 줄이거나 연출 프레임을 건너뛰어 예산을 맞추지 않는다.
4. 사망 후 다른 적의 점멸, 마법 동결·해제, 두 번째 사망, 필드 복귀와 재조우까지
   같은 ROM에서 검사한 뒤 사망 표시 요청을 완료한다. 보스 사망은 별도 원작 분기다.

## 전멸과 게임오버

`35/A458..A486`은 HP 합계가 아니라 네 명 모두의 상태 1에 `C0`(사망 또는 석화)이
있는지를 검사한다. 도주 결과 비트 2가 우선이고, 그 다음 전멸, 그 다음 적 0명 승리다.
HP가 0이어도 상태 확정 전이면 바로 패배로 판정하지 않는다.

`34/811C..8184`의 종료 코어는 실제 소유자 완료를 기다리는 요청으로 구성했다.

| 결과 | 원작 종료 순서 |
|---|---|
| 일반 승리 | HP → 승리 문구 → 승리 연출/곡 07 → 보상 → 파티 반영 → 필요시 백어택 행 복원 → 가방 정리 → 페이드 → 필드 |
| 일반 패배 | HP → 전멸 문구 1C → Requiem 13·A 입력 대기 → 가방 정리 → 페이드 → 시작 루틴 |
| 도주 | HP → 파티 반영 → 필요시 행 복원 → 가방 정리 → 페이드 → 필드 |
| 0173/0178 승리 | 승리 문구·연출·보상을 건너뛰고 파티 반영부터 |
| 0179 패배 | 전멸 문구·Requiem, A 대기 생략 → 가방 정리 후 결과를 0으로 지움 → 페이드 → 이벤트 복귀 |

0179를 0079와 혼동하지 않는다. 원작은 하위 바이트와 0이 아닌 상위 바이트를
비교한다. 패배 시 파티 반영/보상/백어택 행 복원을 성공처럼 호출하지 않는다.
`3F/FA7D`가 결과를 carry로 전달하고 `3E/C058..C05A`가 `$C000`으로 이동한다.
종료 코어는 이 목적지를 별도로 요청한다. 타이틀/새 게임 소유자와 연결되기 전
임의로 던전을 재시작하거나 필드 복원을 게임오버처럼 처리하지 않는다.

필드의 독과 지형 피해가 쓰는 `3B/A10D..A12A`는 살아 있는 HP를 1 아래로
내리지 않는다. 원작의 일반 게임오버 경로는 위 전투 패배 분기에서 확인했다.
별도로 예언 화면 Start(`3A/887C`)와 이벤트 D8(`3B/B5B7`)도 시작 루틴으로
이동하므로 모든 재시작을 전투 패배라고 단정하지 않는다.

## 메모리와 검증

WRAM 5 `[0,828)`은 12명 레코드·지연 상태·슬롯/결과, `[832,1007)`은
행동 계산 출력/저장 방어, `[1008,1019)`는 스크립트 인계 입력이다.
필드 정본 HP/장비는 정상 종료 소유자가 반영할 때까지 별개다.
계산 중에만 `D600..D93B`와 `D200..D3BC`를 빌리고, 표시 전에 저장한다.
타이머 IRQ나 VBlank는 이 작업 공간을 읽지 않는다. 동결 그림의 팔레트 캐시는
재사용 전에 무효화하며, 숫자용 동결은 상태 확정 전에 원상 복귀한다.
명중 루프는 8번마다 기존 오디오 생산자를 서비스하고 원작 RNG 순서는 유지한다.

- 호스트 원작 검사: 실제 `9DE4` 호출, 치명타/명중 수/처치 문구, 상태 확정,
  사망 슬롯·보상과 종료 순서, Requiem/A 대기, 필드 HP 하한.
- GBC 대조 ROM: 3,470건. 실제 속성 명령 264, 상태 문맥 96, 피격 상태 14,
  512편성×3결과×2행 상태의 종료 경로 3,072, 일반 사망 24시나리오·1,800경계.
  기대 바이트 하나를 변조한 별도 ROM도 실패를 검출한다.
- 통합 표시 검사는 자연 조우 후 명시적으로 선택된 행동 튜플을 제출한다.
  무사망 일반 공격 분리를 위해 적 HP를 2,000으로, 공격자의 치명타 확률을 0으로
  바꾸는 진단 개입이 있다. 정상 버튼 선택/턴 순서/승패 플레이 증거로 세지 않는다.

### 이번 실행 결과

- 호스트 전체 219/219 통과, 이후 추가한 전멸 혼합/우선순위 경계까지 명령 검사 8/8 통과.
- 코어 ROM: `6b07e5ead91d5c5cf8972fd61670ebc509add5c61cb3d7585206a6834d90f153`.
  실제 GBC 3,470건 성공, 음성/그림 검사가 아닌 계산·요청 순서 검사다.
  변조 ROM은 case 0/index 0에서 실패했다.
- 던전 통합 ROM: `35f699236cebcfdd31530f9742e3bd15f1f275c70c1d27edbdd0ea6e75d16309`.
  자연 조우 3회/이동 114회 확률 호출, 9개 화면 대조, 1회 명시적 공격에서
  원작과 동일한 1회 명중·피해 7·적 HP 2,000→1,993·RNG 커서를 확인했다.
  최종 RNG는 계산뿐 아니라 원작 `2F/B24F` 공격 표시 호출 후와 대조한다.
- 전체 명령은 371 GBC 프레임/6,213.6ms다. 명령 문구·원작 64회 스크립트 대기·
  이동·공격·숫자·상태 확정을 포함한다. 과거 이펙트 단독 시간과 직접 비교하지 않으며,
  원작 전체 시간과 동등하다는 성능 승인은 아니다.
- 오디오 3,108틱, 실제 APU 쓰기 17,899회가 원작 변환 스트림과 일치했다.
  누락/지각/전송 오류 0, 타이머 편차 범위 339μs, 뱅크 복사 3,997회 오류 0.
  스택 감시 여유 174바이트, 고정 RAM 여유 37바이트. 음색 청취 승인은 별도다.

- 기존 왕복 회귀 ROM: `1811bd4743902985778e036e89953eab235eb54ddbc0f2c26f136a2917d0ee01`.
  같은 부팅의 두 번 표시 왕복, 54개 마법 그림, 복귀 후 이동/NPC 대화를 포함한
  79개 화면을 대조했다. 오디오 7,200틱/실제 APU 쓰기 30,443회 일치,
  뱅크 복사 9,033회 오류 0, 스택 여유 286바이트였다.

통합 생성기는 오래된 독립 시제품의 메시지 사전을 복사하지 않고 현재 검토된
비공개 번역 연결표에서 사전을 만든다. 명중/빗나감·처치/전멸 문구를 연결하며,
번역/보충 문구/원본/생성 데이터는 공개하지 않는다. 실제 표시 소비자의 치명타·
상태 변화·사망 미지원 경계는 남아 있으므로 계산 코어 지원 범위와 구분한다.

R2 0/8·제품 0/3을 유지한다. 사망/보상/타이틀까지 정상 진행했다는 주장은 하지 않는다.
