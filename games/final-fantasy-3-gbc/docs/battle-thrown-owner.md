# 부메랑·원월륜·수리검의 실제 화면 연결

기준은 PR 86 병합 `22b907d43fe337d8a53a00690aa1f3352aae7b8c`다.
원작 무기 ID 63/64/65, kind 5/6/7의 적 대상 일반 공격 연출을 연결한다.
장비 적합성·소모·계산·정상 선택 통합은 별도이며 상태 이상·치명타·아군 대상은
기존 preflight에서 명시적으로 거절한다.

## 원작 호출·수명

- `2F/B24F → 33/A0C0`: 공통 전진, 직업 및 양손 그림 로드, 오른손/왼손 호출,
  원래 자세·상주 타일·팔레트 복구와 복귀를 유지한다. kind 5..7의 손별 명중 상한은 6이다.
  혼합 하프는 원래 호출자의 오른손 명중 수 복사 후 각각 상한을 적용한다.
- `33/A130..A19F`: 부메랑/원월륜은 `$BB` 요청 후 16회 발사 대기, 앞/뒤 각 8회
  같은 그림이다. 오른손은 아군→무기, 왼손은 무기→아군 순서다.
- `A4D4..A593`: `A7A5` 각도와 `BFC6` 정수 벡터, 거리 16·속도 16에서 시작한다.
  원작 8비트 중간점 비교로 속도와 호 높이를 바꾸고 속도의 1/4만큼 거리를 진행한다.
  원월륜만 매 갱신 후 호 높이를 0으로 되돌린다. 도착 판정은 unsigned x 비교다.
- `A593..A5FD`: `$DB` 요청 후 같은 거리에서 귀환한다. 명중 수×8을 한도로
  `32/97EB` 고정 명중 그림을 추가하지만 거리 8 미만이면 남은 명중 대기와 무관하게 종료한다.
  이 그림은 난수를 소비하거나 매번 효과음을 요청하지 않는다. 왕복 중 무기는 2회마다 회전한다.
- `A1EF..A242`, `A5FE..A6C2`: 수리검은 `$AF`, 16회 발사, 거리 8에서 16씩 진행한다.
  양손 모두 아군→무기 순서이며 비행 그림은 4회마다 바뀐다. 도착 후 아군 그림만
  남기고 첫 수리검을 실제 도착 좌표에 추가한다.
- `32/986C..98D0`: 오른손/왼손 tile `$4B/$53`, 명중마다 `$DA`와 6회 대기.
  첫 명중에는 `A6B6`의 1회 대기가 추가된다. 빗나감도 그 1회는 유지한다.
  후속 명중은 `9823`에서 x·버리는 난수·y 순서로 소비하고 기존 수리검을 누적한다.
- 각 손 종료의 `AC35`는 `$FF`와 자세 복구를 담당한다. 활처럼 두 손을 한 번의
  결합 장비 호출로 바꾸지 않는다.

## GBC 구조

bank 58의 작은 상태 실행기가 위 대기·거리·호·속도·누적 수를 소유한다. 원작
메타스프라이트, 벡터, 난수 소비 함수는 공유하고 완성 프레임이나 궤적을 저장하지 않는다.
공통 소유자가 자원 로드/복구와 음악·효과음 큐를 유지한다. 같은 8회 발사 그림과
누적 명중 대기는 현재 OAM을 재게시하여 반복 준비 비용만 제거한다.

원작 raw OAM과 GBC 투영은 분리한다. 축소된 적에 맞춘 출발점→도착점 이동은
현재 원작 x 진행률을 사용하며, 부메랑의 호도 유지한다. 따라서 사전 궤적 전체 탐색이나
프레임 배열이 필요 없다. 명중의 대상 상대 위치만 조정하고 무기·아군·숫자 도트는 유지한다.
원작 전체 호출의 OAM·자세·타일·팔레트·난수·효과음과 GBC 전체 픽셀을 각각 검사한다.

링크된 bank 58 코드는 2,817바이트, 추가 고정 상태는 27바이트다. 공통 bank 55는
4,894바이트이고 bank 52/57은 기존 3,154/2,195바이트를 유지한다. 고정 WRAM 끝은
`CF29`, `D000`까지 215바이트가 남는다. 궤적/프레임 캐시를 더 두는 대안은 이 여유를
소모하므로 채택하지 않았다. 원작보다 빠르다는 주장은 전체 행동 비용 비교 없이는 하지 않는다.

## 검증

검증은 최종 동일 ROM 기준이다. 원작 호출 경계에 상태를 주입하는 진단이므로
정상 플레이·실기·음질 승인을 대신하지 않는다.

| 자동 재생 진단 | 게시 수 | 새 준비/재게시 | 전체 행동 | 실제 첫→끝 DMA | 최대 DMA 간격 |
|---|---:|---:|---:|---:|---:|
| 후열 부메랑+원월륜, 가까운 적, 최대 명중 | 111 | 83/28 | 2663.217ms | 2578.378ms | 83.707ms |
| 같은 아군·양손, 먼 적 | 157 | 129/28 | 3433.423ms | 3348.573ms | 83.707ms |
| 양손 수리검, 손별 6명중 | 139 | 49/90 | 2529.191ms | 2444.467ms | 83.956ms |

요청 수는 각각 6/6/16이다. 수리검은 각 손의 발사·6명중·정지를 모두 요청한다.
재게시한 28/90회는 원작 대기를 삭제한 수가 아니라 같은 그림을 유지하며 게시한 수다.
원작의 논리 프레임·호출 순서 일치와 실시간 60fps 달성은 별도이며, 현재 잔여 지연을 숨기지 않는다.

기존 무기의 자동 회귀에서 검/봉 2110.180ms, 하프 3282.779ms, 맨손
3098.538ms, 활 1808.809ms를 확인했다. 실제 DMA 첫→끝 시간은 PR 86과 같은
게시 간격을 유지한다. 이번 공통 호출 분기 추가로 VBlank가 한 번 더 들어가는 회귀는 없다.
PR 85에서 이미 기록한 하프의 이전 대비 33.436ms 증가까지 해결했다는 뜻은 아니다.

```powershell
node tools/build-battle-party-oam.mjs --effects
node tools/verify-battle-strike.mjs --thrown
node tools/verify-battle-strike.mjs --thrown --back
node tools/verify-battle-strike.mjs --thrown --positions --actor 0
node tools/verify-battle-strike.mjs --thrown --positions --actor 0 --back
# actor 1, 2, 3도 정면/백어택을 각각 실행한다.
node tools/verify-battle-strike.mjs --thrown --numbers
node tools/verify-battle-strike.mjs --thrown --auto
node tools/verify-battle-strike.mjs --thrown --auto --far
node tools/verify-battle-strike.mjs --thrown --auto --shuriken
node tools/verify-battle-effects.mjs --skip-build
node --test tests/battle-motion-sprites.test.mjs tests/battle-animation.test.mjs
```

정면/백어택 및 아군별 캡처를 나누어 각 검사 안에서 7,200틱 오디오 일정을 끝까지
검증한다. 검·봉·하프·맨손·활의 `--auto`와 활 `--numbers`도 같은 ROM으로 회귀 검사한다.
혼합 무기의 비어 있는 옛 타격 슬롯과 새 투척의 8비트 좌표 래핑은 표시 소유자별로
구분하여 검증한다. 이미 수집한 캡처의 재검사는 ROM SHA가 같을 때만 `--reuse`로 허용한다.

최종 ROM SHA-256: `6a613f63901b1a54748fd88bfde88dce62ef068a83fc7b6e3919a22b2d127e1e`.

총 6,860화면·21회 × 7,200틱(151,200틱)을 대조했다. 이 중 새 투척은 6,498화면이며,
정면/백어택 양손·빗나감·검/하프 혼합, 네 아군×여덟 적×양 방향의 64위치, 피해 숫자
32프레임으로의 전환을 포함한다. 나머지는 활 숫자 164화면과 공통 창/숫자 198화면이다.
오디오 underrun/late, 메모리 guard 및 VRAM/OAM 위반은 0이다.
호스트 12검사는 원작 벡터 65,536조합·메타스프라이트/난수 및 공통 호출·숫자를 포함한다.
공개 소스 600파일과 로컬 입력만 둔 독립 폴더에서 주요 산출물 9개가 바이트 단위로 같았다.
기존 컴파일된 생성기 ROM도 이전 SHA를 유지하며, 이를 새 정상 플레이 통합 승인으로 세지 않는다.
