# 적 등장·아군 상태·아이템의 표시 수명

2026-11-24. PR 28 병합 `3b33005fe4086923766afa853486a9a1ab159e08` 이후 작업.
[전투 전체 표시 계약](battle-scene-contract.md)의 본문 실행 근거를 확장한다.
원본 ROM의 코드를 호스트 6502 참조기로 실행했다. **새 GBC 전투 실행기나 전체 예산 통과가 아니다.**
적·지형·팔레트를 원작 초기화로 만든 뒤 같은 VRAM/OAM에서 상태와 아이템의 교체/복원을 검사한다.

## 등장: 정지 그림 로드와 다른 비용

`2E/9E8E..9F28` 초기화 접두부, 편성 표 소비와 명시한 수량, `9D5F` 그래픽 초기화,
`2F/B469` 등장 본문을 실행한다. 합법 조우 선택/RNG는 이 검사에 포함하지 않는다.

- `AD53`에서 적의 배경 스크롤, 지형 마스크 변화와 메뉴 스크롤이 함께 진행된다.
- `AE5E`의 29회 갱신에서 일반 적 스크롤은 `$F0`부터, 백어택은 `$10`부터 반대 방향으로 16씩 이동해 0으로 정착한다.
  메뉴 스크롤은 별도 카운터로 진행한다. 처음부터 정지 적을 그리는 것으로 대체할 수 없다.
- 레이아웃 9와 보스 플래그를 함께 만족하면 `BE97`의 추가 CHR 이동이 실행된다.
- `B489`는 아군의 논리 X를 열에 따라 `$D0/$E0`로 정착시키고 반전을 허용한다.
  백어택도 이 논리 좌표를 쓰며 표시 소비자가 반전한다. 등장 전 왼쪽 좌표를 계속 쓰면 복귀 위치가 어긋난다.

| 명시한 입력 | NMI 대기 함수 호출 | 등장 중 CHR 쓰기 | 지도 쓰기 | 팔레트 쓰기 |
|---|---:|---:|---:|---:|
| 편성 3 일반 | 35 | 1,792 | 28 | 64 |
| 편성 3 백어택 | 35 | 1,792 | 28 | 64 |
| 편성 79 보스 | 83 | 4,864 | 28 | 64 |

쓰기 수는 바이트 단위이며 반복 쓰기도 센다. 대기 호출을 가로채므로 실제 NES 프레임 수·GBC 전송량·시간이 아니다.
특수 최종 보스의 다른 은행 진입과 기습의 정상 호출 조건은 아직 이 세 입력으로 포괄하지 않는다.

## 상태: 자세, CHR 교체, 배경 소유권을 함께 갱신

원작 전투 상태의 첫 바이트는 사망/석화/개구리/침묵/미니/암흑/독/빈사, 둘째 바이트 상위 비트는
마비/수면/혼란을 포함한다. `34/9D1D`가 표시용 상태와 이름 옆 상태 ID로 변환하고,
`2E/9E80`이 이를 표시 작업 영역으로 복사한다. `B607/B5F2`가 우선순위와 혼란 반전을 적용한다.
두 입력 바이트 **65,536조합**을 원작 코드와 대조했다. 불가능한 조합도 포함한 함수 시험이지 정상 전투 상태 수가 아니다.

`2F/B5C3` 전체를 반복 호출하여 다음 경로를 같은 장면에서 검사한다.

1. 정상→독/암흑/침묵/수면/마비/혼란→혼란 해제.
2. 개구리→개구리+석화→개구리+사망, 미니→미니+석화→미니+사망.
3. 석화→사망→빈사→정상 복원.

총 18상태이며 22직업의 기본 슬롯과 4슬롯×2열×일반/백어택을 분리해 **37프로필·666상태 전환**을 검사한다.
직업×슬롯×열×방향의 전체 곱이나 모든 상태 간 전이를 검사한 것은 아니다.

| 경계 | 원작 주소 | 자원 계약 |
|---|---|---|
| 그림 종류 캐시와 재로드 | `B651`, `AB0D` | 정상 직업 14타일, 사망 6타일, 개구리/미니 8타일. 바뀔 때 아군 OAM을 먼저 숨김 |
| 혼란 진입/해제 | `B6AB`, `AF4E` | 좌표 이동과 자세 반전; 해제 후 열 좌표 복원 |
| 자세 우선순위 | `B607`, `B5F2` | 사망/석화 우선, 상태 및 작은 형태에 따른 자세 선택 |
| 석화 표시 | `B72B`, `B6C8` | 해당 아군 OBJ를 숨기고 BG 두 열을 사용. 슬롯별 4/3/4/3행, 백어택 열 반전 |
| 석화 해제 | `B82D` | BG 영역 지우기와 원래 직업 그림 복원 |

정상 복귀 시 원래 직업 CHR 224바이트와 배경 두 이름표 전체가 초기 값과 일치한다.
적·지형의 밑그림도 같은 비교에 포함한다. OAM 검사에서 타일 ID 0이 아닌 가시 슬롯 수를 보조 지표로 쓰며,
이 값은 최종 픽셀 수나 GBC OBJ 최소량이 아니다. 상태 발생/치유 계산과 `32/9F11`의 상태 아이콘·대상 번호 갱신은 미실행이다.

## 아이템: 명령 선택부터 결과까지 같은 전투 경로

원작의 연결 관계는 다음과 같다. 아래 중 실행 검사는 **A65E 경로와 B15E 표시 본문**이며,
나머지 선택/대상 검증/반환은 분해 자료에서 추적한 후속 구현 경계다.

| 단계 | 원작 주소 | 이어서 유지할 조건 |
|---|---|---|
| 선택과 예약 | `35/B4F7`, `B5BA`, `B5C6` | 무기/소모품/비대상 구분, 사용 가능 표, 대상 선택 취소, 예약과 실제 소모 구분 |
| 예약 반환 | `34/8374`, `9AE7` | 행동 전 복구/실패 경계를 실제 가방 상태에 연결 |
| 아이템별 대상 검증 | `35/A3BB..A3D7` | 부활/석화 해제의 예외, 사망/석화/점프 대상 제거, 아이템 시전 플래그 `$CC` |
| 실제 효과 조회/소모 | `31/A65E` | 무기 속성 또는 `2E/91A0`의 효과 마법, 효과 없음, 미니 금지 조건, 이름은 아이템으로 유지 |
| 공유 공격 준비 | `31/AF77..B009` | `$7E88` 효과 마법과 `$7E9D` 그래픽 종류, 배율과 대상 속성 |
| 행동/효과 표시 | `34/8411`, `8577`, `2F/B15E` | 사용자 전진→아이템 조건의 시전→실제 대상별 효과→복귀→숫자 CHR 재로드→`$CC` 해제 |
| 결과 처리 | `34/8FF7` 행동 스크립트 | 아이템 이름/대상/회복·실패 숫자/상태/HP/결과 창의 원작 순서 |

`A65E`를 아이템 바이트 256개×미니 금지 2조건으로 실행해 **512입력 중 효과 경로 227, 무효 경로 285**를 확인했다.
선택 메뉴가 거부할 장비/ID도 포함하므로 227개의 사용 가능한 아이템이라는 뜻은 아니다.
소모품은 유효 경로에서만 실제 개수가 줄고, 무효/미니 금지 경로는 유지된다.
포션 `$A6`은 효과 마법 `$3F`, 배율 3, 그래픽 종류 0으로 이어지고 메시지 ID는 아이템 `$A6`를 유지한다.

회복/상태 계열 `$A6..$AF`의 10개 표시와 포션의 4사용자×4대상×일반/백어택을 중복 제외한
**41프로필**에서 `B15E` 전체를 실행했다. 실제 선택 대상의 `33/B6F3`에 도달하고 사용자가 원위치로 돌아오며,
`$1610..$16FF`에 피해 숫자 CHR 240바이트가 복원되고 아이템 플래그가 해제된다.
대기 호출은 89–137회다. HP 계산이나 회복 성공, 메시지 창과 동시 실행, 공격용 아이템 전체를 증명한 결과는 아니다.

## 다음 통합에 적용할 변경

- 등장 중 적/지형/메뉴 스크롤을 시간에 따른 변경 입력으로 공급한다. 보스 CHR 이동은 별도 최대 부하로 넣는다.
- 아군을 항상 OBJ만 차지하는 고정 4인으로 세지 않는다. 석화 BG와 혼란 이동/복원도 같은 타일·팔레트·창 밑그림 소유권에 넣는다.
- 아이템은 일반 마법과 그래픽을 공유해도 시전/투사체 조건과 메시지 정체성이 다르다.
  원작의 유효 대상 마스크로 착탄 위치를 선택하고, 소모/실패/상태 갱신을 표시 성공과 혼동하지 않는다.
- 후속 작업은 이 상태 전환과 기존 행동 창/숫자 경계를 공통 합성기 입력에 연결한다.
  등장→선택→행동→결과/복원→다음 선택의 한 경로를 먼저 측정하고, 소환/특수 보스/종료를 같은 계약으로 확장한다.
  기능군별 독립 샘플을 계속 추가하는 것을 R2 완료 기준으로 삼지 않는다.

전체 전투 통합은 **0/8**, 제품 관문은 **0/3**, R2는 열려 있다.
현재 실패 편성의 OBJ/공급 문제, 한글 5창·HP·상태/커서의 동시 표시와 실제 오디오 기한 검사는 남아 있다.
아군 무축소·7×7 한글과 기존 UI 컨셉을 유지하고, 음질 개선은 후순위로 둔다.

## 재현

```powershell
node tools/audit-battle-transitions.mjs --rom "D:/private/Final Fantasy III (Japan).nes"
node --test tests/battle-transitions.test.mjs
npm test
node tools/export-source.mjs --check
```

보고서는 `evidence/battle-transitions/audit.json`에만 생성한다. ROM과 추출물/관측값은 공개하지 않는다.
PPU 래치/쓰기 범위는 기록하나 실제 PPU 래스터·IRQ·APU는 실행하지 않는다. NMI/래스터 대기와
음악 요청을 명시적으로 가로채므로 대기 개수/쓰기 해시는 실제 프레임·영상·음악 연속성의 근거가 아니다.
사용자 제공 영상은 기존 관찰을 참고했으며 이번 재현에는 원본 ROM 외의 비공개 입력이 필요 없다.

검증 기록: 전체 호스트 시험 **62/62**, 신규 시험 **5/5** 통과. 등장/상태/아이템 분기 코드를
변조했을 때 검사 실패도 확인했다. 런타임 소스는 변경하지 않았으며 실제 GBC 재생은 이번에 재실행하지 않았다.
원작 전환 보고서 SHA-256: `3c0fe1943c81268abae1cba8a783627e5d79406777de9f610f79bbee547fc65b`.
갱신된 전체 표시 계약 보고서 SHA-256: `b6483f06825c5453f8a00af6df9f2b139774f4e185a137f82cd46d016bda6dc8`.
공개 허용 소스 290파일과 원본 ROM 경로만 새 폴더에 공급해 전환 감사·신규 시험·매니페스트 검사를
재현했고 전환 보고서 해시가 일치했다. 이 소스 재현은 완성 게임의 배포 관문 통과와 구분한다.
