# 원작 문자열과 한글 대사창

이 문서는 첫 정적 창 단계의 검증 기록이다. 후속 [NPC 조건·이름/아이템/금액 치환](npc-dialogue.md)은 별도 진단 ROM과 검증 기록을 사용하며, 기존 정적 창 검사는 회귀 검사로 유지한다.

2026-11-23. 원작 공용 문자열 표를 필드/메뉴 소비자 기준으로 분석하고, 검수한 비공개 번역을 7×7 한글 창에 연결했다. 원작 ID로 요청하는 `ff3_text_open_source`가 원작 포인터 유효성 확인 → 검수된 대응 찾기 → 은행 데이터 읽기 → 페이지 구성 → 글꼴 상주 → 창 표시를 수행한다. 이것은 맵/NPC 위의 공통 표시 경로이며, NPC 대화 조건이나 전체 메뉴 실행기가 완성됐다는 뜻은 아니다.

## 원작에서 확정한 범위

기준 자료는 [고정 리비전의 ff3j.asm](https://github.com/everything8215/ff3/blob/1acef8117120ff891003de249b1a74bc8d94d674/ff3j.asm)과 지원 ROM이다. 제품 빌드는 디스어셈블리·인터넷에 의존하지 않는다. 아래 주소는 원작 은행/CPU 주소이며 파일 오프셋은 iNES 헤더 16바이트를 포함한다.

| 대상 | 소비 근거와 결과 |
|---|---|
| 공용 포인터 1,712슬롯 | `3F/EE9A..EEBE`, 파일 `30010..30D6F`. 16비트 값에 `30010`을 더한 물리 주소. 원작 명령을 실제 실행해 1,712개 모두 대조 |
| 문자열 본문 | `30D70..3E00F`. 1,692개의 유효 시작점, 중복/내부 진입 0개. 토큰의 원시 바이트를 합쳐 원문과 대조한 왕복 1,692개 |
| 미해결 20슬롯 | `00FF`, `03ED..03FF`의 포인터가 0이며 포인터 표 자체를 가리킴. 문자열로 해독하거나 빈 대사로 성공 처리하지 않음. 사용되지 않는다는 도달성 증명은 아직 없음 |
| 종료 | `00` 1,687개, `0A` 5개. `00`은 포인터를 소비하지 않고 반환, `0A`는 소비 후 A=09/C=0으로 반환(`3F/EEFA`, `EFE4..EFEB`). 뒤에 00이 나올 때까지 무조건 읽으면 잘못된 범위가 됨 |
| 글자 | `28..5B`는 `F4E1/F515`의 가나/탁점 두 행, `5C..FF`는 직접 패턴. 필드 모드에서는 `5C..6F`를 공백으로 숨김. 216개 코드×2모드=432개 원작 실행 비교 |
| 인수 | `10..27` 모두 다음 1바이트 소비. `1D`는 소비하면서 값은 기존 `$67`을 사용. 24명령×256인수=6,144개 원작 실행 비교, 포인터 페이지 넘김 포함 |
| 선택지 | `15..17`은 인수 뒤 2바이트를 미리 읽어 커서 자료로 사용하지만 그 2바이트를 추가 소비하지 않음(`F063..F068`). 원시 순서/문맥 보존 필요 |

원작 문자 코드와 패턴 번호를 보존한다. 전체 일본어를 Unicode로 전사했다고 주장하지 않는다. 읽기용 참조 문서와 실제 ROM 바이트를 대조해 번역 대응을 검수했다. 현재 추출기는 필드/메뉴 문법의 소비 범위를 기록한다. 같은 표를 쓰는 전투 소비자 `35/A609`, `34/966A`, 별도 컷신 17슬롯, 크레딧 31슬롯과 RAM/인라인 문자열은 별도 계약으로 남는다.

## 제어 코드 계약

`tools/text-source.mjs`의 40항목 명세와 로컬 `build/text/text-analysis.json`에 원시 토큰, 주소, 해시, 출현 수를 남긴다. 아래 의미는 원작 분석 결과이며, GBC 구현 여부는 별도 열로 구분한다.

| 코드 | 원작 의미 | 이번 GBC 창 |
|---|---|---|
| 00 / 0A | 보통 종료 / 마지막 행의 반행 반환 | 종료 처리. 1bpp 한글에는 별도 탁점 행이 없어 종료 시 표시 분기가 합쳐짐 |
| 01 / 09 | 2타일 행 / 1타일 행 이동 | 지원, 18열 경계 자동 줄바꿈 및 다음 페이지 추가 |
| 02 / 03 | 문맥 아이템명 / 보물 금액 | 미구현 오류. 03은 편집기 정의의 spell이 아니라 실제 `EF6A..EF79`의 금액 처리 |
| 04 / 05 | 24비트 변수 금액 / 보유 금액 | 미구현 오류 |
| 06 / 0B / 0E | 이 소비자에서 다음 코드로 진행 | 원작의 무동작 보존. 06의 주석만 보고 속도 변경을 발명하지 않음 |
| 07 / 08 / 0C / 0D / 0F | 동행 NPC명 / CP / 현재 캐릭터명 / 저장 횟수 / 2×2 휴지통 | 미구현 오류 |
| 10..13 | 파티 슬롯별 이름·상태·직업·장비·마법·수치 선택 | 미구현 오류. 인수 02=이름, 00=레벨/상태, 01=직업, 03..07=장비, 08..1F=마법, 30..FE=수치 계열, FF=다음 레벨 경험치 |
| 14 | 열 위치 지정 | 0..17 지원, GBC 폭 밖은 오류 |
| 15..17 | 선택지 위치와 커서 메타데이터 | 미구현 오류 |
| 18..1B / 20 / 22 | 사용 가능 아이템·상점·가방·보관함·판매·아이콘 없는 이름 | 미구현 오류 |
| 1C / 1D / 1F / 21 | 가방 수량·보관 수량·직업 CP·가격 | 미구현 오류 |
| 1E | 직업 이름/해금 검사 | 미구현 오류 |
| 23..27 | 인수 소비 후 다음 코드 | 원작 무동작 보존 |

치환·선택 명령의 의미 분석 완료와 구현 완료를 혼동하지 않는다. 아직 미검수인 캐릭터 하위 인수 `20..2F`의 사용 여부도 이름 처리로 간주하지 않는다. 번역 빌더는 레이아웃 코드와 의미 코드를 구분하고 의미 코드의 원시 값·인수·순서가 사라지거나 바뀌면 실패한다. 레이아웃 변경은 이 시제품의 GBC 화면 적응이다. 실시간 문자열 치환, 선택지 실행, 원작 스크롤/입력 대기 타이밍은 후속 작업이다.

## 비공개 번역과 글꼴

실제 원작 초반 대사 3묶음과 첨부 번역의 9개 키를 수동 대조했다. 문구는 첨부 한국어 그대로이며, 원작 화자 표식과 문장 순서를 유지하고 줄 배치만 변경한다. 원작 ID·해시·대응 키·본문·생성물·화면 캡처는 공개 목록에 넣지 않는다. 특정 콘텐츠 분기가 C 소스에 들어가지 않으며 대응 자료가 바뀌면 동일 경로로 다시 조립한다.

`local.json.text`는 `font`, `bindings`, `translationDir`를 가리킨다. 대응 JSON은 `schema:1`, `entries:[{id,reviewed,sourceSha256,parts}]` 구조다. 각 part는 `{key,jaSha256,koSha256,prefix?}` 또는 `{control:[opcode,operand?]}`다. 이 단계는 `story_mes_ja.txt`와 `story_mes_ko.txt`를 사용한다. 자동 키 추정은 하지 않는다. 검수 여부/양쪽 값의 해시/원작 해시, 중복 ID·키, 미해결 마크업, 누락 글자, 의미 토큰 손실을 검사한다. 검수된 대응이 없는 ID는 오류 25, 원작 범위/포인터 오류는 26이다.

사용자가 선택한 Harry Potter 작업의 `7x7_comp.fnt`를 그대로 사용한다. 18,800바이트, 완성형 2,350자, EUC-KR `B0A1..C8FE`, 글자당 8행 MSB 우선 1bpp다. SHA-256은 `04ba6bb04d33662dd0a1f324c31c31b4cc7824b593e6b80a5bdcdf1111bb43f6`. 모든 글자의 비어 있지 않음과 매핑의 유일성을 확인한다. 미포함 한글이나 문장부호는 임의 그림/공백으로 대체하지 않는다. 문장부호·숫자·테두리는 원작 패턴을 사용한다. 예를 들어 한국어 입력의 마침표는 원작 `C1` 도형으로 표시한다. 일반 영문 글꼴까지 지원한 것은 아니다.

폰트 출처 표기는 기존 작업의 “7x7 yamche 변형 [작자미상]”을 유지한다. 배포 권한을 새로 확인한 것이 아니므로 파일은 계속 비공개 입력이다. 이 경로의 한글 ROM 재현에는 원작 ROM 외에 사용자의 비공개 글꼴·번역·검수 대응 파일도 필요하다. ROM만으로 한국어를 생성한다고 주장하지 않는다.

## GBC 표시와 상주 예산

창은 160×64, 화면 y=80, 테두리 안쪽 18열이다. 보통 줄 간격은 16픽셀, 7×7 글자를 8×8 셀에 배치한다. NES 스크롤 대신 페이지 교체를 사용하며 A=다음 페이지/끝에서 닫기/재열기, B=닫기, 좌우=검수 대사 선택이다. 원작 게임 조작/이벤트 순서를 대신하는 진단용 선택기다.

[Pan Docs 타일맵·Window](https://github.com/gbdev/pandocs/blob/master/src/Tile_Maps.md)에 따라 Window `9C00`, WX=7/WY=80, VRAM 은행 1 패턴 `9000..97FF`, BG 팔레트 7을 사용한다. 맵의 은행 0과 NPC의 은행 1 `8000..8BFF`는 보존한다. 창의 바탕을 색 인덱스 1로 올리고 인덱스 0과 같은 색으로 지정해, NPC가 창 바탕을 뚫고 나오지 않도록 우선순위를 적용한다.

전체 글꼴은 ROM 은행에 두고 페이지에서 사용하는 패턴만 최대 128개 캐시에 올린다. 이번 전 글자 검증의 최대는 테두리/공백 포함 63개였다. 페이지 교체 시 캐시는 전부 다시 구성하며 이전 페이지 포인터/패턴을 재사용하지 않는다. 문자 ID와 ROM 핸들은 WRAM 값이고, 읽기마다 원래 코드 은행으로 복귀한다. 디렉터리는 은행 12, 창 코드는 14, 원시 포인터/본문과 글꼴/문장은 공통 자산 은행에 분할한다. 하나의 자산은 은행 경계를 넘지 않는다.

현재 업로드는 LCD-off 진단 경로다. 음악 동시 재생의 프레임 예산·무점멸 업로드·원작 표시 속도 합격으로 계산하지 않는다. 실제 대화 통합 전에 VBlank 업로드와 오디오 스케줄러 연결이 필요하다. NPC 밀집 OAM 제한은 [기존 기록](field-objects.md) 그대로 미해결이다.

## 실행과 검증

```text
npm run build:text
node tools/build-text-verifier.mjs
npm run verify:text
npm test
node tools/export-source.mjs --check
```

로컬 결과는 `build/text/ff3-text-viewer.gbc`, `text-analysis.json`, `catalog.json`, `report.json`, `compiler.log`와 `evidence/text/`다. 카탈로그는 자산별 원본 범위/변환 입력 해시를 기록한다. 제어 코드/전 글꼴 검증용 스트림은 원작 대사와 구분해 별도 진단 핸들로 넣고 일반 좌우 선택기에는 노출하지 않는다.

검증 결과: 원작 포인터 1,712·글자 432·인수 6,144개 비교, 1,692개 토큰 왕복. 고정 MesenCore에서 요청 79개 중 정상 67개와 의도된 오류 12개, 실제 조이패드 입력 57개, 한글 2,350자 업로드, 67개 캡처의 1,543,680픽셀 비교를 통과했다. 오류는 미구현 치환, 잘못된 탭/글자/잘린 문장, 없는 핸들, 미번역/범위 밖 원작 ID를 포함한다. 모든 요청에서 원작 초기 GameState·맵 패턴/타일맵·NPC 패턴/OAM·은행 복귀·WRAM 경계 가드를 검사했다. 3개 묶음의 실제 대사 화면도 육안 확인했다.

GBDK 4.5.0과 MesenCore 해시는 기존 `spec/toolchain.json`/검증기 고정을 따른다. Mesen 색 보정에 맞춘 이미지 비교이며 독립 SameBoy·실기 합격은 아니다. ROM SHA-256은 `b824c855fd203d1838b5530228b5aa6a358173a207193be62204a2d079b3f565`다. 공통 호스트 테스트 28개와 소스 allowlist 146개만 복사한 별도 폴더의 ROM 바이트 재현도 확인했다. 일반 대사 연결과 오류 처리를 검증했지만 원작 플레이에서 해당 대사가 호출됐다는 검증은 아직 아니다.

다음 연결은 원작 NPC 조건/대사 선택기 → 원작 문자열 ID → 동적 이름/아이템/금액 치환 → 한글 창 → 대화 종료 복귀다. 메뉴의 선택지/직업/장비 하위 명령과 컷신/전투 소비자는 각 호출 문맥을 확보해 별도로 확장한다. 한글 이름 입력과 저장 인코딩 계약도 이 과정에 포함한다.
