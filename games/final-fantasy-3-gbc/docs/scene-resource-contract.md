# 장면 자원 등록부와 원작 인계 경계 검사

2026-11-27. 기준: PR 103 병합 `b954cfc6c40859357680d703ebc999dda2f5895c`.
[수정한 순서](implementation-roadmap.md)의 첫 묶음 중 저장 은행·소유자 등록과
원작 문맥/가방 경계의 실행 검사를 구현했다. **필드와 전투를 합친 ROM은 아직 아니다.**
기존 화면·사운드 런타임 코드는 변경하지 않았다.

## 원작에서 실행한 것

`tools/field-battle-boundary.mjs`는 지원 ROM의 명령을 기존 6502 실행기로 호출한다.
원작 호출자는 `3E/C049..C060`, `3F/FA26..FA80`이다. 그 안의 다음 소비자를
부분 실행 경계로 삼았으며, 호출을 성공 처리하는 가짜 함수로 바꾸지 않았다.

| 원작 소비자 | 직접 확인한 소유권 |
| --- | --- |
| `3F/FB17`, `F83B` | DP 240바이트를 저장·복원하고 사운드 DP `$D0..DF` 16바이트는 건드리지 않음 |
| `3F/FAB5`, `FADD` | `$0100..0105`의 NMI/IRQ 점프 코드 6바이트를 교체했다가 원래 값으로 복원 |
| `3D/BC12`, `BC2D` | 같은 지속 상태의 32슬롯 가방을 ID/수량 배열↔쌍으로 변환; 복귀 시 바뀐 가방을 유지 |

256개 바이트 패턴마다 같은 CPU에서 두 번 반복해 총 **512개 경계 사이클,
3,072회 소비자 호출, 1,861,120개 명령**을 실행했다. 각 사이클에서 문맥 저장 후
지속 상태와 사운드 DP에 새 입력을 공급하고, 복귀 소비자가 그 값을 과거 스냅샷으로
덮지 않는지 검사한다. 이 입력은 HP 계산·아이템 소비를 대신하는 **경계 테스트 입력**이다.
원작 전투 결과 생성이나 정상 플레이·APU 재생·프레임 속도를 검증했다는 뜻이 아니다.
가방 반환에서 마지막 슬롯을 빼거나 사운드 DP까지 복원하도록 ROM 명령의 피연산자를
메모리에서 변이시킨 음성 검사도 실패를 검출한다. 변이 ROM은 저장·배포하지 않는다.

GBC는 원작 주소 전체를 흉내 낼 필요가 없다. 기존 `inventory.c`처럼 단일 정본 가방을
유지하면서 필요한 소비자 경계에서만 형태를 바꿀 수 있다. 다만 문맥 복원으로 전투 후
HP·장비·가방·이벤트 결과를 지우거나 오디오 엔진을 재시작해서는 안 된다. 원작의
240바이트를 그대로 GBC 필드 구조의 크기로 사용하지 않는다.

## 저장 은행에서 자동으로 잡는 충돌

`tools/scene-resource-contract.mjs`에 기존 진단들의 **19개 물리 저장 범위**를
등록했다. 범위는 은행 내부의 시작 포함/끝 제외 오프셋이다.

| 은행 | 기존 소유자와 주요 범위 |
| --- | --- |
| 2 | 오디오 진단 스냅샷 `[0,464)` |
| 3 | 이펙트 지도 `[0,1152)`, OAM `[1152,1312)`, 팔레트 `[1312,1344)`, 합성 패턴 `[2816,4096)` |
| 4 | 이펙트 의존성 `[0,608)`, 마법 원본 패턴 `[1152,1408)`, 글리프 캐시 `[1408,3280)` |
| 5 | 아이템/장비 상태 `[1024,1280)`; 별도 구형 합성 진단 캐시와 충돌 가능 |
| 6 | 합성 진단의 지도/속성/키; 아이템 atlas의 저장 키 `[1600,1856)` |
| 7 | 등록된 비진단 저장 사용 없음. **새 예약 승인이나 미사용 증명이 아님** |

각 기존 진단의 저장 범위는 겹치지 않는다. 그러나 예전 ‘필드 보존용 WRAM 3 전체’
예약을 전투 이펙트와 함께 넣으면 **4개 충돌**을 검출한다. 구형 composition-window,
현재 이펙트, item-atlas의 저장 소유자를 모두 동시에 넣으면 **9개 충돌**을 검출한다.
이는 현재 따로 실행하는 진단이 고장 났다는 뜻이 아니라, 통합 전에 폐기하거나
재배치할 소유자를 식별하는 검사다. 옛 합성 캐시를 그대로 새 실행기에 포함하지 않는다.

`tools/memory-layout.mjs`도 이 공통 등록부를 사용한다. ‘필드 보존 예약’, ‘미할당’,
‘미래 전투 예약’이라는 오래된 단정은 제거했다. 기존 탐색의 고정 RAM 256바이트
여유·스택 바닥·절대 주소 검사는 완화하지 않았다. 탐색 보고서는 탐색 링크의 증거다.

## 숫자 주소 외에 남긴 계약

등록부에는 지속 GameState, 오디오, 필드 문맥, 필드 작업 공간, 전투 작업 공간,
고정 RAM/스택, VRAM, 게시 큐, ROM 자산, 파괴적 메모리 진단의 10개 소유권을
함께 기록했다. 특히 아래 조건은 ‘남는 은행’만 찾아서는 해결되지 않는다.

- 필드 지도 `D000..D7EE`와 전투 합성·애니메이션 작업 공간은 덮어쓰기를 전제로
  수명을 나눠야 한다. NPC/이벤트 문맥은 별도로 확정해 보존한다.
- `text pending/owner`, `field.pending/upload_pending`, `party_pending`,
  `memory_busy`가 남은 동안 소유자·버퍼·VBlank 콜백을 바꾸지 않는다.
- 전투의 signed clone과 정지 합성 캐시는 새 장면에서 무효화한다. VRAM 내용이
  달라진 뒤에도 같은 프로필 번호라는 이유로 유효성을 이어받지 않는다.
- `memory-probe.c`는 은행 2..7을 쓰는 파괴적 독립 진단이다. 그 검사가 통과했다고
  게임 중 필드 보존 기능으로 호출하면 안 된다.

절대 배치·은행 접근·VBlank 등록이 있는 소스와 주요 상태 소유자 **52개 파일,
151개 배치/접근 지점**을 `spec/scene-resource-sources.json`에 해시와 함께 고정했다.
새 접근 파일이나 기존 파일의 간접 오프셋 공식이 바뀌면 감사가 실패한다. 의도적 변경도
해당 수명·범위를 검토한 뒤 기록을 갱신한다. 이 검색은 C 파서나 전체 정적 분석이 아니다.
일반 정적 변수의 크기, 매크로 확장, 생성 자산/은행 배치, IRQ 최저 SP, VRAM의 모든
동시 상태를 검증하려면 **합친 실행기의 링크와 실행 증거가 별도로 필요하다.**

## 재현과 남은 관문

```text
npm run test:scene-lifecycle
npm run audit:scene-lifecycle
node tools/audit-scene-lifecycle.mjs --require-roundtrip
```

앞의 두 명령은 경계·등록부 검사다. 마지막 명령은 현재 의도적으로 실패한다.
`roundtripReady:false`를 출력하므로 단독 검사의 성공을 통합 합격으로 오인할 수 없다.
원본 ROM은 기존 `local.json` 또는 `--rom`으로 제공하며, 실행 결과는 비공개
`evidence/scene-lifecycle/report.json`에 기록한다.

전체 호스트 테스트 189개(신규 6개 포함)와 기존 탐색 메모리의 오류 주입 75개가
통과했다. 후자는 기존 탐색 ROM `c41f0c86fe2590950638e5829be383532122943ed80b5e0c20825bad22c49e89`
및 링크 심볼에 대한 기계어/배치 검사이며, 새 통합 ROM이나 새 화면·음원 실행 결과가
아니다. 단일 ROM 관문은 예상대로 실패하는 것도 확인했다.

다음 구현은 원작 일반맵 조우/복귀의 NPC·이벤트 문맥 추적을 마치고, 기존 두 main에서
부팅·공통 오디오·장면 진입/갱신/해제를 분리하는 것이다. 먼저 한 ROM의 링크 한계와
전송 배출 API를 확보한 뒤 실제 조우→적재→진단 종료→필드 복구→두 번째 조우를
검증한다. 진단 종료는 승리/보상으로 세지 않는다. 자연 전투 결과와 월드/차량·연속
이벤트는 그 경계를 통과한 후 연결한다. **R2 0/8·제품 0/3은 유지한다.**
