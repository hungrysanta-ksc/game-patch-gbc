# 원작 편성·효과 위치와 자산 공급의 적용 조건

2026-11-24, PR 26 병합 `0250309504ee9964bd05844d6bf97473bccb7d26` 기준.
이번 변경은 원본 소비자 실행과 호스트 예산 분석이다. GBC 런타임/음원은 변경하지 않았다.
[표시 시계](battle-timeline.md)의 실제 출력 증거와 이번 호스트 결과를 구분한다.

## 결론과 사용자 요구

**일반 마법의 대상별 피격, 소환의 화면 연출, 아군의 무기 공격은 같은 고정 위치를 쓰지 않는다.**
2026-11-24 사용자 요청을 이 문서와 [현재 계획](implementation-roadmap.md)에 반영했다.
대상 수·시전 가능 조건·연출 범위·좌표 기준을 각각 유지해야 한다. 전체 대상이라고 항상 화면 전체
이펙트인 것은 아니며, 소환을 일반 피격 스프라이트의 반복으로 대체하지 않는다.

현재 세부 전투 연출 전체를 구현하는 단계는 아니다. 이번에는 원작 편성의 위치·기준점과
호출/대상 선택 일부를 실행 대조하고, 나머지 시전 조건과 전용 연출의 구현 관문을 등록했다.
대표 마법 29를 모든 점유 슬롯에 적용한 예산 검사는 합법 시전/적 내성/스토리 도달성 증거가 아니다.

## 원작 배치와 포인터 대조

기준은 비공개 `ff3j.asm`과 고정 일본어 ROM이다. 아래 bank는 MMC3 8 KiB 단위다.
소스 도구는 참고 asm 파일이나 인터넷 없이 원본 ROM에서 다시 실행한다.

| 소비자 / 참고 자료 행 | 검증/구현 의미 |
|---|---|
| `2E/9FAA`, `2F/A02A`, `A31F` / 3617–4096 부근 | 편성·수량 범위·크기별 레이아웃·실제 슬롯 타입. 최소/최대 수량은 별도 진단 입력 |
| `2F/A247`, `A2D4`, `A5E6` / 3967–4094, 4439–4500 부근 | 슬롯 위치/크기표로 원작 타일맵을 생성하고 독립 재구성한 448바이트와 비교 |
| `2F/A492`, `A4AC` / 4318–4334 부근 | 4×4 그림은 4×6 슬롯 아래에 적재. 빈 상단 16픽셀을 없애고 중심을 다시 잡지 않음 |
| `2F/BDBA..BE64` / 7713–7805 | 중심, 앞쪽/상단, 커서 기준을 별도로 계산. 레이아웃 9는 중심 `(88,80)` 특수 처리 |
| `33/A7A5..A7D6`, `A7D7/A7E1` / 17871–17905 부근 | 편성·아군 인덱스·대상 인덱스로 원작 투사체 각도표 조회. 반환값과 X/Y 보존 비교 |

512 편성 슬롯 × 최소/최대 수량 = **1,024입력** 중 710입력의 배치·타일맵·각도 조회를 대조했다.
이는 독립 수량 끝점 검사이며 중간 수량 전수 검사나 RNG 결합/정상 조우의 도달성 검사가 아니다.
나머지 314입력은 다음과 같이 명시적으로 분리한다. 데이터를 고치거나 개체를 자동 삭제하지 않는다.

| 미해결 분류 | 입력 수 | 예시 |
|---|---:|---|
| 전체 적 ID가 FF인 그룹 | 20 | 편성 71 |
| FF 적 ID에 양수 수량 | 277 | 편성 131 |
| 초기화된 슬롯이 위치표 범위를 넘음 | 13 | 편성 138 최대 수량 |
| 고정 타입 시작점 때문에 수량 배정이 덮어써짐 | 4 | 편성 149·411 최소/최대 |

각 분류는 원작 소비자에 대한 현재 입력의 해석 한계다. 정상 게임에서 같은 결함이 발생한다고
주장하지 않는다. 해당 편성의 조우/이벤트 호출 및 수량 보정 경로를 확인해야 한다.

기존 계획의 “보스 210” 표현은 **큰 적 210**으로 정정한다. 이 ID는 타입 4의 48×96 그림이고
편성 83/레이아웃 6에 들어간다. 이번 축소 후보는 42×84다. 18×12 보스 표본은 편성 44와 79이며
144×96→96×64 후보를 사용한다. 기존 코드의 크기 판정은 유지하고 계획의 분류를 바로잡았다.

**시전 가능 판정은 아래 원작 경로를 R3/R5에서 연결한 뒤 완료로 센다.** 이번 대상 분기 검증은
마법 전체의 시전 조건 검증이 아니다.

- `35/B877..B8C3` (28795–28837 부근): 빈 마법 슬롯·미니 제한·레벨별 남은 MP·취소/확정.
- `35/B953..BA29` (28922 이후): 직업 사용 가능, 흑/백/소환 구분, 자동 전체·다중 선택 허용·기본 진영.
- `34/9E5F..9F57` (25257–25371 부근): 사망/석화·수면/마비, 유효 대상, 실행 시 MP 차감, 소환 분기.
- `31/AF77..AFC5` (10332–10377 부근): 무효·개구리·침묵 및 원작 예외. UI에서 고를 수 있음과 실행 성공을 구분.
- `34/9FD6..35/A017` (25442 이후): 직업 13/14의 세 번째 소환 변형과 다른 직업의 RNG 선택.

후속 각 효과의 등록 필드는 `actor`, `targetSide`, `targetMask`, `eligibility`, `variant`,
`anchorKind(center/top/front/actor/screen)`, `sourceCaller`, `sourceDuration`, `restoreOwner`다.
화면 연출 범위와 피해 대상 마스크는 별도 값으로 둔다. 화면 전체 소환의 기준은 전장/화면 좌표,
개별 피격은 개체 좌표이며 창 가림·스크롤·소환 종료 후 아군/적/팔레트 복원까지 검사한다.
뒤집기/축소로 대상 인덱스나 논리 명중 결과를 바꾸지 않는다. 세부 연출 시 이 항목을 생략할 수 없다.

## 여러 적과 큰 그림의 표시 예산

원작 슬롯 상대 배치를 사용해 일반 적 영역 `(16..160,48..144)`을 후보 영역
`(0..126,16..100)`으로, 보스는 96×64로 대응했다. 중심/앞쪽/상단 오프셋을 구분하고
아군의 원본 16×24 픽셀을 유지한다. 이것은 추가된 **예산 후보**이며 최종 배치/아트 승인이 아니다.
적 210의 표본을 포함해 일반 7/8을 전체 적에 승인한 것으로 취급하지 않는다.

8편성에서 원작 마법 29의 여섯 엔트리와 지우기를 각 점유 대상에 적용했다. BG 7팔레트로 제한해
한글 창 팔레트 1개를 남긴다. 지형/메뉴 픽셀과 공격 자세는 아직 포함하지 않는다.
정확한 RGB555로 합성한 그림을 역복원해 비교하며, 실패 상태는 공급량 추정에서 통과 상태로 쓰지 않는다.

|---|---:|---:|---:|---:|---:|
| 3 / 8체 | 57 | 0 | 277 | 177 | 42 |
| 13 / 6체 | 43 | 22 | 259* | 163* | 42 |
| 47 / 6체 | 43 | 36 | 191* | 미확정 | 41 |
| 44 / 보스 1체 | 8 | 0 | 114 | 99 | 42 |
| 234 / 큰 적 2체 | 15 | 2 | 220* | 151* | 44 |
| 301 / 가로로 큰 적 2체 | 15 | 0 | 254 | 167 | 41 |
| 79 / 보스 206 | 8 | 0 | 82 | 67 | 42 |
| 83 / 큰 적 210 | 8 | 0 | 129 | 110 | 38 |

`*`는 일부 그림/인접 전환만 계산한 값이다. 실패 그림을 포함한 전체 상한이 아니다.
197상태 중 137상태가 합성/픽셀 대조를 통과하고 60상태는 현재 분할기의 40 OBJ 한도로 거부됐다.
이는 현재 팔레트 선택/분할 방식의 실패이지 GBC 하드웨어에서 다른 무손실 분할도 불가능하다는 증명은 아니다.

편성 3은 개별 그림 최대 BG 150·OBJ 33·한 줄 8개로 호스트 예산에 들어가지만,
모든 대상 그림의 BG 합집합은 277·OBJ 패턴 합집합은 322개다. PR 26의 128슬롯 상주 방식으로
확장할 수 없다. 활성+다음 그림의 합집합도 177개다. 연속 그림의 새 BG 패턴 차이는 최대 480바이트로,
타일 인덱스를 안정적으로 배정한다면 전체 합집합 상주보다 변경 셀 공급이 유리할 가능성이 있다.
이는 패턴 집합의 차이일 뿐 지도/속성/OBJ/팔레트 전송이나 실제 준비 시간의 실측값이 아니다.

왼쪽 대상에 원작 크기 효과를 붙인 일부 입력은 화면 밖 불투명 픽셀 최대 46개가 발생한다.
이를 숨겨 성공 처리하지 않는다. 효과 크기/자리 조정과 클리핑 정책은 적 중심에 붙는다는 조건과
함께 다시 검토한다. 이번 입력의 메뉴 영역 침범 0은 화면 전체 소환/다른 마법의 창 안전 보증이 아니다.

## 다음 결정과 검증

1. 편성 13·47·234의 팔레트/잔여 OBJ 실패를 먼저 해결한다. 상주 적/아군 타일과 효과가 바뀐 셀을
   나누고 팔레트 분할 후보를 비교한다. 모든 편성×직업×자세×마법의 완성 화면을 미리 만들지 않는다.
2. 해결한 대표 편성에서 활성/다음 타일 수명, 변경 지도/OBJ 전송, 창 팔레트와 위치/클리핑을 검사한다.
   그 뒤 기존 원작 표시 시계·오디오에 연결해 실제 GBC의 준비 기한과 픽셀을 검증한다.
3. 필드/전투 메모리 소유권·탐색 입력 응답을 정리해 R2를 닫고 R3 공유 규칙으로 진행한다.
   전투 통합 때 위 시전 조건과 마법·소환·물리 연출 목록을 소비한다. 음질 개선은 후순위다.

재현: `npm run audit:battle-placement`, `node --test tests/battle-placement.test.mjs`.
보고서는 비공개 `evidence/battle-placement/audit.json`에 저장한다.

원작 중심/대상 루프/물리 대상/소환 플래그 변조를 거부하는 음성 검사도 포함한다.
원본·추출 그림·번역·폰트·원시 보고서는 공개 허용 목록에 넣지 않는다.

검증: 전체 호스트 회귀 52개 통과. 공개 허용 소스 281파일만 새 폴더에 복사하고 원본 ROM의
외부 경로만 지정해 새 분석과 관련 3개 테스트를 재실행했다. 보고서 해시와 공개 목록 해시가 일치했다.
런타임 코드 변경이 없어 장시간 GBC/오디오 실행은 반복하지 않았으며, PR 26의 게시 오차/음원
증거를 이번 실행 결과로 바꾸지 않는다. 새로운 표시 후보의 실제 GBC 검증은 다음 관문이다.
