# 원작 사운드 제어부 C 이식

기준일: 2026-11-22. 사용자가 음색 조정을 보류했으므로 [청취 피드백](audio-backlog.md)을 미해결로 유지하고, 원작의 실행 규칙을 옮기는 작업으로 진행한다. 기존 GBC 출력 변환과 타이밍 플레이어는 수정하지 않는다.

## 이번에 옮긴 범위

`src/audio-control.c`와 `.h`는 사운드 요청·효과음 채널 소유·논리 NES APU 출력의 C 구현이다. 실제 GBC/SM83 코드로 컴파일한다. 이 코드는 음표를 미리 녹음한 샘플을 선택하는 플레이어가 아니라, 원작 사운드 RAM 상태를 소비하는 제어 루틴이다.

| 원작 bank/CPU 주소 | C 역할 |
|---|---|
| `36/81C3..81E5` | 초기화; 원작이 지우지 않는 RAM은 보존 |
| `36/8BB8..8C28` | 효과음 초기화, 원본 포인터 표/헤더 읽기 |
| `36/8C29..8C57` | 기존 효과음 채널 해제와 BGM key-off 표시 |
| `36/8B9D..8BB7`, `8C58..8C76` | 요청·정지·재생 중 분기 및 스크립트/엔벌로프 호출 순서 |
| `36/8030..80AA` | 효과음의 pulse 2/noise 출력 |
| `36/80AB..81C2` | BGM 출력, 점유된 채널 보호, key-on 비트 소비 |
| `36/8AC0..8AEF` | BGM 음소거 중 효과음 출력 보존 |
| `36/8003..802F` | 논리 틱 전체 호출 순서와 곡 `$37` 예외 |

원작 의미를 확인한 주요 동작은 다음과 같다.

- 음악 요청은 `$7F43=ID`, `$7F42=1`; 효과음 요청은 `$7F49=$80|ID`다. 공개 요청 API는 음악 65개, 효과음 97개 슬롯 범위를 검사한다.
- 효과음은 pulse 2와 noise를 점유하며, 새 요청은 기존 효과음을 교체한다. ID별 임의 우선순위나 별도 대기열을 추가하지 않는다. 같은 ID를 다시 요청해도 초기화 경로로 들어간다.
- `$FF`는 다음 갱신에서 효과음 정지로 처리한다. 점유 채널을 해제하며 해당 BGM 채널에 key-off 비트를 세운다. 곧바로 이전 음량/주파수를 복사해 재시작하는 규칙으로 바꾸지 않는다.
- BGM의 pulse 1/triangle은 계속 출력하고, pulse 2/noise는 효과음 소유 비트에 따라 출력을 막는다. key-on 시에만 쓰는 레지스터와 하드웨어 sweep 활성 중 생략하는 저위 타이머 쓰기를 구분한다.
- 곡 `$37`은 효과음 요청 바이트를 0으로 만든다. 여기서 기존 소유 플래그를 별도로 정리하지 않는 원작 동작도 보존한다.

상태 구조는 비교를 위해 `$7F40..$7FFF` 192바이트와 논리 APU 레지스터 24바이트를 유지한다. CPU 레지스터·스택·제로 페이지 임시 변수는 C 호출 규약으로 대체한다. `FF3AudioOps`의 ROM 읽기/논리 APU 쓰기/미이식 함수 호출을 플랫폼과 분리한다. 하위 루틴은 검증된 상태를 전제로 하며 게임 호출은 범위 검사 API를 사용한다. 콜백은 재진입하지 않는 단일 사운드 상태에 연결한다.

`ff3_audio_tick` 한 번은 원작 드라이버의 한 논리 틱이다. 이 모듈이 직접 GBC VBlank에 연결되거나 NES/GBC 속도 차이를 보정하지는 않는다. 시간 스케줄과 실제 GB 레지스터 출력은 후속 통합 단계다.

## 검증 방식과 한계

음악 스크립트 해석기 `36/81E6`, 엔벌로프 처리 `36/857D`, 음악 갱신 `36/8925`의 본문은 **아직 C로 이식하지 않았다**. 테스트에서는 원본 실행에서 기록한 함수 진입 상태를 C 호출 직전과 비교하고, 원본 반환 상태와 쓰기를 재생한다. 함수 경계가 틀리면 즉시 실패한다. 이 방식은 제어부의 분기·호출 인자·호출 순서·소유권·출력 동등성을 검사하며, 전체 음악 VM을 GBC에서 실행했다는 증거가 아니다.

기준 결과는 지원 ROM의 명령 바이트를 기존 `Driver6502`로 실행해 만든다. 호출 경계를 기록한 실행과 기록 훅이 없는 실행의 전체 사운드 RAM·APU 상태·쓰기 목록이 일치하는지도 빌드에서 검사한다. GBC 테스트 ROM은 그 기준과 C 구현을 직접 비교한다. APU 쓰기는 로그 버퍼로 보내고 GBC 음원은 꺼 두므로 음색을 조정하거나 녹음하지 않는다.

검사 사례는 모든 음악 65슬롯과 효과음 97슬롯의 실제 상태, 시작·진행·정지·교체·재요청·곡 `$37`, 그리고 플래그 조합을 위한 합성 RAM 상태를 포함한다. 합성 상태를 실제 게임에서 도달한 상황으로 계산하지 않는다. 음악/효과음 모든 조합의 게임 플레이나 자연 종료 시간 전체를 검증한 것도 아니다. 효과음 진행 샘플은 최대 301틱이다.

총 2,360사례, 원본 함수 경계 2,435개, 최종 APU 쓰기 12,923개를 비교한다. 쓰기 수에는 명시적으로 재생한 미이식 함수의 출력도 포함된다. 기준 결과 한 바이트를 일부러 틀린 별도 ROM도 만들어 검사기가 이를 실패로 검출하는지 확인한다. 원본 ROM과 정상 테스트 ROM은 수정하지 않는다.

## 확인 결과

GBDK 4.5.0으로 빌드한 최종 ROM을 Mesen CE (`20ba206cef5ba207c21203176d02cb9f43dda9fb`, emucap patchset `2e5e6e9db63a24b3fc549f026ce7f4d69b7aa539bc859b537a002cdc116210dd`)의 CGB 배속 실행에서 검사했다.

| 검사 | 결과 |
|---|---|
| C 제어부와 원본 기준 비교 | 2,360/2,360 PASS, 실패 코드 0 |
| 잘못된 기대값 1바이트 | 첫 사례의 최종 RAM 비교에서 FAIL, 코드 4 / 인덱스 0 |
| 원본 실행 기록 훅 | 훅 없는 실행과 RAM·APU 상태·쓰기 목록 일치 |
| 공개 소스 별도 폴더 재빌드 | 정상/오류 검출용 ROM과 기준 데이터·보고서 동일 |
| 기존 청취 ROM | `6f4fc6a8…` 해시 유지, 음색 코드 미변경 |

정상 ROM SHA-256: `374f312c190324a33e45f84c584391d89631c788669fb041a4fed2b67c9f882b`.

오류 검출용 ROM SHA-256: `f689c631972323a92d6711dd59222649bbab3cf8b63b095ebd8e5ee0790f5ec2`.

`gameboyMemory $C2A9..$C2AF`의 최종 관측은 정상 `A5 01 00 38 09 00 00`, 오류 검출용 `A5 02 04 00 00 00 00`이었다. 각각 ready, 상태, 실패 코드, 사례 번호 u16, 실패 인덱스 u16이다. 정상판은 6,001번째 에뮬레이터 프레임에서 최종 상태와 PASS 화면을 관측했고 오류판은 121번째 프레임에서 확인했다. 이 프레임 수를 게임의 사운드 틱 수나 모듈의 실시간 성능 측정으로 사용하지 않는다. 실기·다른 에뮬레이터·전체 게임 통합은 미검증이다.

## 재현

```powershell
node tools/build-control.mjs --rom "D:/private/Final Fantasy III (Japan).nes" --gbdk "D:/tools/gbdk"
```

`build/control/ff3-control-test.gbc`를 GBC 에뮬레이터에서 열면 자동 검사 후 PASS 또는 FAIL을 표시한다. `ff3-control-negative.gbc`는 의도적으로 틀린 첫 사례를 넣어 FAIL이 정상이다. 각 결과·주소별 기준·원시 사례는 `build/control/`에 로컬로 생성되며 업로드하지 않는다. 테스트 ROM의 크기는 검사 데이터 때문에 2 MiB이며, 제어 모듈 자체의 게임 ROM 비용이 아니다.

공개 소스는 원본 ROM과 GBDK만으로 검사 ROM을 재생성한다. VGZ, 기존 생성 ROM, 개인 디스어셈블리 파일이나 번역 자료를 빌드 입력으로 요구하지 않는다. 분석에 참고한 디스어셈블리는 [everything8215/ff3](https://github.com/everything8215/ff3), 고정 커밋 `1acef8117120ff891003de249b1a74bc8d94d674`이며 실행 기준은 로컬 원본 ROM이다.

## 다음 단계

같은 함수 경계 검증을 유지하며 원작 채널 스크립트의 명령 읽기·음표 길이·점프·반복, 볼륨/피치 엔벌로프, 음악 요청·템포·페이드를 순서대로 C로 대체한다. 그 후 콜백 재생을 제거한 엔진을 기존 GBC 출력 백엔드와 연결하고, 임의 시점의 BGM+효과음과 실제 게임 호출을 검증한다. VGZ는 비교 기준으로 유지하고 최종 배포물의 원본 NES ROM 입력 계약은 유지한다.
