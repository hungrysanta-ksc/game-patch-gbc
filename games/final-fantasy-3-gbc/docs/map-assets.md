# 일반맵 자산 공급과 공통 배경 표시

2026-11-23. [로드맵](implementation-roadmap.md) 단계 3의 첫 묶음이다. 한 동굴에 고정했던 추출/표시 범위를 **일반맵 전체의 원시 배경 자산**으로 확장했다. 사용자의 원본 ROM에서 표를 읽고 변환·재배치한 뒤, GBC가 종류/ID로 자산을 선택하여 같은 로더로 읽는다. 원본/추출물/비교 정답을 공개 소스에 넣지 않는다.

이 단계는 맵 이동이나 게임 진행이 아니다. 보물·문·트리거 번호를 초기화하는 원작 맵 변환, NPC/플레이어, 물 애니메이션, 월드맵, 실제 전투, 대사/한글 UI는 해당 소비자 연결로 남는다. 이번 ROM의 방향키는 **배경 검사 카메라**이며 게임의 이동·충돌·스크롤 규칙으로 채택하지 않는다. 원작의 저장 플래그를 반영한 최종 맵 상태와도 구분한다.

## 원작 소비 코드로 확인한 계약

자료 기준은 [everything8215/ff3 고정 리비전](https://github.com/everything8215/ff3/tree/1acef8117120ff891003de249b1a74bc8d94d674)이다. 실제 비교 정답은 사용자 ROM의 6502 코드를 실행해 만든다. 빌드 때 디스어셈블리 파일이나 네트워크가 필요하지 않다.

| 자산 | 분모 | 원작 경계와 출력 |
|---|---:|---|
| 일반맵 속성 | 512 × 16바이트 | `3A/915E..918A`, `$0780..078F` 복사 |
| 레이아웃 | 256 × 1,024바이트 | `3E/CBA4..CC41`, RLE 해제한 32×32 메타타일 |
| 그림 묶음 | 48 × 1,792바이트 | `3E/DE82..DECD`, 8부분의 112패턴을 실제 PPU 쓰기와 비교 |
| 메타타일/색/속성 | 7묶음, 각각 512/128/256바이트 | `3A/9267..92D9`, 네 사분면·팔레트·타일 속성 복사 |
| 배경 팔레트 | 속성표별 512 × 32바이트 | `3A/9091..914A`, 공통 배경색 및 세 사용자 팔레트/창 팔레트 |
| 공용 창/문자 그림 | 144패턴 | `3E/DED6..DEE7`, 배경 패턴 `$70..FF` |
| 배치/그림 선택표 | 512 × 2바이트 | 레이아웃 ID와 그림 묶음 ID, 별도 속성표 ID와 혼동하지 않음 |

일반맵 그래픽의 NES 두 비트플레인을 GBC의 행별 두 바이트로 변환한다. 픽셀 인덱스는 보존하며 재도트/축소하지 않는다. 색은 기존 필드 검사에서 사용한 NES 프리뷰 팔레트의 RGB555 변환을 재사용한다. NES의 아날로그 출력이나 실기 LCD의 정확한 색 재현을 주장하지 않는다.

### 월드 값에 따라 다른 두 선택 조건

| 월드 입력 | 속성표 | 레이아웃/그림 선택표 |
|---|---|---|
| 0 | 앞 256개 | 앞 256개 |
| 1 | 뒤 256개 | 앞 256개 |
| 2 이상 | 뒤 256개 | 뒤 256개 |

속성표는 `world != 0`(`3A/9177`), 배치/그림은 `world >= 2`(`3E/CBAD`, `3E/DE63`)로 분기한다. 월드 바이트 256값 × 맵 ID 256값 **65,536조합**을 원작과 대조했다. 따라서 세 가지 선택 조합 × 256 ID = **768개 로드 프로필**을 검사한다. 이것을 실제 플레이 가능한 지역 768곳이라고 세지 않는다. 비어 있는 항목이나 정상 진행 도달성이 확인되지 않은 조합도 포함된다. 기존 등록부의 512개 동순서 표 연결은 저장 슬롯 기준이며, 이 런타임 선택 계약으로 보완한다.

### 삭제하지 않은 교차 참조

일반맵 그림으로 등록된 영역은 파일 `$6010..CC0F`다. 일부 그림 묶음은 `$CF10..D00F`도 256바이트씩 읽는다. 등록부에서는 적 마법 프레임 영역에 속하는 구간이다. 원작의 실제 PPU 전송까지 대조했으므로 이 특정 겹침을 보존한다. 그 사이의 다른 포인터/스크립트 영역을 일반 그림으로 무제한 허용하지 않는다. 잘못된 `$CC10` 참조를 주입한 검사도 거부한다.

또한 768개 프로필 중 3개는 메타타일이 배경 패턴 112 이상을 선택한다. 기존 동굴 추출기의 112패턴 가정만으로는 이 조합을 표시할 수 없다. 원작 로더처럼 뒤의 144패턴도 공급했다. 여기에는 일본어 문자 그림이 있지만 **한글 UI를 일본어로 대체한 것이 아니다**. 아직 문자 엔진으로 소비하지 않는 원작 배경 패턴이고, 별도 한글 토큰/글꼴 공급이 다음 작업에 필요하다.

## GBC 저장·조회·상주·표시

- 자산 종류/ID별 5바이트 핸들: ROM 은행 1바이트, 은행 내 오프셋 2바이트, 길이 2바이트. 디렉터리는 은행 12, 데이터는 은행 16 이후에 배치한다. 자산 하나가 16KiB 은행을 가로지르지 않는다.
- 총 **1,862자산**, 실제 페이로드 382,336바이트, 디렉터리 9,310바이트다. 슬롯의 중복 데이터도 현재는 보존한다. 이번 검사 ROM은 64은행/1MiB이며 MBC5의 하위 8비트 은행 범위 안에 있다.
- `ff3_asset_open/read`는 고정 ROM에서 동작한다. 은행 포인터를 외부에 반환하지 않고 WRAM 핸들/버퍼를 사용한다. 종류/ID·코드 은행·구간 초과를 거부하고, 읽은 뒤 호출자의 은행을 복원한다. 핸들은 WRAM에 보관해야 하며 IRQ에서 사용하지 않는다.
- `ff3_map_display`는 은행 11이다. 필요한 맵과 메타타일/속성만 작업 공간에 유지하고, 그림은 16바이트 단위로 VRAM에 전달한다. 모든 맵을 WRAM/VRAM에 상주시킬 필요가 없다.
- 작업 공간은 **`$D000..D7EE` 2,031바이트**다. 맵 1,024바이트 뒤의 7바이트는 기존 필드 이벤트 구조와 맞게 예약했다. 메타타일·타일 속성·팔레트·행/그림 버퍼도 이 안에 들어간다. `$D7EF`는 비워 두고 `$D7F0..D7FF` 가드와 기존 스택 경계를 보존한다. SVBK는 1이다. 이는 구조 호환 예약이며 기존 이벤트 실행기를 새 표시기에 연결했다는 뜻은 아니다.
- 160×144 화면은 20×18개의 8×8패턴으로 구성한다. 부호 있는 배경 패턴 주소 방식을 사용하여 ID 0..127을 `$9000..97FF`, 128..255를 `$8800..8FFF`에 올린다. [Pan Docs Tile Data](https://github.com/gbdev/pandocs/blob/master/src/Tile_Data.md), [Tile Maps](https://github.com/gbdev/pandocs/blob/master/src/Tile_Maps.md)
- 현재 로드/카메라 재구성은 화면을 끈 상태에서 수행한다. 기존 사운드용 분할 VRAM 업로드와 아직 합치지 않았다. 이 검사 ROM의 무음 재로딩을 실제 게임의 맵 전환 성능으로 세지 않는다.

## 사용법

```powershell
node tools/build-maps.mjs --rom "D:/private/Final Fantasy III (Japan).nes" --gbdk "D:/tools/gbdk"
node tools/build-maps-verifier.mjs
node tools/verify-maps.mjs
node tools/verify-maps.mjs --negative
npm test
```

출력: `build/maps/ff3-map-viewer.gbc`. A/B는 맵 ID 증감, SELECT는 선택 조합 0/1/2 전환, 방향키는 검사 카메라 이동이다. 원작 메뉴나 플레이어 조작을 흉내 낸 UI는 추가하지 않았다. ID·출처·해시는 `build/maps/catalog.json`에서 확인한다. 녹음하지 않는다.

검증기는 `local.json`의 고정 MesenCore/.NET 경로를 사용한다. 새 `.local/mesen-maps-*` 홈에서 실행하며, `evidence/maps/`에 원시 관측과 결과를 남긴다. `--reuse`는 같은 ROM/코어 해시와 동일 요청 목록의 기존 관측만 다시 검사한다. 외부 조작은 실제 로드 요청 전 입력 파라미터 설정에만 사용하며, 정답 타일이나 팔레트를 GBC 메모리에 주입하지 않는다.

## 검증 결과와 다음 경계

원작 대조는 레이아웃 256, 그림 48, 지형 7, 팔레트 512, 선택 입력 65,536조합을 통과했다. GBC에서는 768프로필에 카메라 네 모서리/홀수 좌표, 높은 패턴 ID, 월드 255, 잘못된 카메라, 재로딩을 더해 **813요청**을 검사한다. 활성 맵·속성·지형 속성, VRAM 그림/타일맵/속성, 팔레트, 은행 복원과 메모리 가드를 직접 읽는다. 잘못된 카메라는 기존 상주 데이터와 화면을 바꾸지 않아야 한다.

8개 캡처는 원본에서 계산한 픽셀과 대조한다. PNG 비교는 고정 Mesen의 기본 CGB 색 보정 행렬을 명시적으로 적용하며, 실기 색의 기준으로 삼지 않는다. 한 캡처는 원본이 선택한 빈 배경이다. 독립 에뮬레이터/실기 화면 검증은 아직 남는다. 디렉터리의 은행을 코드/비할당 영역으로 훼손한 ROM은 명시적 오류로 실패해야 한다.

최종 작업 공간 버전에서도 **813요청, 768프로필, 7지형, 경계 오류 5종, 캡처 8장(184,320픽셀)** 검사를 통과했다. 별도 디렉터리 훼손 ROM도 오류 2로 거부했다. 모든 요청에서 은행 복원·SVBK 1·16바이트 작업 공간 가드를 확인했고, 단위/회귀 검사 20개도 통과했다.

공개 허용 목록의 소스 121개만 별도 폴더에 복사하고 비공개 입력 경로를 제공해 재빌드했다. 맵 검사 ROM은 바이트 단위로 일치했고, 기존 필드/사운드 통합 ROM도 이전 결과와 동일했다. 원본 ROM·추출 자산·번역·관측/캡처는 공개 패키지에 포함하지 않는다.

| 결과물 | SHA-256 |
|---|---|
| 맵 검사 ROM | `7989e6b8ca39cc5ded2a38a273022280018e20a0be77b9713736997d9f19e9b3` |
| 디렉터리 훼손 검사 ROM | `f0131ecd0cc6d0a5a10a74e262f85bf6787eff3003fef77054f3818979f10d8d` |
| 기존 필드/사운드 ROM | `5ec1a1803d11b76bdc15518d93326179e7d2599a427c81b241497f3f26dba306` |

고정 ROM 사용 끝은 `$08D7`, 고정 WRAM 정적 영역 끝은 `$C0BC`, 맵 코드 은행 11은 861바이트다. 이 수치는 독립 맵 검사 ROM의 예산이며 전체 게임을 통합한 사용량으로 해석하지 않는다.

다음은 같은 자산 조회 계약 위에 **일반맵 객체 배치·캐릭터 그림/포즈와 문자열/제어 코드 공급**을 연결하는 일이다. 전체 월드행 자산 공급, 한국어 토큰·7×7 글꼴/이름, 창/선택 표시도 각각의 소비 계약을 확인한다. 이후 원작 맵 초기화·이동·이벤트가 공통 상태를 읽게 연결한다. 보상/포션/메뉴 규칙을 임의로 만든 시제품을 기반으로 사용하지 않는다.
