# PR 15까지의 회고

2026-11-23. 판정: **원작 데이터와 공통 실행기를 옮긴 방향은 적절하다. 기존 결과는 계속 사용한다.
다만 같은 순서로 탐색 기능만 늘리지 않고 메모리·표시 위험과 전투 계산을 앞당긴다.**

## 기준과 조사 범위

기준은 PR 15 병합 커밋 `aeeedf69c071a597c06237c0e6ebcb0ce6440264`이며,
당시 [로드맵](https://github.com/hungrysanta-ksc/game-patch-gbc/blob/aeeedf69c071a597c06237c0e6ebcb0ce6440264/games/final-fantasy-3-gbc/docs/implementation-roadmap.md),
PR 1–15 이력, 공개 소스/기능 문서, 로컬 빌드 보고서와 검증 결과를 대조했다.
이번 작업은 회고와 계획 갱신이다. ROM 실행을 새로 수행하거나 원작 모든 함수의 의미를 다시 증명한 것은 아니다.
`create-kr-patch`의 기준선/증거/판정 구분, `nes-reverse-engineering`의 원작 소비 코드 대조,
`gb-hardware-research`의 메모리·표시 제약 검토를 프로젝트의 [스킬 적용 규칙](development-skills.md)에 맞춰 사용했다.

기존 로드맵은 단계 1/3에서 최악 전투 자산·밀집 NPC를 조기에 확인하고, 단계 4부터 전투 계산을
호스트에서 시작하도록 했다. 실제로는 PR 4 뒤 11개 PR이 자산/한글/탐색 쪽으로 이어졌다.
각 PR은 유효했지만 프로젝트 전체의 위험 분산은 계획보다 늦어졌다. 기존 코드를 폐기할 이유는 없으며,
**누락된 위험 검증과 공통 규칙 작업을 현재 실행 가능한 기반 위에 올리는 것**이 개선이다.

## 확인한 위험과 결정

### A. 고정 WRAM 여유와 모드 전환

[PR 15 기록](event-motion.md)의 정적 WRAM 끝은 `$CFCA`다. `$D000`까지 **54바이트**가 남는다.
이는 GBC 전체 RAM 잔량이 아니다. 현재 `$D000` 창에는 맵/영상 작업 공간과 스택 등이 있고,
추가 WRAM 은행은 현재 실행기에 통합되지 않았다. `src/exploration.h`의 탐색 상태는 76/80바이트,
스택 예약은 848바이트다. GameState도 1,024바이트를 유지한다.

따라서 동행/전투 상태를 고정 영역에 계속 덧붙이는 순서는 위험하다. 탐색·메뉴·전투의 생존 기간을
나누고 은행/공유 작업 공간·스택·IRQ의 소유권을 먼저 설계한다. 스택이 은행 창에 있는 채로
SVBK를 바꾸는 식의 단순 확장은 허용하지 않는다. 기존 [플랫폼 문서](platform-foundation.md)는
초기 PR의 배치 기록이므로 최신 링크 맵의 대체 자료로 쓰지 않는다. 개선 계획 R1로 승격한다.

### B. 밀집 객체와 전투 자산 예산

[객체 검사](field-objects.md)는 1,624,320개 전체 표시 진단 위치 중 OAM 초과 592개,
한 줄 초과 45개를 검출했다. 최대 48개/줄당 12개이며 두 실패 집합은 겹칠 수 있다.
초기 플래그를 적용해도 world 1/2, map 86/87, camera (16,2)는 실패한다.
후반 월드에 초기 플래그를 적용한 상태의 실제 도달성은 미확인이다. 진단에서 발견됐다는 이유로
무시할 수도, 전부 정상 플레이 결함이라고 단정할 수도 없다.

실패 시 OAM을 비우고 오류를 내는 것은 올바른 검출이지만 제품 표시의 해결은 아니다.
PR 15 경로의 줄당 최대 6개도 이 문제를 닫지 않는다. 실제 공존 조건·플레이어/동행을 포함한
예산과 큰 보스/무기/마법/한글의 동시 자산을 R2에서 조사한다. 8×16 병합은 위/아래 색과
우선순위까지 보존할 수 있는지 확인한다. 아군 얼굴 축소·NPC 누락·깜박임을 승인 없이 채택하지 않는다.

### C. 스트레스 검사와 정상 게임 호출의 간격

`tools/text-audio-assets.mjs`와 `native-plan.mjs`의 요청 순서는 개발용 부하 입력이다.
실제 원작 음악/효과음을 해석하고 GBC APU에 쓰는 검증은 유효하지만, 게임 이벤트가 원작 조건에서
동일한 요청을 만드는 것까지 증명하지 않는다. `src/npc-dialogue.c`의 현재 이벤트 명령군에는
음악 요청 F8, 맵 전환, 전투 요청 등의 소비자가 아직 빠져 있다.

탐색 부팅은 `src/audio-native.c`에서 수동 모드 `start(0)`와 맵 곡 요청을 사용한다.
검증기가 `native_request=255`로 자동 부하 순서를 켠다. 따라서 7,200틱 검사를 근거로
“게임이 7,200틱 뒤 자동 종료된다”고 해석해서도 안 된다.
R4에서 정상 이벤트/맵 조건→사운드 요청을 연결하고 스트레스 검사와 별도로 검증한다.

### D. 진단 빌드와 제품 통합의 간격

저장 함수의 3슬롯 재시작 복원은 [독립 상태 ROM](state-save-rng.md)에서 검증했다.
현재 탐색 빌드는 `tools/build-text.mjs`의 MBC5 타입 `0x19`이며 `game-save.c`를 링크하지 않는다.
탐색에 저장 메뉴와 SRAM이 연결됐다고 계산할 수 없다. 한글 이름의 입력/저장 계약도 남았다.
R5에서 모드 전환과 같은 GameState를 공유하는 실행 경로에 통합한다.

공개 허용 소스 190개로 일곱 진단 ROM을 동일하게 재빌드한 것은 좋은 재현 증거다.
일곱 개가 하나의 완성 게임이라는 뜻은 아니다. 현재 한글 빌드에는 비공개 번역·검수 대응표·폰트가
추가로 필요하다. ROM만 제공하는 최종 사용자가 어떤 허용 입력으로 한글판을 만들지의 공급 계약은
출시 전 해결해야 한다. 비공개 입력을 저장소에 올리는 방식으로 해결하지 않는다.

### E. 계획과 완료 기준 관리

기존 로드맵은 완료 내용을 계속 덧붙여 처음의 “다음은 등록/기반”과 마지막의 “다음은 동행”이 공존했다.
제품 정책의 다음 작업도 초기 사운드 단계에 머물렀다. 현재 우선순위는 로드맵으로 통일하고,
PR별 문서는 과거 결과로 남긴다. 슬롯·지원 명령·검사 수를 전체 완성률로 쓰지 않는다.
원격 자동 체크가 없는 PR에서 로컬 검증을 원격 CI 통과라고 표현하지 않는다.
