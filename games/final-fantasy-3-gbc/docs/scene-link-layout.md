# 필드·전투 공통 ROM/RAM 배치

2026-11-27. 기준은 PR 105 병합 `bc2269ec0784e1c3fc68e12ba2bd6e6abddd3cde`.
이 단계는 실제 탐색·전투 모듈과 자산을 한 ROM에 링크하고, 같은 바이너리의
별도 부팅에서 기존 표시·오디오 회귀를 실행한다. **자연 조우부터 복귀하는
같은 부팅의 게임 진행은 아직 아니다.** 다음 관문을 위해 배치 충돌을 먼저 없앤다.

## 원작 소비자와 선택한 구조

- `3F/FB17`의 문맥 보존은 sound DP `$D0..DF`를 제외하고 `3F/F83B`가 복구한다.
  표시 문맥을 저장하더라도 진행 중인 오디오를 이전 시점으로 되돌리지 않는다.
- `3F/FAB5,FADD`는 IRQ 표시 디스패치를 교체한다. 기존 공통 `scene-video` 경계로
  전송·OAM·LCD 콜백을 먼저 비운 다음 장면 RAM의 주인을 바꾼다.
- `3F/E7EC`의 새 맵 진입과 `E7F8`의 전투 복귀는 다르다. 복귀는 `E811`의 NPC
  초기화를 건너뛴다. GBC도 복귀 때 `field_init`으로 다시 만드는 방식은 사용하지 않는다.
- `3E/C049`의 가방 전달과 전투 결과는 지속 상태의 문제다. 정본 GameState는
  저장 이미지 밖에 두어 전투에서 바뀐 HP·가방·이벤트가 복귀로 취소되지 않게 한다.
- `3F/E1E1..E201`의 필드 루프는 표시 갱신 주변에서 사운드를 진행한다.
  공유 오디오 서비스는 현재 활성 장면의 요청만 읽고 비활성 DATA는 읽지 않는다.

직전 무수정 합친 링크는 고정 RAM 897B, 고정 ROM 3,131B를 초과하고
자산 뱅크가 겹쳤다. 자산이나 도트를 삭제하지 않고 **수명이 겹치지 않는 장면 DATA를
같은 주소에 배치**하고, 초기화·기존 진단 main을 ROM 뱅크로 옮겼다.
상주 IRQ·전송·공통 상태는 유지한다.

GBC의 고정 WRAM `C000..CFFF`, 뱅크 WRAM `D000..DFFF` 제약은
[Pan Docs](https://raw.githubusercontent.com/gbdev/pandocs/master/src/Memory_Map.md)를 따른다.
뱅크 코드 호출은 [GBDK 문서](https://gbdk.org/docs/api/docs_rombanking_mbcs.html)를
참고하되 실제 프로젝트의 고정 GBDK 4.5.0으로 링크·실행했다.

## 배치와 보존 범위

| 영역 | 소유자·수명 |
|---|---|
| 고정 RAM 앞부분 | GameState, 오디오 엔진·큐, 텍스트 전송, 장면 경계, 초기값 있는 전역 |
| `CA80`부터 | 필드 DATA / 전투 DATA 중 활성 장면 하나 |
| WRAM1 `D000..DBFF` | 활성 장면 작업 공간; 전투 동안 필드 사본은 WRAM7 |
| WRAM1 `DC00` 이후 | OAM·가드·스택; 필드 보존 이미지에서 제외 |
| WRAM2 | 기존 오디오 진단 스냅샷 |
| WRAM3/4 | 기존 전투 동결·마법 상주 자원 |
| WRAM7 | 필드 DATA + `D000..DBFF`의 완전한 사본 |

필드 DATA에는 NPC·이벤트·창 상태도 포함한다. 현재는 문맥 최소화보다 정확한
보존을 우선한다. 전투 DATA는 초기 진입 전에 0으로 지우고 필드 복귀 시 저장된
바이트를 되돌린다. 초기값 있는 전역은 공통 영역에 남으므로 향후 재진입 초기화에서
각 변수의 기본값을 명시해야 한다. VRAM과 OAM은 재구성이 필요하며 RAM 복원만으로
그림을 다시 게시하지 않는다. heap 함수가 링크되면 겹침 위험 때문에 빌드를 거부한다.

저장/복구는 기존 16B WRAM 전송 경계를 쓰고 64B마다 오디오 생산 기회를 준다.
다른 표시 소유자, 미완료 전송, 열린 Window, 중복 진입·잘못된 복귀는 거부한다.
오류 뒤 부분 복원 상태에서 성공한 것처럼 계속하지 않는다. 저장 뱅크를 덮어쓰는
기존 파괴적 메모리 진단도 통합 빌드에서는 명시적으로 거부한다.

필드의 기존 ROM 16..51은 80..115로 옮겼다. 2,726개 생성 디렉터리 항목의
뱅크 바이트만 바뀌고 offset/length와 36개 전체 payload는 그대로다. 전투·오디오
123개 생성 배열도 링크 후 정확한 바이트를 비교한다. 기존 field main은 72,
battle main은 73, 공통 cold 초기화·메모리 경계는 74, 제어 진단은 75에 둔다.
필드 main과 boot는 실행 중 자기 ROM 뱅크를 1로 바꾸지 않도록 분기한다.

## 실행 방법과 검증 범위

원본 ROM·번역·생성 자산은 로컬 전용이다. 먼저 기존 `build:exploration`과
`build:battle-effects`를 실행하고 다음을 사용한다.

```text
npm run build:scene-layout
npm run verify:scene-layout
npm run verify:exploration-scene-layout
npm run verify:battle-effects-scene-layout
npm run verify:battle-magic-scene-layout
```

현 개발 빌더는 두 진단의 생성 자산·보고서를 입력으로 사용하며 최종 배포 빌더가 아니다.
입력 ROM/컴파일러, 모든 런타임 C와 헤더·include·생성 입력의 해시, 배치, 최종 ROM을
로컬 `build/scene-layout/report.json`에 기록한다. 원본 ROM만으로 최종 제품을 만드는
배포 패키지는 별도 제품 관문이다.

`state_start=1`은 64회 저장→다른 장면 바이트 덮어쓰기→복원으로 문맥과 GameState
변경의 공존을 검사한다. `2`와 `3`은 같은 ROM에서 각각 실제 필드/전투 표시기를
처음부터 실행한다. 따로 부팅한 두 결과를 실제 게임 왕복이라고 합산하지 않는다.

통합 ROM SHA-256:
`ddd7ac52714d20e226374e73d98bbfbe98992534afba10aa1a0e539799e97ea1`.

통합 중 실제로 발견하고 수정한 문제:

- `FF3_EXPLORATION` 컴파일 정의가 전투의 진단 오디오 시작도 필드 설정으로
  바꿨다. 현재 표시 소유자에 맞춰 시작한다. 향후 실제 게임 진입에서는 이 시작 함수를
  장면마다 다시 부르지 않고 원작 음악 요청만 전달해야 한다.
- 공유 오디오가 비활성 필드/전투 DATA를 읽거나, 필드 업로드가 전투의 캐시 변수를
  지우지 않도록 소유자별 접근을 제한했다.
- 초기 필드 실행의 timer drift 범위 585.6μs는 기준을 초과했다. 타이머 쓰기와
  OAM/스크롤 버스 기록으로 4,204 master-cycle 간격을 찾았다. OAM DMA 뒤 대기 중인
  타이머를 첫 배경 행보다 먼저 처리하여 두 edge의 합쳐짐을 막았다. 전송량은 같다.
- 이동 검증이 `speed=0`과 타일 좌표 갱신 사이에 멈춰 미완료 값을 읽었다.
  정확한 목표 좌표와 정지 상태를 함께 기다린다. 실제 이동 규칙은 변경하지 않는다.
- 기존 독립 필드는 다른 오디오 빌드 설정으로 약 67ms의 표시 정체가 나타났다.
  실제 스크롤 쓰기 관찰을 추가하여 표본 오차가 아니라는 것을 확인하고, 통합/전투에서
  이미 쓰는 `FF3_AUDIO_FAST` 경로를 독립 필드에도 적용한다. 원작 고정 음원 뱅크의
  직접 읽기와 기존 변환 경로의 상수화이며, 선행량·명령·출력 패킷은 줄이지 않는다.
  검증에는 기존 표본 간격 기준을 그대로 두고 실제 버스 간격 기준도 추가했다.

숫자와 마법 검사에서 잘못된 VRAM/OAM 접근, 상주 자원·동결 지도·원본 도트
불일치는 없다. 이 수치는 해당 대표 소비자 범위이며 소환·특수 경로 전체의 통과가 아니다.
고정 RAM/ROM 여유가 작으므로 후속 기능은 같은 링크의 예산 검사 없이 추가하지 않는다.

독립 필드의 최종 회귀도 7,194관측·12장·7,200오디오 틱을 통과했다.
실제 화면 최대 간격은 66.971→50.261ms, 오디오 생산 최장 점유는
39.873→29.992ms, 준비→실제 SCX는 최대 30.643ms다. 기존 표본 기준과
추가 버스 기준을 모두 통과하며 timer drift 범위는 356.197μs다.
독립 필드 ROM은 `7b22f664d35b3b9a30ac6c7fee280f34c0541a1578287e6f7d80574b2f4b9631`.
독립 전투 ROM은 PR 105의 `bcafef68c82502bbf5ea7898264ccd35ddad3f8a1a7882f36badafadbf959895`
와 바이트가 같다. 최종 독립 입력으로 통합 빌드를 다시 실행해 위 통합 ROM 해시가
그대로 재현됨을 확인했고 216개 빌드 입력 해시도 다시 대조했다.

## 다음 관문

1. 원작 일반맵의 자연 조우/복귀 실행에서 지속되는 NPC·이벤트 문맥을 관찰한다.
2. 기존 두 main의 부팅 초기화와 장면 진입/프레임/퇴장을 분리하고, 한 번만 초기화한
   오디오·GameState를 유지한 채 공통 표시 경계와 RAM 보존을 연결한다.
3. 실제 현재 파티/편성 공급, VRAM/OAM 재구성·캐시 무효화를 연결하고 같은 부팅의
   두 번째 진입 및 복귀 후 이동·대화를 검사한다. 진단 중단을 승리·보상으로 치환하지 않는다.

석화/보스/아이템 atlas 등의 다른 진단 변형은 이 통합 ROM에 모두 포함된 것이 아니다.
이들의 추가 자원 수명도 같은 계약에 대조해야 한다. 정상 전투 전체, 제품 출시,
음질 청취 승인과 구분하며 R2 0/8·제품 0/3을 유지한다.
