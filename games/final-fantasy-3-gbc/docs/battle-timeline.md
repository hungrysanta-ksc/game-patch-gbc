# 원작 마법의 준비와 표시 시계

2026-11-24. 기준: PR 25 병합 `a5266d1c8c22f97dddb32b145bca4b849232fbd2`.
[이전 전투 합성](battle-composition.md)의 유한 표본에서 다음 그림 준비와 표시 시점을 분리한다.
적 6·정상 자세 직업 0/1/2/3·마법 스크립트 29의 진단이며 정상 전투 호출자 구현은 아니다.

```powershell
npm run build:battle-timeline
npm run verify:battle-timeline
```

원본 ROM·고정 GBDK·비공개 번역/대응표·7×7 글꼴로 `build/battle-timeline/ff3-battle-timeline.gbc`를
만든다. 고정 MesenCore/.NET 검증기는 자동 재생 요청 5와 한글 창 열기/넘기기/닫기를 반복한다.
요청 후 개별 프레임을 외부 도구가 밀어 넣지 않는다. 실제 화면과 원시 관측은 로컬에만 남긴다.
한글 창은 기존 검수 본문 7의 두 페이지를 부하 입력으로 쓴다. 전투 대사로 지정한 문장이 아니다.

## 원작 순서와 이식 경계

원작 `33/B6F3`의 비반사 피격 루프 전체를 실행한다. 하드웨어 대기 `3F/F8C5`와 `3F/F8B0`만
호스트 관측 경계로 바꾸고 그 시점의 OAM을 수집한다. `33/B7A9`의 네 번 대기를 포함해
`13,13,14,14,15,15`의 24회 대기와 `33/B70B` 효과 지우기 이후 한 번의 대기를 확인한다.
여섯 그림의 OAM은 앞서 개별 소비자로 얻은 OAM 해시와 같고, 마지막 지우기는 아군을 유지한다.
대기 횟수나 OAM이 달라지면 빌드가 실패한다. 반사/다중 대상/Life 분기는
여기서 일반화하지 않는다. 원작의 사운드 pending 쓰기도 실행하지만 GBC 전투 효과음 호출자에
연결하지 않는다. 기존 필드 음악·효과음·페이드 부하는 독립된 회귀 일정이다.

| 엔트리 | 그림 | 시작 NES 프레임 | 시작 타이머 틱 |
|---|---:|---:|---:|
| 0 | 13 | 0 | 0 |
| 1 | 13 | 4 | 273 |
| 2 | 14 | 8 | 546 |
| 3 | 14 | 12 | 818 |
| 4 | 15 | 16 | 1091 |
| 5 | 15 | 20 | 1364 |
| 6 | 효과 지우기 | 24 | 1636 |

기존 원작 논리 시계인 60.0988Hz와 4096Hz 타이머로 절대 기한을 계산하며 일찍 표시하지 않도록
올림한다. 동일 그림의 엔트리도 생략하지 않는다. 끝점은 첫 효과 게시에서 24 NES 프레임 뒤의
지우기 게시다. 원작 CPU 명령 실행 비용/PPU 사이클을 에뮬레이트한다는 의미는 아니다.

GBC 화면 주기는 NES와 다르므로 원작 논리 시점 이후 처음 사용 가능한 VBlank에 게시한다.
고정 4 GBC 프레임씩 더해 오차를 누적시키지 않는다. 사양 근거는 Pan Docs의
[화면 주기](https://raw.githubusercontent.com/gbdev/pandocs/master/src/Rendering.md)와
[OAM DMA](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM_DMA_Transfer.md)다.
웹 403/curl DNS 실패 후 같은 문서의 GitHub 원문을 사용했다.

## 준비·전송·게시

기존 BG 80타일을 상주시킨다. 마지막 효과 지우기는 기존 타일 조합을 재사용하므로 타일 수가 늘지
않는다. 현재 그림을 보여 주는 동안 비활성 지도/OBJ 영역에 다음 **달라지는** 그림을 준비한다.
준비된 엔트리와 페이지를 고정 WRAM에 게시하고, 원작 기한을 확인하는 고정 ROM VBlank 코드가
그림과 OAM을 함께 바꾼다. 준비 실패는 `scene_error=13`으로 중단하며 속도를 늦춰 숨기지 않는다.

VBlank에서는 대기 중인 전송을 먼저 수행하되 게시 기한이 된 프레임은 통째로 게시에 양보한다.
이 순서 변경은 이 진단 빌드에만 적용한다. DMA는 계속 128바이트 이하이고 작은 전송 사이에는
타이머 IRQ를 허용한다. GBDK의 기본 OAM DMA가 사용자 콜백보다 앞서 실행될 수 있으므로
실제 교체 시에는 IME를 끈 채 HRAM의 `.refresh_OAM`을 실행해 새 BG와 같은 프레임에 반영한다.
GBDK 4.5.0의 C 함수 `refresh_OAM()`은 기본 `$C000`을 읽으므로 여기서는 사용할 수 없다.
[고정 버전 crt0.s](https://raw.githubusercontent.com/gbdk-2020/gbdk-2020/4.5.0/gbdk-lib/libc/targets/sm83/gb/crt0.s)의
선택형 HRAM 진입점을 사용하고, 링크된 점프 바이트/포인터 주소 및 실제 DMA 소스와 IME를 검사한다.
교체 직후 첫 프레임도 캡처해 한 프레임의 보조 OBJ 누락을 잡는다.

일곱 BG 팔레트/네 OBJ 팔레트가 전 엔트리에서 같은지 빌드가 검사한다. LCD를 끈 최초 부팅에서
한 번만 적재한다. 한글 창은 BG 팔레트 7만 사용하므로 재생을 시작할 때마다 다시 쓰지 않는다.
실행 중에는 LCD를 끄지 않는다. 모드 전환에서 팔레트를 다른 시스템에 넘기는 계약은 후속 과제다.

검증기는 원작 기한과 실제 VBlank 콜백 진입/게시를 읽기 전용으로 관측한다. 처음 기한을 만족한
콜백에서 정확히 한 번 게시했는지, 게시 작업이 한 VBlank 안에 끝났는지, 다음 그림이 원작
기한 전에 준비됐는지를 따로 검사한다. 표시 시각의 허용 경계는 한 화면 주기+VBlank 내 게시
비용+타이머 한 틱이며 관측된 오차도 기록한다. 이전 PR의 동기 요청 완료 시간과 다른 지표다.
모든 엔트리/별칭/지우기와 타이머 순환을 검사하며 처음 두 재생의 각 엔트리도 실제로 캡처한다.
프레임 캡처를 위한 추가 게임 시간 대기를 넣지 않는다.
에뮬레이터의 순환 로그 버퍼가 덮이기 전에 각 디버거 정지점에서 기록을 회수한다. 완료 요청 수와
관측된 전체 엔트리 수가 맞아야 성공하며, 로그 누락을 프레임 생략이나 성공으로 처리하지 않는다.

## 최종 검증

고정 MesenCore에서 원작 오디오 7,200틱 동안 84회 자동 재생,
588개 엔트리/지우기를 관측했다. 다음 그림 준비 실패 0회이고, 모든 엔트리가 원작
기한을 만족한 첫 VBlank에서 게시됐다. 원작 시점 대비 실제 게시 오차의 최댓값은
**2.904ms**, 게시 콜백 작업은 최대 0.648ms다.
다음 변경 그림은 원작 기한보다 최소 31.494ms 먼저 준비됐다.
엔트리 사이 관측 간격은 66.516–67.582ms다.
타이머 한 바퀴(16초)를 넘는 실행이며 논리 기한은 16비트 순환 후에도 절대 간격을 유지했다.
이 수치는 이 표본의 측정값으로, 모든 마법/편성의 시간 보장이 아니다.

초기 준비와 여섯 엔트리 재생/지우기를 모두 포함한 요청은 중앙값 519.332ms·최대 602.856ms다.
이 전체 재생 시간은 위의 게시 오차와 구분한다. 한글 창 열기는 중앙값/최대 351.665/519.111ms,
다음 페이지는 318.176/418.637ms, 닫기는 16.743/33.606ms다. 창 응답 개선은 여전히 남아 있다.
84회 재생 후 창 열기/넘기기와 83회 닫기·재진입을 관측했으며, 마지막에는 오디오 일정이 끝나
열린 창의 두 번째 페이지에서 검사가 종료됐다.

실제 22장·506,880픽셀(처음 두 재생의 별칭/지우기와 한글 창)이 일치했다.
원작 이벤트 21,366개와 실제 APU 쓰기 30,938개를 대조했다.
음악/효과음 지연·큐 부족, 잘못된 영상/DMA 접근, 활성 타일 덮어쓰기, 메모리/스택 가드 오류는 0건이다.
OAM DMA 7,494회의 소스·VBlank·IME도 확인했다.
오디오 타이머 편차는 0.070ms다. 고정 WRAM 끝은 $CE07
(여유 505바이트), 관측 스택 미사용은 286바이트다.

전체 호스트 49테스트가 통과했다. 원작 대기를 4→3으로 바꾼 입력, 엔트리 누락, 준비 지연,
기한을 만족한 VBlank 누락을 거부하는 검사와 타이머 순환 조건을 포함한다. 공개 소스 276개만
별도 디렉터리에 복사하고 비공개 원본/번역/글꼴·고정 도구를 외부 경로로 참조한 빌드에서도
ROM과 빌드 보고서가 동일했다. 그 복사본의 새 호스트 2테스트와 공개 목록 검사도 통과했다.

기존 전투 합성/탐색·한글 창 ROM은 재빌드 시 각각 PR 25/PR 23의 해시와 같았다. 기존 관측을
새 검증기로 다시 판정한 회귀이며 기존 경로의 새 에뮬레이터 실행으로 세지 않는다. 새 시간 경로의
실제 실행은 위 해시와 관측에 연결된다. 독립 에뮬레이터/실기 및 최종 배포 계약은 남아 있다.

## 남은 범위

이 결과는 고정 표본의 시간/전송 경계를 확인한다. 전투 계산, 공격/마법 호출자, 지형/메뉴,
모든 자세/다중 대상/반사/특수 연출 및 정상 필드 복귀는 아직 아니다. 아군 크기/픽셀을 유지하고
적의 7/8 축소는 계속 후보로 둔다. 모든 편성×직업×자세를 사전 합성하는 방식을 제품 설계로
채택하지 않는다. 다음은 보스 210·여러 적의 원작 편성에서 팔레트/변경량/메모리 상한을 확인하고
확장 가능한 자산 공급 조건을 정하는 것이다. 탐색 입력/월드와 모드 소유권도 남아 있어 R2와
제품 관문 0/3은 유지한다. 음질 개선은 후순위다.
