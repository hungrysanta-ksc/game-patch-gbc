# 원작 사운드 구조에 맞춘 행동 중 생산·보충

기준은 PR 78 병합 `1d615142a2b50fce4d6ac6d276d3a34eb15c9f22`, 효과 ROM
`24b1ceefcf97b8dd3fafd09b61906469734b602a34a288e05187d444d4a284eb`다.
프로젝트 `AGENTS.md`에 **모든 구현/최적화에서 원작 소비자·호출자·실행 관찰을
먼저 확인한다**는 지침을 명시했다. 음원뿐 아니라 UI/게임 규칙/로딩에도 적용한다.

## 원작과 유지할 구조

- `3F/FB52→FAF2..FB16`: 사운드 요청을 옮기고 사운드 은행으로 전환한 뒤 갱신,
  호출자의 은행/레지스터를 복원한다.
- `36/8003..802F`: 효과음 → 음악 → 효과음 APU 출력 → 음악 APU 출력 순서다.
  음악/효과음의 채널 점유, 곡 `$37` 예외와 상태 갱신을 그대로 유지한다.
- `36/820B..872C`, `8925..8B9C`: 원작의 8비트 채널 색인과 192바이트 상태 영역,
  악보·반복·엔벌로프·템포·페이드 순서를 사용한다. 원작 포인터는 계속 16비트다.
- `33/A389..A38B`: `$B6` 요청을 기록한 뒤 바로 그림을 준비한다. `33/AC35`도
  `$FF` 정지 요청 후 정리한다. 생산기 확인을 기다리는 별도 전경 루프는 없다.

GBC에서는 변환/소프트웨어 스윕/화면 전송과의 공존 때문에 전경 생산기와 타이머
소비 큐를 유지한다. 원작 논리 주기와 GBC VBlank를 같다고 간주하지 않는다.
기존 205타이머 틱 선행량과 화면 작업 중 136틱 양보 기준, 16칸 큐, 출력 시각,
스윕/노이즈 차용·복원 및 진단 해시는 유지한다. 음색 조정이나 채널 생략은 없다.
큐를 제거하고 원작처럼 전체 VM을 IRQ에서 실행하는 변경은 현재 검증 범위를 벗어나며,
화면 DMA와의 최악 공존을 입증하지 않은 상태에서 적용하지 않는다.

## 제거한 추가 비용

1. 보충 루프에서 `full()`과 양보 검사에 쓰던 원자적 시계 읽기를 하나로 합친다.
   큐 색인은 8비트로 비교하고, 작업 여부에 따른 205/136 중 한 기준만 비교한다.
   음수인 래핑 차이는 먼저 제외하므로 부호 있는 원래 조건과 같은 판정이다.
2. 단일 엔진의 제어부 내부 출력 헬퍼에서 사용하지 않는 상태/콜백 포인터 전달을
   없앤다. 공개 API와 일반 소비자의 다중 인스턴스 경로는 유지한다.
3. 채널 RAM 접근의 색인은 8비트로 제한한다. 가장 큰 오프셋은 `185+6=191`이고,
   공개 채널 함수는 0..6 범위를 먼저 검사한다. 음악/효과음의 초기화 루프도 원작
   상태 영역 안에 머문다. 주소 공간 전체나 악보 포인터를 8비트로 줄이지 않는다.
   고정 컴파일러에서 악보 명령 함수의 임시 스택은 63→35바이트로 줄었다.
4. 칼질의 효과음 요청은 비동기로 등록하고 화면 준비를 계속한다. 이전 요청이
   아직 있으면 먼저 인계하여 덮어쓰기를 막는다. 새 요청을 올린 뒤의 생산기 확인
   대기만 제거한다. 그 확인은 원래 실제 APU 재생 시각과도 같지 않았다.
   화면의 기존 오디오 서비스 지점과 IRQ 소비를 계속 사용한다.

변경은 `FF3_EFFECTS` 소비자에 한정한다. 효과음의 순서/횟수, 두 손의 정지 요청,
원작의 83장 게시와 59회 준비/24회 동일 화면 재사용을 모두 검증한다. 다른 무기나
마법을 연결할 때도 원작 요청 등록 경계와 화면 준비를 분리하며, 요청 덮어쓰기 방지는
공통 계약으로 유지한다. 아직 연결되지 않은 소유자의 동작을 완료로 세지 않는다.

## 계측 및 대조

읽기 전용 Lua로 원작 VM, 출력 변환, 패킷 구성, 메타데이터/해시, 보충 제어, 진단을
분리한다. IRQ는 별도로 빼고, 합계가 행동 전체 시간의 98% 이상인지 확인한다.
각 CALL과 반환 지점/해시 구간은 고정 컴파일러 listing과 실제 ROM 명령 바이트를
대조한다. 추측한 주소에 훅을 걸지 않는다. 실행 훅은 행동 구간에서만 설치한다.
이는 배타적인 에뮬레이션 경과 시간이며 순수 명령 실행 시간만을 뜻하지 않는다.

PR 78의 2,311.208ms 중 오디오 1,219.177ms는 VM 540.100, 보충 제어 283.859,
출력 변환 200.342, 패킷 133.552, 메타데이터/해시 61.325ms로 나뉜다. 행동 중
진단 스냅샷은 원래 억제되어 이 구간의 비용이 없었다. 해시를 없애서 빠르게 만든
결과가 아니다. 보충 검사만 줄인 중간안은 최대 간격을 줄여도 전체가 약 2.31초로
남았다. 전체 행동 시간을 같이 측정해야 하는 이유다.

```powershell
node tools/build-engine.mjs --effects
node tools/verify-native.mjs --engine --effects
node tools/verify-native.mjs --engine --effects --negative
npm run build:battle-effects
node tools/verify-battle-strike.mjs --auto --profile-producer
npm run verify:battle-strike
npm run verify:battle-strike-positions
npm run verify:battle-strike-numbers
npm run verify:battle-effects
npm test
```

기준 ROM은 `--auto --baseline --profile-producer --build-dir <baseline-directory>
--profile-listing <baseline-audio-native-profile.lst>`로 대조한다. 과거 ROM을 현재
소스의 listing으로 해석하지 않는다. `--reuse`는 저장된 실제 ROM 해시가 일치하는
관측만 다시 검사한다. 생성 listing/ROM/입력/캡처는 비공개다.

전체 엔진 대조는 65곡·97효과음 슬롯과 요청/페이드/템포 경계의 11,524틱,
95,940개 순서 있는 APU 쓰기다. 원작 RAM 192바이트와 APU 24바이트도 매 틱 비교한다.
곡별 전체 재생이나 모든 곡×효과음 조합의 전수 증명은 아니다. 실행기 일반 테스트와
실제 은행 전환/화면/소비 오디오 검증은 서로 다른 관문으로 유지한다.

행동 전체는 **5.80%**, 최대 게시 간격은 **30.22%** 줄었다. 오디오 합계는
1,219.177→1,044.768ms다. 짧아진 행동 구간에서 생산하는 틱/패킷 수도 달라지므로
VM 합계 감소를 그대로 한 틱의 속도 향상률로 해석하지 않는다. 출력 변환과 게시 대기는
오히려 늘었으며, 남은 비용을 숨기지 않는다. 원작 전체 속도 도달을 주장하지 않는다.
추가 RAM 없이 은행 8 코드는 `0x37EB→0x363B`로 432바이트 줄었고 고정 WRAM 끝은
`0xCEF1`로 같다. 기존 기본 `--windows` ROM은 바이트 단위로 동일하다.

- 83회 게시, 59회 준비/24회 동일 그림 재사용, 10회 효과음/정지 요청을 유지했다.
- 양손 368장·대상 위치 544장·무기→숫자 116장·숫자 회귀 198장, 총 1,226장을
  원작 OAM/타일/팔레트와 GBC 전체 화면 기준으로 검사했다. 도트와 숫자 생략은 없다.
- 자동/양손/위치/숫자 연결/숫자 회귀 각각 7,200오디오 틱의 실제 소비 해시를
  원작 VM과 출력 변환 기준에 대조했다. 부족·지연·가드 손상·잘못된 VRAM/OAM 접근은 0이다.
- 최적화된 엔진의 11,524틱·95,940 APU 쓰기 대조와 오류 주입 검사가 통과했다.
  호스트 검사는 173/173이다.
- 공개 허용 소스 586파일만 복사한 독립 디렉터리에서 효과/엔진 ROM·보고서 등
  9산출물이 바이트 단위로 재현됐다. 원본 ROM·번역·추출 데이터·관측은 공개하지 않는다.

## 남은 경계와 다음 작업

원작 전체 속도와 실제 소리·화면의 정밀한 위상 일치는 별도 관문이다. 기존 선행 큐의
요청→실제 출력 지연을 소급 수정하지 않는다. 정상 게임 입력·피해 계산·다른 무기·마법·
사망 통합, 음질/실기 승인은 아직 완료되지 않았다. 원작과의 구조 대조는 다음 작업에도
계속 적용하며, 이 최적화를 다른 시스템의 완성률 증가로 세지 않는다.
