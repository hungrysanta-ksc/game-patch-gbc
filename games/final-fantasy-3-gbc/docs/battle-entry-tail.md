# 보스 등장·상태 복원의 자원 실행기

2026-11-25, 기준은 PR 55 병합 `35c1a1fe9589ba7f6abb0c3cb8189e3c88ebc379`이다.
앞선 [등장 전반부](battle-entry-resources.md)의 `B479` 경계에서 이어 받아
`B909` 반환까지의 논리 상태, 원작 대기 순서와 필요한 패턴/맵 바이트를 이식했다.
두 C 소비자를 같은 GBC ROM에서 실제로 이어 실행해 원작과 비교한다.
**OAM 구성과 V6 VRAM 게시 어댑터는 아직 연결하지 않았다.**

## 원작 구조를 유지한 부분

| 경로 | 원작 소비자 | 이번 실행기의 작업 단위 |
|---|---|---|
| 보스 조건 | `2F/B479..B486` | 레이아웃 9이고 `$7D68` bit 6이 있을 때만 보스 등장 |
| 보스 등장 | `2F/BE97..BF92`, `A3B8,A40B` | 4타일/64바이트 블록을 7→0 픽셀 시프트로 8번 게시한 뒤 다음 블록. 짝/홀 픽셀 행은 서로 반대 방향. 소환 그래픽의 추가 반전도 유지 |
| 정규 진열 | `2F/B489..B4A3` | 원래 진열의 X/목적지로 복원하고, 백어택 OAM 반전을 허용하는 경계에서 대기 |
| 상태 그림 캐시 | `2F/B651,AA95..AB3C` | 그래픽 종류가 같으면 재적재하지 않음. 다를 때 해당 아군 OAM을 숨긴 뒤 64바이트 단위와 마지막 32바이트를 게시 |
| 혼란 이동 | `2F/B6AB,B3D9`, `33/BE9A` | B0 위치로 이동한 뒤 내부 상태 갱신, 혼란 위치 캐시 해제, 외부 상태 갱신. 같은 그림이어도 두 대기를 합치지 않음 |
| 석화·해제 | `2F/B72B,B6C8` | 아군별 2열 × 3/4행 맵만 갱신. 일반/개구리/미니 석화 표와 비석화 시 0으로 지우는 표를 구분하고 백어택 열 순서를 유지 |
| 완료 | `2F/B909` | 네 종류별 적 수와 전체 수를 원작 슬롯에서 계산한 뒤에만 DONE |

지형·적·아군을 완성 화면으로 합성하지 않는다. `battle-entry-tail.c`가 상태에서
다음 작업을 계산하며, 원작 표와 요청한 자원 블록만 사용한다. 실행 상태는 75바이트이고
블록 출력 버퍼는 최대 64바이트다. 보스가 256번 이상 대기할 수 있어 ticket은 16비트다.
틀린 ticket, 중간 재시작, 완료 후 승인은 상태를 바꾸지 않고 거절한다.

`Ff3EntryDisplay`는 화면 진행 상태다. 기존 전투 진입 규칙의 `Ff3Entry`와 이름이
겹치던 문제를 분리했고, 같은 C 검사 파일에서 두 헤더를 함께 컴파일한다.
전반부와 혼란 이동이 같은 `33/BE89` 이식 함수를 사용하도록 공유했다.
공유 함수의 banked 호출로 전반부 단독 검사 ROM의 bank 16은 1,569→1,594바이트로
25바이트 늘었다. 코드 공유가 자동으로 크기나 실행 시간 감소를 뜻하지 않으며,
통합 실행기의 뱅크 배치와 호출 비용은 다음 표시 어댑터 측정에 포함한다.

## 플랫폼 차이와 개선 판단

원작 `3F/F94F`는 반전 전송마다 256바이트 비트 반전표를 새로 만든다.
가장 큰 보스 자료의 백어택 조사에서는 후반부만 3,661,707개의 원작 명령을 실행했다.
이식 코드는 바이트의 비트 순서를 세 단계 연산으로 뒤집으며 표 생성과 해당 RAM 버퍼를
없앴다. 행별 이동·반전 순서와 최종 바이트는 그대로 대조했다.
이는 불변 표 생성의 중복을 제거한 것이며, 서로 다른 CPU의 명령 수를 시간 비율로
환산하거나 GBC가 몇 배 빠르다고 주장하지 않는다.

캐시 적중 시 재적재 생략, 4타일 블록의 수명, 석화 맵의 작은 갱신 범위는 원작 구조를
유지했다. 모든 보스 시프트 그림을 미리 저장하는 방식은 채택하지 않았다. 반전 표를
ROM에 상주시켜 조회하는 대안도 가능하지만, 최종 실행기와 함께 CPU/뱅킹 비용을
측정하기 전에는 추가 ROM 자료가 더 낫다고 단정하지 않는다.

공개 실행기는 원본 자원 ID/바이트 오프셋/게시량/원래 PPU 위치를 작업 설명으로 반환한다.
이는 변환기의 추적 기준이지 GBC에서 NES PPU 메모리를 에뮬레이트하라는 계약이 아니다.
GBC 어댑터는 이 ID를 변환 자산과 native 타일/맵 위치로 연결해야 한다. 상태와 입력/출력
버퍼는 WRAM이고, 작업 승인 시점은 실제 게시가 완료된 뒤다.

## 검증과 범위

- 512개 원작 편성 슬롯을 조회해 보스 등장 조건에 연결되는 20개 그래픽 ID를 찾았다.
  24개 그래픽 자료 중 5, 9, 10, 14는 해당 편성 연결을 찾지 못했으므로 강제 함수 입력
  검사로 구분했다. 미사용이라고 단정하지 않는다.
- 정면/백어택 × 상태·캐시·직업·진열 64조합과 보스 24자료: 176건.
  알려진 20개 보스 자료는 원작에서 찾은 실제 편성으로 시작한다. 초기 상태와 백어택은
  명시적으로 주입하므로 전부 합법적인 인카운터라는 뜻은 아니다.
- GBC에서 전반부를 실행한 결과가 후반부의 원작 입력과 일치하는지 먼저 확인한다.
  이어 15,168개 후반부 상태/대기, 자원 설명, 출력 426,048바이트를 원작과 대조해 통과했다.
  원작의 실제 PPU 쓰기 이후 메모리를 정답으로 사용하며 C 공식을 정답 생성기로 쓰지 않는다.
- 오차를 심은 비교 ROM은 case 0/index 0에서 실패했다. 출력 버퍼 끝의 보존,
  잘못된 승인/재시작 시 상태 불변도 검사한다.
- 호스트 검사 135개와 공유 이동 함수를 사용하는 기존 전반부 512건 GBC 회귀 검사를
  통과했다. 공개 대상 소스 454개만 새 폴더에 복사한 빌드에서도 ROM과 보고서가
  바이트 단위로 동일했다. 원본 입력과 도구 경로는 비공개 로컬 설정으로 제공했다.
- 검증 ROM SHA-256: `d61d73c3177331896529b80c3aa972ec9aa2d26bb586fce53a9648fdf7363d4f`.
- 원본 SHA-256: `262a98737975df25fff80ad91090c3da039d2828035c6253140d2c5f3b176ea2`.
- Mesen core: `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`.
- 검사 ROM의 bank 16은 전반부/후반부/표를 합쳐 4,597바이트다. 이는 전체 전투 ROM과
  함께 링크한 메모리 예산이나 화면·오디오 동시 부하의 합격 수치가 아니다.

백어택의 원작 반전표 재생성 때문에 기존 전환 조사기의 300만 명령 한도를 넘는 보스가
있다. 기존 조사기의 한도와 검증은 바꾸지 않았다. 새 후반부 조사에는 전체 원작 명령을
생략 없이 실행하는 별도 600만 명령/600대기 상한을 두었다. 실제 최대 자료의 측정값을
위에 기록했고, 무한 대기나 미지원 입력은 계속 실패한다.

원시 ROM·추출 표·픽셀·비교용 정답·검사 ROM은 비공개다. 보고서는
`evidence/battle-entry-tail/`에 생성한다.
재현: `npm run audit:battle-entry-tail`, `npm run build:battle-entry-tail`,
`npm run verify:battle-entry-tail`, `node tools/verify-battle-select.mjs --entry-tail --negative`.

## 다음 완료 경계

다음은 원작 자산을 상주시킨 V6 어댑터다. HIDE는 해당 아군 OAM만 숨기고,
CANONICAL은 백어택 방향을 허용하며, MOVE는 아군 및 `9F11` 상태/대상 OAM을 함께
갱신해야 한다. 석화 BG와 이동하는 적의 겹침, 스크롤의 계산/게시 시점, 부분 타일 변경을
전체 OAM·VRAM 예산 안에서 처리한다. 이 어댑터까지 연결한 후 기존 픽셀 기준과
음악/효과음 연속성·최악 프레임 비용을 검사한다.

이번 변경은 기존 V6 표시·오디오 경로를 교체하지 않는다. 소리 요청이 없는 원작 보스
등장에 효과음을 추가하지 않았고, 새 표시 경로에서 오디오가 유지된다는 검증은 아직 남아 있다.
