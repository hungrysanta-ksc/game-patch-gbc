# 원작 전투 창·HP·상태·행동 호출 연결

2026-11-24. PR 34 이후 R2 표시 소비자 연결이다. 전투 계산기나 정상 플레이 완료가 아니다.

## 이번에 연결한 경계

원작의 같은 RAM/PPU 상태에서 `34/9BA2` HP 4행, `2F/B304` 선택 준비,
`32/9F11` 상태 아이콘, `2F/B2EB` 행동 준비, `34/8FF7` 행동 스크립트,
숫자·메시지 대기·창 복원·`2F/AFD8` 정리, 다음 선택 준비를 실행한다.
포션 표시 경로(스크립트 1)와 적 8명 독 피해 표시 경로(스크립트 5)를 정면/백어택으로 검사한다.
피해/회복 값, HP, 상태는 명시한 **효과 계산 이후 경계 입력**이다. 실제 아이템 소비·치료·독 계산이나
이 입력의 정상 전투 도달성을 구현했다고 세지 않는다. 파티 이름 `0..3`은 슬롯 식별용 입력이다.

| 소비자 | 출처와 보존 조건 |
|---|---|
| 행동 순서 | `34/950D` 포인터와 `9519..956A` 스크립트/분기표. 원작 실행에서 실제 선택한 순서로 내린다 |
| 사용자·행동·대상·상태·결과 창 | `34/905B..9450`, 창 정보 `8E83`, 열기 `8D1B`, 닫기 `8E14`. `FF` 조건은 빈 성공 메시지로 바꾸지 않는다 |
| HP | `34/9BA2..9CE0`, 원작 네 이름과 현재/최대 HP 출력 버퍼. 앞/뒤 네 행을 각각 대조 |
| 상태 | `34/9D06`, `2E/9E80`, `2F/B304`, `32/9F11`. `$AC=0`인 행동 중에는 아이콘을 강제로 겹쳐 그리지 않는다 |
| 숫자 | `34/9354 → 8460 → 868A`, `33/AD2B`. 대상/공격자 숫자 버퍼를 각각 확인. 공격자 버퍼의 `FFFF`는 표시 없음 |
| 유지·정리 | `34/9450` 메시지 속도, `94D6/94E7` 조건부 닫기, `9056 → FA0E → 2F/AFD8`. 임의의 33번째 숫자 지우기 프레임을 넣지 않는다 |

메시지 속도 4·버튼 입력 없음에서 대기는 32 원작 프레임이다. 검사 입력은 정상화된 상태와
렌더러 상태를 일치시키며, HP가 1/4 이하인 두 슬롯에는 원래의 빈사 비트를 설정한다.
상태 변경 시 숫자 수명이 달라질 수 있으므로 다른 입력도 항상 원작 호출에서 결정해야 한다.
현재 실제 GBC에서는 창 0/1/2/4를 연다. 창 3의 실제 상태 메시지와 변수 치환·복수 결과 큐는 후속 범위다.

## 원작 UI와 V6 보존

[실제 NES 화면 관찰](battle-ui-observation.md)을 기준으로 수정했다. 메시지 창은 ROM
`34/8E83`의 좌표/너비를 읽고, HP 창은 원작 실행이 작성한 PPU의 양쪽 모서리도 확인한다.
하단 y=106/38px, 아군 y=10/34/58/82와 원본 도트를 유지한다. 기존 y=96 시작 시안은 폐기했다.
이름·HP 4행, 왼쪽 행동자/대상과 오른쪽 행동/상태, 아래 결과 창의 겹침 순서를 보존한다.
사용자가 승인한 HP 숫자만 5×7이며 한글은 비공개 7×7 글꼴이다.

원작 프레임 F7..FF에서 반복 테두리 여백을 줄여 14px 메시지 창과 38px HP 창을 만든다.
HP 수치 x=111..155는 메시지 창의 x<104 범위에 가리지 않는다. 최대 HP 대신 행동명/상태명을
표시하는 원작 조건은 별도 선택 소비자 연결 범위이며 현재 4개 입력은 현재/최대 HP 상태다.
테두리/배경은 원작 NES 색 인덱스를 기존 RGB555 변환으로 내린다. NES 색표와 GBC LCD 보정의
차이가 있어 첨부 이미지와 최종 RGB가 동일하다고 주장하지 않는다.

BG 좌표를 6px 옮기고 SCY=6을 적용해 화면 위치를 보존하면서 y=106 경계를 타일에 정렬한다.
적 그림은 7:8로 유지하고 기준 y를 18로 조정하며 숫자는 이전 기준점을 보존한다. 아군·상태·
숫자의 모든 원본 픽셀과 UI에 가려지는 그림이 없는지 검사한다. 상단 배경 높이는 11px다.

## 공유 표시 경로

기존 `battle-atlas.c`의 비활성 BG 페이지 준비와 VBlank 원자 전환을 사용한다.
HP와 메시지 창은 전투 그림과 독립된 계층이다. 이번 제한 입력에서는 원작 창 마스크에 따른
작은 UI 지도만 미리 합성하며, 닫을 때 하위 창을 복원한다. 전체 전투 화면 조합표는 만들지 않는다.
일반 문자열/선택 입력의 실행 중 지도 생산자는 후속 범위다.
기하/효과 프레임은 아직 제한된 진단용 사전 변환이며, 일반 전투 상태의 실시간 공급기는 남아 있다.

BG 슬롯 0..175는 그림, 176..255는 UI로 분리한다. UI 타일은 프로필 전환 시 비활성 BG 은행에만 적재하고 게시 후 재사용한다.
열린 창과 HP를 포함한 BG 행 13..18은 WRAM 스테이징에서 비활성 지도에 DMA한다. 각 행/창 처리 사이에
오디오 생산자를 실행하며, 활성 BG/OBJ 저장소는 전환까지 보존한다.
숫자 32프레임 동안 지도/패턴/팔레트는 고정하고 OAM만 교체한다. 마지막 OAM은 원작 후속 호출까지 남는다.
다음 준비 때 활성 OAM을 덮어쓰지 않도록 숫자 종료 뒤 두 그림자 버퍼 소유권을 정리한다.
관찰용 단계/일련번호도 같은 시점에 게시해 다음 단계 준비가 이전 관찰을 바꾸지 않게 한다.

검증기는 외부에서 행동 하나를 시작할 뿐, 내부 창·숫자·다음 선택 단계를 구동하지 않는다.
음악/효과음은 기존 7,200틱 독립 원작 스트레스 순서다. 이번 행동 자체의 효과음 요청 연결을 증명하는
검사가 아니다. 테스트 음원 종료가 진단 타이머를 정지시키므로 마지막 1,200틱에는 새 행동을 시작하지 않으며,
검증기는 모든 시작된 행동이 음원 종료 전에 돌아오는지 별도로 확인한다.

## 실행과 검증

```powershell
npm run build:battle-action
npm run verify:battle-action
node --test tests/battle-action.test.mjs
```

산출물: `build/battle-action/ff3-battle-action.gbc`, `evidence/battle-action/load-result.json`.
이미지·ROM·원시 로그는 로컬 전용이다.

2026-11-24 최종 GBC 실행: ROM SHA-256
`9c996c2c9a393f401f7778a535d386afbcfd789b0d8363a005e9d1d132dd8fc5`.

- 정면/백어택 × 아이템/독 4경로, 요청 15회. 첫 두 순환에서 220단계와 선택 복귀 8회를 확인했다.
- 실제 화면 484장, 11,151,360픽셀 일치. 숫자 재생 15회/480엔트리, 최대 39 OBJ·한 줄 8개.
- 숫자 32 원작 대기: 532.457ms. 준비 실패 0, 첫 가능한 VBlank에 게시, 최대 표시 오차 3.207ms.
- 원작 음악/효과음 독립 부하 7,200틱, APU 쓰기 30,938회. 지연·언더런 0.
- 잘못된 VRAM/DMA/페이지 게시·활성 OAM 쓰기·메모리 접근 오류 0. 스택 미사용 여유 289바이트.
- 전체 행동은 준비 비용 포함 중앙값 9,660.542ms, 최대 10,095.852ms다. **전체 원작 속도 관문은 미통과**다.

원작 창 호출의 열림/닫힘 마스크를 연결했지만 창의 타일 행이 점진적으로 전송되는 중간 상태까지
같은 프레임으로 재현한 것은 아니다. 정지 화면 대조, 숫자 시간 검증, 전체 창 전환 시간 검증을 구분한다.

## 남은 범위

긴 이름/메시지, 창 3·가변 문자열/HP/아이템 치환, 다중 결과 큐, 상태 변경/소멸/반사/흡수 및
모든 무기·마법·소환 조합, 선택 커서·조작 가능한 명령 메뉴, 실제 효과 계산/AI/승패/보상·필드 복귀가 남는다.
미지원 문구/색/타일/OBJ 한도는 빌드 오류로 남기며 줄이거나 일부를 숨겨 통과시키지 않는다.
전체 행동의 준비 비용은 숫자 자동 재생의 원작 속도 검증과 구분한다. R2 전체 장면 관문과
제품의 첫 정상 진행 관문은 아직 완료되지 않았다. 음질 개선은 후순위를 유지한다.
