# 일반 NPC 이동과 애니메이션

개발 진입 맵 29에서 원작의 일반 NPC 이동을 탐색·한글 대화에 연결한다.
원작 배치의 NPC 49/51은 돌아다니고 NPC 55는 제자리 애니메이션을 한다.
배치·속도·포즈·난수 표를 새로 만들지 않고 사용자가 제공한 ROM에서 읽는다.
동행 NPC, 이벤트가 지시하는 이동, 맵 전환은 별도 후속 소비자다.

## 원작 근거와 실행 순서

| 원작 코드 | 연결한 의미 |
|---|---|
| `3F/E1E1..E249`, `3E/D844..D857` | 일반맵 프레임마다 객체 명령 6 실행 |
| `3B/B17C..B1EE` | 픽셀 이동, 접촉 시 속도 마스크 무시, 반 칸에서 높이 층 갱신 |
| `3B/AF97..B0C4` | 다음 NPC 슬롯 선택, 대기 감소, 난수 방향 선택, 목적지 예약 |
| `3B/B0C5..B17B` | 맵/채움 타일, 높이 층, 플레이어·다른 NPC 예약 충돌 |
| `3B/B1EE..B2FA`, `AEAD` | 원래 포즈·보행 보정·연속 애니메이션·대화 방향 |
| `3B/AEEE..AF30`, `AF7F` | 일반 프레임의 교대 표시 순서와 대화의 고정 순서 |
| `3E/C4A7`, `3F/FE00` | NPC 전용 난수 인덱스 초기화와 256바이트 표 |
| `3F/ECB5/ECC7/ECDB` | 대화 중에도 증가하는 프레임 카운터 |

디스어셈블리 주석에는 무작위 이동 검사를 “every other frame”으로 설명하지만,
실제 호출 경로는 프레임마다 한 슬롯을 검사한다. 홀짝 분기는 NPC 표시 순서를
뒤집는다. 주석 대신 원본 명령 실행 결과를 기준으로 한다.

논리 프레임은 기존 60.0988Hz를 유지한다. 플레이어 처리 다음에 NPC 픽셀/높이
층을 갱신한 뒤 다음 이동을 예약한다. 원작은 표시 후 예약하므로, 예약이 바꾸는
좌표·포즈 6바이트를 따로 보존해 마지막 논리 프레임의 예약 전 모습으로 합성한다.
실제 OAM 제출은 한 번에 최대 두 논리 프레임을 처리한 뒤 수행한다. 마감 시각을
버리거나 현재 시각으로 덮어쓰지 않으므로 남은 프레임은 다음 순환에서 처리한다. 그림을 생략한
프레임에서도 NPC 논리는 빠짐없이 진행한다. 대화에서는 이동과
예약 검사를 멈추되 프레임 카운터는 계속 진행한다. 창을 표시하는 동안에는
진입 시 포즈를 유지한다. 한글 창의 실제 표시 시간은 여전히 원작 창 타이밍과
동일하다고 주장하지 않는다.

왼쪽/위 이동은 예약 시 실제 타일 좌표를 먼저 바꾸고 서브픽셀을 15로 설정한다.
오른쪽/아래는 현재 좌표에서 시작한다. 목적지 예약 때문에 서로의 이동 칸을
침범하지 않는다. NPC RNG `$F4`와 인카운터 RNG `$F5/$F6`는 독립이다.
개발 진입의 초기값은 전원이 켜질 때 `$F4=0`인 조건에서 원작 초기화를 적용한
`$1B`다. 임의 시점의 원작 저장 상태에서 시작한 난수 경로와 동일하다는 뜻은 아니다.

맵 밖에서는 채움 타일을 검사하지만 원작의 `$67` 타일 임시값을 덮어쓰지 않는
동작도 보존한다. 이벤트 실행 중 `$6C!=0`인 강제 이동 분기는 이번 일반 이동
소비자에 포함하지 않는다. 기존 이벤트 지원 범위 밖의 명령은 계속 오류로 거부한다.

## 메모리와 표시 범위

탐색 상태 예약 80바이트 안에서 NPC 커서·RNG·임시 타일·플레이어 예약 좌표와
프레임/대화 포즈 시계를 관리한다(사용 75바이트). 예약 전 표시 캐시는 슬롯·유효
표시를 포함해 정적 RAM 8바이트를 추가한다. 오디오·한글 작업 공간과 스택 예약은 유지한다.
NPC 로직은 은행 9, 화면 합성은 은행 10에 둔다. OAM 40개와 한 줄 10개를
넘기는 상태는 계속 명시적인 개발 오류다. 전체 맵의 밀집 배치 해결, 동행/다리의
플레이어-객체 우선순위 조합까지 완료했다고 확대하지 않는다.

## 검증 방식

`node tools/build-text.mjs --explore`로 빌드한 뒤
`node tools/build-exploration-verifier.mjs`,
`node tools/verify-exploration.mjs --units`,
`node tools/verify-exploration.mjs`를 실행한다.

단위 검사의 기대값은 수정하지 않은 원본 ROM의 6502 코드를 실행해 만든다.
속도 마스크·접촉·좌표 경계·모든 지형 속성·높이 층·숨김/고정/대기 상태와 목적지
경합을 비교한다. 애니메이션은 원작 `B1EE/AEAD`가 만든 OAM과 비교하며 GBC
뷰포트·타일/팔레트 번호만 변환한다.

실제 버튼 경로에서 정상 논리 전이 1,024개를 읽기 전용 관측하고 같은 원작
루틴과 대조한다. 관측기는 Mesen 로그의 500행 제한 전에 원시 기록을 수집하며
누락/중복 번호를 검사한다. 대화 중 플레이어와 NPC 정지, 종료 후 재개를 검사한다.

픽셀 체크포인트에서는 진단 일시정지 후 현재 상태를 다시 그려 2프레임 기다린다.
좌표·NPC 상태·RNG는 쓰지 않는다. 이 12개 캡처는 특정 상태의 합성을 증명하며,
원작과 같은 버튼 타이밍의 무개입 플레이스루 증거로 세지 않는다. 화면 갱신 간격과
음악/효과음/페이드는 별도의 연속 이동 구간 및 실제 하드웨어 레지스터 쓰기로 검사한다.
기존 성능 회귀 기준을 완화하지 않는다.

원시 결과는 로컬 `evidence/exploration/`에 둔다. ROM·원작 데이터·번역·폰트·캡처와
메모리 관측은 공개 패키지에 포함하지 않는다.

후속 맵 전환에서는 초기 진입과 재진입을 나누어 `$4A/$F4`의 수명을 보존해야 한다.
이번 `ff3_field_init()`의 초기화는 개발 진입 한 번에 대한 계약이다. 메뉴/이벤트와
공유하는 원작 임시 변수의 외부 갱신, 동행 NPC의 우선순위와 강제 이동도 해당
소비자를 연결할 때 별도로 대조한다.

## 표시와 사운드 예산

NPC 합성·스캔라인 집계를 별도 함수로 나누고, 스캔라인 수는 각 스프라이트의
8줄 구간 시작/끝을 누적해 계산한다. 행 준비는 같은 원작 메타타일의 인접 셀
조회 결과를 공유한다. 열 전송은 64바이트 작업 공간을 타일·속성 쌍 순서로
채워 전송 중 주소 왕복 계산을 없앤다. 원작 메타타일/팔레트 값은 바꾸지 않는다.

VBlank에서 행 32바이트 한 은행 또는 열 최대 네 쌍을 먼저 처리한다. 타이머
IRQ가 이미 대기 중이면 열은 두 쌍만 처리한 뒤 IRQ를 허용한다. 남은 행 은행/열 최대 네 쌍은 각각의 짧은 임계 구간으로 전송한다.
열 반복의 상태 검사·분기는 고정 은행의 SM83 루프에서 수행한다. VRAM 쓰기는
계속 VBlank로 제한한다. 행 DMA 시작은 LY 150 이내이며 열 전송도 매 구간
화면 모드를 확인한다. 어셈블리의 오류 필드 오프셋은 빌드 시 검사한다.

오디오 명령·시계·출력 변환·IRQ 소비자는 유지한다. 다음 탐색 프레임의 마감이
지났고 두 틱 이상 미리 준비되어 있으면 생산 함수가 실행 시간을 돌려준다.
마감 전에는 기존 세 틱 목표까지 보충한다. 초기 준비와 대화/진단 일시정지는 기존 경로다.
논리 두 프레임을 따라잡을 때 첫 프레임 뒤에 보충하고 두 번째 뒤에는 그림을
제출한다. 같은 오디오 소스를 공유하는 나머지 다섯 ROM의 바이트 동일성도 검사한다.

실제 SCX 반영과 이동 갱신 간격 외에 배경 전송 요청→완료 시간도 계측한다.
타이머 카운터를 에뮬레이터 master clock과 비교해, IRQ를 막아 음원이 느려지는
경우를 검출한다. NPC 원시 전이는 네 관측 프레임마다 수집해 로그 상한 이전에
보존한다. 논리 프레임 실행과 오디오 이벤트를 생략하지 않는다.

## 검증 결과 (2026-11-23)

대상 ROM SHA-256: `9f03be8f20e549d393b7ecf85500b38f89be3b1e53fda927b4f26c5e0c7bc024`.
고정 Mesen core는 `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.

- 원작 코드 실행과 GBC 상태/OAM 비교 8,640건. 기존 4,288건에 NPC 포즈
  512건, 픽셀 이동·예약 3,712건, 예약 전 표시 보존 128건을 추가했다.
- 실제 입력 경로의 NPC 전이 1,024건 일치: 픽셀 변경 352회, 목적지 예약
  22회. 일반 탐색 논리 6334프레임에서 NPC 갱신 횟수도 일치한다.
- 대화/복귀 세 번, 12개 상태 캡처 276,480픽셀 일치. OAM 한 줄 최대
  6개, 영상 쓰기 78,576회. 잘못된 영상/OAM/스크롤 쓰기와 LCD-off 0.
- 원작 오디오 7,200틱/21,366이벤트. 지연·큐 고갈 0, 실제 APU 쓰기
  30,938회/해시 16366. master clock 대비 타이머 관측 오차는
  -0.415..0.012ms 범위였다.

| 측정 범위 | 결과 | 회귀 한계 |
|---|---:|---:|
| 이동 중 갱신 간격 최대 | 50.420ms | 55ms |
| 이동 중 갱신 간격 95백분위 | 33.545ms | 35ms |
| 준비 시작 → 실제 SCX 반영 최대 | 31.670ms | 35ms |
| CPU 표시 작업 최대 | 16.602ms | 20ms |
| 오디오 생산 호출 최대 | 32.096ms | 55ms |

기존 다섯 표시/오디오 회귀 한계는 유지한다. 추가한 배경 전송 지표는 현재
화면이 반영된 뒤에도 진행하는 **보이지 않는 링 버퍼 테두리 채우기**다.
SCX 반영의 35ms 한계를 이 지표에 다시 적용하지 않고, 전체 갱신 정체의
55ms 예산으로 제한한다. 두 시간을 합치거나 더 짧은 값으로 대체하지 않는다.
진단 일시정지 구간을 제외한 연속 이동의 논리 시계 차이 5.103ms / 96.77초도
기존 200ms 한계 안이다.
고정 60fps나 전체 맵 성능을 보장하는 결과는 아니다.

정적 WRAM 끝은 `0xCFC5`, 스택 예약은 848바이트다.
호스트 검사 30개와 공개 허용 소스 186개만 복사한 여섯 ROM 재현 빌드도
확인한다. 원작 ROM·번역·폰트는 명시적인 외부 로컬 입력으로만 제공한다.
