# 원작 호출자에서 상주 숫자 화면까지

2026-11-26. PR 74의 공통 호출자/숫자 함수 다음 단계다. `--effects`는 별도
검증 빌드이며 기본 `--windows` 빌드를 교체하지 않는다. **무기·마법·피격·사망을
포함한 요청 전체는 아직 완료되지 않았다.** 원작 숫자 처리자 28과 정리 37을
실제 상주 화면에 연결한 범위만 검증한다. 정상 플레이나 전투 계산 완료를 뜻하지 않는다.

## 원작 수명과 GBC 연결

- 원작 행동 스크립트 5 → `34/8411` 공통 호출자 → 그래픽 28 → `33/AD2B`
  숫자 본체 → 두 번째 숫자 버퍼 → 스크립트 정리 순서를 유지한다.
- 값/미스/회복/숨김과 32프레임의 원작 좌표는 PR 74의 검증된 C 소비자가
  런타임에 생성한다. 빌드에 들어가는 것은 원작 리소스 로더로 얻은 글리프,
  팔레트, 초기 편성 좌표와 읽기 전용 표다. 관측 화면/OAM 영화는 런타임 입력이 아니다.
- 원작 `F8C5`처럼 다음 OAM을 먼저 준비하고 VBlank에서 게시한다. 게시 뒤
  타이머로 한 프레임을 추가 대기하지 않는다. 32장을 모두 표시하며 건너뛰지 않는다.
- 숫자 도트, 색과 아군 크기를 유지한다. 적 숫자 위치만 승인된 V6의 7:8 적 배치에
  맞춘다. 가장자리에서는 글리프 전체를 이동시키고 픽셀 행을 자르지 않는다.
- 움직이는 숫자의 X/글리프/속성은 32장 동안 불변이므로 최초 구성만 보존하고
  후속 장에서는 Y와 줄당 OBJ 예산을 갱신한다. 원작 숫자 상태/OAM 생성은 계속 실행한다.
- 전투 행동을 메인 루프의 작업 상태로 포함해 불필요한 유휴 오디오 선행 보충을 줄인다.
  원작 음악·효과음의 명령, 틱, 변환 출력이나 IRQ 소비는 생략하지 않는다.

## 밀집 숫자의 임시 소유권

8체×4자리 32 OBJ에 기존 아군 24 OBJ와 적 색 보완 OBJ를 그대로 더할 수는 없다.
숫자 단계에서 멈춘 아군 부분만 BG 타일로 임시 보존한다. 숫자 종료 후 원래 OBJ와
실제 비활성 타일맵/팔레트를 복구한다. 일반 아군 이동을 BG로 바꾸는 구조가 아니다.

GBC의 signed BG 주소 방식에서는 BG의 낮은 타일 번호가 `$9000` 영역을 사용하고,
OBJ는 기존 `$8000..8FFF`를 계속 사용한다. 따라서 원래 그림을 덮어쓰지 않고
임시 BG를 둘 수 있다. [Pan Docs 타일 주소 설명](https://raw.githubusercontent.com/gbdev/pandocs/master/src/Tile_Data.md).
전체 40개/줄당 10개 조건은 게시 전 매번 검사한다.
[Pan Docs OBJ 조건](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md).

- 숫자 32개 + 적 색 보완 6개 + 하단 아군 발 2개를 남긴다. 발을 OBJ로 남겨
  HP 창의 첫 타일 행과 임시 아군 타일이 서로를 덮어쓰지 않게 한다.
- 검정 배경 셀은 원래 비트플레인으로 합성한다. 상단 배경과 만나는 셀은
  RGB555 색을 정확하게 대조해 별도 팔레트로 구성한다. 근사색이나 도트 생략은 없다.
- BG 팔레트 4..7을 빌린다. 기존 화면이 이 팔레트를 이미 사용하거나 색/타일/
  OBJ 조건이 맞지 않으면 명시적으로 실패한다. 현재 편성 3의 정면/백어택 경계다.
- 아군/적 보완 OBJ가 같은 임시 셀에서 겹치는 경우, 보스·석화 동시 소유권,
  변화한 편성의 재배치, 한 셀의 표현 불가능한 혼색은 아직 지원하지 않는다.
  이런 경로를 성공한 무표시 처리로 넘기지 않는다.

## 메모리와 비용

| 영역 | 수명/내용 |
|---|---|
| WRAM1 `$D200..D37F` 이내 | 원래 창/맵과 배타적인 셀 변환 임시 공간 |
| `$D600..D85F` | 원작 숫자 OAM, 보존 OAM, 줄당 예산 두 벌 |
| `$D870..D8EF` | 원래/임시 BG·OBJ 팔레트 |
| WRAM3 | 타일맵 백업/작업본, OAM/팔레트 백업, 최대 80개 임시 패턴 |
| VRAM bank0 `$9000..94FF` | 숫자 단계의 멈춘 아군 BG |
| VRAM bank0 `$9700..97FF` | signed 주소를 위한 첫 UI 행의 낮은 타일 사본 |
| VRAM bank1 `$9000..97FF` | signed 주소용 상주 BG 패턴 사본 |
| OBJ tile 223..255, palette 3 | 원작 피해/회복/미스 글리프 |

WRAM3는 저장소로만 매핑하며 스택/실행은 bank1에 남긴다. 원래 전송 API의
16바이트 메모리 이동, VBlank DMA와 오디오 보충을 사용한다. UI 갱신은 낮은
UI 타일의 signed 사본도 함께 갱신한다. 정리 실패 시 완료 티켓을 반환하지 않는다.

최초 밀집 준비는 일반 색 셀 변환에서 비트플레인 빠른 경로를 추가하며 약 4.5초에서
약 2.5초로 줄었지만 **게임용으로 허용할 수 있는 지연이 아니다**. VRAM 전체 사본,
지도 읽기와 셀 준비를 자원 로드/변경 수명에 맞춰 나눠야 한다. 아직 0.5초 진입
예산이나 원작 전체 속도를 만족했다고 주장하지 않는다. 자동 32장도 실제 측정값을
보고하며 단순 함수 일치로 속도를 추정하지 않는다.

## 검증과 재현

최종 검증 ROM은 `fbb93150ac779b900e360e88c1959409ec117e205cc434caa8d655f731193052`다.

- 6조건 × 33장 = 198장: 원작 숫자 바이트, 실제 OAM과 전체 픽셀 일치.
- 원작 오디오 7,200틱: 소비 순서/원작 출력/변환 출력 일치, 부족·지연 0.
- 전체 캡처의 OAM DMA 421회: 잘못된 전송 0, 막힌 VRAM 읽기/쓰기 0.
- 별도 자동 실행: 32장 모두 게시. 첫 장→마지막 장 653.739ms,
  게시 간격 17.290..31.982ms, 원작 31간격 약 515.817ms에는 아직 못 미친다.
  전체 숫자 요청/준비/정리는 3,450.327ms, 임시 BG 준비는 약 2,495.782ms다.
- 호스트 169/169 통과. 기본 `--windows` ROM은 이전 해시
  `7ea1b2aa74600984cee212c2fa10821377daa46cf43a21c646350a4609bebe7a`와 동일하다.
- 공개 허용 소스 564파일과 로컬 입력 설정을 별도 디렉터리에 복사해 두 ROM,
  보고서와 효과 리소스 추출 결과를 바이트 단위로 재현했다.
- 정적 WRAM 끝 `$CE2F`는 `$D000` 고정 상태보다 앞이다. 코드 bank 49는 2,083바이트,
  bank 51은 5,317바이트이며 변환 전후 원작/숫자 생성기 검증 결과와 구분한다.

```powershell
node tools/build-battle-party-oam.mjs --effects
node tools/verify-battle-effects.mjs
node tools/verify-battle-effects.mjs --auto --dense
```

정면/백어택 각각 적 단일 9999, 아군 회복+미스, 적 8체 9999의 6조건을 사용한다.
각각 원작 숫자 OAM 32장과 정리 1장을 독립 원작 실행/픽셀 기준에 대조한다.
고정 게이트를 이용한 모든 장의 픽셀 검증과 게이트 없는 속도 측정은 별개다.
원작 음악·효과음 일정 7,200틱의 소비 기록을 원작 실행 및 변환 출력에 대조한다.
이 일정은 공존 부하이며 아직 무기/마법 동작에서 발생한 사운드 요청은 아니다.

Mesen의 읽기 전용 추적은 VRAM 접근 모드와 OAM DMA 시점, 실제 숫자 게시 시각을
검사한다. 실기 검증/음질 승인은 별도다. 생성 ROM·픽셀·원문·번역·로그는 비공개다.

## 남은 사용자 요청

1. `2F/B24F/B201/B024`: 무기 전진/양손·명중 반복/복귀, 피격·감싸기,
   공격하는 적 점멸과 각 반복 효과음. 직업 레벨에서 산출된 명중 횟수를 그대로 받는다.
2. `2F/B15E/B050`: 19개 마법 본체와 소환, 개별/전체/화면 대상, 실제 사운드 요청과 자원 복원.
3. 상태 확정 → 그래픽 7/10/11/12/35의 아군 상태/적 사망·소환·분열·변형.
   사망을 숫자 뒤 단순 숨김으로 대체하지 않는다. 보스 사망은 별도 원작 분기다.
4. 위 소유자를 같은 상태/창/자원 계약으로 통합하고 밀집 준비 지연과 최악 공존을 검증한다.

R2 통합 0/8, 제품 관문 0/3을 유지한다.
