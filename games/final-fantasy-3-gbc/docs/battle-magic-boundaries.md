# 일반 마법 대상 경계와 복구 비용

기준은 PR 94 병합 `fc154ec10d47a77e421487e19021391527e05307`과
[현재 그림을 유지하며 다음 그림 준비](battle-magic-next-picture.md)다.
이번 범위는 기존 적→아군 일반 마법의 동기 준비·복구이며 새 마법이나 정상
전투 통합의 완료로 세지 않는다.

## 원작 구조와 변경

원작 `2F/B15E → AF14 → 33/BAFD`가 보통 마법 본체를 호출한다.
`33/B68D → B589`에서 그림 자원을 적재하고 `B696..B6D1`에서 시퀀스를
한 번 읽는다. `B6DD`가 대상을 순회하고 `B6F3`에서 대상별 소리를 요청한 뒤
`B6F5..B6F7`은 커서만 1로 되돌린다. GBC도 시퀀스를 행동당 한 번 검증하고
대상마다 커서만 되돌린다. 각 그림의 기존 엄격한 prefix/커서 검사는 유지한다.

`B765..B797`은 같은 여섯 X좌표를 행마다 반복한다. 첫 행만으로 전체 48px
외곽을 계산한다. 투명한 셀·반전·백어택도 포함하고, 원작의 36셀 압축 해제나
GBC의 모든 불투명 타일쌍은 생략하지 않는다. 원작 함수 실행 1,022가지에서
모든 행의 X좌표가 같은지 검증했다.

`B70B/B70E`와 `BB0F/BB12`는 각각 OAM을 지우고 한 번 기다린다.
`A42B..A435`는 160바이트 전부를 F0으로 쓴다. 마지막 대상 뒤에는 이미 같은
빈 그림이 게시되어 있으므로 재계산 대신 현재 페이지를 한 번 더 게시한다.
두 원작 대기·소리 요청 순서는 그대로다. 빈 그림의 GBC OAM은 최대 8개의
잔류 객체뿐이어서 완전히 겹쳐도 주사선 한도 10개를 넘지 않는다. 빈 그림에
한해 144행 카운터 재계산을 생략하며, 실제 효과 그림의 한도 검사는 유지한다.

GBC는 아군과 36셀 효과를 동시에 OBJ로 두기 어려워 동결된 아군 픽셀을
signed BG에 두고 8×16 효과를 사용한다. 이 차이에 필요한 잔류 객체의 타일은
게시 전 준비 중에만 임시 소유한다. 32바이트씩 따로 전송하던 최대 8쌍을
기존 256바이트 버퍼에 모아 요청한다. 소스 VRAM을 읽고 뒤집는 과정에서
음악 생산은 계속 서비스하며, scratch/VRAM 주소 충돌 검사는 유지한다.

복구는 `2F/B175`의 숫자 자원 재적재에 대응해 상주 정본을 되돌린 다음,
OBJ 크기·팔레트·아군 페이지와 배경 지도를 복원한다. 인접 dirty 지도 블록과
잔류 타일 256바이트를 기존 버퍼에서 묶는다. 실제 RAM→VRAM DMA는 여전히
128바이트 이하의 기존 VBlank 구간이고 WRAM 은행 복사도 16바이트씩 수행한다.
전체 복구 바이트와 원래 비활성 지도의 내용까지 보존한다. 추가 RAM은 없다.

## 측정과 검증

구간 계측은 오디오·대기 시간을 포함한 에뮬레이터 벽시계 비용이며 CPU 전용
시간이 아니다. 자동 재생 검증의
`cadence.boundaries`에 동기 그림의 원작 OAM 준비·투영·한도 검사·게시 대기와
마지막 게시 이후 복구 시간을 분리해 저장한다. 읽기 전용 콜백으로 측정하며
ROM에 계측 명령을 추가하거나 원작 대기를 바꾸지 않는다.

| 같은 원작 행동 | 게시 수 | PR 94 전체 | 이번 전체 | 첫 대상 그림의 실제 DMA 간격 | 마지막 게시 이후 복구 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 대표 마법 29 | 35 | 2,227.741ms | 2,093.459ms | 66.970→50.235ms | 300.705→283.138ms |
| 최대 30쌍 마법 36 | 35 | 2,261.079ms | 2,126.942ms | 50.247→33.485ms | 331.234→299.495ms |
| 아군 4명 대상 마법 0 | 142 | 4,170.391ms | 4,036.408ms | 83.681→83.721ms | 301.566→267.936ms |

초기 자원 준비를 포함한 최대 DMA 간격은 대표/전체 대상에서
1,138.298→1,037.834ms, 최대 30쌍에서 1,155.021→1,054.585ms다.
대표 마법 전체 약 6.0%, 전체 대상 약 3.2% 감소다. 초기 0.5초나 원작 속도에
도달한 것은 아니다. 양손 지팡이 회귀는 83게시/2,110.162ms와 실제 DMA 최대
간격 83.956ms로 이전과 같다.

전체 대상의 후속 대상 전환 세 곳은 83.726/67.003/67.002ms에서
83.681/66.940/66.948ms로 사실상 같다. 대상당 재검사를 없애도 같은 VBlank
경계를 넘는다. 초기 이후 최대 간격은 대표 50.235ms, 최대 30쌍 50.355ms,
전체 대상 83.721ms다. 최대 30쌍의 이전 50.247ms와 비교하면 소폭 증가다.
따라서 첫 그림 개선을 모든 대상 전환/모든 연출 간격의 개선으로 일반화하지 않는다.

대표 첫 그림의 동기 준비 단계는 원작 OAM 7.268ms, 투영 11.799ms,
주사선 한도 검사 23.283ms, 게시·완료 대기 18.428ms다. 전체 대상 첫 그림은
한도 검사 구간만 45.609ms이며 이후 대상도 28.343~40.918ms다. 이 안에는
`ff3_native_service`의 오디오 보충이 포함된다. DMA는 함수가 돌아오기 전에
발생할 수 있어 단계 합계와 실제 화면 간격은 다른 측정이다. 다음 개선은 이
검사/오디오 비용의 분리와 초기 동결·복구의 호출자/상주 자원 수명 분석이다.
서비스 호출이나 원작 대기를 무작정 줄이는 방식은 채택하지 않는다.

최종 ROM은 `3442d5f345e12d60cd575453eb4ce2994fc907593df3d180e3a5ac25eb5fd790`이다.
고정 RAM 끝 `$CF92`와 여유 110바이트는 그대로이며 은행 65 코드는 `$0EFD`다.
940화면, 11회 × 7,200 = 79,200 오디오 틱에서 원작 OAM/전체 픽셀/동적 소리
요청과 소비 해시 대조를 통과했다. 오디오 부족·늦은 처리·불법 VRAM/OAM 접근은
0이다. 상주 풀 593회, 지도·정본·캐시 복구 13회,
선행 준비 140회의 현재 그림/대기 경계 560회를 포함한다. 호스트 11검사와
공개 소스 629개로 별도 빌드한 12산출물의 바이트 일치도 통과했다.
고정 MesenCore SHA-256은
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.

재현 명령은 [이전 검증 목록](battle-magic-next-picture.md#검증-경계)과 같고,
추가 호스트 검사는 같은 `tests/battle-magic-video.test.mjs`에 포함된다.
R2 0/8·제품 0/3, 아군 시전/발사·적 대상·반사·특수/소환·정상 계산/메뉴 통합의
미완료 경계는 유지한다. ROM·번역·추출 자산·원시 캡처는 공개하지 않는다.
