# 원작 인덱스를 유지하는 최초 합성과 VBlank 읽기

## 원작과 어댑터의 역할

기준은 PR 98 병합 `fac0703a00b7641a67cf36d58b4194236e8350d2`다.
원작 `2F/B15E..B175`의 마법 호출→이동 복귀→숫자 그래픽 전환,
`33/B68D/B589`의 시전당 그래픽 07/08·시퀀스 적재,
`B6DD/B6F3`의 대상 순회와 `B765..B797`의 타일 번호·속성·좌표 갱신을
다시 대조했다. `B7A9..B7B4`의 네 번 대기와 최종 OAM 정리도 유지한다.
원작은 이 반복에서 그래픽을 매번 RGB로 풀어 합성하거나 배경을 복구하지 않는다.

GBC에서는 동시에 필요한 OBJ 수와 주사선 한도 때문에 정지 아군 일부를 BG로
옮기는 기존 어댑터가 남는다. 원작 타일의 상주와 인덱스 사용 원칙을 이 어댑터에도
적용한다. 원작 상태 전이·대기·소리 요청은 바꾸지 않고, 같은 셀을 표현하는
변환과 안전한 VRAM 읽기만 줄인다. 전투 전체 통합이나 소환 경로의 완료 주장은 아니다.

## 합성: 인덱스와 행 단위 처리

혼합 셀은 원래 BG/OBJ 팔레트 인덱스(0..63)를 64바이트에 유지한다. OBJ의
투명색과 앞선 OAM 우선순위가 결정된 뒤 실제 쓰인 인덱스만 RGB로 해석한다.
기존 128바이트 RGB 임시 공간의 나머지 64바이트가 인덱스→최종 색 대응을
보관한다. 서로 다른 인덱스가 같은 RGB를 가리키는 경우도 합치며, 첫 일치
팔레트·첫 색 인덱스·색 등장 순서·5색 오류는 그대로 유지한다.

원본 비트플레인은 행당 한 번 읽는다. 가로/세로 뒤집기와 셀 밖 부분을 먼저
처리하고, 남은 픽셀은 고정 한 비트 시프트로 해석한다. 최종 2bpp 인코딩도
행 단위로 누적한다. 정렬된 단일 팔레트 셀의 기존 직접 합성 경로와 글리프
캐시·재시전 의존성 검사는 유지한다. 새 고정 RAM이나 저장 뱅크는 없다.

## 지도: 백업 구조 유지, 안전한 읽기 확장

현재 활성 지도와 실제 비활성 지도 576바이트씩 두 면을 비교하며, 기존
256바이트 묶음/16바이트 변경 블록과 정확한 비활성 지도 백업을 유지한다.
합성 결과와 현재 지도 백업은 수명이 다르므로 이전 시전의 지도 백업은 재사용하지 않는다.

기존 VRAM 읽기는 VBlank에서도 4바이트마다 접근 가능 여부를 다시 검사했다.
CGB 배속에서 남은 길이가 16 이상이고 LY 144..150이면 IE를 보존·마스킹한 뒤
LY와 mode 1을 다시 확인하고 한 타일(16바이트)을 읽는다. 실패 시 원래 4바이트
경로로 돌아가 새로 검사한다. 일반 속도 1바이트와 나머지 구간의 4바이트 경로는
유지한다. 4바이트 경로에 들어간 뒤에는 배속/특례 진입 조건을 매번 반복하지
않는다. 단, 매 묶음의 STAT 대기와 마스킹 후 재검사는 그대로이며, 4바이트
미만의 잔여 길이도 기존 1바이트 경로로 처리한다. 읽기 동안 배속을 바꾸는
소유자는 없다. VBK=0과 기존 IE를 복원한 뒤 다음 묶음으로 넘어간다.

[Pan Docs의 VRAM 접근 규칙](https://github.com/gbdev/pandocs/blob/master/src/Accessing_VRAM_and_OAM.md)은
mode 검사와 실제 접근 사이 인터럽트로 유효 구간을 넘지 않도록 요구한다.
최대 LY 150에서 마스킹 후 재검사하므로 16바이트 구간은 남은 VBlank 안에 들어간다.
명령열 자체는 96 M-cycle(배속 192 dot, 코어 클록 384틱)이며, ISR/오디오 생산자
호출과 WRAM 뱅크 변경은 그 안에 없다. 실제 실행 PC와 IE/mode/LY를 감시하고
전체 VRAM 접근 및 오디오 지연 검사를 함께 수행한다. DMA 커널은 변경하지 않는다.

## 비교해 제외한 대안

합성 후 임시 공간 전체를 지도 한 면으로 전용하고 연속 구간을 길게 게시하는
대안도 측정했다. 인덱스 변환만 바꾼 중간 ROM의 첫 지도 준비 약 229ms와
재시전 약 177ms가 이 방식에서는 약 285ms/236ms로 늘었다. 총 첫 시전도
1.943초→1.993초, 재시전도 1.407초→1.541초로 악화됐다. 키 재적재·준비 작업과
오디오 보충까지 포함한 총비용이 좋지 않아 새 전송 API와 작업 지도는 제거했다.

## 같은 장면의 비용

대표 마법 29의 원작 35게시/행동을 두 번 실행한다. 다음 수치는 오디오 보충과
VBlank 대기를 포함한 실제 행동 시간이며, 순수 연산 시간으로 부르지 않는다.

| 구간 | PR 98 | 이번 변경 |
|---|---:|---:|
| 첫 시전 전체 | 1,959.527ms | 1,909.232ms |
| 재시전 전체 | 1,423.890ms | 1,390.355ms |
| 최초 합성/기록 | 400.055ms | 314.179ms |
| 첫 지도 준비 | 228.113ms | 226.478ms |
| 재시전 지도 준비 | 176.741ms | 164.053ms |
| 첫 최대 게시 간격 | 1,021.067ms | 954.096ms |
| 재시전 최대 게시 간격 | 519.026ms | 502.280ms |
| 첫 시전 마지막 게시 이후 복구 | 238.704ms | 256.329ms |
| 재시전 마지막 게시 이후 복구 | 218.096ms | 217.708ms |

최초 합성은 약 21.5% 줄었지만 첫 지도 준비 감소는 약 1.6ms로 작다.
재시전 지도 준비는 약 12.7ms 줄었다. 전체 행동의 감소율은 첫 시전 약 2.6%,
재시전 약 2.4%이며, 개별 합성 감소량을 전체 시간 감소로 대체하지 않는다.
그래픽 사본 게시 등 다른 단계의 VBlank/오디오 보충 위상도 함께 달라진다.
지도 백업량과 복구량은 대표 행동당 752/1,504바이트로 그대로다.
첫 시전의 마지막 게시 이후 복구는 오히려 약 17.6ms 늘었다. 복구 알고리즘을
바꾸지는 않았지만 대기까지 포함한 해당 구간은 남은 분석 대상으로 둔다.
모든 세부 구간이 빨라졌다는 주장은 하지 않는다.

최대 30쌍 마법의 첫 시전은 1,993.012→1,942.691ms, 네 명 대상은
3,768.544→3,701.409ms로 줄었다.

## 검증과 남은 범위

최종 ROM: `03b112789a2cd9478559bcea3c87f8ee6667fbcb8cdbfe5700179cd8dd40a586`.
고정 RAM 끝은 `$CF96`, bank 51 코드는 7,182→7,254바이트(+72)다.
기존 지도·팔레트·OAM·합성 캐시 저장 범위는 바뀌지 않는다.

기존 정상 픽셀·숫자·원작 소리 요청·오디오 소비 해시·정확한 지도 복구 검증에
전체 지도 차이, 좌/우 1픽셀 어긋남과 양축 뒤집기의 RAM 개입 검사를 추가한다.
왼쪽 어긋남은 세 번째 아군 6개 OBJ, 오른쪽 어긋남과 양축 뒤집기는 네 번째
아군의 왼쪽 두 OBJ에 적용한다. 어긋남 검사는 강제 재합성과의 비교 외에도 합성 직전 OBJ 화면과 합성 직후
BG+잔류 OBJ 화면을 독립적으로 재구성해 모든 픽셀을 비교한다. RAM 개입과
부분 오디오는 정상 게임 진행이나 완전한 오디오 일정 검증과 구분한다.
처음 시도한 세 번째 아군 전체의 오른쪽 이동+양축 뒤집기는 기존 혼합 팔레트
용량 오류 4로 거부됐다. 같은 주입은 PR 98 ROM에서도 오류 4로 거부됨을 확인했다. 이를 성공으로 바꾸지 않고, 표현 가능한 양성 사례와
별도 5색 거부 검사를 구분한다.

16바이트 특례는 VBlank 진입 시점에 따라 실행되지 않는 시나리오도 있다.
실행하지 않은 경우의 0회/0틱과 실제 실행한 경우의 정확한 384틱을 구분해
검사한다. 전체 검증에서는 특례 실행 증거가 반드시 있어야 하며, 모든 경우
VRAM 접근 안전·IE/mode·오디오 지연 검사를 유지한다.

```text
node tools/verify-battle-freeze-reuse.mjs map-span
node tools/verify-battle-freeze-reuse.mjs offset-left
node tools/verify-battle-freeze-reuse.mjs offset-right
```

최종 28개 실행 작업과 호스트 테스트 12개가 통과했다. 정상 화면 1,080장,
완전한 오디오 일정 14회×7,200틱(총 100,800틱), 주사선 171그림/24,624줄을
검증했다. 별도 RAM 개입 11종은 1,540장/770쌍, 초기 완료 마커 회귀는
140장이다. 어긋남 2종의 합성 전후 8쌍도 전체 픽셀이 같다. 5색 거부와
주사선 10개 허용·11개 거부 경계를 유지한다.

표준 11개 실행 묶음에서 VBlank 특례 26회가 관측됐고 읽기 구간은 384틱이었다.
특례가 실행되지 않은 시나리오는 0회로 따로 기록했다. 모든 실행의 버스 안전·
오디오 부족/지연·지도 복구 검사는 통과했다. 대표 두 시전의 합성 타일은
각각 480바이트가 PR 98의 실제 VRAM과 일치한다.

공개 허용 소스 638개로 만든 깨끗한 빌드의 ROM 3개를 포함한 12개 산출물이
작업 결과와 같다. Mesen 코어 SHA-256은
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`로 고정했다.
이는 에뮬레이터 검증이며 실기 또는 전편 정상 진행의 합격으로 확대하지 않는다.

첫 준비의 최대 게시 간격은 약 954ms, 재시전은 약 502ms로 초기 0.5초
기준을 아직 넘는다. 약 314ms 합성과 226ms 지도 준비에 대해 실제 작업과
전송 대기를 더 분리하고, 서로 다른 자원을 준비하는 동안 진행할 수 있는
작업을 원작의 NMI 갱신/상주 구조와 비교하는 것이 다음 단계다.
소환/특수 마법, 아군 시전/발사·적 대상·반사·정상 계산/메뉴 통합은 별도 작업이며
R2 0/8·제품 0/3을 유지한다. ROM·번역·원작 추출물·캡처와 원시 로그는 공개하지 않는다.
