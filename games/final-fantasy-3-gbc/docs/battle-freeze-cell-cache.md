# 임시 배경 합성의 현재 타일 재사용

기준은 PR 92 병합 `83739faf540c8045cb7097390bd2fd7097d295af`와
[배경 정본·지도 보존](battle-freeze-resources.md)이다. 이 변경은 기존 일반 마법과
밀집 숫자의 임시 아군 BG 합성을 최적화한다. 정상 전투 통합이나 새로운 마법의
지원 완료로 세지 않는다.

## 원작 수명과 변경 이유

`33/B589..B5B8`의 패턴 적재 뒤 `B6DD`는 대상을 순회한다. `B6F3`에서 대상별
효과음을 요청하고 `B711 → B7CF`에서 다음 그림의 셀과 좌표를 만든다.
`B765..B797`은 OAM에 좌표·타일·속성을 복사한다. `B7A9..B7B4`는 같은 그림을
정확히 네 번의 VBlank 동안 유지한다. 패턴을 같은 그림의 셀마다 다시 적재하는
구조가 아니다. 적 본체 호출자 `2F/B15E`와 숫자 자원 복구 `B175`도 유지한다.

GBC의 임시 BG 합성은 OBJ 한도 때문에 필요한 별도 적응이다. 직전 구현은
서로 겹치는 셀에서 같은 현재 VRAM 타일을 다시 읽었다. 원작의 패턴 수명처럼
합성이 끝날 때까지 읽은 패턴을 재사용하되, 현재 상태 이상·직업 그림을 ROM
기본값으로 추정하지 않는다.

- 8개 직접 매핑 타일 캐시는 **현재 VRAM**에서 읽고 은행과 타일 번호를 함께
  키로 쓴다. 충돌하면 다시 읽는다. 합성 시작마다 모든 태그를 무효화한다.
- 지도는 같은 4셀 묶음의 타일/속성을 함께 읽는다. 활성 페이지는 합성 중에
  변하지 않는다. 두 페이지가 같다고 가정하지 않으며 뒤의 실제 지도 보존은 유지한다.
- 캐시 128바이트·태그 16바이트·지도 8바이트는 기존 `text_staging`을 이 구간에서만
  빌린다. 동기 전송이 모두 끝난 뒤 시작하며, 합성 중 다른 전송/지도 작성자는
  실행되지 않는다. 오디오는 별도 자원을 사용한다. 합성 뒤 미러·팔레트·지도 전송이
  임시 메모리를 다시 사용한다. 추가 WRAM 은행이나 지속 캐시는 없다.
- 정렬된 같은 팔레트의 셀은 겹치는 행만 bitplane으로 합친다. 투명색과 앞선
  OBJ 우선순위, 좌우/상하 반전을 보존한다. 가로 오프셋이나 혼합색은 기존 정확한
  색 비교 경로를 계속 사용하며, 표현 불가능한 셀은 명시적으로 실패한다.

다음 그림을 미리 만드는 변경은 이 최적화와 구별한다. 현재 원작 OAM 진단 상태와
실제 표시용 다음 페이지를 함께 쓰므로, 유지 중 같은 버퍼를 덮어쓰면 아직 표시 중인
원작 프레임과 관측 상태가 어긋난다. 선행 계산을 도입할 때는 다음 그림의 소유권과
현재 그림의 진단 상태를 분리하고, `B6F3` 효과음 요청과 네 번의 대기 순서까지
별도로 검증해야 한다. 이번 변경은 그 순서나 소리 요청을 앞당기지 않는다.

## 비용과 남은 한계

같은 35게시 일반 마법을 고정 MesenCore에서 비교했다. 측정은 오디오와 전송
대기가 포함된 에뮬레이터 시간이다. 별도 진단 실행의 구간별 측정도 같은 ROM이다.

| 항목 | PR 92 | 이번 변경 |
| --- | ---: | ---: |
| 아군 셀 합성 구간 | 441.582ms | 370.286ms |
| 초기 준비 포함 최대 게시 간격 | 1,221.980ms | 1,155.021ms |
| 전체 행동 | 2,612.753ms | 2,579.438ms |
| 초기 이후 최대 게시 간격 | 100.470ms | 100.444ms |

합성 구간은 약 16.1%, 초기 최대 지연은 약 5.5%, 전체는 약 1.3% 감소했다.
원작 속도에 도달한 것은 아니며, 연출 중 약 100ms 간격은 실질적으로 그대로다.
캐시만 넣은 중간 후보는 합성 390.414ms·전체 2,579.366ms였다. 행 합성 계산을
더 줄여도 뒤의 오디오 생산과 VBlank 전송 정렬 때문에 전체 시간은 거의 같다.
계산 비용 절감을 그대로 체감 시간 개선으로 환산하지 않는다.

고정 WRAM 끝은 `$CF82`로 경계까지 126바이트가 남는다. 태그/그룹 상태와
진단 카운터로 직전보다 6바이트 늘었으며 캐시 본체는 기존 scratch 152바이트다.
은행 51의 코드 길이는 `$1740`이다. 전송 중인 버퍼와 캐시를 동시에 소유하거나
이 캐시를 다음 행동까지 유지하는 확장은 별도 수명 검증 없이 허용하지 않는다.

## 검증 방법

`battle-freeze-audit.mjs`는 합성 종료 때 유효한 캐시 각 바이트를 물리 VRAM과
비교하고 읽기/재사용 횟수를 기록한다. 기존 두 페이지·두 은행 전체 지도 복구,
정본 패턴·signed 사본, 원작 OAM·전체 화면 픽셀 및 오디오 소비 해시 검증을 유지한다.
타일을 덜 읽었다는 수치만으로 성능 또는 정확성 개선을 판정하지 않는다.

최종 ROM `ea09eb3a45ebb92ec2268fffb856fe416d3e9e7b042ee81a07098da060956a2b`에서
940개 화면·11회 × 7,200 = 79,200 오디오 틱을 통과했다. 원작 명령/출력 해시와
효과음 요청을 대조했고 오디오 부족·늦은 처리·불법 VRAM/OAM 접근은 0이다.
13회 합성의 캐시·전체 지도·정본 패턴·signed 사본 불일치도 모두 0이었다.
그 13회에서 타일 요청 962번 중 523번을 재사용하고 실제로 439번 읽었다.
대표 1회는 74번 중 39번 재사용/35번 읽기다. 상주 효과 풀 중간 검사 593회도 통과했다.

최대 30쌍 마법은 35게시/2,579.366ms, 아군 4명 대상은 142게시/5,694.571ms다.
양손 지팡이는 이전과 같은 83게시/2,110.163ms·최대 간격 83.956ms다.
호스트 10/10 테스트와 공개 소스 625개의 독립 재빌드가 통과했으며, ROM 3개를
포함한 산출물 12개가 바이트 단위로 일치했다. 고정 MesenCore SHA-256은
`1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.

재현 명령은 다음과 같다. 자동 재생은 픽셀/OAM 전수 캡처와 분리해서 같은
ROM의 실제 게시 간격을 측정하며, 두 종류 모두 완전한 오디오 일정을 실행한다.

```text
node tools/build-battle-party-oam.mjs --effects
node --test tests/battle-animation.test.mjs tests/battle-magic-frames.test.mjs tests/battle-magic-video.test.mjs
node tools/verify-battle-magic.mjs
node tools/verify-battle-magic.mjs --back --status --skip-build
node tools/verify-battle-magic.mjs --flips --skip-build
node tools/verify-battle-magic.mjs --flips --back --status --skip-build
node tools/verify-battle-magic.mjs --auto --skip-build
node tools/verify-battle-magic.mjs --auto --case 1 --skip-build
node tools/verify-battle-magic.mjs --auto --case 2 --skip-build
node tools/verify-battle-effects.mjs
node tools/verify-battle-strike.mjs --numbers --skip-build
node tools/verify-battle-hit.mjs --numbers --back --skip-build
node tools/verify-battle-strike.mjs --auto --skip-build
```

R2 0/8·제품 0/3은 유지한다. 돌/보스 변형, 아군 시전·발사, 적 대상·반사·특수/소환과
정상 계산·메뉴 통합은 별도 소비자다. ROM·번역·추출 데이터·캡처는 공개하지 않는다.
