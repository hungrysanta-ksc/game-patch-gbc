# 원작 활·화살 연출의 실제 화면 연결

기준은 PR 85 병합 `c3eef8007e617e76fbafc5dc17ad52fd0535088f`다.
활(kind 3, ID 74..78)과 화살(kind 8, ID 79..86)의 양손 조합을 연결한다.
장비 적합성·소모·피해 계산·정상 선택의 통합 승인은 별도다. 단독 활, 단독 화살,
다른 무기와의 조합, 상태 이상·치명타·아군 대상은 이 실행기에서 명시적으로 거절한다.
원작의 해당 분기가 없다는 뜻은 아니며, 미지원 경계를 성공으로 처리하지 않는다.

## 원작 실행 구조

- `2F/B24F`: 기존 전진·직업 그림·양손 자원 로드·공통 연출·복귀의 소유권을 유지한다.
- `33/A0CF..A0F3`: 3+8 또는 8+3 조합이면 활을 든 손만 실행한다. `A24C`가 오른손
  명중 수를 왼손에 복사한 뒤, `A094/A077`이 **활을 든 손만** 최대 6회로 제한한다.
  반대 손의 복사된 값까지 제한하면 원작과 달라진다.
- `33/A251..A272`: 선택된 손의 명중 수를 보관하고 두 손의 타격 팔레트를 교환한다.
  그래서 활 쪽이 아니라 화살 쪽 팔레트가 표시된다. 효과음 `$AF`를 한 번 요청한다.
- `A275..A2C7`: 16회 VBlank를 기다리며 앞/뒤 8회씩 두 그림을 표시한다. 오른손은
  활→화살→아군, 왼손은 아군→화살→활의 OAM 순서다. pose는 각각 1/6이다.
- `A6D2..A749`: `A7A5`가 원작 배치·아군·대상의 각도표를 읽는다. `BF5F/BFB1`으로
  x/y 각도를 설정하고 거리 16에서 시작해 16씩 증가한다. 매 비행 그림 뒤 원래의
  unsigned x 비교로 도착을 판정한다. 비행 그림은 4회마다 수직 반전한다.
- `33/BFC6..BFFC`, RAM `7EE3`, 원본 표 `10/9A80..9B7F`: 부동소수점 삼각함수를
  사용하지 않는다. 음수 표 값은 먼저 **1의 보수**로 만든 뒤 곱하고 결과를 부호 반전한다.
  정수 절댓값을 곱하면 경계에서 원본과 달라진다.
- `A74F..A798`: 활·아군 그림으로 scratch를 새로 만들고 첫 명중 화살을 추가한다.
  `32/987C..98D0`은 손에 따라 tile `$52/$4A`, 효과음 `$DA`, 6회 대기를 처리한다.
  첫 화살 뒤에는 `A798`의 1회 대기가 추가된다. 빗나감도 `A798`은 기다린다.
- `32/9823..9869`: 추가 화살마다 x RNG(0..24), **버리는 RNG 1회**, y RNG(0..38)를
  순서대로 소비하고 중심에서 16을 뺀 위치에 화살을 누적한다. 기존 화살을 지우지 않는다.
- `A2CC → AC35`: `$FF` 정지 요청·자세·공유 타일/팔레트 복구 후 원래 복귀 흐름으로 간다.

## GBC 표시 구조와 비용 경계

별도 bank 57 실행기가 위 상태를 보관하며, 기존 이동·상주 직업/양손 타일·공유 RNG·
VBlank 게시·복구는 공통 소유자가 처리한다. 완성 OAM 프레임 배열은 제품 ROM에 넣지 않는다.
8회씩 같은 발사 그림과 박힌 화살의 대기는 현재 OAM을 다시 게시한다. 원작 대기를
삭제하지 않고, 동일 그림 준비·스캔라인 검사를 반복하는 비용만 피한다.
GBC 도착점 투영에 필요한 최종 거리는 발사 전 한꺼번에 탐색하지 않는다. 16회 발사
대기 중 한 번씩 원작 벡터를 조사해 준비한다. 같은 그림의 대기에서도 게시와 오디오는
계속 진행하며, 비행 프레임 밖에서는 투영 나눗셈을 하지 않는다.

원작 raw OAM은 변경하지 않고 검증용으로 유지한다. 160×144에서 원작의 고정 각도표를
그대로 좌표로 쓰면 축소·후퇴한 적과 도착점이 어긋난다. 비행의 원작 거리/도착 판정은
논리 프레임 수를 결정하고, GBC 화면은 같은 진행률로 활 앞→축소된 적 중심을 연결한다.
첫 명중 화살이 그 도착점에 남고, 후속 난수 위치는 적 기준 7:8로 투영한다.
화살·활·아군의 타일 크기와 모든 도트는 유지하며, 백어택은 원래의 좌우 반전을 유지한다.
GBC 전용 위치 변환은 원작 raw OAM 비교와 독립적인 투영/전체 픽셀 비교로 검사한다.

검증 입력은 원작 호출 경계에 주입한 진단이다. 각도표와 연출이 일치하더라도 정상 전투의
장비·계산·이벤트 호출까지 완료한 것으로 세지 않는다. 음질 승인도 해시/타이밍 검사와 별도다.


호스트 검사에서는 65,536개 angle/distance 입력을 실제 6502 소비자와 비교한다.
GBC 소비자 검사는 기존 2,560조건에 vector 1,792조건, arrow RNG 1,024조건을 더한다.
RNG 검사는 두 표의 모든 256개 시작 카운터와 wrap, 버리는 호출까지 포함한다.
실제 화면 검사는 원작 `B24F`를 실행해 `A2BF/A720/A798/98C8` 직전의 raw OAM·
아군 상태·상주 타일·팔레트·최종 명중 수·난수 소비·효과음 요청을 비교한다.
각 실행은 원작 음악과 동적 효과음 7,200틱을 끝까지 비교한다.
후열 actor 1/3은 이동 대기와 캡처 시간이 길어 정면·백어택을 별도 묶음으로 실행한다.
두 방향을 한 묶음에 넣으면 유한 7,200틱 진단이 끝난 뒤 다음 요청이 수동 오디오를
시작해 종료 조건을 만족하지 않았다. 시간 제한을 느슨하게 하거나 원작 대기를 줄이지
않고 묶음을 나눴으며, 두 실패 실행은 최종 성공 합계에서 제외한다.

## 최종 검증

최종 ROM SHA-256은 `96d98f91889ab7cb019c68f0ea7cde4639e55f861a2a397102616f525bfeb552`다.
모든 아래 화면/오디오 검사는 이 ROM 하나에서 실행했다.

| 검사 | 결과 |
|---|---|
| 활 5종·화살 8종을 포함한 8장비 조합 × 정면/백어택 | 16조건·1,114장; 빗나감·최대 명중·좌우 명중 불일치 포함 |
| 아군 4명 × 적 8칸 × 정면/백어택 | 64조건·3,926장 |
| 활→9999 피해 숫자 | 2조건·164장; 숫자 32프레임 유지 |
| 기존 검·봉·하프·맨손/클로·공통 효과 회귀 | 2,512장 |
| 전체 화면 대조 | 7,716장; 원작 상태/자원과 GBC 투영·전체 픽셀 검사 통과 |
| 원작 음악·동적 효과음 | 20회 각각 7,200틱, 총 144,000틱; 소비/변환 해시 일치 |
| 안전 검사 | 오디오 부족·지연, 잘못된 VRAM/OAM 접근 0 |
| 컴파일된 스프라이트·벡터·난수 소비자 | 5,376조건 통과; 오류 주입 ROM 첫 잘못된 바이트 검출 |
| 호스트 검사 | 14개 통과; 원작 벡터 65,536입력 포함 |
| 소스 전용 재빌드 | 공개 허용 597파일에서 ROM/보고서 등 9산출물 바이트 일치 |

캡처 파일 번호가 999를 넘을 때도 프레임 순서대로 읽도록 검증기의 정렬을 숫자 순으로
바꿨다. 실패·예비·부분 오디오 실행은 위 합계에 넣지 않는다.

최대 명중 왼손 활 진단은 91게시(57본체+34이동/복구), 8사운드 요청,
최종 명중 `[99,6]`, RNG `[13,23,197]`이 원작과 일치한다.
준비는 46회, 같은 그림 재게시가 45회다. 원작 프레임을 줄인 수치가 아니다.

| 자동 실행 | 초기 집중 계산 | 대기 중 분산 계산 |
|---|---:|---:|
| 전체 행동 ms | 1808.770 | 1808.769 |
| 최초→최종 실제 DMA ms | 1691.046 | 1691.046 |
| 최대 실제 DMA 간격 ms | 100.417 | 83.707 |

초기 구현은 첫 발사에서 기존 90ms 회귀 기준을 넘었다. 최종 거리 탐색을 16회 발사
대기로 분산하고 투영 계산을 비행 구간으로 제한해 해당 기준을 통과했다. **총 행동
시간을 줄였다는 주장은 하지 않는다.** 전체 오디오 검사를 통과한 최종 ROM의 수치다.
먼 대상의 후열 최대 명중은 96게시(62본체+34이동/복구), 전체 1909.253ms,
최대 실제 DMA 간격 83.708ms로 통과했다. 두 자동 검사는 각각 전체 7,200틱을 소비했다.
원작 속도·음질·실기 승인은 별도다.

기존 검/봉의 전체 행동은 각각 2110.170/2110.144ms, 하프 3282.779ms,
맨손 최대 양손 3098.525ms다. 기존 네 계열의 최대 실제 DMA 간격은 약 83.956ms다.
PR 85 대비 실제 표시 기간은 유지되고, 전체 행동의 차이는 0.1ms 이내다.
PR 84→85 때 기록한 하프의 약 33ms 증가는 해결된 것으로 지우지 않는다.

벡터 API는 현재 활 호출자가 쓰는 A 레지스터의 바이트 결과를 반환한다. 다른 투사체
소비자가 6502 carry에 의존한다면 그 플래그도 별도로 이식해야 하며, 단순히 반환 바이트의
부호로 대체하면 안 된다. 후속 부메랑·원월륜·수리검은 호출 순서와 수명을 다시 확인한다.

bank 52 코드/표는 3,154바이트, bank 55는 4,537바이트, 새 bank 57은 2,195바이트다.
고정 WRAM 끝은 `0xCF0E`로 242바이트 여유다. 이전 대비 고정 상태는 22바이트,
원본 sine 표 256바이트와 4진단 프로필의 각도·도착점 표 256바이트가 추가된다.
상주 직업·양손 타일을 재사용하며 완성 연출 프레임을 저장하지 않는다.
