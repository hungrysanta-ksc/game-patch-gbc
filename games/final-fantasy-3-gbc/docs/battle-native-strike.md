# 상주 화면의 원작 칼질 처리

이 변경은 공통 호출자의 그래픽 18 중 **무기 종류 1(검·단검·창·도끼)**을
상주 V6 화면에 연결하는 개발 단계다. 무기·마법·사망 전체 연결 완료가 아니다.
다른 무기 본체, 치명타·특수 상태, 아군 대상 피격, 적 점멸, 마법·소환,
상태 확정과 사망 처리는 완료 티켓을 반환하지 않는다. R2 0/8·제품 0/3을 유지한다.

## 보존한 원작 구조

| 원작 | 런타임 책임 |
|---|---|
| `2F/B24F`, `B38E`, `B25B` | 전열에 따른 전진·원위치 복귀 |
| `2F/A9CF`, `A8EA` | 직업별 행동 그림, 양손 무기 그림·속성 로드 |
| `33/A094`, `A0C0` | 오른손→왼손, 무기별 명중 횟수 상한 |
| `33/A365..A3DA` | 한 번당 8프레임, 뒤 4프레임의 칼질 궤적 |
| `33/A065/A06E`, `32/90EA` | 왼손/오른손에 따른 무기·행동 캐릭터 그리기 순서 |
| `32/9357`, `991F` | 원래 메타스프라이트·슬래시 마스크에서 매 프레임 OAM 생성 |
| `33/AC35`, `2F/AFD8` | 손별 정리, 임시 그림·팔레트 복원, 완료 통지 |

공격 중인 아군은 원래 파티 OAM 위치와 임시 효과 위치에 중복해서 그리지 않는다.
임시 효과 OAM에 원작 순서대로 넣고 나머지 아군·적 색 보완 OBJ를 뒤에 유지한다.
흰 여백이나 그림을 잘라서 예산을 맞추지 않는다. 원본 타일 0인 투명 레코드는
원작 OAM 검증에 그대로 남기며, 실제 GBC OBJ 슬롯만 소비하지 않는다.
게시 전에 전체 40개와 줄당 10개, 전체 8×8 글리프의 화면 경계를 검사한다.

원작 무기 ID 88개와 직업 22개의 로더 결과는 변경되지 않는 리소스로 컴파일한다.
런타임에는 완성 프레임·관측 OAM·시간별 동영상이 들어가지 않는다. 6502 실행기는
빌드·검증 시 원작 기준을 얻는 데만 사용한다. 지원하지 않는 종류의 그림을
추출할 수 있다는 사실을 그 종류의 연출 구현 완료로 세지 않는다.

## 축소된 적과 이펙트 위치

적의 원작 중심 좌표를 실제 상주 배경의 7:8 축소·8px 후퇴·백어택 변환에 통과시킨다.
구형 시안의 `+8,+18` 기준을 쓰면 현재 배경보다 가로 16px·세로 2px가 어긋나므로
사용하지 않는다. 적의 불투명 픽셀 외곽을 다시 재서 기준점을 바꾸지도 않는다.

칼질 크기와 도트는 그대로다. 4프레임의 모든 유효 글리프를 합친 경계는 원작
중심 대비 정면 `[-24,24)`, 백어택 `[-23,25)`, 세로 `[-15,33)`이다.
이 전체 경계가 화면에 들어오게 기준점을 **연출 전체에서 한 번만** 보정한다.
검증 편성의 양 끝 적에서는 최대 4px 안쪽 이동이며, 프레임별 위치 떨림은 없다.
백어택은 점의 반전 `255-x`와 8px 타일 좌상단의 반전 `248-x`를 구분한다.

사용자의 후속 지침은 마법에도 적용한다. 개별 대상의 이펙트는 축소된 해당 적의
기준점을 따르고, 전체 대상/소환은 원작의 범위·화면 기준점을 유지한다.
필요하면 이펙트 축소도 허용되었지만 현재 칼질은 축소하지 않았다.
마법에 칼질의 경계나 보정 수치를 그대로 적용해서는 안 된다.

## 오디오와 자원 수명

각 칼질의 `$B6` 요청과 손별 `$FF` 정리를 원작 오디오 명령 경로에 넣는다.
자동 진단 일정과 동적 요청을 함께 처리하고 실제 소비 틱·원작/변환 출력 해시를
대조한다. 요청 등록만 검사하거나 임의 효과음 파일을 재생하는 방식이 아니다.
비활성 OAM 구성·줄당 검사 사이에 오디오를 보충하며, IRQ 소비는 그대로 유지한다.
밀집 숫자 회귀 검사에서 발견한 셀 중복 검색의 긴 공백도 같은 방식으로 나눈다.
오디오 보충량·음표·엔벌로프·변환 품질 정책을 변경하지 않는다.

코드는 bank 52/55, 원작 불변 리소스는 bank 53/54에 둔다. DMA 원본은 16바이트
경계에 놓고 빌드에서 확인한다. 정렬되지 않은 원본으로 인한 전송 실패를 경계
검사 완화로 숨기지 않는다. 원래 파티용 그림과 임시 무기용 그림의 수명을 나누고
손별 팔레트 및 완료 후 공유 영역 복원을 검사한다.

## 검증 범위와 재현

화면 검증 ROM SHA-256:
`55b577ef36a7e81f42cccd5dba9415c3a090ff8fa455f9188b667ebd839eb9ff`.

- 메타스프라이트/슬래시 생성기: 컴파일된 GBC 1,568조건 원작 일치,
  기대값 오류 주입 ROM도 첫 불일치를 검출한다.
- 양손·명중 상한: 정면/백어택 6조건, 368장. 99는 명중 카운터의 상한 진단값이며
  직업 레벨 99의 실제 피해 계산 결과라는 뜻이 아니다.
- 아군 4명·전/후열과 적 8칸의 위치: 정면/백어택 16조건, 544장.
- 칼질→9999 피해 숫자: 정면/백어택 116장. 원작 숫자 32장씩 모두 이어서 검사한다.
- 기존 8체 네 자리/회복/미스 회귀: 198장. 총 캡처 1,226장 원작 OAM/실제 OAM/
  전체 픽셀 일치. 각 실행의 오디오 7,200틱에서 소비 출력 일치, 부족·지연 0,
  잘못된 VRAM 읽기/쓰기와 OAM DMA 0.
- 호스트 173검사 통과. 이전 `npm test` 목록에서 빠진 공통 애니메이션 검사도 연결했다.
- 기본 `--windows` ROM은 PR 76의
  `43e7794f03574db82e6759480b1a0fa355364e9e40f34510c529e4345f6cfa1c`와 바이트 동일.
- 공개 허용 소스 579파일에서 효과 ROM, 생성기/오류 주입 ROM, 보고서와 원작
  리소스 추출 결과를 별도 디렉터리에서 바이트 단위로 재현했다.
- 정적 WRAM 끝 `$CE1D`, 새 코드 bank 52/55는 각각 1,659/2,399바이트다.
- 게이트 없는 양손 최대 반복: 83장 모두 게시, 최초→최종 게시 5,251.901ms,
  게시 간격 49.561..166.992ms, 요청부터 정리까지 5,392.833ms.
  동적 요청 10개와 오디오 7,200틱도 일치하고 부족·지연은 0이다.
  **원작 속도는 미달**이다. 전체 파티 OAM의 중복 구성, 매 프레임 줄당 예산 계산,
  임시 자원 로드/복원을 분리 계측하고 원작처럼 실제로 바뀐 행동 객체만 준비해야 한다.

```powershell
npm run build:battle-motion-sprites
npm run verify:battle-motion-sprites
node tools/verify-battle-select.mjs --motion-sprites --negative
npm run build:battle-effects
npm run verify:battle-strike
npm run verify:battle-strike-positions
npm run verify:battle-strike-numbers
npm run verify:battle-strike-auto
npm run verify:battle-effects
npm test
```

검증 입력은 실제 원작 로더가 만든 편성 3과 명시한 장비/행동 상태다. 정상 플레이에서
명령을 선택하고 피해 계산 결과를 전달하는 통합 경로가 아니다. 특히 스크립트의
`result=2`로 아직 없는 상태 확정/사망 명령을 원작 분기에 따라 건너뛴다.
이 경계를 숨기고 정상 공격 종료나 다음 선택까지 완성했다고 주장하지 않는다.

게이트로 모든 장의 원작 OAM·실제 GBC OAM·전체 픽셀을 검사하는 실행과,
게이트 없는 자동 속도 측정은 분리한다. 자동 속도가 원작에 도달했다는 승인은
별도이며, 에뮬레이터 타이밍 통과도 실기·음질 청취 승인을 대체하지 않는다.
생성 ROM·번역·원작 그림·캡처·로그는 공개 패키지에 포함하지 않는다.

준비 비용 후속 결과는 [행동 객체의 중복 준비 제거](battle-action-preparation.md)에
기록한다. 위 속도와 소스 수는 PR 77 당시 기준이다. 정적 WRAM의 전체 끝은 초기화
영역까지 포함한 `$CE48`이며 위 `$CE1D`는 초기화 영역을 제외한 값이다.

## 다음 통합 경계

1. 남은 무기 종류와 피격/감싸기, 적 점멸, 특수 상태를 같은 원작 호출 경계에 연결한다.
2. `2F/B15E`→`33/BAFD`의 19개 마법 본체와 소환: 시전 준비·투사체·명중·정리,
   대상 마스크, 개별/전체/화면 기준점, 동적 사운드와 자원 복원까지 검증한다.
3. `34/935F..94D5`, `9D06`의 상태 확정을 먼저 연결한 뒤 그래픽 7/10/11/12/35를
   소비한다. 일반 적의 `2F/BB5E`와 보스 `BEA4`는 서로 다른 사망 처리다.
4. 숫자·HP·상태창·행동창과 한 흐름으로 묶고, 정상 입력→계산→연출→다음 선택을
   검사한다. 최초 밀집 숫자 준비 지연도 별도의 미해결 성능 조건으로 유지한다.
