# 재시전 위상과 상주 준비 전송

## 원작과 자원 수명

원작 `33/B68D → B589`는 그래픽·시퀀스를 시전 시작에 준비한다.
`B6DD/B6F3 → B711`, `B765..B797`은 같은 상주 패턴의 타일·속성·좌표를
대상별로 소비한다. `B7A9..B7B4 → 3F/F8C5`는 준비된 OAM을 NMI에 맞춰
게시하고, `33/A42B`와 마지막 대기가 연출 소유권을 해제한다.

GBC의 OBJ 수 제약 때문에 정지 아군 합성 어댑터는 남지만 원작의 상주 자원과
준비/전송 분리를 따른다. 원작의 프레임·대상·대기 횟수·소리 요청, 원본 도트와
숫자는 바꾸지 않는다. 일반 마법 진단의 최적화이며 소환·반사·전투 전체 완성을
의미하지 않는다.

## 구현과 확인 경계

- 재시전의 glyph 의존성을 WRAM 4에서 4개씩(72바이트) 읽는다. 마지막 부분 묶음은
  실제 개수만 읽는다. 각 키가 가리키는 현재 VRAM 16바이트는 전부 비교한다.
  OAM·팔레트·활성 지도·패턴의 정확한 무효화 조건은 유지한다.
- 합성 결과가 있는 WRAM 3 `[2816,4096)`을 직접 VRAM 전송원으로 쓴다.
  bank 1 임시 복사와 개별 전송 사이의 전경 재진입을 제거한다.
- 상주 bank 1 작업 버퍼의 미러 타일 256바이트 → WRAM 3 합성 패턴 →
  `effect_palettes`의 BG4..7 순서를 한 동기 소유 수명으로 묶는다. ISR은 준비된
  명령만 소비한다. 대기 중 세 원본은 변경하지 않는다. 화면 게시 전에 완료한다.
- 일반 임시 버퍼/미러 전송은 128바이트, 상주 WRAM 패턴은 최대 256바이트다.
  기존 마스킹된 고정 ROM leaf로 SVBK를 전환하고 bank 1로 복귀한 뒤 스택을
  사용한다. 새 은행 전환 방식이나 오디오 선행량 축소는 도입하지 않는다.

`profile-battle-freeze-costs.mjs`는 이전의 프레임 단위 완료 관측을 유지하면서
`action_enabled` 쓰기의 실제 시작/종료 클록도 기록한다. `--settle-frames 1..8`은
진단 입력 전 대기만 바꾸며 기본값 2와 제품 실행 규칙은 그대로다. 고정 도구와
기계어 대조, 배타적 CPU/WRAM/VRAM/오디오/IRQ/전송 대기 합산을 유지한다.

검증은 완전한 오디오 일정과 화면 대조를 별도로 수행한다. 읽기 전용 비용 계측을
음악·효과음 검증이나 정상 플레이 증거로 대신하지 않는다. 경계 주입은 네 번째·
다섯 번째·마지막 부분 묶음의 glyph를 바꾸어 강제 재합성과 비교한다.

## 결과

기준은 PR 100 병합 `a7d3a24ae16ee80b526b1f07dafca6867b504d37`이다.
이전 +16.693ms 회귀는 관측 양자화만의 결과가 아니다. `action_enabled`의 실제
경계도 PR 99의 1384.774ms에서 PR 100의 1401.442ms로 16.668ms 늘었다.
같은 재사용 검사 CPU는 줄었지만 첫 시전 단축으로 재시전의 음악 진행 시점도
달라진다. 재사용 검사 오디오 보충 37.495→46.191ms, 지도 준비 보충
29.458→37.278ms와 VBlank 대기가 증가했다. 오디오 작업을 전부 전송 대기로
오인하거나 특정 위상에 맞춰 원작 대기/선행량을 줄이지 않는다.

실제 데이터 처리량은 유지하며 중간 복사와 반복 진입만 줄였다.

**기본 조건의 첫 시전 전체는 사실상 같다.** 최초 지도 준비의 오디오/대기
위상이 이득 대부분을 흡수했다. 이 증가도 숨기지 않고 다음 분석 대상으로 남긴다.
단순히 16ms의 타일 준비 단축을 전체 시전 단축이라고 부르지 않는다.

위상별 실제 행동 구간을 별도로 비교했다. 입력 전 대기만 1/2/3프레임으로
달리하고 각 조건에서 기존/신규에 같은 입력을 사용했다. 연속 재시전은 첫 시전이
끝난 뒤 시작하므로 두 ROM의 두 번째 절대 음악 클록까지 같다는 뜻은 아니다.

않는다. 최초 합성과 지도 준비, 0.5초 목표, 소환/특수 경로와 정상 전투 전체
통합은 남는다. R2 0/8·제품 0/3은 그대로다.

고정 RAM은 2바이트 늘어 끝주소 CF9C, 여유 100바이트다. 은행 51 코드는
7060→7059바이트다. 두 기존 OAM ROM과 추출 자산은 같고, 변경된 video ROM은
`11aecd29ab1c24dffe78a0b0fe4e080a926f29f86533e230c2af701c3c9ed638`이다.

## 최종 검증

- 호스트 테스트 12개, 에뮬레이터 검증 34종 통과. 일반 화면 1,080장,
  독립 오디오 14회 × 7,200틱 = 100,800틱을 원작 출력·효과음 요청과 대조했다.
  오디오 지연/부족, VRAM/OAM 접근, 은행/가드/전송 오류는 0이다.
- 의존성·지도·좌표·중첩 등 주입 16종의 2,240장과 강제 재합성 1,120프레임이
  일치했다. 독립 OBJ→BG 전체 화면 비교 16쌍과 early-ready 140장도 통과했다.
  새 경계는 실제 의존성 25개의 인덱스 3·4·24를 각각 두 번 바꿔 확인했다.
  로그 보존 수정 후 이 세 경계는 같은 ROM으로 재실행했다.
- 일반/반복 시전에서 합성 타일 업로드 19회, 38청크, 9,120바이트를 원본
  WRAM 및 실제 VRAM과 대조했다. 미러 256바이트와 BG4..7도 매번 비교했다.
  복구 포함 resident DMA 131청크의 최대 leaf는 1,172클록이며 SP·IME·IE·은행·
  VBlank와 마스킹 중 IRQ 미진입을 검사했다. 기존의 하드웨어 계약을 유지한다.
- 기존 오류 경계(주사선 10/11 OBJ, 5색, 금지 지도 팔레트 4..7)와 모든
  지도/패턴 복구를 확인했다. PR 100과 frozen pattern 480바이트 × 2회도 같다.
  별도 자동 마법 두 종류는 1859.004→1859.013ms와 3617.679→3617.638ms로
  사실상 같은 시간이다. 이를 추가 속도 개선으로 세지 않는다.
- 허용 소스 643개를 복사한 깨끗한 빌드에서 산출물 12개가 일치했다.
  검증 중인 고정 Mesen 코어 SHA-256은
  `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`다.
  에뮬레이터 결과를 실제 장치 청취·음질 승인 또는 소환/전편 검증으로 바꾸지 않는다.

집계는 비공개 `.local/recast-final.json`과 `.local/recast-extra.json`에 보존한다.

## 재현

기존 비공개 입력과 고정 도구를 설정한 뒤 빌드한다. 비용 비교는 각 ROM의 실제
소스와 심벌을 함께 사용한다. 실행 중인 검증 DLL은 빌드로 덮어쓰지 않는다.

```powershell
node tools/build-battle-party-oam.mjs --effects
node tools/verify-battle-magic.mjs --repeat
node tools/verify-battle-magic.mjs --auto --repeat --skip-build
node tools/profile-battle-freeze-costs.mjs --settle-frames 2
node tools/verify-battle-freeze-reuse.mjs glyph-fourth
node tools/verify-battle-freeze-reuse.mjs glyph-fifth
node tools/verify-battle-freeze-reuse.mjs glyph-tail
```

위상 비교는 `--settle-frames 1`과 `3`, 기준 소스/ROM은 `--source-root`와
`--video`, 별도 출력은 `--output`으로 지정한다. 원시 기록은 비공개
`.local/recast-*-phase*-summary.json`, `.local/recast-final-*.log`에 보관한다.
ROM·번역·추출 자산·화면·로그는 공개 허용 목록에 추가하지 않는다.
