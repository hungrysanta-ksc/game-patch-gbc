# 첨부 VGZ 활용 조사

기준일 2026-11-22. **새 녹음 없이 첨부 자료를 분석하고 데이터 변환만 수행했다.** 이번 작업으로 기존 GBC 검증 ROM과 비교 녹음은 변경하지 않았다.

## 결론

첨부 VGZ는 NES APU 레지스터 이벤트와 정확한 시간·루프 정보를 가진 입력이므로 GBC용 변환에 사용할 수 있다. 원작 비교용 입력, 전 곡 변환/루프 분석용 자료로 적합하다. 다만 기존 GBC 플레이어에 VGZ를 그대로 넣어 재생할 수 있다는 뜻은 아니다. NES→GBC 음원 변환과 타이밍·루프 실행은 필요하다.

최종 제품의 “사용자 원본 ROM → 추출/변환 → GBC 빌드” 계약은 유지한다. 이 팩은 개발 입력/비교 기준으로 사용하고, 원본 ROM 음악 ID와 대응을 확정한 후 양쪽에 같은 출력 백엔드를 적용한다. 입력 ROM과 이 팩이 모든 경로에서 같은 데이터를 담는다는 증명은 아직 없다.

## 첨부 팩의 실제 내용

- ZIP SHA-256: `69d405cab795a9aaa82be063ac52260fc00f909447384cd66a1c34090bc91500`.
- VGZ 59개, M3U·설명 TXT·PNG 각 1개. 동봉 메타데이터는 2ch-H 제작, 1.00, 2013-12-27, MESS0148 VGM mod 추출이라고 기재한다. 이는 팩 작성자의 설명이며 ROM 리비전 검증을 대신하지 않는다.
- 59개 모두 VGM 1.61, 단일 NES APU 1,789,772 Hz. 다른 음원 칩·FDS·DPCM 데이터 블록 없음.
- 49개에 루프 위치가 있고 10개는 비루프다. 모든 파일의 명령 경계, 총 대기 샘플 수, 루프 구간 샘플 수를 헤더와 대조해 일치했다.
- 명령은 NES APU 쓰기(`B4`), 대기(`61`, `62`, `70..7F`), 종료(`66`)뿐이다.
- 첫 진행 구간 합계 약 33분 29.68초. 이는 반복 재생을 누적한 길이가 아니다.
- 마지막 전투와 엔딩이 분할된 트랙들이 있고, 59번은 **OST Edit**다. 따라서 “원작 음악 슬롯 65개를 모두 일대일로 제공하는 팩”이라고 단정하지 않는다. 원작 97개 효과음의 개별 데이터 모음도 아니다.

## 직접 변환해 확인한 범위

`tools/vgm.mjs`는 VGZ를 gzip 해제하고 VGM을 읽어, 44,100 Hz 샘플 기준의 원본 이벤트 시각과 루프 경계를 보존한다. 음악 파형을 듣거나 채보하지 않으며 NES 실행/녹음도 하지 않는다. 알 수 없는 칩·명령, 깨진 크기/루프는 실패한다.

`tools/audit-vgm.mjs`로 59개 전체를 기존 프레임 패킷 형식에 시험 연결했다.

| 구분 | 바이트 |
|---|---:|
| VGZ 59개 합계 | 417,208 |
| 압축 해제한 VGM 합계 | 1,672,934 |
| 기존 RLE GBC 패킷으로 만든 유한 구간 후보 | 1,055,886 (약 1.01 MiB) |

마지막 수치는 코드·은행 정렬·루프 실행 정보를 제외한 변환 데이터다. 최종 GBC ROM 크기나 품질 보증이 아니다. 이번에는 새 GBC ROM을 빌드하거나 변환 후보를 에뮬레이터/실기에서 재생하지 않았다. 로컬 `build/vgm-audit/report.json`, `*-timeline.json`, `*-candidate.bin`에 결과를 보존했다.

이 팩은 pulse/noise의 constant-volume 및 length-halt 비트가 모두 설정되어 있고, `$4015=0F`, `$4017=40`, triangle `$4008=80/FF`인 범위라 기존 소프트웨어 음량 변환에 연결할 수 있었다. 이 범위를 벗어나는 다른 VGM은 조용히 근사하지 않고 변환을 거절한다. 현재 출력의 기준 클록 1,789,773 Hz와 팩의 1,789,772 Hz 차이도 향후 파라미터화 대상이다.

## VGZ로 더 정확하게 만들 수 있는 부분

기존 약 60.098 Hz 변환은 이벤트를 프레임 시작으로 당겨 최대 약 16.64ms의 시각 오차를 만든다. 데이터에는 그보다 짧은 타격음이 있으므로 이 후보 파일을 그대로 최종 채택하면 안 된다.

5개 트랙(일반 전투·승리·보스·최종 전투 3부·OST 편집본)의 `$4011` 직접 DAC 쓰기를 확인했다. 완료된 비영→0 펄스는 371개, 길이는 26–88샘플, 약 **0.590–1.995ms**다. 기존 GBC의 고정 약 0.49ms CH4 버스트보다 실제 길이를 반영할 수 있는 근거다. 다만 NES DAC와 GBC CH4는 다른 음원이므로 길이 보존만으로 원작 음색이 되지는 않는다.

다음 구현은 원본 이벤트 시간축 유지 → GBC 타이머 기반의 세부 이벤트 스케줄 → 초기 구간/루프 분리 → DAC 펄스 길이 반영 → 변환 재생 확인 순서가 적절하다. 원작 효과음의 BGM 채널 점유·복원, 임의 효과음 요청과 페이드 같은 게임 명령은 원본 드라이버 분석을 계속 사용한다. 정적인 BGM 기록만으로 게임의 사운드 호출 로직을 대신하지 않는다.

## 재현 및 공개 범위

로컬 전용 디렉터리에 팩을 풀고 프로젝트 폴더에서 실행한다.

```powershell
node tools/audit-vgm.mjs --dir "D:/private/ff3-vgz"
node --test tests/vgm.test.mjs
```

파서 회귀 검사는 합성 데이터로 gzip/비압축 동등성, 정확한 대기·루프 시각, 손상/미지원 명령 거절을 확인한다. 입력 VGZ·ZIP과 변환된 음악 데이터는 업로드하지 않는다. 공개하는 것은 파서·변환 연결 코드·조사 문서다.

형식 근거: [VGM 프로젝트의 v1.71 명세](https://github.com/vgmrips/vgmplay-legacy/blob/master/VGMPlay/vgmspec171.txt). VGZ의 gzip 압축, 44,100 Hz 시간축, 상대 루프 오프셋, `B4` NES 쓰기 규칙을 사용했다.
