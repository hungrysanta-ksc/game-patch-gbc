# 혼란·석화가 겹칠 때의 BG 소유권

2026-11-25, PR 62 후속. 32×32 적은 28×28, 아군은 무축소, 지형은 11픽셀을 유지한다.
일반 아군은 OBJ이며, 석화는 원작처럼 BG를 사용한다. 완성 프레임은 개발용 비교 자료이고
실행 ROM에는 원작 초기 자원·상태와 실제 소비자만 들어간다.

## 원작 구조와 이식 차이

`2F/B3D9`의 혼란 전진 뒤 `B58F/B5C3`가 INNER/STATUS를 게시하고, `B6C8`은
배우별 두 열의 석화 맵을 쓴다. 혼란 위치는 정면 원작 열 22, 백어택 열 8이며
V6에서는 각각 열 12와 6이다. 일반·소인·개구리의 실제 원작 글리프를 사용한다.
원작 상태 소비자의 순서·대기·캐시 교체·맵 요청을 유지한다.

GBC 축소 적의 일부 색은 보조 OBJ가 맡는다. 이 OBJ는 원작에 없으므로 석화 BG가
같은 영역을 차지할 때 그대로 두면 적의 색이 석화 위에 남는다. 따라서 원본 적 타일은
상주시킨 채 실제 석화 잉크와 겹치는 비트만 지운 임시 타일을 만든다. 석화색을 BG
팔레트로 직접 나타낼 수 있는 경우에도 이 마스크가 필요하다. 해제 때는 수정 전의 적
타일 ID를 다시 사용한다. 배우 그림 전체를 프레임마다 BG로 바꾸지는 않는다.

BG 셀과 색 보정 OBJ는 기존 비활성 페이지에 준비한 뒤 함께 게시한다. 상태가 같은
페이지는 재구성·VRAM 전송 없이 캐시를 사용한다. 캐시 수명은 정규 위치에 고정된 적
자원과 함께하며, 적 자원/위치가 바뀌는 다른 연출에 자동으로 재사용할 수는 없다.

원작 pose 0이 참조하는 bank 0 타일 0은 빌드에서 전부 투명함을 확인한다. 이 빈 슬롯과
Y=0인 숨김 슬롯만 압축해 색 보정 OBJ에 돌려준다. 보이는 원작 OBJ의 순서는 유지한다.
논리 원작 OAM은 그대로 대조하고, native OAM은 이 압축을 적용한 결과로 별도 대조한다.

적/지형 뒤의 남은 bank 1 공간을 두 페이지로 분할한다. 편성 3은 base 150/48타일,
편성 137의 원작 범위 내 개체 수 `[4,1,0,0]`은 base 162/47타일이다. 고정 150번에서
쓰기 시작하면 뒤 편성의 적 타일을 덮으므로 같은 고정 주소를 강요하지 않는다.
한 페이지 버퍼는 기존 768바이트를 유지하고, 초과는 명시적으로 실패한다.

## 검증 범위와 한계

- 정면/백어택 × 네 명 일반 석화, 일반·개구리·소인 혼합 석화의 4경로.
- 혼란 상태를 유지하면서 석화 비트만 제거하는 진단 입력 뒤 원작 `B5B8`을 실행한다.
  원작 게임의 상태 발생·치료 조건 전체를 증명하는 정상 플레이 검증은 아니다.
- 편성 137의 두 방향 모두 실제 적 보조 OBJ 하나와 석화 잉크가 겹치는 것을 필수로 검사한다.
  단순 사각형 교차만으로 마스크 성공을 판정하지 않는다.
- 석화 지우기는 원작이 요청한 현재 주소만 처리한다. 석화가 남은 배우를 다른 열로
  옮기는 이력은 아직 실패 처리한다. 원작이 내지 않은 지우기를 만들어 넣지 않는다.
- 보스 등장, 창·포격·숫자와의 같은 화면 통합, 원작 속도와 실기 검증은 아직 미완료다.

호스트 152검사가 통과했다. 원작 후반부 비교는 188건, 16,382개 상태·대기,
430,296 전송 바이트이며 C/SM83 대조와 고의 오차 검출이 통과했다.
표시 기준은 668화면이다. 최대 석화 패턴 45개, 색 보정 OBJ 19개이고
실제 겹침 프로필은 마스크 포함 36패턴이다. 한 줄 OBJ 사용량은 최대 5개다.
정적 WRAM 끝은 `CF82`로 126바이트가 남고 bank 16 코드는 7,191바이트다.
다음 상주 자원 추가 전에 임시 버퍼 수명과 공간 재사용을 정리해야 한다.

최종 검증 전에는 상태→명령 선택 전환이 100회 대기 상한을 한 차례 넘었다.
별도 진단에서 상태와 오디오 오류 없이 진행하는 것을 확인한 뒤, 석화 영역과 겹치지 않는
적 보정 타일의 읽기·오디오 보충 호출을 제거했다. 대기 상한을 늘리는 수정은 채택하지 않았다.
`party_max_prepare`는 `present()` 범위이며 그 전에 실행하는 상태 그래픽 로더까지 포함한
전체 요청 지연은 아니다. 다음 비용 분석은 두 범위를 나누어 기록해야 한다.

실행·회귀·공개 소스 재현 결과는 아래 최종 실행 결과를 참조한다.

## 최종 실행 결과

고정 Mesen 코어에서 668화면의 실제 OAM·패턴·896바이트 맵·픽셀과 원작 상태가 일치했다.
원작 BGM·효과음·페이드 10,800틱의 소비 해시가 같고 오디오 지연/버퍼 부족은 0이다.
타이머 오차 0.070ms, 최대 준비 1037.354ms,
자동 대기 게시 간격 최대 8프레임, 지연 게시 1497회다.
석화 패턴/맵 전송 합계는 18240/27264바이트다.
자동 명령 대기의 VRAM 쓰기는 0, 잘못된 DMA/래스터 변경은 0이다.
여러 배우의 상태 변경마다 활성 셀을 다시 구성하는 비용이 커 원작 속도는 달성하지 못했다.
다음 변경에서는 고정 셀 할당과 변경 배우 영역만 갱신하는 방식을 같은 부하로 비교한다.

기존 혼란 이동·복귀 회귀도 642화면/10,800틱 일치, 오디오 지연/버퍼 부족 0이다.
동일 회귀의 최대 준비는 PR 62의 259.766ms에서 274.902ms로 측정됐고
최대 게시 간격은 7프레임이다. 서로 다른 석화 프로필의 수치를 전체 성능 개선으로 해석하지 않는다.
음색 청취 승인과 실기 검증도 별도다.

표시 ROM SHA-256: `556307c5774d72407a5cd8d06edc311a6d6cd2925439918eb46a0c7bc2febc92`.
후반부 함수 검증 ROM: `ed15696d2aba923fade5471a0128dbb82b7ebaa5b05fdc200066be74770350b0`.
공개 허용 소스 496개만으로 표시/함수 대조/오차 주입 ROM 세 개와 보고서가 바이트 단위 재현됐다.
입력 ROM과 고정 도구 경로만 비공개 local.json으로 공급했다.
