# 원작 데이터 등록부와 참조 감사

2026-11-23. 설치된 NES 역분석 스킬의 원본 주소·경계·소비 코드·재현 검증 절차를 적용했다. [스킬 출처와 FF3 적용 제한](development-skills.md).

`spec/data-registry.json`은 원작 PRG 전체의 영역 명세이며, `tools/register-data.mjs`는 지원 ROM에서 슬롯·해시·참조·검증 결과를 생성한다. 디스어셈블리나 번역 파일을 제품 실행에 요구하지 않는다. 생성 보고서는 `build/analysis/data-registry.json`에만 저장하며 Git에 포함하지 않는다. 이 단계는 전체 영역 등록과 일부 소비 경로 검증이다. 모든 내부 테이블 발견, 모든 포맷 추출 또는 게임 완성을 의미하지 않는다.

```powershell
node tools/register-data.mjs --rom "D:/private/Final Fantasy III (Japan).nes"
node --test tests/registry.test.mjs
# 출시/전체 의미 검증 게이트: 현재는 미해결 항목 때문에 반드시 실패한다.
node tools/register-data.mjs --rom "D:/private/Final Fantasy III (Japan).nes" --require-closed
```

기본 명령의 종료 코드 0은 등록 경계와 구현된 대조 검사의 성공이다. `--require-closed`는 별도로 미해결 항목 0을 요구한다. 기존 `survey-source.mjs`는 최초 조사 도구로 유지하며 FE/FF 때문에 종료 코드 1을 유지한다. 이벤트 해석기 자체도 `$C000`을 계속 거부한다.

## 등록 범위와 재현 근거

기준 자료는 [everything8215/ff3 고정 리비전](https://github.com/everything8215/ff3/tree/1acef8117120ff891003de249b1a74bc8d94d674)의 ROM 지도와 주석 코드다. 각 영역에 원본 자료 행, 파일 오프셋, 종류, 기능군, 변환 정책, 의존 기능, 미완료 상태를 남겼다. 보고서는 여기에 원본 바이트의 SHA-256과 8 KiB 뱅크 구간을 덧붙인다. 코드 영역 안의 세부 데이터 표는 발견할 때 하위 등록으로 추가한다.

- PRG 524,288바이트를 166개 명명 영역과 16바이트 미분류 구간으로 빠짐없이 구획한다. iNES 헤더 16바이트는 입력 프로필로 보호한다. 모든 끝 주소는 exclusive다.
- ROM 지도 주소 불일치 12행을 정규화하고, 지형 공격 소비 범위를 추가 수정했다. 크레딧 시작, 컷신 좌표 시작, 조건 스크립트 은행/끝, 효과음 포인터/데이터 경계를 바로잡았다. 고정 영역의 기존 16 KiB 은행 표기는 실제 8 KiB 은행 구간으로 표현한다. 원래 값과 수정 이유를 명세에 보존했다.
- 모든 최상위 포인터 영역 27개와 코드 내부 전투 알고리즘/효과 포인터 2개를 등록한다. 아직 소비자가 검증되지 않은 포인터는 단순 u16 값으로 보존하고, 무조건 파일 오프셋으로 변환하지 않는다. 코드 내부의 미발견 포인터 표까지 전부 찾았다는 뜻은 아니다.
- 이번 등록 결과는 정형 표 32개/6,217슬롯, 포인터 표 29개/5,434슬롯이다. 코드 내부 포인터는 정형 표에도 포함되므로 두 슬롯 수를 더해 콘텐츠 수로 사용하지 않는다.
- 기존 `spec/source.json`의 모든 정형 표와 맵/창/전투 하위 표를 슬롯별로 등록한다. 동일 시작 주소의 두 정의가 개수/크기에 동의하지 않으면 실패한다. 몬스터 AI의 기존 49슬롯 정의도 64슬롯으로 고쳤다.
- 512개 맵의 레이아웃/그래픽 조합/타일셋, 256개 몬스터의 AI, 조건 스크립트 결과와 숙박 이벤트에 대해 2,728개 정적 참조를 기록했다. 음악 조건 결과는 이벤트가 아닌 음악 ID로 분리한다. 나머지 참조 의미는 `remaining-consumer-contracts`로 추적한다.

## 원작 실행과 대조한 범위

| 검사 | 분모와 결과 | 근거/한계 |
|---|---|---|
| 일반 맵 압축 해제 | 256/256 일치 | 원작 `3E/CBFA`, 각 32×32타일 |
| 월드맵 행 압축 해제 | 1,024/1,024 일치 | 원작 `3E/CC47`부터 은행/포인터 선택까지 실행, 각 256타일. 월드 상태 0/1은 첫 표 공유 |
| 몬스터 AI 복사 | 256/256 일치 | `31/A5BA..A5EA`, 속성 +14의 ID로 8바이트 복사 |
| 조건 선택 | 608슬롯, 2,146가지 상태 일치 | NPC 448, 트리거 96, 동행 8, 아이템 48, 음악 8. 원작 `3C/9319`/`92EE`와 비교. 모든 플래그 조합의 전수 검증은 아님 |
| 트리거 선택 인덱스 | 입력 0..255 전부 일치 | `3F/E6C6..E6D5` 실제 명령 실행, 8비트 곱셈의 carry 손실 보존 |
| 이벤트 포인터 선택 | 256슬롯 비교 | 원작 `3E/C72C`; `$FE/$FF`의 비정상 대상도 그대로 관측 |
| 이벤트 명령 경계 | 254슬롯 해석, 2슬롯 명시적 미지원 | E4..FC 및 FE는 2바이트. 명령 실행/스토리 도달성 증명이 아님 |

원작 코드는 사용자 ROM에서 읽고 기존 `Driver6502`로 함수/구간만 실행한다. PPU/APU 전체 에뮬레이션이나 이번 변경의 실제 GBC 실행 검사는 아니다. 대상 코드는 기존 사운드/필드 런타임을 변경하지 않는다.

합성 음수 검사는 등록부 공백/겹침/중복, 잘못된 RLE 길이·누락, `$C000` 이벤트 포인터, 누락된 이벤트 피연산자, 조건 결과 바이트와 조건 비트의 혼동을 검출한다. 손상된 ROM은 입력 SHA-256 검사에서도 거부한다.

2026-11-23 검증: `npm test` 17/17 통과(기존 사운드/VGM 검사 포함), 등록부 검증 오류 0. 공개 허용 소스 90개만 복사한 별도 폴더에서 원본 ROM 경로만 지정해 다시 생성한 보고서가 바이트 단위로 일치했다. 보고서 크기는 3,412,869바이트, SHA-256은 `ecbeb4e72beb27f11131bf4b9847173986314784b123453c71c581ae9e99348b`다. 동일 패키지의 `--require-closed`는 예상대로 종료 코드 1과 명시적 미완료 오류를 반환했다. 원시 로그와 보고서는 로컬 `.local/` 및 `build/analysis/`에 보관한다.

## 미해결 참조 분석과 처리 결정

| 항목 | 확인된 사실 | 구현 시 처리와 다음 조사 |
|---|---|---|
| 이벤트 `$FE`, `$FF` | 둘 다 `$C000`. 실제 MMC3 매핑은 파일 `$7C010`의 고정 코드이며 `$5C010` 전투 데이터가 아니다. 해석한 조건 및 숙박 경로에는 들어오는 참조가 없다 | 각각 미지원 대상으로 등록. 정상 진행에서 도달 불가라고 단정하지 않는다. 공통 상태/이벤트 연결 시 선택 값과 RAM 쓰기 경로를 추적하고, 호출되면 오류 처리 |
| 트리거 개수 | 저장 공간 256 words, 선택 가능한 슬롯 128, 포인터가 있는 슬롯 96. `$60..7F`는 null이고 뒤쪽 128 words도 0 | 256개 스크립트로 추출하지 않는다. 512맵의 타일 초기화/발생 순서/트리거 개수와 월드 경로를 연결해 null 슬롯 참조 여부를 확인. 미분석 상태에서 null을 성공 이벤트로 바꾸지 않음 |
| 몬스터 AI 49개 표기 | 용량 64×8바이트. 전체 몬스터 레코드가 참조하는 ID는 45종. 몬스터 `$DD`의 AI ID는 `$3E`로, 49 이상 영역을 실제로 읽음 | 64슬롯을 보존. 0으로 채워진 `$31..3F`를 무조건 미사용으로 삭제하면 안 됨. 해당 몬스터의 정상 전투 출현 여부는 별도 도달성 조사 |
| 지형 표 뒤 16바이트 | `35/AAD3..AAEA`는 8비트 맵 ID로 `$01:A24E`부터 256바이트만 읽고, 세계에 따라 니블을 선택. 문서상의 271바이트 경계와 다름 | `$235E..236D` 파일 구간은 미분류/예약. 다른 소비자 확인 전 삭제·할당 금지. 아이템 배율 시작 `$236E`는 유지 |
| 나머지 소비 계약 | 상점/보관함, NPC 배치, 텍스트 제어 코드, 그래픽·조우 포인터 등은 영역/슬롯 등록과 의미 검증 수준이 다름 | 등록된 기능군별 다음 PR에서 소비 코드·참조 대상·경계·정상 진행을 추가한다. 원시 포인터 목록을 자동 재배치용으로 사용하지 않음 |
| 정상 진행 도달성 | 조건별 결과 참조는 정적 후보 집합이며 플래그 조합/게임 진행의 가능성을 증명하지 않음 | 초기 상태·RNG·저장 계약 이후 실제 입력 경로로 확인. 의미 미지원 소비자를 성공 처리하지 않음 |

미해결 항목은 FE/FF 각각을 포함해 6건이다. 트리거의 선택 분모와 AI 저장 분모는 해결됐지만, 게임 진행 도달성은 열려 있다. `--require-closed`는 이 차이를 숨기지 않고 실패한다.

## 다음 구현 순서

등록 결과로 기존 의존 순서를 유지한다. 다음은 **코드/데이터 은행 호출 규약, GameState/작업 RAM 수명, 틱과 오디오·VRAM 예약 규약**이다. 이후 초기 상태·원작 RNG·저장 왕복을 붙인다. 이 기반 위에서 일반맵 타일 초기화·객체/트리거 소비자를 연결하면 null 트리거 및 FE/FF 도달성을 실측할 수 있다. 각 기능의 역참조 집합으로 전체 데이터를 다시 검사한다.

동굴별 수작업이나 모든 그래픽의 선행 재제작으로 순서를 바꾸지 않는다. 이번 결과는 [전체 로드맵](implementation-roadmap.md) 첫 등록 작업의 기준이며, 단계 1의 GBC 메모리/최대 부하 위험 검사는 다음 작업으로 남아 있다.
