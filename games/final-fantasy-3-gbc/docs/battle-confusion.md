# 혼란 전진·해제 후 복귀와 상주 표시

2026-11-25. PR 61의 정규 진열·석화·그래픽 캐시 경로 다음 단계다.
일반/개구리/소인 아군의 혼란 이동과 해제 후 전열 복귀를 원작 코드에 따라 연결한다.
무축소 아군 OBJ, 7:8 적 축소(32×32 자원은 28×28), 상단 11픽셀과 V6 좌표를 유지한다.
보스와 **혼란+석화가 같은 배우에 적용된 BG 위치 변경**은 별도 후속 범위다.

## 원작과 같은 상태·수명

- `2F/B6AB`는 혼란이면 X=`B0`으로, 혼란이 해제되고 X=`B0`이면 원래 전열로 이동한다.
  단순히 최종 좌표를 바꾸지 않고 `B3D9/B3F6`의 이동·중간 상태 게시를 실행한다.
- 전진은 `$7DC1`을 올린 뒤 `B45C`를 호출한다. 도착 시 `B58F`의 INNER 대기,
  플래그 해제, 외부 `B5C3`의 STATUS 대기를 각각 유지한다. 같은 그림의 중복 대기도
  원작 호출의 경계이므로 삭제하지 않는다.
- 복귀는 정규화 상태의 혼란 비트를 임시로 세우고 `$7D7D=1`로 걷는다. 도착하면
  임시 비트를 지우고 INNER/STATUS를 게시한다. 기존 함수는 전진만 처리해 복귀를
  생략했으므로, 방향을 받는 공통 `33/BD45` 소비자로 확장했다.
- 일반/개구리는 한 번에 2픽셀, 소인은 1픽셀이다. 개구리의 Y 증감과 두 자세 표는
  원작 자원에서 읽고 복귀 때 방향 비트를 OR한다. 일반/소인의 반전은 임시 혼란
  비트와 `$7DC1` 조건을 따른다. 이동 완료 배우의 Y·자세는 건드리지 않는다.
- 기존 39바이트 이동 상태 및 75바이트 후반부 ABI를 유지한다. 후반부 private chunk의
  bit 6은 보스 단계 종료 후 복귀 방향, bit 7은 독립 B5B8 갱신의 복귀 경로다.
  보스 블록은 최대 36개이므로 두 비트와 충돌하지 않는다. 원작 논리 상태는 별도다.
- 그래픽 캐시 교체→이동→중간 상태→외부 상태 순서를 유지한다. 해제 시 소인/개구리까지
  풀리는 경우와 혼란만 풀려 작은 모습을 유지하는 경우를 구분해 검사한다.

입력은 개발용 정규화 상태 개입이다. 초기 원작 로더 뒤 표시 상태를 설정하고
실제 원작 이동 함수를 호출한다. 혼란 해제 역시 전투 효과 계산 결과를 대신 넣은 것이다.
따라서 주문 성공률·치료 아이템·정상 게임 진행을 검증했다는 뜻이 아니다.

## BG/OBJ 소유권과 비용

혼란 중인 일반 아군도 상주 OBJ로 남는다. 적 BG의 패턴·맵을 배우가 지나갈 때마다
새 그림으로 만들지 않는다. 기존의 상태 아이콘→아군→적 색 보정 OBJ 순서로 겹침을 처리한다.
[Pan Docs OAM 사양](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md)의
CGB 모드에서는 앞선 OAM이 겹침 우선순위를 가진다. 한 줄 선택 한도와 우선순위는
별도 조건이므로 전체 OAM/한 줄 개수와 실제 픽셀을 모두 검사한다.

정규 진열의 다른 석화 배우는 기존 BG 경로를 유지한다. 이동 배우가 원작의 혼란 위치에
clear 맵 명령을 내는 것은 허용하지만, 혼란 위치에 석화 그림을 쓰는 명령은 거부한다.
그 경우는 적 BG의 색 보정 OBJ 마스킹과 석화 BG의 좌표/타일/팔레트 소유권을 함께
해결해야 한다. 그림을 생략하거나 모든 아군을 BG에 합성해 우회하지 않는다.

변하지 않은 석화 페이지의 캐시를 그대로 재사용하며, 두 번의 원작 상태 게시가 같은
자원 갱신을 반복하게 하지 않는다. 다만 현재 descriptor는 빈 clear 위치도 저장하므로
좌표가 달라진 clear 이후 다른 활성 석화 셀을 다시 구성하는 비용은 남는다.
이 비용과 PR 61의 최대 준비 지연은 별도 최적화 과제다. 본 변경은 구조에 맞는
새 소비자 연결이며 원작 속도나 전체 성능 개선 완료로 세지 않는다.

## 검증

- 호스트 150검사 통과. C/SM83 후반부 184건, 15,946개 상태/대기,
  자원 출력 429,448바이트 일치. 기대 상태 변조 ROM은 첫 케이스 첫 바이트에서 실패한다.
  혼란 해제 시 임시 비트, 이동 속도, 도착 좌표와 관련 없는 적 수 보존도 대조한다.
- 표시 기준은 정면/백어택 × 일반/작은 모습의 두 경로, 총 642화면이다.
  218화면에서 불투명 아군/적 픽셀이 겹치며 최대 38픽셀이다. 원작 좌표를 V6로
  변환한 뒤 모든 아군 도트가 화면 안에 있고 독립 NES/GB RGB가 일치하는지 빌드에서 검사한다.
  일반 아군 전진, 작은 배우의 반전, 백어택, 복귀 후 자세를 실제 캡처로 확인했다.
- 최종 GBC 642화면의 픽셀·원작/물리 OAM·논리 상태·전체 아군 CHR·석화 맵/패턴·가드가
  일치했다. 한 줄 최대 OBJ 5개, 표시·전송 오류 0이다. 동일 ROM에서 원작 음악·효과음·
  페이드 10,800틱 소비 해시가 일치했고 지연/버퍼 부족 0, 타이머 오차 +0.071ms다.
  네 경로의 전체 캡처 후에도 자동 명령 대기 부하를 측정할 수 있도록 진단 오디오만
  기존 두 주기에서 세 주기로 늘렸다. 원작 곡/효과음/페이드 내용은 바꾸지 않았다.
- 이번 혼란 경로의 최대 준비 259.766ms, 자동 대기 게시 간격 최대 7프레임,
  지연 게시 2,319회다. 자동 대기 VRAM 쓰기 0, OAM DMA 2,320회, 잘못된 DMA/래스터 변경 0,
  최대 DMA 시작 LY=149. 수동 경로의 석화 패턴/맵 합계는 2,560/6,144바이트다.
  전송 총량과 자동 대기 계측의 범위는 다르다. 이전 석화 프로필과 작업량도 다르므로
  601ms→260ms의 전체 성능 개선으로 해석하지 않는다. 음색 청취 승인도 별도다.
- 기존 석화 회귀 317화면과 원작 오디오 7,200틱 일치, 지연/버퍼 부족 0,
  타이머 오차 −0.006ms. 자동 명령 대기 VRAM 쓰기 0이다. 최대 준비 601.318ms와
  게시 간격 최대 7프레임은 남아 있다. PR 61의 6프레임보다 나쁜 관측도 기록한다.
- bank 16 코드 7,191바이트, 정적 WRAM 끝 `CD80`. 방향과 복귀는 기존 상태의
  private 비트로 보관하며 프레임별 완성 그림, 동적 패턴 버퍼나 별도 BG 공간을 추가하지 않는다.
- 공개 허용 소스 495개만 복사한 빌드에서 표시/함수 검증/오차 주입 ROM 세 개와
  보고서가 바이트 단위로 재현됐다. 입력 ROM·고정 도구 경로는 비공개 local.json으로 공급한다.
