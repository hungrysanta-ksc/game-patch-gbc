# 전체 작업 진척

기준: 2026-11-25, V6 유지와 [실제 NES 전투 UI 관찰](battle-ui-observation.md), [네 명 명령 수집·HP 행동명](battle-party-commands.md) 반영.
이번 작업의 기준 커밋은 PR 56 병합 `07940e892004f0ba6780abf3405e67b07724d570`다.
PR 15 병합 `aeeedf69c071a597c06237c0e6ebcb0ce6440264`의 고정 기준선은 회고에 보존한다.
[회고](retrospective-pr15.md) / [현재 작업 순서](implementation-roadmap.md).

**현재 위치: 기반 검증을 확보하고, 일반맵의 부분 탐색·한글 대화·NPC 이벤트를 통합한 단계.**
첫 정상 게임 진행, 전편, 배포 패키지는 아직 완료되지 않았다.

이번 후속은 [V6 BG/OBJ 소유권 재점검과 아군 상주 OBJ](battle-object-ownership.md)다.
일반 아군을 배경 합성하는 기본 구조를 폐기하고 원작의 포즈/좌표 소비자를 실제 GBC
아군 표시로 연결한다. 대표 1,302장면의 한도와 축소 색 보정 비용을 함께 조사했다.
이는 아군 단독 표시 검증이며 적·지형·석화 BG·아이콘·창과 전체 전투 통합은 미완료다.
전체 게임 진척률을 올리거나 기존 원작 속도 지연 문제를 완료로 표시하지 않는다.

직전 후속은 [보스·상태 복원 자원 실행기](battle-entry-tail.md)다.
원작 전반부와 후반부를 GBC에서 이어 실행해 176건, 15,168개 상태/대기,
자원 출력 426,048바이트를 대조했다. 보스의 블록별 시프트, 상태 그림 캐시,
혼란 이동, 석화/해제 맵과 적 수 갱신을 포함한다.
다음은 상주 자산을 쓰는 실제 V6 OAM·VRAM 어댑터다. 화면·오디오 동시 통합은 미완료다.

직전 후속은 [등장 자원 계약과 상태 소비자](battle-entry-resources.md)다.
원작 `B469..B479`의 타일 수명·스크롤·이동·지형 마스크를 C로 옮기고,
512건/16,064상태 및 지형 917,504바이트를 GBC 컴파일 결과와 대조했다.
등장 표시를 위한 새 소비자는 완성 그림 목록을 사용하지 않는다. 보스/상태 복원 뒤 실제 V6 표시·오디오에
연결하는 작업은 아직 남아 있다. 전체 전투 렌더러 완료나 게임 진척률 증가로 세지 않는다.

직전 후속은 [원작 전투 구조 회고](battle-render-architecture.md)다.
음악/규칙/호출자는 원작 이식이지만 전투 표시의 주 경로는 미리 합성한 제한된 그림 자료다.
원작의 스크롤·OAM 변경을 BG 패턴 전송으로 바꾸는 추가 비용을 확인했다.
새 성능 후보는 최대 준비 지연 목표를 충족하지 못해 병합하지 않고 로컬에 보존했다.
다음 작업을 원작 자원 수명·실제 등장 소비자·상주 타일/스크롤/OAM 구조로 변경한다.
이번 회고는 실제 전투 렌더러 완료나 전체 게임 진척률 증가로 세지 않는다.

직전 후속은 [오디오 계산·보충 집중 구간](audio-refill-latency.md)이다.
고정 ROM 표 읽기, 채널별 출력 변환, 보충 루프의 중복 시계/조건 계산을 줄인다.
보충량을 낮추는 안은 언더런이 발생해 폐기하고 기존 안전 기준을 유지한다.
최대 준비 지연은 269.531→218.994ms, 최대 오디오 서비스 호출은 77.899→52.065ms로 줄었다.
8경로 총시간은 3.62~6.28% 단축됐고 픽셀·숫자·21,600틱 오디오 검증을 통과했다.
늦은 준비 수는 1162→1163회로 1회 늘어 추가 목표는 미달이다. 전체 원작 속도 관문도 미통과다.

직전 후속은 [오디오 생산자 내부 비용](audio-producer-costs.md)이다.
실제 호출 경계로 원작 명령 처리·출력 변환·진단 기록을 분리하고, 엔벌로프 읽기와
패킷 메타데이터 복사를 최적화했다. 같은 8경로의 전체 시간은 2.30~5.13% 줄었고,
128개 호스트 테스트·327,680건 GBC 읽기·1,784장 픽셀·21,600 오디오 틱 검증을 통과했다.
최대 준비 지연은 252.197→269.531ms로 늘어 후속 과제로 남긴다. 전체 원작 속도 관문은 미통과다.

직전 후속은 [준비 비용 분리와 완료 후 복귀](battle-opening-costs.md)다.
오디오 서비스·화면 구성·전송/게시 대기를 중복 없이 계측하고, 창 주소 계산과 완료된
화면 요청을 붙잡는 오디오 보충 경계를 줄인다. 원작 속도 관문은 아직 통과하지 않았다.
후속 내부 계측으로 이어졌고, 음색 변경은 계속 후순위다.

직전 후속은 [현재 화면 표시 중 다음 그림 준비](battle-opening-pipeline.md)다.
일반 그림의 준비와 게시를 분리해 원작 대기와 준비 시간을 겹친다. 다음 요청의 상태 확정과
효과음·게시는 대기 이후로 유지하고, 숫자 전용 스케줄러의 두 버퍼 소유권은 보존한다.
준비 마감 초과는 그림을 버리지 않고 기록하며, 전체 원작 속도 관문은 별도로 남긴다.

직전 후속은 [등장·포격 준비 최적화](battle-opening-performance.md)다.
창 상태의 버퍼별 재사용과 여섯 행의 일괄 준비·전송으로 중복 작업을 줄인다.
기준 ROM과 같은 모든 그림·요청·원작 대기·오디오 데이터를 유지하며 실제 실행으로 대조한다.
이후 선행 준비와 비용 분리 작업이 이어졌으며, 전체 연출의 원작 속도 관문은 별도로 남긴다.

직전 후속은 [등장·포격의 V6 화면·오디오 연결](battle-opening-video.md)이다.
앞선 [실행 흐름](battle-opening-flow.md)의 GBC 호출자가 화면 게시 완료를 기다린 뒤 진행한다.
정면/백어택 × 생존/전멸의 원작 표시 자산 4경로와 동적 효과음 요청을 연결했다.
원작 도트와 32회 숫자 재생을 보존하되, 전체 장면의 준비 지연은 아직 최적화 대상이다.
이 연결 경로의 표시 준비 지연을 줄인 뒤 일반 렌더러로 확장한다.
이 결과는 모든 편성의 실시간 전투나 정상 게임 진행 완료가 아니다.

직전 후속은 [전투 진입 상태·인빈시블 포격·주변 규칙](battle-entry-context.md)이다.
진입 조건/상태별 표시 요청/포격 계산/재지정/분열 준비 10,785입력과 도주 피격을 포함한
물리 호출자 3,532입력을 GBC로 대조한다. 등장 전 상태를 넣은 원작 그래픽 경로도 8구성 검사한다.
포격 화면·사운드와 진입/승패의 통합, 재지정·분열의 물리 호출자 연결은 아직 남았다.

직전 후속은 [대상 확정 후 물리 공격 호출자](battle-fight.md)의 GBC 이식이다.
손별 명중·피해·HP·상태 버퍼·숫자 플래그·메시지 인계와 RNG를 원작 2,505입력과 대조했다.
당시 미지원인 도주 중 피격은 이번에 연결했다. 실제 행동 실행/화면/오디오 연결은 남아 있다.
직전 [직업 숙련도별 검 공격 길이](battle-weapon-duration.md)의 원작 실측에서는
캐릭터 레벨 고정·숙련도 1/99의 3쌍, 원작 PNG 338장/음성 6개와 이벤트 시점 대조를 확보했다.
실제 명중 수와 최대 4회의 검 연출을 분리하는 계약을 추가했다. GBC 연출 연결은 아직 남아 있다.
직전 [명중·피해 산술](battle-physical.md)의 GBC 이식은 원작 실행과 4,720건 및
난수 카운터가 일치했고 기대값 변조를 검출했다. 무기 10종의 양손 순서·적 점멸·피격/감싸기
제어 경계도 원본으로 확인했다. 최신 호출자 범위는 위 후속 문서를 따른다.
다음 우선순위는 [로드맵의 물리 공격 연결 갱신](implementation-roadmap.md)을 따른다.
R2 통합 0/8과 제품 관문 0/3은 유지하며 함수 검증 건수를 게임 완성도로 환산하지 않는다.

```text
기반 검증 ── 부분 탐색 통합 [현재] ── 첫 정상 진행 ── 전편 진행 ── 배포 검증
```

이 선은 단계 표시이며 작업량 비율이 아니다. 아직 전투/공유 규칙/월드/전체 이벤트의 실제 구현량을
산정하지 않았으므로 전체 공수의 완료율을 숫자로 추정하지 않는다. 테스트 10,826건이나
PR 15개를 게임 완성률로 환산하지 않는다. 아래의 검증된 범위와 제품 관문으로 진척을 표시한다.

최근 후속으로 [공통 가방·목록 입력·예약 반환](battle-items.md)을 연결했다. 원작 대조 18,497건과
기존 수집기의 이전 아군 복귀 시 같은 가방으로 반환하는 경로를 검증한다. 후속
[아이템 창·가로 스크롤·대상 선택](battle-item-window.md)은 같은 가방을 읽고 예약 생산자를 연결한다.
후속 [장비 교환·능력치 갱신](battle-equipment.md)을 원작 15,630건과 대조해 연결했다.
[진열 변경 규칙](battle-row.md)은 원작 선택·취소·예약·실행 경계 10,240건을 컴파일된 GBC 커널과 대조했다.
화살표·취소·예약과 수집기 복귀를 연결해 GBC 430요청·304장 및 원작 오디오 7,200틱을 검증했다. 실제 이동/행동 실행과 물리 전후열 피해 계산은 다음 단계다. 원작의 명중률·명중 수·원거리 예외 2,142경계를 추가 검사했지만 GBC 피해 이식 완료로 세지 않는다. 효과 실행·진열 전체 통합·직업별 특수 명령은 미완료다. 전체 22직업의 조건/대상/효과/액션을
누락 없이 추적하는 항목을 현재 계획에 명시했다.
이번 여백 수정 아이템 창은 1,005요청/762장과 원작 오디오 21,600틱을 통과했다. 선택한 긴 이름만 흐르고,
공백은 8px→3px다. 하단 선택창을 3px 위로 넓혀 손가락 기준 커서와 마지막 행의
원본 손 도트를 보존했다. 후속으로 창 크기와 커서는 그대로 두고 내부 글자/HP만 1px 내려 위 여백을 확보했다. 열 이동 자체는 연속 6프레임이지만 준비 포함 최대 536ms,
창 열기 최대 603ms는 남은 최적화 항목이다. 자세한 최신 수치/한계는 [진열 규칙·UI 후속 검증](battle-row.md)을 따른다.

직전에는 네 명의 공격/막기/도주 예약, 이전 아군 B 취소와 HP 행동명을 연결했다.
원작 커널 7,935개 입력과 실제 NES 하단 76,800픽셀을 대조했다. 정상 전투 실행·아이템/마법은
아직 미완료이며 제품 관문 **0/3**, R2 통합 시나리오 **0/8**은 유지한다.

## 제품 관문: 0 / 3 통과

이 수치는 아래 세 가지 사용자 경험의 완료 여부다. 전체 개발 공수 0%라는 뜻이 아니다.

| 관문 | 상태 | 통과 조건 |
|---|---|---|
| P1 첫 정상 진행 | 미통과 | 개발 직행 없이 새 게임·이름→첫 실제 전투/동굴/보스/크리스털·직업 해금→원작에서 저장 가능한 곳의 저장·재개 |
| P2 전편 진행 | 미통과 | 같은 공통 실행기로 새 게임부터 엔딩, 필수 분기와 전멸/취소/저장 복원, 전체 한글 소비자 검증 |
| P3 배포 | 미통과 | 원본 ROM과 명시한 허용 외부 입력으로 깨끗한 오프라인 재현 빌드, 공개 제외 정책, 음색 및 독립 에뮬레이터/실기 검증 |

문법상 지원하는 이벤트 ID는 254개 해석 가능 슬롯 중 66개다. 빈 스크립트·별칭도 포함하며,
66개 스토리 이벤트를 모두 정상 플레이로 검증한 수치가 아니다. PR 15의 대표 이벤트 실행은
