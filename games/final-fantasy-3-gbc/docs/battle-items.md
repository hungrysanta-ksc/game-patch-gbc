# 공통 가방과 전투 아이템 선택 경계

후속 [실제 아이템 창·스크롤·대상 선택](battle-item-window.md)이 아래 커널의 소비자를 연결한다.
이 문서의 미연결 항목과 수치는 PR 38 당시 기록이다. 현재 순서는 구현 로드맵을 따른다.

기준: PR 37 병합 `6faefc3b863a1f94eadb189be24823262e5a249e`, 2026-11-24.
이번 단계는 **가방 상태·목록 입력의 원작 대조와 기존 전투 수집기의 예약 반환 연결**이다.
V6의 아이템 창 렌더러, 실제 아이템 선택→효과 실행, 장비 교체 완료를 뜻하지 않는다.

## 원작 데이터와 상태 계약

원작 `3D/BC12`는 필드 `$60C0..60DF`의 ID 32개와 `$60E0..60FF`의 수량 32개를
전투용 ID/수량 32쌍으로 바꾼다. `3D/BC2D`는 역변환한다. GBC의 정본은 기존
`ff3_game_state+$C0` 64바이트이며 필드 형식을 유지한다. 변환 API의 입출력은 겹치지 않는
호출자 소유 버퍼다. 별도 상주 전투 가방을 만들지 않는다. 장비 자체는 원래 GameState
장비 영역에 남고, 아군별 4바이트 `party_used_equipped`는 임시 예약 표시일 뿐이다.

- `35/B5C6..B5F6`: 대상 선택이 끝난 뒤 사용 ID를 기록하고 수량을 DEC한다.
  마지막 하나라면 ID도 지운다. 현재 C API는 가방 슬롯만 처리하며 사용 가능성·대상 판정을
  먼저 마친 호출자만 진입할 수 있다. 이 호출자는 아직 아이템 창에 연결되지 않았다.
- `34/9AE7..9B20`: 같은 ID를 먼저 찾고, 없으면 첫 빈 칸에 ID를 넣어 수량을 INC한다.
  장착 아이템이면 가방을 늘리지 않는다. 사용 ID/장비 예약 표시를 지운다.
  원작의 바이트 증감·순서와 마지막 아이템의 반환 위치 변경을 보존한다. 반환 때 99로
  임의 제한하지 않는다. 빈 ID 슬롯의 수량도 1 대입이 아닌 INC다.
- 정상 예약과 모순되어 가방 32칸에 같은 ID도 빈 칸도 없다면 변경 전에 실패한다.
  원작은 이 조건에서 배열 밖까지 검색할 수 있으므로, 정상 예약의 선행조건 밖이라는
  차이를 명시한다. 성공한 반환으로 숨기거나 다른 아이템을 덮지 않는다.

기존 `party_enter`가 `RETURN_ITEM`에 도달하면 이 반환 함수를 같은 GameState에 적용하고
원작 선택 진입의 나머지 표시를 계속한다. 자동 행동, 장비 교체, 네 명 확정 뒤 실행 전 일괄
예약 반환/실제 소비는 여전히 후속 호출자다. 아이템 명령을 성공한 무효 동작으로 처리하지 않는다.

## 원작 목록과 실제 화면 관찰

`35/AE9D..AF9C`, `B198..B1AE`, `B2EA`, `B3A3`를 실행해 입력 결과를 만든다.
원작은 장비 열 0과 가방 열 1~8 중 두 열을 표시한다. 각 열은 4행이고 장비 열에서는
오른손/왼손의 홀수 행 1/3만 선택한다. 첫 A는 두 번째 손 커서를 만들고, 같은 칸에서
두 번째 A가 사용 분기로 들어간다. 다른 칸이면 장비 교환 또는 오류 분기다. B는 먼저
선택 표시를 해제하고 다음 B에서 닫는다. 명령 창과 달리 복합 버튼은 우선순위를 적용하지
않고 정확한 입력 바이트와 비교한다.

가로 스크롤은 원작에서 120px를 20px씩 6프레임 이동한다. 이번 커널은 열/스크롤의 최종
상태를 반환하며 GBC에서 이 애니메이션을 그렸다는 뜻은 아니다. 원작 실행 기준에서는
그리기/대기/사운드 소비자만 우회하고 원작 스크롤 증감을 실행한다. USE/EQUIP/CLOSE/ERROR는
후속 호출자에 전달할 경계이며 실제 효과나 장비 교체 성공을 뜻하지 않는다.

원본 NES의 첫 전투를 실제 실행해 빈 가방 열림, 장비 열, 아래 손, 가방 열 복귀,
첫 A와 B 해제를 관찰했다. 메모리 주입 없는 5상태의 커서 값과 손 OAM 10개를 원작 실행
기준에 대조했다. PNG/PPU/RAM은 `.local/item-source-*`와 로컬 증거에만 보관한다.
이 관찰을 채워진 가방의 정상 플레이 검증으로 확대하지 않는다.

## 검증

- 원작 ROM SHA-256: `262a98737975df25fff80ad91090c3da039d2828035c6253140d2c5f3b176ea2`.
- 원작 대조 커널 18,497건: 형식 변환 256, 예약 640, 반환 1,152, 목록 입력 16,449.
  실제 컴파일된 GBC 코드를 실행해 전체 상태/반환값을 비교한다. 첫 기대값 변조 대조군은
  첫 사례에서 실패해야 한다. 가방 가득 참/범위 밖/이중 예약의 실패 계약도 검사한다.
- 기존 전투 화면에 대한 반환 시험은 **진단 개입**이다. 아군 1의 선택 화면에서 아군 0의
  예약 상태를 주입하고 B를 눌러 기존 수집기 경로로 복귀한다. 빈 칸/기존 스택/장착 제외를
  보통·백어택 양쪽에서 검사한다. 주입은 테스트 도구에만 있고 제품 코드에 가방 샘플을 넣지 않는다.
- 각 요청 뒤 정본 가방 64바이트, 아군 상태, 장비 예약 표시를 대조하며 나머지 GameState
  960바이트가 변하지 않는지 검사한다. 원작 음악/효과음 출력, VRAM/OAM, 스택/은행 검사도 유지한다.
- 결과와 최종 산출물 해시는 이 문서의 아래 실행 결과에 기록한다.

```powershell
npm run build:battle-items
npm run verify:battle-items
node tools/verify-battle-select.mjs --items --negative
npm run build:battle-party-commands
npm run verify:battle-party-commands
node tools/audit-battle-items-observations.mjs
npm test
node tools/export-source.mjs --check
```

원작 관찰 감사는 로컬 관측 파일을 요구한다. 공개 소스에는 관측/ROM/번역/폰트를 넣지 않는다.

## 실행 결과

기존 전투 화면에서 479요청, 예약 반환 27회, 실제 GBC 화면 208장/4,792,320픽셀을 대조했다.
원작 오디오 7,200틱/21,366이벤트/30,938 APU 쓰기를 끝까지 비교했으며 지연·버퍼 부족,
잘못된 VRAM/DMA·활성 페이지 쓰기·메모리/은행/원자적 화면 교체 오류는 모두 0이다.
OBJ 최대 20개, 주사선 최대 6개였다. 일반 입력 최대 50.249ms, 아군/HP 전환 최대
602.737ms, 시작/재시작 최대 686.451ms다. 순서/부하가 달라졌으므로 PR 37과의 수치 차이를
최적화 성과로 보지 않는다. 아군 전환의 준비 비용은 여전히 후속 개선 대상이다.

고정 ROM 끝 14,859바이트, 정적 WRAM 끝 52,893(0xCE9D), 0xCF00 가드까지 99바이트가
남는다. 새 상주는 장비 예약 표시 4바이트다. 스택 미사용 여유는 304바이트이며, 다음 창을 위해
추가 상주 가방/문자 래스터를 무조건 할당하지 않고 은행별 작업 공간 수명을 정해야 한다.
호스트 테스트 87건이 통과했다. 원작 관찰 5상태/손 10개도 일치했다.
공유 검증 도구 변경에 대한 기존 단일 아군 선택 ROM 회귀도 1,374요청/148장과
7,200 오디오 틱을 통과했다(ROM 해시는 PR 36의 9a558dcb…f30c6 그대로).
공개 허용 소스 348파일의 새 복사본에서 세 ROM을 재생성해 SHA-256이 일치했고,
정상 커널 18,497건 통과/변조 커널 첫 사례 실패를 다시 확인했다. 이 재현은 비공개 번역·폰트와
검수 대응표, 고정 도구 경로를 외부 입력으로 사용하며 ROM 하나만의 제품 빌드라는 뜻은 아니다.

- 전투 표시 ROM: `d62f1b670ebd84f16d9c9bcdcc12def84d9de9323a6eafd154e04820ec8c514c`.
- 가방/목록 커널: `24e4bfe7a789d4e73b985273c2c27ef1cc900464b2ecdb19c73bd9e1bbe36cf9`.
- 기대값 변조 커널: `e9e988293d3fa37351ca4acd1b125de6df27f0dd238943919b3b2094c28966fe`.
