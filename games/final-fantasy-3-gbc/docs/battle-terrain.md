# 원작 지형 마스크와 분리 스크롤

2026-11-25. 기준 PR 58 병합 `3d0af497650ecd34cc881823dac765746c51110c`.
승인한 32×32 적의 28×28 표현과 일반 아군의 원본 크기를 유지한다.

## 원작 소비자와 자원 수명

원작 `2F/AD53`은 지형 번호 `$7CEF`로 `0C/8000 + 번호×256`의 지형 패턴을
`$7900`에 읽는다. `AD9A..ADC0`은 `AEA7`의 7×8 마스크와 4개의 64바이트
묶음을 사용한다. 28회의 원작 대기/상태 갱신을 유지하고, 실제 C 소비자가 만든
64바이트 결과를 현재 지형 패턴에 반영한다. 처음부터 완성 지형을 표시하거나
프레임 번호별 그림을 공급하지 않는다. 초기화 전 `$7900`에는 다른 임시 자료가
있으므로 AD53의 로드 이후 바이트를 추출하고 ROM의 원본 256바이트와 대조한다.

현재 대표 편성은 지형 0이며 다른 지형의 자동 공급 완료를 의미하지 않는다.
V6의 승인된 상단 11픽셀은 원작 y=8..18을 사용하고 가로 256→160으로 샘플링한다.
원작 맵에서 읽은 패턴/비트 주소의 동일성으로 40개 화면 타일을 **10개 패턴**으로
공유한다. 현재 색의 우연한 일치로 합치지 않아 이후 마스크가 변해도 공유가 유지된다.
264개의 비트 연결과 12개 256바이트 변환표를 빌드 때 만들며, 미래 관측 화면은
생성 입력에 필요하지 않다. 승인된 세로 잘림 밖의 두 묶음도 원작 상태기는 실행한다.

## GBC 대응과 비용

상단의 SCX는 VBlank마다 0으로 복원한다. LYC=11에서 적의 현재 SCX를 복원하며
적 그림이 시작되는 16행 전까지의 빈 영역을 사용한다. 이는 하나의 SCX를 공유하는
GBC에서 고정 지형과 움직이는 적을 분리하는 어댑터다.
[Pan Docs STAT](https://raw.githubusercontent.com/gbdev/pandocs/master/src/STAT.md)와
[VRAM DMA](https://raw.githubusercontent.com/gbdev/pandocs/master/src/VDMA.md)를
기준으로 실제 LY·DMA·화면 결과를 검증한다.

적의 130개 패턴은 초기 적재 후 불변이다. 지형은 VRAM bank 1의 뒤쪽에 맵 페이지별
10패턴씩을 예약한다. D500의 160바이트 현재 그림을 공유하며 각 VRAM 페이지의
변경 표식으로 필요한 80바이트 묶음만 게시한다. 페이지를 바꿀 때도 그 페이지의
지형 버전이 최신 상태가 된다. 지형 소스 256바이트와 원작 마스크 결과 64바이트는
별도 WRAM에 둔다. 지형 자산은 프로필당 4,738바이트, VRAM은 320바이트 추가된다.
작은 런타임 변환표와 갱신 비용을 늘려 완성 화면의 반복 합성을 피하는 선택이다.

적 맵 704바이트를 WRAM에서 직접 전송하는 후보도 비교했다. 중간 복사는 줄었지만
동일한 지형 없는 123장면/7,200틱 검증에서 최대 준비 147.217→152.588ms,
전송 구간 최대 95.215→98.633ms로 악화됐다. 최대 게시 간격은 11→10프레임이지만
최악 준비 비용 개선으로 판단할 근거가 없어 이 후보를 제외했다. 기존 맵 전송을
유지하고, 새 주변 맵의 선행 준비/부분 전송은 후속에 남긴다.

지형 변환은 원작 64바이트 결과를 받는 SM83 비트 선택 루프로 처리하며 32개 연결마다
음악 생산자에게 실행 시간을 돌려준다. DMA 주소도 VBlank 전에 준비한다. 게시 시에는
80바이트 묶음의 짧은 전송 구간만 인터럽트를 막고 사이에는 TIMA를 허용한다.
SCX 전용 LCD 핸들러는 VRAM을 건드리지 않으므로 GBDK의 기본 LCD 모드 대기를 끈다.
초기 후보의 오디오 버퍼 부족·22ms 누적 시계 지연·늦은 OAM 게시를 재현한 뒤 수정했다.

## 검증과 범위

호스트 검사는 원본 ROM 바이트, 28회 마스크 결과, 123개의 독립 NES/GBC 화면,
모든 256가지 비트 값의 변환, 미래 관측 없이 동일한 자산 생성을 대조한다.
실행 검사는 같은 GBC ROM에서 정상/혼합 상태의 정면·백어택 123장면, OAM,
현재 지형 버퍼, 가드, 적 패턴 불변성, 원작 음악·효과음의 소비 기록을 검사한다.
자동 재생은 지형 이외 패턴 쓰기와 스크롤 래스터 경계도 감시한다.
기존 전송 감사가 write-only인 HDMA3/4를 읽어 주소를 분류하던 오류도 수정했다.
이제 레지스터 쓰기 콜백으로 목적지를 추적한다. PR 58의 자동 재생 패턴/맵 분류
주장은 이 재검증으로 보완하며, 당시 123장면의 실제 적 VRAM 바이트 비교는 별도다.

등장 전반부의 지형·적·아군 연결이다. `B479` 이후 정규 진열·석화 BG·상태 아이콘,
하단 창과 포격·숫자·무기의 동시 통합은 남아 있다. 혼합 상태에서 숨겨진 석화 멤버를
정상 게임의 최종 표현으로 간주하지 않는다. 전체 원작 속도나 전편 완료를 뜻하지 않는다.

  타이머 누적 오차 +0.010ms. 음색의 청취 승인은 별도 후순위다.
- 자동 재생의 지형 패턴 103,440바이트, 적 주변 맵 207,680바이트, 그 합은 실제
  VRAM 쓰기 311,120바이트와 일치. 적 패턴 변경 0, 잘못된 전송/래스터 변경 0.
  OAM DMA 1,933회, 가장 늦은 시작 LY=150, VBlank 밖 시작 0.
- 최대 화면 준비 140.137ms, 지형 변환 단계 53.711ms, 게시 최대 간격 10프레임,
  지연 게시 1,852회. 준비 구간은 지형 단계를 제외하며 각각 음악 보충을 포함한다.

  원작보다 효율적이라고 주장하지 않는다.
- 맵 구성 최대 67.139ms, 전송 구간 97.656ms, 직접 음악 보충 합계 최대 76.172ms.
