# 석화 셀의 원작 입력과 VRAM 재사용

## 기준과 유지한 구조

기준은 PR 66 병합 `daf45d636e85b8c160c3c8b5669d99b8e290f2b6`이다.
원작 `2F/B6C8..B72A`는 `$7DC5..7DC9`의 주소·글리프 포인터·행 수로
배우의 두 열을 갱신한다. 정면/백어택은 두 글리프를 읽는 순서만 달리하고,
행마다 주소를 32씩 진행한다. 다른 배우의 완성 그림을 다시 합성하는 루틴이 아니다.
기존 원작 상태 소비자의 요청·대기·OAM 게시 순서는 유지한다.

GBC는 세로 위치가 8px 경계와 어긋나고 축소 적과 팔레트를 공유하므로,
석화 BG 일부 셀과 보조 OBJ의 비트 합성이 필요하다. 기존 구현은 페이지 상태가
바뀌면 모든 활성 셀을 합성했다. 이제 VRAM 각 타일의 입력이 같으면 그대로 사용한다.
아군 무축소, 적 28×28, V6 지형, 원작 도트와 OAM 순서는 변경하지 않는다.
빌드의 668개 화면 기준 자료가 PR 66과 동일하며, 실행 ROM에는 완성 프레임 자료를 넣지 않는다.

## 재사용 조건

- 원작에서 변환한 12종 글리프에 대해 각 8×8 셀이 투명한지를 24바이트로 기록한다.
  기존의 “16바이트를 읽어 모두 0이면 건너뛰기”와 동일한 판정이다. 호스트 검사와
  링크 후 원본 변환 바이트 대조로 검증하며, 프레임별 표시 결과를 저장하지 않는다.
- 두 VRAM 페이지는 각각 셀 좌표, BG/보조 패턴 구분, 팔레트, 보조 패턴 존재 여부와
  겹친 네 배우의 원작 종류를 기억한다. 해시가 아닌 완전한 입력 식별이다.
  허용 열은 모두 짝수라 셀 좌표의 홀짝과 배우의 고정 세로 위치로 글리프 오프셋도 정해진다.
- 배경 자산·글리프·색은 이 상태 표시 구간에서 고정이다. 프로필 교체 때 식별 정보를
  무효화한다. 동적으로 바뀌는 적/지형에 이 캐시를 자동 적용하지 않는다.
- 필요한 BG와 보조 패턴의 기존 번호를 먼저 모두 예약한다. 그 뒤 변경 셀에 빈 번호를
  배정하므로, 앞 배우의 해제가 뒤 배우의 번호를 밀어내지 않는다. 다른 셀로 재배정된
  번호는 다시 합성한다. 적 보조 OBJ 마스크가 쓴 번호도 무효화한다.
- 이전 맵 소유자를 먼저 확인해 지워야 할 행을 기록한다. 변경 셀과 해제된 셀이 있는
  16바이트 반쪽 행만 게시한다. 사용 중지된 패턴이 VRAM에 남아 있어도 맵 소유권은 별도로
  관리하므로, 이후 재사용할 때 맵 복원을 생략하지 않는다.
- 변경 패턴만 연속 구간으로 묶고 최대 128바이트씩 전송한다. 실제 소유권 변경 동안은
  기존 3틱 오디오 선행 준비를 사용하고, 같은 상태 페이지는 기존 빠른 경로를 유지한다.
  예약 루프도 셀마다 생산자에게 시간을 돌려준다. 큐 크기·소비 시각·원작 음표/효과음·타이머·
  DMA 상한과 초기 로딩의 별도 256바이트 경로는 바꾸지 않는다.

추가 상주 메모리는 484바이트다. 정적 WRAM 끝은 0xCFBB, 0xD000 앞 여유는 69바이트다.
패턴 버퍼 768바이트와 기존 두 VRAM 페이지를 재사용한다. 다음 상주 상태를 추가하기 전
메모리 수명을 다시 확인해야 한다.

## 검증과 측정

최종 표시 ROM: `28228cc05ea0a3c75b10c0e953304fafac8544388b5dc4d95bc22b11b08646c9`.
PR 66 기준 ROM: `f3ecc9a5a063497f193a821586c79840edca53f4f658fd68fc18aa0aa2212df4`.
동일한 668개 독립 화면 기준을 통과했다. 660셀 중 272셀을 합성하고 388셀은 재사용했다.

| 지표 | PR 66 | 이번 |
|---|---:|---:|
| present 최대 준비 | 829.102ms | 511.963ms |
| 초기 로딩 제외 664개 step 총 경과 | 48.583초 | 41.333초 |
| step p95 / 최대 전체 요청 | 348.799 / 839.585ms | 282.763 / 525.070ms |
| 석화 패턴 전송 | 18240바이트 | 7712바이트 |
| 석화 맵 전송 | 13632바이트 | 7424바이트 |

요청 전체 시간과 present 함수 시간은 범위가 다르므로 혼합하지 않는다. 오디오를 제외한
석화 함수 경과 합계는 9.995→9.189초다. 같은 원작 요청을 순회하지만, 준비 시간 변화로
후속 요청의 음악 위상은 달라진다. 개별 함수의 단독 속도 개선이나 원작 속도 달성으로 세지 않는다.
원작 APU/GBC 소비·음악/효과음/페이드 10,800틱이 일치했고, 지연·버퍼 부족·잘못된 DMA는 0이다.
최대 자동 게시 간격은 5프레임, 타이머 오차는 0.022ms 미만이다.

혼란 단독 회귀도 642화면/10,800틱, 오디오 지연·버퍼 부족·잘못된 DMA 0을 통과했다.
패턴/맵 전송은 2560/3072→1024/1536바이트지만, **최대 present는 239.502→280.518ms**다.
예약/합성 동안의 3틱 준비가 안전 여유를 확보하는 대신 일부 대기를 늘린다. 전체 경로의
최대 지연 개선을 이 회귀의 개선으로 확대하지 않는다. 회귀 ROM:
`44944d09956ae4ee53ff6a1dd3bebdef946e55d8f871f3886f349998b584923a`.

초기 진입의 원작 소비 틱 96/224 × 4프로필은 702.518/768.180ms로 유지됐다.
511개 공개 허용 소스만 복사한 별도 빌드에서 ROM 세 개와 보고서가 바이트 단위로 재현됐다.
호스트 155검사는 원작 글리프 점유 비트와 번호 대응 검증기의 고의 오차 검출을 포함한다.

## 다음 범위

현재 검증 대상은 정면/백어택의 일반·개구리·소인 석화, 혼란 위치, 적 보조 OBJ의 실제
겹침과 같은 열에서의 해제다. 원작 상태·원작 OAM·실제 픽셀은 이전 기준 그대로 대조한다.
GBC의 석화 타일 번호는 바뀌므로 독립 기준의 번호와 일대일 대응시킨 뒤 모든 활성 패턴
바이트, 맵 셀/속성, OAM 순서/좌표/속성을 검사한다. 번호 공유, 다른 페이지 참조,
미참조 활성 패턴, 도트/속성 손상은 실패한다. 검증용 독립 합성기는 이전과 동일하며
실행기의 할당 알고리즘을 복제하지 않는다. 초기 사망·상태 전이 전체나 전편의 정상 플레이를
완료했다는 뜻은 아니다.

연속 번호를 유지한 첫 후보는 660셀 중 56셀만 재사용했고, 전체 step 경과 합계가
48.583초에서 49.402초로 늘어 채택하지 않았다. 뒤 셀의 번호 이동과 검사 비용이 원인이어서
필요한 타일을 먼저 예약하는 방식으로 바꿨다. 물리 타일 번호는 GBC 자원 배치의 차이이며
원작 상태나 도트를 바꾸는 근거로 삼지 않는다. 다른 열에 석화 이력을 남기는 경로와 보스 블록
시프트, 창·포격·숫자의 같은 자원 수명 통합도 여전히 미완료다.
다음 상주 기능을 추가하기 전 예약/전송 작업용 메타데이터의 중복 수명을 정리한다.
캐시 적중 경로의 CPU 비용과 오디오 준비 대기도 함께 추적한다.
500ms 초기 진입 목표, 음질/CH4 충돌, 실기 검증은 별도 과제로 유지한다.
