# 원작 네 팔레트·월드 타일 공급·한글 창 공존

기준은 PR 22 병합 `fb0a8d2733427c4405152aa4fe52da7c57b8bf1c`이다.
[원작 표시 입력](composition-input.md)의 일반맵 29 함수 경계 상태를 이어받아, 원작 타일
공급→GBC 합성/캐시→VBlank 표시→한글 창 열기/페이지/닫기→배경 복구를 한 진단 ROM에 연결한다.
원작 네 OBJ 팔레트를 처리하고, 창과 충돌하던 주소·지도·작업 공간의 실제 전환을 검사한다.

## 이번 범위와 남은 경계

원작 플레이어/동행/NPC를 포함한 12상태다. 미세 스크롤 1/8픽셀, 네 방향의 승인된 이동 후
상태, 동행/전체 숨김과 재표시를 포함한다. 해당 상태는 PR 22의 원작 6502 함수 실행에서
생성한다. 정상 스토리 도달성·이동 충돌·동행 게임 로직의 GBC 이식을 주장하지 않는다.

빌더는 1024픽셀 월드에서 21×19 타일과 원작의 정렬된 OBJ 조각을 공급한다. 셀 키는
BG 원본 비트·색 대응·겹치는 OBJ 원본 비트/좌표/순서/가림을 모두 포함하며 짧은 해시가 아니다.
148개 유일 입력 중 객체 없는 입력만 정적으로 변환하고, 나머지는 캐시 미스 때 GBC에서
실제로 합성한다. 동적 완성 화면이나 기대 픽셀을 ROM에 넣지 않는다.

**입력 생산과 키 등록은 아직 빌드 시점의 유한 진단 추적이다.** PR 22의 GBC 변경 마스크와
기존 일반맵 이동 실행기를 여기에 연결한 것은 아니다. 399셀 전체의 비교/메타데이터 접근이
남아 있어 응답 측정값을 정상 이동 성능으로 받아들이지 않는다. 원작 논리 틱·충돌 코드는
변경하지 않으며, 새 진단을 기존 탐색 실행기 대신 사용하지 않는다.

## 색·타일·지도 계약

- 합성기의 원작 OBJ 팔레트를 2개에서 4개로 확장한다. 기본 2팔레트 형식은 기존 ROM을
  바이트 단위로 유지한다. 새 형식은 색 대응 20바이트와 BG/잔여 OBJ 네 평면의 80바이트 결과다.
- 원작 첫 불투명 OBJ의 우선순위를 먼저 결정한다. BG 뒤에 가려진 객체도 뒤 객체를 막는다.
  팔레트 비트를 `&1`로 잘라 처리하는 회귀는 호스트 음성 검사에서 원작 픽셀과 달라진다.
- 12상태가 BG 팔레트 7개를 공유하며 7번은 한글 창 전용이다. 색을 줄이거나 캐릭터를 축소하지
  않는다. 이 결과는 모든 맵/동행/전투 팔레트의 보장이 아니다.
- BG 합성 그림은 VRAM 은행 0 `$9000..97FF`의 128슬롯, 한글 글꼴은 은행 1의 같은 주소다.
  BG/창 모두 LCDC.4=0을 사용한다. 잔여 OBJ는 은행 1 `$8000..87FF`의 두 영역을 사용한다.
- 표시 중인 슬롯은 교체하지 않는다. 다음 지도와 OBJ를 준비한 뒤 VBlank에서 스크롤과
  `$9800/$9C00` 지도를 함께 바꾼다. 준비/활성 입력 합집합이 128슬롯을 넘으면 빌드 실패다.
- 창을 열 때 남은 제출을 끝내고 배경을 `$9800`에 정착시킨 뒤 `$9C00`을 창에 빌려준다.
  페이지 교체 중에는 창만 숨긴다. 닫은 후 `$9C00`의 이전 캐시 상태를 무효화하고 다음
  배경 제출 전에 다시 채운다. 원작 캐릭터와 음악은 계속 살아 있다.

Pan Docs의 [타일 주소](https://github.com/gbdev/pandocs/blob/master/src/Tile_Data.md)와
[LCDC.4](https://github.com/gbdev/pandocs/blob/master/src/LCDC.md#lcdc4--bg-and-window-tile-data-area)가
사양 근거다. 직접 페이지는 403, curl은 DNS 실패여서 동일 명세의 GitHub 원문으로 확인했다.
BG와 창이 주소 선택 비트를 공유하고 OBJ 주소는 독립이라는 사양을 적용했다.

## WRAM 수명

| 영역 | 탐색 그림 준비 | 창 표시 |
|---|---|---|
| 은행 1 `$D000..D7EF` | 원작 맵 작업 공간 보존 | 보존 |
| `$D800..D8FF` | 128개 캐시 키 | 키를 은행 6에 저장 후 기존 `text_cells`에 반환 |
| `$D950..DA4F` | 합성 결과/VRAM 전송 | 글꼴/창 전송 |
| `$DA60..DB5F` | 최대 256바이트 셀 입력 | 기존 글꼴 검색표 |
| `$DB70..DBFF` | 기존 필드 상태/줄 버퍼 예약 보존 | 보존 |
| `$DC00/$DD00` | 두 OAM 그림자, 뒤의 80바이트씩은 OBJ 키 | 배경 OAM 유지 |
| `$DE00..DFFF` | 은행 1 스택 | 동일 스택 |
| 은행 3/4/5 | 51/51/26슬롯, 결과 10,240바이트 | 유지 |
| 은행 6 | 이전 셀 키/슬롯/속성 및 창 임대 키, 1,856바이트 예약 | 유지 |

은행 2의 오디오 진단 스냅샷은 유지한다. 다른 WRAM 은행은 기존 16바이트 제한 고정-ROM
복사 함수로만 접근하며, 스택/IRQ/DMA가 사용하는 은행 1을 실행 중 바꿔 두지 않는다.
R1의 은행 3/5 미래 모드 예약을 실제 탐색 저장·전투와 함께 쓰는 전환은 아직 미구현이다.
전체 필드 실행기와 함께 링크한 여유로 오인하지 않는다. 이 진단에서는 맵과 필드 영역의
센티널을 매 프레임 검사하고 실제 한글 창과의 링크/임대/복원을 검증한다.

첫 은행 13 구현에서 데이터 은행으로 바꾼 뒤 같은 은행의 코드를 계속 실행하는 결함을
검출했다. 데이터 복사를 고정 ROM 함수로 옮겨 호출자의 ROM 은행을 복원하도록 수정했다.
실패 관측은 로컬 `evidence/composition-window/rejected-rom-bank/`에 보존한다.

## 재현과 검증 기준

```powershell
node tools/build-composition-window.mjs
node tools/verify-composition-window.mjs
node tools/verify-composition-window.mjs --idle
npm test
```

`local.json.text`의 승인된 7×7 폰트·비공개 번역·검수 바인딩을 사용한다. 기존 검수 번역의
원작 문자열 ID 7을 `ff3_text_open_source`로 열며 페이지 2개를 검사한다. 이 장면에서 NPC와
대화 조건을 충족했다는 검사는 아니다. 번역문·글꼴·기대 이미지·ROM·관측은 모두 로컬이다.

호스트의 월드 타일 픽셀 기준은 PR 22의 독립 계산과 대조한다. 실제 GBC 캡처는 원작 논리
합성 픽셀과 비교하며, 한글은 기존 독립 레이아웃/승인 폰트 기준과 비교한다. 각 상태에서
표시→동일 요청→창→페이지→닫기→동일 요청을 두 차례 캡처하며 캐시 복원과 창 뒤 배경을
확인한다. 첫 상태는 이미 `$9800`인 상태에서 재열기도 검사한다.

매 프레임 원작 사운드 소비 이벤트, 실제 APU 레지스터 순서, 맵/필드/가드·은행 복원을
검사한다. 독립 버스 관찰자는 활성 BG/OBJ 그림과 지도 및 표시 중인 창 글꼴의 덮어쓰기,
VBlank 외 VRAM/팔레트 전송과 부적절한 DMA를 거부한다. 시간은 요청에서 완료까지이며
합성·은행 복사·전송·VBlank 대기와 오디오 서비스를 포함한다. 캡처 안정화 대기는 제외한다.
고정 Mesen의 관측이며 실기나 독립 에뮬레이터의 합격은 아니다.

재현 폴더에는 ROM·폰트·번역을 복사하지 않고 외부 경로로 참조한다. 필요한 외부 입력은
지원 원본 ROM, 승인 7×7 폰트·검수 바인딩·일한 번역, 고정 GBDK/MesenCore와 .NET이다.
최종 전편 오프라인 배포의 완료를 의미하지 않는다.

음질 변환 표는 변경하지 않았다. 이번에는 원작 맵 29의 BGM 선택값을 사용하므로 PR 22의
진단 BGM과 APU 쓰기 수는 다르다. 각각 동일 원작 계획의 부하/무부하를 비교하며 음색/청취
합격으로 세지 않는다.

| 요청→완료 시간 | 중앙값 | 최대 |
|---|---:|---:|
| 첫 표시 이후 다른 상태 표시 | 1,088.728ms | 1,524.168ms |
| 동일 상태 재요청/닫기 후 재요청 | 16.743ms | 16.885ms |
| 창 열기: 배경 지도 정착 포함 | 753.596ms | 954.826ms |
| 다음 한글 페이지 | 318.153ms | 385.145ms |
| 닫기: 키 복원 포함 | 16.743ms | 33.576ms |

첫 표시를 포함한 최대는 2,529.232ms다. 셀별 순차 검색을 정확한 ID 검색표로 바꾸고 미변경
행의 메타데이터 쓰기를 생략하여 첫 표시 이후 중앙값을 1,691.762→1,088.728ms로 줄였다.
초기 결과와 원시 계측은 `linear-cache-baseline/`에 보존한다. 여전히 정상 이동에는 느리다.
시간이 짧은 동일 요청을 섞은 전체 중앙값으로 성능을 설명하지 않는다. 399셀의 비교/은행
공급과 창 열기 때의 지도 정착 비용이 남으며, 다음 실시간 통합은 월드 링과 실제 변경 셀
공급을 기준으로 설계해야 한다. 이 진단을 매 게임 틱 호출하는 구조는 채택하지 않는다.

ROM SHA-256: `cd83a961cca65bc732fe2c87b251d4720d147d410de53044da25f5de11e8c708`.
보고서 SHA-256: `a62606f77eb55c5f01d6e2e7cca54284c6feb5d0487ea5769f1bc7fff2037860`.
MesenCore SHA-256: `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`.
현재 ROM은 검증기가 `scene_page`와 `scene_request`에 주는 요청을 실행하는 진단용이다.
일반 게임 입력/메뉴를 갖춘 샘플이라고 표시하지 않는다.
