NES는 원본 드라이버의 `$7F40..$7FFF` 192바이트 상태를 PC 추출기와 비교했다. GBC는 실제 ROM에서 소비한 11바이트 패킷을 생성 데이터와 비교했다. GBC 프레임률 보정으로 두 소스 틱을 한 화면 프레임에 처리하는 경우가 있어 관측 수가 적다. 관측한 상태는 모두 일치했고 모든 구간이 지정한 종료 틱에 도달했다. 이 검사는 두 콘솔의 파형 완전 일치나 청취 품질 합격을 의미하지 않는다.

원작 음악 65개 슬롯과 효과음 97개 슬롯은 각각 300틱씩 실행하는 별도 입력 데이터 검사도 통과했다. 모든 곡의 끝/루프/분기를 조사했다는 뜻은 아니다. 6502 carry/overflow/borrow, JMP 간접 주소의 페이지 래핑, 알 수 없는 명령 거절, RLE 트리거/255틱/은행 경계, NES harness 보호 영역을 검사했다.

## 녹음과 화면/입력

14개 WAV는 Mesen 네이티브 PCM 녹음이며 모두 비무음, 클리핑 샘플 0이다. 1440틱 구간의 실제 길이는 NES 23.960667초, GBC 23.975563초다. 전체 구간에서 기대 길이와의 차이가 0.15초 이내인 것을 검사했다. 원본 WAV와 평균 음량을 맞춘 별도 WAV, 8초씩 A→B 비교 WAV를 생성한다.

GBC ROM을 별도 emucap 세션으로 부팅해 160×144 선택 화면을 확인했다. 오른쪽으로 일반 전투 선택 → A 재생 후 `audio_tick=123`, B 정지 후 카운터 유지, SELECT로 DMC 후보 비활성화 상태 변화를 확인했다. 최종 화면 PNG SHA-256: `0c7aeedcbc6d371600f6268d93135cb6cc95a5cc33b28a51464c36ff0b86335c`. 화면은 기술 검증 UI이며 게임의 한글 메뉴를 대신하는 설계가 아니다.

로컬 증거: `build/audio/report.json`, `evidence/audio/capture-all.json`, `comparison.json`, 각 `*.wav.json` 상태 관측과 `*.wav.log`, `player.png`. 게임 데이터가 포함된 원시 로그/녹음은 Git에서 제외한다. 공개 문서의 수치는 위 고정 아티팩트에 대한 기록이다.

## 해결한 검증 장치 문제

- NES 네이티브 코어의 채널 기본 음량 0으로 인한 무음: NES 설정을 명시하고 PCM 비무음 검사를 추가.
- NES `$2002` 폴링으로 누락될 수 있는 vblank: NMI 카운터를 사용.
- 프레임 중간 정지에서 다음 틱 일부를 잘못 비교: 양쪽 ROM의 갱신 구간 표시를 읽고 갱신 완료 후 스냅샷.
- 디버거 정지 진입 중 다음 step을 보내는 경쟁: 정지/일시정지 상태를 함께 확인. 짧은 PPU 스텝으로 안전한 오디오 경계까지 진행.
- CGB 테스트 화면의 초기 팔레트 누락: 명시적인 배경 팔레트 설정 후 최종 화면 재확인.
