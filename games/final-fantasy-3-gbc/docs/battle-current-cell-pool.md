# 현재 셀 마스크와 공유 타일 풀

2026-11-28, PR 118 이후. 석화의 별도 풀을 추가하기 전에 실제 적 사망/점멸이 쓰는
마스크 처리와 타일 배출을 공통 소비자로 옮긴 단계다. 순수 석화 화면 통합은 아직 아니다.

## 원작 구조와 GBC 변경

원작 `2F/B33E → BB0A`, `BAA2/BB13/A247`은 생존 슬롯으로 지도를 재구성한다.
`BC84`의 두 NMI 대기 다음 OAM·PPU를 갱신하고 `BCB1`에서 완성된 사망 그림이
보인다. 석화의 `B5B8/B5C3 → B72B/B6C8` 역시 상태가 달라졌을 때 현재 지도를
갱신한다. 슬롯의 생존/상태, 패턴 번호, 화면 페이지는 서로 다른 수명이다.

GBC에서는 28픽셀 적 배치로 한 8×8 셀에 두 적의 도트가 들어갈 수 있다. 따라서
타일 번호만 보고 적을 삭제하지 않는다. 기존 공간별 슬롯 마스크로 현재 지워질 도트를
구한 뒤 `ff3_cell_mask`가 변경 없음/완전 소거/일부 변경을 구분한다. 일부 변경만
`ff3_cell_pool_tile`에 공급한다. 살아 있는 적의 원본 도트와 팔레트는 그대로 유지한다.

공통 풀은 비활성 페이지마다 begin → 셀 공급 → finish → 지도 공개 순서다.
BG와 잔여 OBJ가 같은 최종 16바이트를 만들면 한 타일을 공유할 수 있지만, 팔레트와
원작 슬롯 ID는 합치지 않는다. 8비트 서명은 검색 필터이며, 일치 후보도 16바이트 전체를
비교한다. 예전 페이지의 디렉터리 항목은 재사용하지 않는다. 공개된 VRAM은 페이지가
계속 소유하고, 검색 디렉터리만 다음 begin에서 폐기된다.

한 적만 삭제/소거 중이면 직접 배출 경로를 쓴다. 여러 슬롯의 소거 상태가 공존할 때만
공유 검색을 켠다. 향후 석화 합성을 추가할 때도 첫 셀 이전에 이 정책을 선택해야 한다.
완성 화면의 타일 수나 원본 도트를 줄이는 방식이 아니다.
원작의 빈 적 슬롯도 사망 비트를 가진다. 세 적 중 첫 적만 사라진 실제 관찰의
마스크는 9F였지만, 원작 공간 소유자에서 유도한 E0과 교차하면 실제 대상은 80이다.
전투의 사망 마스크를 바꾸지 않고 이 물리 소유자 교차만 전송 정책 선택에 사용한다.

## 자원 수명

| 자원 | 범위 | 수명 |
| --- | --- | --- |
| 셀 서명 | bank 1 D640..D675 | 현재 비활성 페이지 구성 중 |
| 전체 비교 버퍼 | bank 1 D680..D68F | 한 후보 비교 중 |
| 정확한 글리프 디렉터리 | WRAM 6 [192,1056) | begin부터 finish까지 |
| 적의 현재 잔여 OBJ | WRAM 6 [0,192) | 기존 페이지·점멸 소유자 유지 |
| 변경 타일 전송 | 기존 `text_staging` | 16타일씩 배출 후 재사용 |

기존 셀 D600..D627, 소거 마스크 D628..D62F, 글리프 D630..D63F,
행동 OAM D6A0..D73F와 겹치지 않는다. 필드 보존은 WRAM 7, 파티/결과는 WRAM 5,
마법 보존·복구는 WRAM 3/4를 유지한다. 과거 독립 composition-window의 WRAM 6
캐시는 같은 통합 ROM에 링크되지 않는다. 독립 석화 D600 버퍼를 그대로 링크해도 된다는
뜻은 아니다. 석화는 이 공통 소비자의 작업 순서에 맞춰 옮겨야 한다.

빌더는 현재 44개 조우 배치의 풀 시작·페이지 길이·54타일 디렉터리 상한을 검사한다.
기존 사망 상한보다 할당 수가 늘어나지 않으며 기존 두 VRAM 페이지의 예약 크기는
유지한다. 공유가 검증됐다는 이유로 석화에 남은 공간을 임의 예약하지 않는다.

## 검증 범위와 성능 선택

SM83 단위 ROM은 실제 `ff3_wram_copy`를 사용하고 LCD 전송은 기록기로 대체한다.
서명 충돌, 같은 타일 재사용, 꽉 찬 풀에서 재사용/초과 거부, 54타일 배치 경계,
새 페이지의 이전 항목 무효화, 중첩 소유자 거부, 주소 범위, 직접 배출을 검사한다.
원작 8적 편성의 정면/백어택 사망 그림에서도 15개의 변경 글리프가 14개의 서로 다른
타일로 표현되는 사례를 실행한다. 각 타일 ID와 배출된 모든 도트를 비교한다.
음성 ROM은 첫 기대값을 틀리게 하여 검증기가 오류를 잡는지 확인한다.

이 사례의 절약은 각각 **1타일**이며, 모든 장면의 큰 절감을 증명하지 않는다.
초기 구현에서 공유 검색을 항상 켜자 단일 적 사망은 재사용 0회인데 자동 행동이
117.108ms 느려졌다. 이 경로는 채택하지 않고 단일 소유자의 직접 배출을 복구했다.
성능 비교는 자동 재생에서 수행하고, 단계별 캡처를 위한 대기 시간과 구분한다.

통합 ROM은 실제 조우→적 사망 37그림→생존 적 점멸/공격→마법 27그림·복구→
필드 복귀 3회를 검사한다. 원작 픽셀·계산, 실제 APU 쓰기·누적 해시, 타이머·은행 전송·
스택을 함께 검증한다. 수동 진단 명령과 강제 치명적 수치를 정상 턴 완료로 세지 않는다.

재현: `build:cell-pool` → `verify:cell-pool` / `verify:cell-pool-negative`,
`build:dungeon` → `verify:dungeon-death` / `verify:dungeon-death-auto` npm 스크립트.
단위 ROM의 원작 글리프·통합 ROM·관찰 JSON·로그는 build/evidence에만 둔다.

## 최종 기록

통합 ROM SHA-256은 `24b6c8347a1af2c90a20833871710e804bf4ac34706d5241940a8791838f6fa5`다.
호스트 전체 229건, 후속 빈 슬롯 회귀를 포함한 최종 계약 18건, SM83 단위 11개 묶음과
음성 검사를 통과했다. 고정 전투 DATA는 1,400바이트, 남은 고정 RAM/ROM은 8/894바이트다.
새 7바이트에는 풀 소유 상태와 진단 계수가 포함되며, 추가 석화 상태를 무작정 고정 RAM에
넣을 여유로 간주하지 않는다.

완성 화면 검사는 사망 37그림·생존 적 점멸 8단계·마법 27그림·정확한 복구·필드 왕복
3회를 통과했다. 원작 오디오 4,584틱, 실제 APU 쓰기 26,979회, 타이머 편차 357.151µs,
은행 전송 오류 0, 오디오 underrun 0이었다. 복합 상태 파티 패배 회귀도 20 VBlank 페이드와
재시작 메뉴 화면까지 통과했다(2,071틱, 12,076회 APU 쓰기, 편차 349.522µs, 오류 0).

아래는 캡처 대기를 끈 **자동** 재생의 같은 첫 편성/난수/두 명령 비교다. 이후 필드 조우는
플레이 시간에 따라 난수 시드가 달라지므로 이 성능 비교에 합산하지 않는다.

이 단일 적 경로의 할당은 78타일, 최대 페이지 12타일, 공유 재사용은 0회다. 직접 배출
선택으로 불필요한 WRAM 디렉터리 접근을 제거했지만 위의 전체 시간 증가는 남는다.
이번 변경은 속도 개선으로 주장하지 않는다. 다음 합성 연결에서 실제 처리·호출·공개 대기를
분리하여 이 비용도 줄여야 한다. 자동 재생의 오디오 편차는 355.721µs, 전송 오류/underrun은 0이다.

## 다음 경계

1. 석화 글리프를 공간별 현재 소거 마스크와 함께 합성하여 이 풀에 공급한다.
   현재 구현은 적 소비자만 연결했으며 독립 석화의 초기 ROM 지도 읽기는 아직 교체 전이다.
   공통화 후 남은 자동 행동 지연도 실제 처리·호출·전송 대기로 나누어 줄인다.
2. UI 첫 행과 회색 팔레트, 잔여 OBJ의 주사선 제한을 같은 합성으로 해결한다.
3. 석화 변경/해제·적 사망·마법 동결/복구·필드 재진입의 동시 상태에서 검증한 뒤
   순수 석화의 명시적 거부 검사를 해제한다. 현재 풀의 여유만으로 통합 완료를 선언하지 않는다.
