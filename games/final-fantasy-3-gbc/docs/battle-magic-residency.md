# 일반 마법의 상주 타일쌍과 준비 비용

기준은 PR 90 병합 `50e79e5347bed500aa9ec28584795598f3b2ff93`의
[적→아군 일반 마법](battle-magic-video.md)이다. 같은 원작 입력·V6 도트·창·대상
순서·대기 수·오디오를 유지하면서 준비와 복구 비용을 줄인다. 새 마법 종류나
정상 전투 계산의 완료로 세지 않는다. 아래 시간은 고정 MesenCore의 CGB 측정이다.

## 원작 구조와 변경

`33/B68D → B589`는 대상 반복에 들어가기 전에 그래픽 07/08을 **한 번** 적재한다.
`B6DD`의 대상 반복과 `B6F3/B711`의 그림 반복은 상주 타일 번호·좌표·반전만 바꾸며,
그림마다 4대기, 대상 끝 1대기를 유지한다. `2F/B175`는 행동 후 숫자 자원을 복원한다.
앞선 GBC 구현은 8×16 표현을 위해 매 그림마다 원본 셀을 CPU로 다시 변환하고
576바이트씩 전송했다. 원작의 상주 수명을 따르지 않아 새 그림마다 지연이 생겼다.

- 원본 88개 시퀀스가 참조하는 타일쌍을 중복 제거한 사전으로 변환한다. 시퀀스의
  FF 접두사를 파싱하며, 좌표/대상/OAM 완성 화면은 저장하지 않는다. 최대 30쌍,
  960바이트로 한 마법 전체를 담는다. 원본 128그림 RLE와 진행 커서는 계속 실행한다.
- 소유권 획득 시 사전을 한 번 전송한다. 같은 그림의 반복뿐 아니라 다음 그림과
  다음 대상에서도 그대로 참조한다. 좌우·상하·백어택은 OBJ의 전체 쌍 반전으로 표현한다.
  8×8 반쪽마다 있던 개별 반전은 변환 사전에 보존한다. 도트/색/숫자를 줄이지 않는다.
- 효과용 VRAM 백업·복구는 고정 1152바이트 대신 실제 사전 길이만 수행한다.
  마법 29는 384바이트, 마법 36은 960바이트다. 최초 적재·마지막 복원 수명을 유지한다.
- 명중 마스크가 0이면 두 원작 대기와 FF 소리 정지만 실행한다. 화면을 바꾸지 않으므로
  signed BG/OBJ 크기/패턴 자원을 빌리지 않는다. 사용하지 않는 자원의 물리적 적재를
  생략하는 GBC 최적화이며 원작 결과·대기·요청을 성공한 no-op으로 바꾸지 않는다.
- 아군 동결 셀별 기여 OBJ 목록을 한 번 만들고 색 합성에서 재사용한다. 목록은
  `$D380..D4BF`의 기존 704바이트 작업 공간 안에 둔다. 4개를 넘으면 원래 전체
  검색으로 돌아가며 도트를 버리지 않는다. 합성 후에는 다른 소유자가 공간을 재사용한다.

사전 자료는 2개 은행, 26,576바이트다. 이전 88개 원시 그래픽/팔레트 레코드는
46,024바이트였다. 이 비교는 자료 본체 크기이며 전체 ROM 크기는 여전히 2MiB다.
좌표와 실행 순서를 담은 프레임 동영상 캐시를 새로 추가한 것이 아니다.

## VRAM 읽기와 안전 구간

[Pan Docs VRAM 접근](https://gbdev.io/pandocs/Accessing_VRAM_and_OAM.html)과
[PPU 모드 길이](https://gbdev.io/pandocs/Rendering.html)에 따라 모드 0/1을 확인한 뒤
모드 2의 80도트 안에서 읽는다. 인터럽트가 확인과 접근 사이를 넘지 않도록 IE를
저장·마스킹하고 STAT를 다시 확인한다. IME는 변경하지 않는다.

기존의 C 코드 1바이트 반복을 SM83의 짧은 묶음으로 바꿨다. CGB 배속에서 네 번째
읽기까지 STAT 재확인 이후 112 CPU 클록(56도트)이며, 일반 속도는 한 바이트 경로다.
IE/BC와 VBK=0을 복원하고 최대 128바이트 단위로 오디오 생산을 재개한다. 이번
실행 검증은 배속 CGB 경로이며 다른 기종/일반 속도 합격으로 확대하지 않는다.
숫자와 마법의 공유 동결 읽기에 적용하므로 밀집 숫자 경로도 함께 검증한다.
생성된 SM83 목록에서도 마스킹 재확인부터 네 읽기까지의 명령을 확인했다.
고정 WRAM 끝은 `$CF6F`로 경계까지 145바이트가 남고, 셀 목록 주소와 읽기 함수
은행은 링크 결과에서 검사한다. 셀 목록 때문에 새 WRAM 은행을 할당하지 않는다.

## 측정과 검증

기준 5,543.654ms에 대해 최초 상주 사전+읽기 개선은 3,182.191ms,
셀별 OBJ 목록까지 적용한 후보는 2,797.034ms였다. 원작 속도 도달을 뜻하지 않는다.
같은 35게시 자동 재생의 최종 결과는 다음과 같다.

| 항목 | PR 90 | 이번 변경 |
| --- | ---: | ---: |
| 행동 전체 | 5,543.654ms | 2,797.034ms |
| 초기 준비를 포함한 최대 게시 간격 | 2,779.052ms | 1,439.874ms |
| 초기 준비 이후 최대 게시 간격 | 368.373ms | 83.723ms |

전체 시간은 약 49.5% 줄었지만 최초 자원 동결이 여전히 길다. 오디오 엔진 자체는
바꾸지 않았다. 화면 준비가 짧아지면서 행동 구간의 오디오 호출 시간도 줄었으며,
이 수치를 음질 개선이나 오디오 엔진의 속도 향상으로 세지 않는다.

호스트는 88마법·215개 참조 그림의 **824개 유효 반전 조건**에서 원작 B711의
실행 결과와 사전 픽셀을 대조한다. 단독 FF는 수직 접두사라 그림 코드로 세지 않는다.
GBC 검증은 실제 PNG, 원작 OAM/픽셀, 마지막 VRAM·팔레트·창 복구와 원작/변환
오디오 해시를 함께 대조한다. 읽기/쓰기 모드 위반과 OAM DMA 경계도 검사한다.
추가 읽기 전용 관측으로 첫 그림 이후 대상 변경을 포함해 효과 풀의 쓰기가 0인지
확인한다. 화면이 같다는 사실만으로 불필요한 재전송 제거를 주장하지 않는다.

자동 전체 대상 검사 중 Mesen의 500개 로그 항목 한도로 초기 측정 행이 유실되는
문제를 발견했다. 읽기 전용 관측기가 프레임별 기록을 행동 종료 때 한 항목으로
보존하도록 선택 기능을 추가했다. 검사 개수나 VBlank 경계 조건은 완화하지 않는다.
이 변경은 ROM 실행 코드와 오디오에 영향을 주지 않는다.

검증 ROM SHA-256은
`f469196ad8970cd444b718db479fb818acb98cdc71fe166f16865047eccb8728`이다.
기준 ROM은 `21fbe3662df27bcab67e8a384a31b2fd4163dd4be9268990145b9bdf1897c48e`,
MesenCore는 `1ba99d2c848e007c60cbd7fceca058440758eb44837a93a6724d29d72723c994`로 고정했다.

- 일반/백어택+상태 마법 444장, 반전 마법 54장, 밀집/일반 피해 숫자 198장,
  무기+숫자 116장, 피격/감싸기+숫자 128장으로 **940장**을 대조했다.
  8명×9999를 포함하며 원작 픽셀·창·마지막 복구가 일치했다.
- 호스트 10검사, 88마법 사전의 824조건이 통과했다. 마법 실제 표시의 최대는
  30 OBJ·한 줄 9개이며 8×16 빈 셀을 제외한 원작 유효 도트는 보존한다.
- 11회 각각 7,200틱, 총 **79,200틱**의 원작/변환 오디오 해시·요청·연속성이
  일치했다. underrun/late·잘못된 VRAM 읽기/쓰기·OAM DMA 경계 위반은 0이다.
  7개 마법 실행의 593개 그림 사이에서 효과 풀 재전송은 0이었다.
- 자동 재생은 기준 마법 35게시/2,797.034ms, 최대 30쌍 마법
  35게시/2,947.715ms, 아군 네 명 순차 대상은 142게시/5,879.129ms다.
  서로 다른 대상 수를 성능 개선 비율로 비교하지 않는다. 기존 양손 지팡이는
  83게시/2,110.163ms, 최대 게시 간격 83.956ms로 유지됐다.
- 공개 허용 소스 622개를 별도 디렉터리에 복사한 재현 빌드에서 3개 ROM과
  자료/헤더를 포함한 12개 산출물이 일치했다. 원본·번역·추출 자료와 검증 화면은
  공개하지 않는다. 이 검증은 기존의 원작 호출자 진단이며 정상 게임 통합은 아니다.

재현 명령은
`node tools/build-battle-party-oam.mjs --effects`,
`node tools/verify-battle-magic.mjs` 및 `--back --status`, `--flips`, `--auto`다.
`--auto --case 1`은 최대 사전, `--auto --case 2`는 아군 전체 대상의 자동 재생이다.
`node tools/verify-battle-effects.mjs`는 8명×9999를 포함한 숫자 회귀다.
호스트는 `node --test tests/battle-magic-video.test.mjs tests/battle-magic-frames.test.mjs tests/battle-animation.test.mjs`다.

초기 동결과 페이지 준비는 아직 남는다. 다음은 그 수명을 원작의 정본 패턴/지도
관리와 비교하여 반복 백업을 줄이는 것이다. 배경/아군/창 자원 복구를 증명하지 않은
추정 초기값 복사나 화면 생략으로 비용을 숨기지 않는다. 아군 시전·발사·적 대상·반사·
특수/소환·정상 전투 계산은 별도 범위이고 R2 0/8·제품 0/3은 유지한다.
