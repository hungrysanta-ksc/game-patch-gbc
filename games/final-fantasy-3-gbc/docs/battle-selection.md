# 원작 명령·대상 선택 경계

2026-11-24. 기준은 PR 35 병합 `beaeceea1f73dea35778a47f3c89741e17850558`다.
V6 배치, 원본 아군 도트, 적 7/8 축소와 y=106/38px 하단 창을 유지한다.
글꼴 재선정은 사용자 승인에 따라 후속으로 남긴다.

## 실제 화면에서 확인한 범위

원본 일본판 ROM의 새 게임 첫 전투 저장 상태에서 실제 방향키와 B로 적→아군→다음 아군→취소를 실행했다.
RAM을 고쳐 장면을 만들지 않았다. 네 정지 화면의 PPU/CHR/팔레트/OAM으로 하단 76,800픽셀을
재구성해 캡처와 대조했고 차이는 0이었다. 세 입력 전이의 `$AD..$B5`, 선택 적 마스크도
원작 함수 실행과 일치했다. 음악 실행기가 소비할 수 있는 사운드 메일박스는 이 정지 관측 비교에서 제외했다.
원시 관측은 `.local/original-battle-selection/`에만 보관한다.

실제 명령창은 적 이름 창 앞, HP 창 왼쪽에 겹친다. 이를 V6에서는 적 창 x=0/48px,
명령창 x=16/40px, HP 창 x=48/112px로 옮겼다. ROM의 테두리/팔레트·명령 ID와 손 모양을 사용한다.
커서 네 조각의 원본 16×16 도트는 축소하지 않고 앵커만 옮긴다. HP 숫자만 기존 승인한 작은 글꼴이다.
선택 장면의 이름 `0..3`과 HP 32/32는 명시적 진단 입력이며 제품 이름/능력치가 아니다.

| 명령 목록 이동 | `34/89EE..8A7F` | 첫 활성 비트 우선순위, 네 행 순환, 세 번째 명령 없음 처리 |
| 버튼 반복 | `3F/FBC6..FBEE` | 이전/현재 눌림, 8/4 반복 카운터, 대상 진입 16 초기화 |

`battle-select.c`는 표와 게임 상태만 받는 공통 로직이다. 화면용 `battle-selection.inc`는
기존 `battle-atlas.c`와 VBlank 전송기를 재사용한다. 첫 전투 편성의 정면/백어택 두 장면만 추가한다.
선택 조합마다 전체 화면을 생성하는 방식은 쓰지 않는다. 초기 준비 시 두 비활성/활성 페이지를 채우고,
후속 커서 변경은 준비된 타일/창을 유지하면서 OAM을 교체한다. 원본 손 모양을 위한 네 OBJ와
네 타일을 별도 예약하고, 배경/아군/기존 숫자를 생략하지 않는다.

## 검증과 재현

```powershell
npm run build:battle-select
npm run verify:battle-select
node tools/verify-battle-select.mjs --negative
npm run build:battle-selection
npm run verify:battle-selection
node tools/audit-battle-selection-observations.mjs --observations .local/original-battle-selection
npm test
```

원작 함수를 직접 실행한 52,128개 입력/기대값을 실제 GBC 커널과 대조한다.
대상 시작 3,696건, 대상 입력 38,192건, 명령 이동 2,048건, 반복 입력 8,192건이다.
10개 원작 배치·빈 슬롯·백어택·대상 제외·단일/전체 가능 플래그를 포함한다.
기대값 한 바이트를 일부러 바꾼 검사는 첫 사례의 불일치를 잡는다.
이는 유한 입력 검증이며 모든 합법 게임 상태를 전수 검증했다는 뜻은 아니다.

화면 검증은 원작 함수의 선택 상태와 화면의 픽셀/OAM을 별도로 검사한다.
실제 버튼 입력은 emucap의 joypad를 통해 명령 아래/위, A, 적→아군, B, A/A로 확인한다.
메모리 요청으로만 성공한 것을 실제 버튼 입력 검사로 세지 않는다.
오디오 검사는 기존 독립 원작 음악/효과음/페이드 스트레스 7,200틱을 사용한다.
선택 시 사운드 요청 값은 원작과 대조하지만 아직 실제 커서 효과음 호출자로 연결하지 않았다.

명령창의 효과음 요청은 `$C9/$CA`, 대상 선택의 요청은 `$7F49`를 사용한다.
진단용 `selection_sound`는 이를 상위 비트가 설정된 ID로 정규화한 값이며 두 원본 메일박스의
전체 수명을 이식했다는 뜻은 아니다. `34/99C6..99FA`의 실제 분기와 여섯 명령 슬롯/확정 요청도 검사한다.

## 남은 연결과 다음 순서

현재 화면은 한 명의 명령과 공격 대상 선택까지다. 확정하면 `selection_dispatch`와
`selection_target`에 호출자 결과를 남기고 멈춘다. 막기/도주/아이템/전후열 요청도 실제 동작을
성공 처리하지 않는다. 아이템 목록을 열거나 전투를 실행한 것으로 표시하지 않는다.
처음부터 네 명의 선택 예약·이전 아군 복귀·직업별 하위 메뉴·HP 행 행동명까지 구현된 것은 아니다.
원작 반복 함수는 이식했지만 화면 준비 비용을 포함한 전체 입력 반복 주기의 원작 일치도 아직 별도 관문이다.

다음은 **원작 네 명의 명령 수집/취소 호출자와 HP 행 행동명**을 같은 상태에 연결한다.
이어서 실제 ROM/PPU 관측으로 아이템·마법 목록의 스크롤/선택/복원과 사용 가능 조건을 연결한다.
마법의 개별/집단/전체 대상 허용 플래그와 소환의 시전 조건은 원작 호출자에서 넘겨야 하며,
공격의 단일 대상 설정을 마법에 일괄 적용하지 않는다. 선택과 숫자/효과 표시의 공존 수명을 검증한 뒤
공통 능력치·가방·장비·첫 공격 계산으로 이어간다. R2 전체 및 제품 관문 0/3은 유지한다.

## 전체 선택 조건 재확인 (2026-11-25)

사용자 요구에 따라 **아군 전체·적 전체·같은 종류의 적 집단**을 서로 다른 선택 상태로 유지한다.
전체 선택을 임의 버튼으로 추가하거나 모든 마법에 무조건 허용하지 않는다.

- 원작 마법 호출자 `35/B953..BA29`는 사용 가능 여부를 먼저 확인한다.
  `30/98C0` 공격 속성의 8바이트 레코드 중 `+05`를 사용한다.
- `B979`: `property & 18h`가 0인 소환 경로는 이 선택기를 열지 않는다.
- `B983`: `40h`이면 자동 적 전체 경로 `B9F0`. 생존/석화 조건을 확인한 적 마스크를 만들며,
  수동 전체 선택과 피해 분산 규칙을 혼동하지 않는다.
- 수동 경로 `B98A..B9A2`: `20h`가 없으면 복수 선택을 허용하고, `80h`이면 아군부터 시작한다.
- 기존 선택기 `32/9B8C..9EAC`는 화면 바깥 방향으로 이동할 때 적 전체/아군 전체로 확장한다.
  보통 전투는 적 쪽 끝에서 왼쪽으로 적 전체, 아군에서 오른쪽으로 아군 전체이며 백어택은 반대다.
  위/아래에 의한 같은 종류 집단 선택은 전체 선택과 별도 상태다. 단일 전용이면 확장을 되돌린다.
  A 확정/B 취소 및 대상 마스크·복수 대상 플래그도 원작을 따른다.

`sourceMagicTargetMode`는 등록부의 원본 115개 **공격 속성 레코드**의 위 분기를 원작 명령으로 실행한다.
이는 플레이어가 115종 마법을 사용할 수 있다는 뜻이 아니다. 회귀 검사에는 정상/백어택,
아군 일부 제외, 적 빈 슬롯, 허용/금지, 양 진영 전체 선택, 확정/취소를 포함했다.
현재 공통 선택기의 지원을 모든 직업·마법의 라이브 연결 완료로 세지 않는다.

후속 각 기술/마법/아이템 소비자는 다음 항목을 한 묶음으로 통과해야 한다:
사용 가능 직업·상태/MP → 허용 대상 및 초기 진영 → 원작 방향 입력·전체 표시 →
취소 시 비용 불변 → 확정 마스크·예약 → 실행 시 대상/위력 분산·비용 → 개별/전체 이펙트 위치.
자동 전체·소환·직업 전용기는 각각의 실제 호출자를 확인하며 수동 선택 규칙으로 대체하지 않는다.
