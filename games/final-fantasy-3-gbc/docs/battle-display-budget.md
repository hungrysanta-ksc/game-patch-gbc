# 전투 표시의 원작 소비자와 공존 예산

2026-11-24. 기준은 PR 23 병합 `21edbd66d5d081834f60c0a52f6d3c74b652d2de`.
R2의 **호스트 분석과 변환 후보 검증**이다. 전투 실행기나 GBC 표시 루프를 추가하지 않았으며,
기존 이동·한글 창·음원 런타임도 변경하지 않았다. 실제 GBC의 이번 실행/음질 개선 결과로 읽으면 안 된다.

## 재현과 근거

```powershell
node tools/audit-battle-display.mjs
node --test tests/battle-display.test.mjs
```

`local.json`의 지원 원본 ROM 해시를 확인한다. 상세 프레임/OAM 해시와 조합별 결과는
`evidence/battle-display/audit.json`에 생성하며 공개 목록에서 제외한다. 원작 주소는
설치된 역공학 스킬의 지침에 따라 주석만 인용하지 않고 ROM의 6502 함수를 실행해 대조했다.

하드웨어 근거는 사양 권위인 Pan Docs의 [OAM](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md)과
[LCDC](https://raw.githubusercontent.com/gbdev/pandocs/master/src/LCDC.md)다. 사이트 403 및 curl DNS 실패 후
같은 문서의 GitHub 원문을 읽었다. GBC는 OAM 40개·한 줄 10개, 전역 8×8/8×16 크기를 사용한다.
가로로 화면 밖에 있거나 픽셀이 투명해도 Y가 겹치면 선택 슬롯을 소비한다. 새 예산 함수는 X로
자동 제외하지 않으며 혼합 크기도 거부한다. 과거 `spriteBudget`의 화면 밖 X 제외를 새 전투 증거에 사용하지 않는다.

## 보스 206의 외부 타일 해결 범위

기존 추출기는 보스 전용 `$0700` 이후 CHR만 받았으므로 `$2A` 참조를 미해결로 보고했다.
실제 전투 초기화 `2E/9F25 → 9F98`은 PPU `$0000..$2FFF`를 0으로 지운다.
비영 값으로 채운 전송 기록 버퍼에서 원작을 실행해 12,288바이트 각각의 1회 지우기를 확인했다.
그 뒤 `A9ED`의 파티/메뉴 적재와 `A3B8/A40B`의 보스 적재를 실행해도 `$02A0..$02AF`의
마지막 기록자는 `2E/9FA0`이다. `A21E/F90A`의 18×12 지도 복사도 대조했고 참조 좌표는 `(6,10)`이다.
따라서 **초기 표시에서는 검증된 빈 타일**이며 임의 대체 그림이 아니다.

`AC66`의 석화 개구리/미니는 `$0380` 이후, `ACD7`의 석화 파티는 `$0440` 이후에 쓴다.
지형 `ADC0`는 `$0600..$06FF`, 보스 입장 `BEE0..BF75`도 `$0700` 이후를 대상으로 한다.
실행 기록은 대표 직업 0/1/2/3의 초기 적재이며 후반 특수 보스 애니메이션/CHR 은행의 전 프레임
실행 증거는 아니다. 전송 기록기는 순차 PPU 레지스터 기록만 모델링하며 PPU/IRQ 에뮬레이터를 주장하지 않는다.

명시적 외부 타일 입력 없이 호출하는 기존 추출기는 계속 미해결을 반환한다. 검증 함수만 타일 `$2A`를
공급하고, 다른 외부 타일은 빈 타일로 처리하지 않는다. 지우기 명령 변조와 `$2B` 참조를 넣은
음성 검사로 이 경계를 확인한다. 초기 적 그림 해독은 223→224 ID, 적·팔레트 조합은 250→251이다.

## 원작 마법 OAM과 8×16 후보

`33/AF6F`의 선택, `B589`의 그래픽 적재, `B696`의 스크립트 복사, `B711..B799`의 위치/뒤집기와
`B7B5`의 순서 교환을 실행한다. 원작의 256바이트 스크립트 복사 동작도 그대로 유지한다.
91 스크립트 슬롯의 435 엔트리 각각을 적/아군 대상·정면/후면으로 대조해 **1,740조건**을 검사했다.
프레임 데이터로 독립 계산한 36조각의 위치·타일·뒤집기를 원작 출력과 비교한다.
적 대상에서는 0–23번과 40–63번을 교환하므로 큰 마법의 표시 순서는 24–35, 40–63이 된다.
주석의 설명만으로 마법과 아군의 우선순위를 일괄 고정하지 않는다.

원작 대상 루프 `B6CA..B710`은 대상별 재생이다. 최대 여덟 대상의 36조각을 동시에 더하지 않는다.
이번 입력은 원작 좌표 경계의 고정 대상 1번이며, GBC로 옮길 때 적 중심 `(56,56)`과
아군 `(128,34)`를 쓰는 **표시 예산용 좌표 변환**이다. 네 아군은 원래 조각 크기로 y=10/34/58/82에 둔다.
후면은 뷰포트를 좌우 반전한다. 모든 실제 편성/타깃 위치의 배치를 결정한 것은 아니다.

| 표시 후보 | 최대 OAM | 최대 한 줄 | 40개 초과 조건 | 한 줄 10개 초과 |
|---|---:|---:|---:|---:|
| 아군 24조각 + 8×8 마법 | 60 | 8 | 468 / 1,740 | 0 |
| 아군 16조각 + 8×16 재배치 마법 | 34 | 10 | 0 / 1,740 | 0 |

8×16 후보는 뒤집기를 원본 픽셀에 적용한 뒤 같은 소유자/팔레트의 수직 이웃만 합친다.
팔레트가 다르면 별도 객체로 남긴다. 홀수 행에는 투명 여백을 넣으며 이 여백도 한 줄 예산에 포함한다.
마법의 모든 불투명 픽셀과 팔레트 값이 재배치 전후 같은지 1,740조건에서 검사했다.
이는 **후보의 호스트 픽셀/배치 검사**다. VRAM의 짝수 타일 할당, 실제 GBC 업로드/오디오 부하,
아군 모든 자세와 상태, Life 추가 오프셋, 반사, 투사체, 소환, 피해 숫자/커서는 아직 별도 관문이다.
타깃 조건/도달성도 이 카테시안 검사로 입증되지 않는다.

## 적 색 보존 후보의 실패를 숨기지 않음

기존 가운데 최근접 축소의 RGB555를 그대로 유지하고, 타일마다 두 원작 팔레트 중 하나를 BG에
배정한다. 그 팔레트에 없는 색만 다른 원작 팔레트의 투명 OBJ 마스크로 보충한다.
251조합 전부 색 복원을 검사했다. 그중 161조합·452타일은 여전히 4색을 넘는다.
8×8 보조 OBJ 최대 11개, 같은 팔레트끼리 합친 8×16은 최대 10개다.

하지만 아군 16개 + 큰 마법 18개를 예약하고 적을 y=24에 둔 보수적 공존 검사에서는
**17/251조합이 총 40개, 168/251조합이 한 줄 10개를 초과**한다. 예를 들어 적 210의
팔레트 58/114는 총 44개·한 줄 15개다. 이는 개별 최대치를 결합한 설계 거부 조건이며,
168개의 실제 플레이 전투가 깨진다는 의미는 아니다. 여러 적 동시 배치는 아직 포함되지 않았다.

따라서 이 보조 OBJ 방식은 전체 전투의 단일 해결책으로 승인하지 않는다. 선택 순서를 바꿔서
뒤쪽 그림을 누락시키거나 색을 줄이지 않는다. 보조 OBJ가 마법/아군 아래에 위치할 때의
BG 우선순위와 한글 창 가림도 실제 장면에서 확인해야 한다. 일반 7/8 및 보스 96×64의 전체
적 적용은 여전히 미승인 미술 후보이며, 이전 승인 표본의 확대 해석을 하지 않는다.

## 메모리·전송 계약과 다음 관문

- 아군/마법을 OBJ로 두면 큰 마법 때 남는 것은 총 6슬롯, 일부 줄에서는 0슬롯이다.
  적 보조 OBJ의 단독 성공을 전투 성공으로 확대하지 않는다.
- 기존 BG 제안은 한글 116 + 지형 40 + 적 셀 224 = 380타일, 두 은행의 signed BG 512타일
  중 132타일 여유다. 이 값은 상주 지도 예산이며 8팔레트 충족이나 이중 갱신 버퍼를 보장하지 않는다.
  OBJ 전용 `$8000..$87FF` 두 은행의 256타일과 공유 `$8800..$8FFF`를 중복 계산하지 않는다.
- 탐색 합성 캐시 10,240바이트가 WRAM 3/4/5, 메타데이터 1,856바이트가 은행 6을 점유한다.
  R1의 필드 중단 은행 3/전투 은행 5 예약과 동시에 상주할 수 없다. 전투 진입 시 화면 전송을
  끝낸 뒤 표시 캐시를 폐기하고 필드 논리 상태를 보존하는 **모드별 재사용 후보**로 진행한다.
  이것을 실제 구현된 전환이나 필드 전체를 초기화해도 된다는 허가로 보지 않는다.
- 다음은 40개/10개 실패 표본과 원작 큰 마법을 함께 써서, **적을 BG 안에 유지하는 색 보존 후보와
  마법 일부의 BG 합성 후보를 비교**한다. 변경 셀·팔레트·VRAM·전송량을 먼저 계산한다.
  미술 변경이 필요하면 승인 표본과 비교할 수 있는 후보를 제시하며 자동으로 아군을 줄이지 않는다.
  선택한 한 후보에 원작 프레임 순서/기간·7×7 한글 창·음원 큐를 연결해 실제 GBC에서 검증한다.
- 전투 관문과 별개로 탐색의 실시간 입력 연결·월드 링·1초대 전체 응답은 미해결이다.
  두 경로의 적용 조건을 정해야 R2를 닫을 수 있다. R3 완료나 정상 게임 전투 구현으로 세지 않는다.
  음색 개선은 후순위를 유지한다.

원시 보고서 SHA-256: `6d8f6f715554cd923e23b02965b4aee488d3aa1d0b27272312c6780d9947a7fd`.
보스 빈 타일 SHA-256: `374708fff7719dd5979ec875d56cd2286f6d3cf7ec317a3b25632aab28ec37bb`.
이 해시는 비공개 입력으로 재생성한 증거를 식별하며, 보고서/추출물 자체는 배포하지 않는다.

검증: 전체 호스트 회귀 45개 통과. 공개 허용 소스 266파일만 별도 폴더에 복사하고 원본 ROM 경로만
외부 입력으로 지정해 새 분석 및 관련 3개 테스트를 실행했다. 상세 보고서 해시가 위 값과 일치했다.
기존 추출기의 미해결 경계도 회귀 검사에 유지된다. 원본/번역/글꼴·추출물·원시 보고서는 복사하거나
공개하지 않았다. 런타임 소스 변경이 없으므로 GBC/오디오 장시간 실행을 이번 검증으로 반복하지 않았다.
