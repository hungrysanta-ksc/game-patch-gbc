# 일반맵 NPC 배치·그림·정적 포즈

2026-11-23. [일반맵 자산 공급](map-assets.md)에 원작 객체 초기화와 NPC 그림 공급을 연결했다. 사용자 ROM에서 추출한 목록과 그림을 공통 은행 디렉터리에 넣고, GBC에서 맵의 NPC 목록 ID와 GameState의 표시 플래그를 읽어 표시한다. 원본 16×16 크기와 픽셀 인덱스를 보존한다.

현재 범위는 **이벤트 적용 전 배경에 배치한 정적 NPC 검사**다. 실제 이동·충돌 판단·대화·조건 스크립트·상점·플레이어/동행 NPC·시간에 따른 애니메이션·특수 다중 슬롯 연출·사운드 전환은 연결하지 않았다. START의 두 포즈 전환은 그림 검사 기능이며 원작의 애니메이션 진행 규칙으로 사용하지 않는다. 한국어 번역/폰트 입력은 이번 변경에서 읽거나 공개하지 않았다.

## 원작 소비 계약

기준은 [everything8215/ff3 고정 리비전](https://github.com/everything8215/ff3/tree/1acef8117120ff891003de249b1a74bc8d94d674)이다. 추출 카탈로그에는 파일 오프셋·은행/주소·소비 코드·참고 행 번호·해시가 남는다. 비교 정답은 사용자 ROM의 원래 6502 명령을 실행하여 얻으며, 원본 명령을 패치하거나 성공 반환으로 대체하지 않는다. 제품 ROM에는 이 6502 실행기가 들어가지 않는다.

| 대상 | 원작 소비자 | 확인한 계약 |
|---|---|---|
| 배치 포인터 256슬롯 | `3B/B2FD..B34D` | 맵 속성 byte 4로 선택. 4바이트 레코드의 첫 byte가 0이면 종료 |
| 객체 초기화 | `3B/B34E..B3F7` | 최대 12슬롯. 원작 두 16바이트 구조를 보존. 첫 구조는 지우고, 둘째 구조의 미지정 바이트는 보존 |
| 표시 플래그 | `3B/B51A..B536` | GameState `$80..BF`. `world != 0`이면 뒤 256비트. 숨긴 객체도 원래 NPC ID/좌표/그림 정보를 유지 |
| 이동/애니메이션 속도 데이터 | `3B/B3CA..B3E6` | 512바이트, `world != 0` 분기. 저장할 뿐 이동 실행기는 아직 미연결 |
| NPC 그림 선택 | `3E/DF08..DF10, DF41..DFD3` | 512바이트 선택표. **`world >= 2`** 분기. 표시 플래그/속도의 조건과 다름 |
| NPC 그림 117블록 | `3E/DF50..DFD3` | ID 0..63: 256바이트, 64..87: 128바이트 두 번, 88..116: 64바이트 네 번 복사 |
| 일반 포즈 256바이트 | `3B/B3F8, B41A..B519; 3E/DA3A` | 4가지 위/아래 팔레트 × 4방향 × 2프레임. 타일 순서/좌우 뒤집기 보존 |
| 지형 우선순위 | `3B/AEAD..AEEA` | 지형 속성 `$14`/`$24` 마스크로 윗부분/아랫부분의 BG 뒤 표시 비트를 각각 토글 |
| NPC 팔레트 | `3A/9123..9130` | 맵 속성 byte 8/9로 두 3색 팔레트 선택. 투명 색 인덱스는 0 |

정적 좌표의 세로 기준은 `B1EE..B20F`의 캐리/빌림과 NES OAM의 실제 표시 Y+1을 합친 **타일 기준 −3픽셀**이다. 주석의 “2픽셀”만 보고 옮기지 않았다. 카메라와 화면 밖 잘라내기는 160×144 검사 화면에 맞춘 표시 정책이며 원작 이동 카메라 구현은 아니다.

### 배치 표의 미해결 영역

197개 목록(ID `$00..C4`)은 최대 12레코드와 종료 바이트를 갖는다. 나머지 **59슬롯 `$C5..FF`는 모두 `$9943`**, 즉 배치 영역 다음의 NPC 대사 스크립트 시작을 가리킨다. 빈 배치로 바꾸지 않고 비지원 포인터로 기록한다. 512개 맵 속성 레코드에는 이 59개를 참조하는 항목이 없다. 런타임 목록 요청도 이 범위를 거부한다.

정상 형식 목록 중 맵 속성표가 참조하는 것은 **188개**다. 나머지 9개(ID 70, 92, 97, 116, 117, 120, 121, 127, 160)는 추출·경계 검증을 보존하지만 정상 플레이 도달성을 주장하지 않는다. “배치 256개 완료”나 “197개 지역 구현”으로 계산하지 않는다.

## GBC 상주와 표시

- 기존 종류 0..8의 ID를 유지하고 배치·NPC 그림·선택표·속도·포즈·팔레트를 뒤에 추가한다. 합계 2,691자산, 디렉터리 13,455바이트다. 같은 원본 그림을 참조하는 NPC는 117개 그림 ID를 공유한다.
- 맵 작업 공간 `$D000..D7EE`와 `$D7F0..D7FF` 가드는 유지한다. NPC 구조는 고정 WRAM 384바이트다. GameState는 기존 1,024바이트 초기화 함수를 사용한다. 추가 WRAM 은행이나 스택 은행 변경은 없다.
- NPC 그림은 **VRAM 은행 1의 `$8000..8BFF`**에 현재 맵의 최대 12슬롯만 올린다. 기존 배경 그림은 은행 0에 유지한다. 숨겨진 NPC도 원작처럼 그림을 공급하며, 맵을 바꾸면 남은 슬롯을 지워 이전 그림이 새 맵에 남지 않게 한다.
- 8×8 OAM 네 조각으로 16×16 NPC를 구성한다. NES와 GBC의 속성 비트 위치를 변환하고, 위/아래 팔레트 및 배경 우선순위를 독립적으로 보존한다. 화면 밖 조각은 OAM에서 제외한다. CGB의 OAM 순서 우선순위를 사용한다.
- 현재 전환은 LCD를 끈 상태의 자산 검사 경로다. 지속적인 NPC/플레이어 갱신 및 기존 오디오와의 동시 부하 검증으로 계산하지 않는다.

하드웨어 근거: [Pan Docs OAM](https://github.com/gbdev/pandocs/blob/master/src/OAM.md). GBC는 전체 40개, 한 스캔라인에 10개 OBJ를 선택한다. X좌표만 화면 밖으로 보내도 스캔라인 한도에 포함되므로, 숨기는 항목은 Y도 지운다. 객체 간 선택이 먼저이고 BG 우선순위가 그 뒤에 적용되는 순서도 픽셀 비교에 반영한다.

### 밀집 배치에서 남은 하드웨어 한계

전체 768선택 프로필 × 카메라 45×47 = **1,624,320개 위치**를 모든 표시 플래그가 켜진 진단 상태로 검사했다. 전체 OAM 40개를 넘는 위치는 592개, 한 줄 10개를 넘는 위치는 45개다. 두 집합은 겹칠 수 있다. 최대치는 48개/줄당 12개였다.

| 재현 입력 | 결과 |
|---|---|
| world 1, map 86, camera (12,0), 모든 표시 플래그 | 48개 필요, 오류 12 |
| world 0, map 139, camera (0,42), 모든 표시 플래그 | 한 줄 12개 필요, 오류 13 |

검사기는 일부 NPC를 조용히 누락하지 않고 OAM 전체를 비운 뒤 배경과 오류 코드를 남긴다. **이는 해결 완료가 아니라 검출된 렌더러 한계다.** 모든 플래그를 동시에 켠 상태가 정상 스토리에서 도달 가능한지는 미확인이다. 플레이어/동행 NPC까지 추가하면 예산이 더 필요하다. 후속 작업은 실제 도달 상태의 공존 집합과 8×16 합치기 가능성(위/아래 색·우선순위가 다른 경우 포함)을 분석해야 한다. NPC 생략·색 손실·깜박임을 제품 정책으로 채택한 것이 아니다.

원작 **초기 플래그를 적용한 검사에서도 world 1/2의 map 86/87, camera (16,2)는 오류 12**가 발생했다. 따라서 한계가 전체 표시 진단에서만 생긴다고 해석하면 안 된다. 초기 플래그를 후반 월드에 적용한 조합의 정상 진행 도달성은 별도 확인 대상이며, 현재 표시기는 이 네 조합을 정상 표시하지 못한다.

## 재현과 검증

```powershell
node tools/build-objects.mjs --rom "D:/private/Final Fantasy III (Japan).nes" --gbdk "D:/tools/gbdk"
node tools/build-objects-verifier.mjs
node tools/verify-objects.mjs
npm test
```

ROM: `build/objects/ff3-object-viewer.gbc`. A/B는 맵 변경, SELECT는 월드 선택 조합 0/1/2, START는 두 기본 포즈 전환, 방향키는 검사 카메라 이동이다. 부팅 화면은 원작 초기 플래그를 사용한다. 자동 검증의 전체 표시/전체 숨김은 진단 입력이며 게임 기능이 아니다.

고정 MesenCore에서 새 홈으로 실행한다. 관측은 `evidence/objects/`에 비공개로 남긴다. 검증 입력은 로드 전 요청 파라미터뿐이며, 예상 객체/그림/OAM을 GBC 메모리에 주입하지 않는다. `--reuse`는 동일 ROM/코어 해시와 요청 목록일 때만 허용한다. 독립 에뮬레이터/실기 합격은 별도다.

최종 ROM에서 **2,321요청**을 검증했다. 768프로필에 원작 초기 플래그·전체 숨김·전체 표시를 적용하고, 두 포즈·모서리/홀수 카메라·world 255·재로딩·잘못된 목록/포즈 요청을 추가했다. **2,309개 정상 표시, 예상 오류 12개**(OAM 초과 9, 스캔라인 초과 1, 비지원 목록 1, 잘못된 포즈 1)를 확인했다. 밀집도 오류를 정상 표시 합격으로 세지 않는다.

- 원작 실행 대조: 그림 117블록, 팔레트 512개, 월드/ID 선택 65,536조합, 포즈/팔레트/지형 우선순위 2,048조합. GBC 객체 초기 상태는 요청별 원작 `B2FD` 실행과 비교하며 지정하지 않은 바이트의 보존도 포함한다.
- GBC 관측: GameState, 두 객체 구조, VRAM의 NPC/배경 그림, 배경 타일맵/속성, BG/OBJ 팔레트, **실제 OAM RAM**, 은행 복원·SVBK·작업 공간 가드. 화면 출력 중 CPU 버스 읽기는 OAM이 차단될 수 있어 Mesen의 OAM 직접 관측 경로를 쓴다.
- 캡처 21장, **483,840픽셀**이 소스 데이터 기반 예상 화면과 일치했다. 배경에 가려진 첫 객체가 뒤 객체의 선택도 막는 순서를 포함한다. `ff3-object-viewer_000.png`의 실내 NPC와 `_010/011.png`의 숲 NPC는 직접 보아 크기·얼굴·포즈·팔레트와 배경 배치도 확인했다. 캡처 홈/입력은 비공개 결과 JSON에 기록한다.
- 단위/회귀 검사 **24개 통과**. 공개 허용 소스 **133개**만 별도 폴더에 복사해 재빌드한 NPC ROM이 바이트 단위로 일치했다. 기존 맵 ROM과 필드/사운드 ROM도 이전 해시와 동일했다. 원본/추출물/번역/관측/캡처는 Git에 포함하지 않는다.

고정 ROM 사용 끝은 `$0A18`, 고정 WRAM 정적 영역 끝은 `$C651`, 객체 코드 은행 13은 2,806바이트다. 맵 작업 공간/스택 가드는 기존 배치를 유지한다. 이는 무음 검사 ROM의 사용량이며 전체 게임 통합 예산 검증으로 대신하지 않는다.

다음은 밀집 표시의 해결 조건을 추적하면서 **문자열 포인터·제어 코드·이름 치환·한글 7×7 글꼴과 창 표시**의 공급 계약을 연결하는 일이다. NPC 조건 대사/상점은 그 소비자를 이식할 때 붙이고, 대화 내용을 임의로 만든 창으로 대체하지 않는다.
