# 메모리 배치와 변경 검토

은행/주소는 현재 지원 원본에서 확인한 값이다. 다른 게임에 복사할 안전한 여유 공간 목록이 아니다.

| 소유자 | 공간 | 수명·소비자 |
|---|---|---|
| 커서 기록 | 고정 WRAM CFF8–CFFE | 두 스택 초기화의 시작을 CFF8로 낮추고 상단 7바이트를 분리, 부팅 시 초기화 |
| 한글 마스크 | WRAM7 DD80–DD87 | 글리프당 8바이트 |
| 한글 실행 코드 | WRAM7 DDA0–DFCF | 원래 텍스트/tree/metrics 뒤, 실행 경로에서 보존 대조 |
| 상태 패널 임시 공간 | WRAM7 DFD0–DFFF | 반환 전 48바이트 정리 |
| 음원 공간 | WRAM3 DF00–DFFF | 같은 CPU 주소라도 WRAM7과 물리적으로 별도 |
| 치트 설정 | WRAM6 D577 | 조합 51개는 D570–D576, 저장/로드는 8바이트, 원본 카운터는 7바이트 |
| 디버그 입력 카운터 | 고정 WRAM CE16 | 원래 입력 변수를 재사용, 필드 진입과 완료 시 초기화 |
| 숫자/지연 문자열 | C23A/C24A/C25A | 각 16바이트, 최종 확장은 WRAM7 D400 |
| 패널 타일 | VRAM1 9000–917F | 메뉴의 24타일, 외부 참조 검사 |
| 패널 타일맵 | WRAM1 D800/DC00 기반 | 열11–18/행4–6 및 대응 속성 |
| 화살표 | OAM C000–C09F | 기존 스프라이트 뒤 여유 공간에 4바이트만 추가 |

원래 WRAM7 D000–D3FF는 폰트, D400–D7FF/D800–DBFF는 텍스트, DC00부터 164바이트는 Huffman tree, DD00–DD7F는 metrics다. 이 용도를 무시하고 반복되는 00/FF를 새 변수 공간으로 쓰면 장면에 따라 손상된다.

## ROM에서 실제 발생한 충돌

- 01:4A3E부터 이어지는 네 워프 표는 치트 장소 이동뿐 아니라 일반 이벤트에서도 읽는다. 표는 보존하고 새 라벨과 헬퍼는 검토한 언어 풀로 이동했다.
- 03:7E51–7E8C 점수표의 FFFF는 빈 공간이 아니라 보조 표 선택 표식이다. 커서 코드가 들어갔던 03:7E5F를 원래 데이터로 복구하고 코드 은행을 분리했다.

두 범위는 빌드의 보호 영역이다. 현재 ledger는 비본문 쓰기 160개, 본문 3,063개, RAM 영역 21개를 확인한다. 내용 해시를 고정하므로 기존 루틴의 RAM 주소만 바꾸는 경우도 재검토해야 한다.

## 감사 범위

v026의 전체 writer와 FF 영역 22개를 포함한 낮은 ROM 쓰기를 조사했다. 사용한 고정 은행 헬퍼는 함수 종료와 은행 끝 경계, 원본 참조 후보, 실행 경로를 대조했다. 26회/178,458프레임의 두 코어 회귀에서 한글 코드 보존과 스택 표식을 관측했다. 최소 남은 스택 표식은 8바이트였다.

v027은 이 실행 코드/RAM 배치를 그대로 유지하며 지도 Y 좌표 5바이트와 체크섬만 바꾼다. 이 결과는 모든 간접 참조나 관측하지 않은 호출 깊이의 전역 안전성 증명이 아니다. ledger는 회귀 방지 장치이며 빈 공간을 자동 발견하거나 승인하는 도구가 아니다.
