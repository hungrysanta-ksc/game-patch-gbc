# 유지보수 원칙

- 지원 원본과 private input SHA-256을 먼저 확인한다. ROM/세이브/전체 원문·번역/폰트 파일을 Git에 넣지 않는다.
- 제품 빌드는 config 명세와 src만 소비한다. research의 후보 결과를 자동 채택하지 않는다.
- 모든 쓰기는 불변 원본 지문·주소·길이·내용·단일 작성자로 등록한다. 보호 영역/중첩/미등록 차이는 실패시킨다.
- FF/00 연속 영역만으로 빈 공간을 선언하지 않는다. CPU 주소에 ROM/WRAM 뱅크와 수명을 함께 기록한다.
- 실행 코드/주소 변경 시 config/memory-layout-*.json을 수동 검토한다. 빌드가 목록을 자동 승인하게 만들지 않는다.
- 기계어는 ASM 원천의 조립·역해석·재조립으로 검산한다.
- 표시 조건은 실제 소비 루틴의 조건을 따른다. 이미 보유한 보상과 그 장소의 소비 상태를 혼동하지 않는다.
- 현재 릴리즈와 과거 QA, 통제 개입과 자연 입력, 코드 검사와 사람의 플레이 검수를 구분한다.
- 공개 갱신은 export-manifest.json의 명시 목록을 갱신하고 누락/개인 경로/비공개 자산을 검사한다.
