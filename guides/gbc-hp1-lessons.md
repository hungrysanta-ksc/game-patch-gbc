# 마법사의 돌에서 얻은 GBC 한글패치 작업 원칙

[마법사의 돌 소스](../games/harry-potter-sorcerers-stone/maintenance/README.md) · [비밀의 방 사례](gbc-hp2-qa.md)

이 문서는 특정 게임의 주소를 다음 게임에 복사하기 위한 목록이 아니다. 관측 → 가설 → 판별 검사 → 원본 조건에 맞춘 수정 → 회귀의 순서를 재사용한다.

## 1. FF는 소유권 증거가 아니다

기숙사 점수표의 FFFF가 빈 공간처럼 보였지만 실제로는 보조 표를 선택하는 값이었다. 새 커서 코드가 여기에 들어가면서 진행도에 따라 숫자가 수만 점으로 바뀌었다. 정적 즉시 주소 검색에 안 잡히더라도 계산된 포인터로 읽힐 수 있다.

빈 공간 후보에는 앞뒤 함수 경계, 원본 테이블 구조, 참조를 만드는 코드, 호출·인터럽트·저장/로드 수명을 함께 기록한다. 원본과 같은 FF인지 확인하는 expected byte 검사는 필요하지만 공간을 사용할 권한의 증거는 아니다.

## 2. 메뉴 이름으로 데이터의 소비자를 판단하지 않는다

원래 장소 이동 치트가 사용하는 표는 일반 금고 동행 이벤트도 사용했다. 메뉴를 지웠다고 표까지 폐기할 수 없었다. 기능 제거 시 코드·자료의 다른 소비자까지 확인하고, 공유 자료는 보호 영역으로 고정한다.

## 3. 주소에는 뱅크와 수명을 붙인다

WRAM3의 음원 영역과 WRAM7의 같은 CPU 주소는 다른 공간이다. 반대로 고정 WRAM 끝은 스택이 내려올 수 있다. 커서처럼 장면을 넘는 값은 임시 문자열 버퍼에 저장하지 않는다. 스택 위에 예약할 때는 모든 스택 초기화와 부팅 초기화 경로를 함께 바꾼다.

등록된 주소뿐 아니라 실행 코드 내용도 해시로 검토 목록에 묶는다. 기존 헬퍼 안의 RAM 주소 하나를 바꾸어도 재검토를 우회할 수 없게 한다. 목록을 자동 재생성하여 새 쓰기를 스스로 승인하지 않는다.

## 4. 표시 조건의 권위는 실제 소비 루틴이다

이미 보유한 카드 조합과 그 장소에서 받을 보상의 소비 여부는 다른 상태다. 선택한 덱에 따라 장소별 발견 슬롯이 다를 수도 있다. 소지품 이름이나 사용자 눈에 보이는 완료 표시를 추측해서 판정하지 말고, A 입력이 실제 읽고 쓰는 변수를 확인한다.

일반 아이템, 약초, 카드 조합, 퀘스트 재료, 주문·제조법은 서로 다른 경로일 수 있다. 배치 목록·이벤트 진입 조건·지급 명령·완료 변수의 연결을 추적하고 유사 opcode만으로 무차별 표시하지 않는다.

## 5. 표시와 접근 가능성은 따로 검사한다

화살표가 맞는 보상을 가리켜도 사각형이 벽 안에 있으면 조사할 수 없다. 보상 슬롯이 이미 FF인지, 액터 위치와 캐시된 충돌 사각형이 일치하는지, 플레이어가 실제로 어디에서 멈추는지 분리해서 본다.

좌표만 실시간으로 바꾸면 초기화 때 만든 캐시 사각형이 남을 수 있다. 데이터 레코드를 바꾼 뒤 정상 맵 로드로 확인한다. 네 방향과 주변 좌표도 비교해 좁은 우회 경로가 있는 사례를 완전한 획득 불능으로 과장하지 않는다. 최종 수정은 접근 가능한 방향의 최소한의 데이터 변경으로 제한한다.

## 6. 공용 타일도 공급 경로로 확인한다

화살표처럼 생긴 지역 타일 번호를 사용하면 맵을 바꿨을 때 다른 그림이 된다. 공용 폰트/대화 자산이 언제 어느 VRAM 뱅크에 올라오는지 확인한다. 원래 OAM을 모두 사용한 뒤의 여유만 쓰고 스프라이트 예산·상단 경계·장면 전환도 검사한다.

## 7. 번역의 공백은 구조일 수 있다

설명 앞의 두 공백과 줄바꿈을 소비자가 미리 건너뛰는 경우가 있었다. 불필요해 보이는 공백을 없애면 첫 한글 코드가 잘려 보인다. 원문 제어 코드와 선행/후행 공백, 변수 토큰을 보호하고 실제 소비 규칙에 따라 정규화한다. 문구를 짧게 만드는 것으로 기술 버그를 가리지 않는다.

## 8. 세이브 수리는 좁은 증거에 묶는다

과거 버그가 계산한 값이 저장되어 있으면 ROM만 수정해도 저장 숫자는 남는다. 일반 로드의 서명/체크섬 검증 뒤, 정확한 손상 패턴과 유효한 진행 조건이 맞는 경우에만 재계산한다. 높은 수치 전체를 이상값으로 간주하지 않는다. 정상·비대상 상태 보존과 수정 대상 바이트 외 무변경을 검사한다.

## 9. 검사 종류를 분리한다

불변 원본 기반 빌드, 기계어 왕복, BPS 재적용, 실제 CPU 하네스, 정상 입력 경로, 사람의 플레이 검수는 서로 다른 증거다. 통제된 위치·재고·퀘스트 상태는 개입으로 기록한다. 두 코어에 같은 입력을 적용하고 차이가 있으면 애니메이션 위상과 텍스트/상태 차이를 구분한다.

세이브로 시작한 경로는 입력 SAV의 해시도 묶는다. 이전 ROM의 savestate는 코드까지 복원하므로 수정 ROM 검증에 사용하지 않는다. 게임 내 저장→리셋→이어하기로 지속 상태를 확인한다.

## 10. 배포와 지식을 함께 재현한다

공개 버전과 내부 빌드를 분리하고 최종 ROM의 지문을 고정한다. 배포 파일을 다시 원본에 적용해 전체 바이트를 비교한다. ZIP은 명시 파일 목록으로 만들고 ROM/세이브/개인 경로를 넣지 않는다.

소스·명세·ASM·회귀 도구·검증 범위를 남긴다. 공개할 수 없는 번역/폰트 입력은 경로와 해시만 남기고, 공개 소스만으로 완전 빌드되는 것처럼 설명하지 않는다. 참고 사례의 주소와 수치는 현재 게임에서 재검증해야 한다.
